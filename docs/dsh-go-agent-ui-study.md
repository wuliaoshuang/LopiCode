# 读 dsh-Go：一轮里的多次工具调用怎么显示、确认卡长什么样、引擎多做了什么

2026-11-24。霜霜的原话：多轮工具调用的界面“在聊天窗口里拉屎，要不就聚在一起，要不然就做好看点”，确认卡“配色太垃圾”，学 dsh-Go。

读的是源码 `~/workspace/reference/dsh-go`（AGPL）。**只学做法和交互，代码、文案、素材都是自己重写的，没有复制。**
下面每一条标了：**源码所见**（直接读到）/ **推断**（从字段、补丁上下文反推）/ **未知**。

一个要先说的事实：dsh-Go 的 Agent 引擎主体是一个 npm 包（`@deepseek-ai/dsh`），**源码不在仓库里**，仓库里只有给它打的约 180 个补丁、
客户端协议（`packages/dsh_client`）、设置样本，以及另一套完整的 Dart 小 Agent（陪伴角色用，`app/lib/companion/`）。
所以“界面”部分是完整读到的，“引擎”部分有不少只能推断。

## 一、界面（`app/lib/ui/chat/`，源码所见）

### 1. 一轮里的多次工具调用

- 聊天列表不是“一条记录一行”，而是先用一个纯函数把记录**折成行**再画（`chat_rows.dart`）。
- 连续 3 次以上的工具调用折成一个“工具组”：标题是一句汇总（执行了几条命令、读了几个文件……），失败数用红色小标，
  **正在跑的和等确认的那一行露在折叠标题下面**。
- 一轮**正常结束**后再折一层：思考、工具、中间说的话全部收进一行很安静的“已完成 · N 次工具调用 · M 条消息”，最后的回答留在外面。
  被停止或出错的轮次不折，方便看停在哪。
- 汇总的数法（`turn_summary.dart`）：命令数；读、改的文件按路径去重，失败和被拒绝的不算；搜索、联网、子代理、待办各自计数；失败单列。
- 每一行工具调用是同一种“行”的骨架（`stream_row.dart`、`tool_row.dart`）：左边一个小图标，动词 + 等宽的对象，右边只有状态
  （转圈 / 失败 / 已拒绝 / 等待确认），成功不标。点开是参数和结果，放在代码底色的小块里，限高，可“查看全部”。子代理那一行点开是子对话。
- 模型在工具之间说的话：轮次做完后和工具一起收进折叠行；展开时按原来的顺序夹在步骤中间。
- 思考过程（`thinking_pill.dart`）：也是同一种行，默认收着。
- 输入框上方有一条“正在做什么”的活动条和一条待办条（`dock/todo_bar.dart`：“已完成/总数 + 当前项”，点开是清单）。

### 2. 确认卡（`approval_card.dart`、`chat_card.dart`）

- 所有卡片共用一个卡壳：中性底、大圆角、统一内边距。**颜色只出现在标题图标和一条细线上**，没有整块色底。
- 标题直接是问题；命令放等宽小块里，前面带 `$`；原因用更浅的字。
- 两个等宽按钮：拒绝（描边）、允许本次（实心，卡上唯一的主色）。“本对话都允许”降成一个小文字按钮，点了还要再确认一次风险。
- 引擎给的审批请求里**没有风险等级字段**（`packages/dsh_client/lib/src/models.dart`）；“本对话都允许”是 App 自己做的
  （之后的请求自动回“允许一次”），引擎层没有“始终允许”。

## 二、引擎（多数是推断；详见各条）

| 方面 | dsh-Go | 把握 |
| --- | --- | --- |
| 步数上限 | 协议和设置里都没有“到步数上限”这个概念，靠取消、压缩、重复提醒兜底 | 推断 |
| 工具出错 | 失败作为**工具结果**回给模型（带 `isError`），不是整轮失败；另有一份只给人看的原因 | 源码所见（协议） |
| 参数 JSON 坏了 | 主引擎当成“模型接口返回格式错误”，默认**不在**可重试清单里；陪伴 Agent 则是半截或畸形的工具调用一律不执行 | 源码所见（补丁上下文、companion） |
| 输出被截断 | 因长度上限截断时，工具调用即使看起来完整也不执行 | 源码所见（companion） |
| 接口出错重试 | 默认最多 5 次；可重试的是空回复、限流、服务端错误、超时、传输错误；退避起点 500ms、封顶 10s、带抖动；流 5 分钟没数据算断；每次重试有事件，界面显示“正在重试” | 源码所见（设置样本）；是否指数退避是推断 |
| 工具结果过长 | 旧的工具结果超过约 8K 字符就只留头 4096 + 尾 1024；命令输出超长留尾部，完整内容转存成文件并告诉模型路径；读文件按窗口读 | 源码所见（预设配置、补丁）；提示语原文未知 |
| 上下文快满 | 有自动压缩（生成摘要再替换）和手动 `/compact`，另有“裁旧工具结果”一步；界面有上下文小环和“正在压缩” | 源码所见有这几块；触发阈值、摘要提示词未知 |
| 并行 | 同一轮的工具调用并行执行，默认最多 10 个，可调；哪些能并行、写操作是否互斥未知 | 源码所见（设置）/ 未知 |
| 重复调用 | 有专门的“重复工具提醒”模块：参数按键排序规范化后比较，到阈值往上下文里插一条提醒；阈值、是否会打断未知 | 源码所见 / 推断 |
| 待办 | 工具每次整表重写，每项只有“内容 + 状态（没做 / 在做 / 做完）”；下一轮开始时清空，本轮结束不清；计划模式里不许用 | 源码所见 |
| 思考内容 | 存成 assistant 消息里的一个内容块；下一次请求把服务商原样的回放数据带回去；出错的回复不保存 | 源码所见有这套机制；字段细节未知 |
| 审批 | 回答只有“允许一次 / 拒绝 / 让给别的客户端”；被拒绝的调用以失败结果回给模型；轮次取消时撤卡 | 源码所见 |

## 三、我们这次怎么做

### 照 dsh-Go 的做法做的

- 聊天列表先折成行再画（`lib/session/chat_rows.dart` 的 `deriveChatRows`，纯函数；存盘格式一点没动，旧对话打开就是新样子）。
- 一轮里的工具调用和中间的话收成一个“步骤组”，回答留在外面；汇总按路径去重、失败和被拒绝的不算读 / 改。
- 步骤行：图标 + 动词 + 等宽对象，右边只标异常状态；点开看参数与结果，长结果先截断、可“显示全部”。
- 确认卡：中性卡壳，颜色只有一小处；命令放等宽小块带 `$`；主按钮只有一个；“本对话都允许”降成小文字按钮。
- 工具出错回给模型而不是整轮失败（原来就是这样，这次把错误说得更清楚）；截断的调用不执行；参数规范化后比较重复调用；
  接口临时出错自动重试并在界面上说明；裁旧工具结果；同轮只读工具并行；待办清单整表重写、输入框上方一条。
- 思考内容存下来、带回去（细节按 DeepSeek 官方文档，见 `docs/api-notes.md`）。

### 自己定的（和 dsh-Go 不一样，或它那边看不到）

- **一组而不是两层**：dsh-Go 是“3 个以上折成工具组”再加“轮次做完整体再折”两层；我们只有一层——同一段里从第一个到最后一个工具调用
  （含中间的话）就是一组，进行中显示“现在在做什么 + 第 N 步”一行，做完折成“执行了 N 步 · 读 … · 改 … · … 条命令”。
  只有 1 步时不套组，直接是一行。理由：手机上一行只做一件事，两层折叠要点两次。
- 折叠时**失败 / 被拒绝的步骤露在外面**（最多 2 条），再多看红色计数。dsh-Go 露的是“正在跑 / 等确认”的；我们进行中本来就只显示当前这一步。
- 被停止或出错的轮次我们**也折**（dsh-Go 不折）：失败的步骤已经露在外面了。
- **危险程度三档（普通 / 需留意 / 危险）是我们自己加的**，dsh-Go 的审批请求里没有这个字段。它只影响卡上那一个小圆点和一句说明，
  **不影响要不要确认**（`lib/agent/approval_risk.dart`，纯显示）。判断规则是一张简单的关键字表，可能有漏判、误判。
- “本对话都允许”点了**没有**加二次确认（dsh-Go 有）：这会改交互流程和现有测试的断言，这次只改外观，留给霜霜定。
- 重复调用：dsh-Go 只提醒；我们更硬一点——同样参数连续失败 2 次后，第 3、4 次不再真的执行、直接告诉模型换办法，第 5 次整轮停下；
  连续成功 4 次（比如反复读同一个文件）只提醒一句。数值是自己定的。
- 重试：最多 2 次（1.5 秒、6 秒），而且只在一个字都没回时重试。比 dsh-Go 的 5 次保守，免得在手机上干等。
- 工具结果兜底上限 24000 字符（头 70% + 尾 30%）；上下文估算到 85% 时把较早的长工具结果换成一句占位，最近 6 条不动。数值自己定的。
- 只读工具一批最多 4 个并行（dsh-Go 默认 10）；写文件、删除、执行命令仍然一个一个来，顺序不会被只读的越过。
- 待办：同一时间只许一项“在做”（dsh-Go 的预设允许多项）；最多 20 条；发了新消息清单就不再显示。计划模式下也能用（它只是记一笔）。
- `read_file` 加了按行号读一段（`start_line` / `end_line`），这样长文件被截断后模型有办法接着看。dsh-Go 的分页参数名未知，这是自己设计的。

### 没做的

- **自动压缩（生成摘要）没做**：只做了“裁旧工具结果”这一步；真正的自动摘要要多调一次模型、多花钱，而且摘要失败的处理要想清楚，留到下一轮。
  手动 `/compact` 和 80% 时的提醒照旧。
- 思考过程**不显示**在聊天里（只存、只带回）。
- 命令输出超长时转存成文件、把路径告诉模型：没做（现在是截断）。
- “等结果时 App 被杀”的未知结果提示、发消息的幂等重发、输入框上方的活动条：没做。
- 步数上限仍是每轮 12 步（dsh-Go 似乎不设上限），没改。
