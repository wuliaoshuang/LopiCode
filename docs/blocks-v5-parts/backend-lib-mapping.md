# 后端积木改写成库：对照表

（核心 2 第 5 段，2026-11-26，分支 v5r2-core。这一份是给霜霜看的，下一轮“库 1”照它动手。这一轮**没有**改任何一块现有后端积木。）

## 先说结论

- 现在后端积木页里“最早的那一批”积木一共 **34 种：12 种语句、22 种值**（从代码里数的，`lib/backend/backend_blocks.dart`，和设计文档写的一致）。
- 改写以后，其中 **15 种**（6 种语句、9 种值）搬进一个叫“**接口服务**”的库里，成为库里的积木；另外 **19 种**（6 种语句、13 种值）本来就不是后端专用的（设变量、如果、重复、运算、拼文字……），归到“**语言核心**”，哪个环境都能用。这两个数也和设计文档一致。
- **你看到的样子不变**：积木的名字、颜色分类、槽的位置、读出来的那句话都不动；旧文档照常打开、照常生成、行为不变。变的只是“底下由谁来实现”——从写死在应用里，变成由库来提供。
- 现在后端积木页里其实不止这 34 种。后来加的还有 72 种（见最后一节“这张表以外的积木”），它们当初就是照“语言核心”做的，改写时不用搬家。
- 这一轮顺手做了一件给“库 1”探路的事：把“接口服务”这一层按现在的规矩，用严格规矩的积木语言写了一遍（只在测试里），拿现有一致性样例里只考“服务”这一层的 74 条请求去跑，**五种语言里 Node、Python、PHP、Go 74 条全对，Java 73 条对、1 条先没比**（原因见“风险”）。也就是说：“接口服务库用语言核心＋几个宿主接口就能拼出来、行为和现在逐字节一样”这件事，已经真跑验证过一大半。

名词解释（只这三个）：

- **语言核心**：变量、如果、循环、运算、列表、字典、文字这些“哪种程序都要用”的积木。
- **库**：一包积木。“接口服务”是我们自己写的第一个库；以后你也能自己写库。
- **宿主接口**：库没法自己拼出来、必须由手机或服务器替它做的那几件事（开服务、读写一小块存储、写一行日志、现在几点、请求别的网址……）。到这一轮为止一共 14 个，五种语言都有、都真跑过。

**原来不是积木、以后是库积木的两样**：文档里的一个“接口”（GET /todos 那一行）→ 库里的帽子积木“当收到请求”；文档里的“端口”→ 库的设置项。它们在界面上也保持现在的样子（接口还是一张卡片、端口还是设置里的一行）。

## “接口服务”库会长什么样

**库里的积木（17 块）**

- 帽子：当收到 [方式▾] [路径] 的请求（下面接一串积木）。
- 回应 2 块：返回数据、返回文字。
- 读请求 5 块：路径参数、网址参数、请求内容的字段、整个请求内容、请求头。
- 集合 7 块：加一条、改一条、删一条、全部、一条、符合的、有几条。
- 网络 1 块：请求别的网址（成功后/失败后）。
- 另有 1 块给会写库的人用的：“回应（状态码、说明、内容）”——上面两块“返回…”都是它包出来的。

**库里的类型（3 个）**

- “请求”：方式、路径参数、网址参数、请求头、请求内容。
- “回应”：状态码、几行说明、内容。
- “一条记录”：一个字典，一定带编号 id。

**设置项（2 个）**

- 端口（默认 8080；服务器上设了 PORT 就听 PORT 的）。
- 集合的名单（现在文档里的“数据集合”那一栏）。

**写死在库里、不让改的规矩**（都是现在就有的，原样搬）：请求内容最大 1MB；允许别的网站来请求；找不到接口回 404、方式不对回 405、出错回 500；一串积木走完没返回就回“没有内容”（204）。

## 用户自己写库是怎么回事

一个库就是一包“你自己定义的积木”。定义一块积木有四种办法，各举一个例子：

1. **调一个函数**：你用积木拼了一个函数“算折扣（原价、几折）”，把它公开，别人的积木盒里就多出一块“算折扣 [原价] [几折]”。
2. **调对象的方法**：你做了一个类“购物车”，它有个方法“加一件”，积木盒里就多出“[购物车] 加一件 [商品]”。
3. **调类自己的方法**（不用先造对象）：类“日期”上有个“今天”，积木盒里就多出“日期 的 今天”。
4. **一段模板**：你想要一块“重试 3 次…”这样中间能塞积木的，就写一段“用的时候原地换成这几块”的模板。（能塞积木的口、能往变量里放结果的槽，都只能用这种。）

用户库默认只能用语言核心和别的库拼；“带一段手写代码”默认关着（你定过的）。

## 风险和这一轮查出来的事

- **Java 的“开服务”要换**：Java 自带的那个服务，碰到网址以两个斜杠开头的请求会自己回“请求不对”，到不了我们的积木（现有后端当初就是因为这个自己写了一个）。74 条里就这 1 条在 Java 上没比。库 1 接通之前要把 Java 这一个宿主接口换成自己读请求。
- **宽松和严格的差别集中在“运算 / 比较”“如果”“有几个”这几块**：135 条里另外 61 条考的就是这些宽松规矩（文字当数字加、除以 0 得 0……）。旧文档只要留在旧规矩里就照旧；升级到严格规矩的文档，这些地方会提示要改——这是升级的本意，不是出毛病。
- **这一轮没做到的**：严格规矩的文档现在还是不能生成、不能启动，“升级到严格规矩…”入口仍然关着。原因和已经做到哪一步，见 `B-gen-notes.md` 第 15 节。

## 这张表以外的积木（不用搬家）
