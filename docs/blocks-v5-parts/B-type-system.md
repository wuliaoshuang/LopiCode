# B · 类型系统

（积木第 5 版基础设计的 B 部分。只做设计和验证，没改任何产品代码。验证原型在 `docs/blocks-v5-prototypes/types/`。写于 2026-11-25。）

## 0. 结论摘要

1. **类型一共 17 种，第一版做 14 种**：整数、小数、文字、是否、空、可空、列表〈T〉、字典〈V〉（键只许文字）、记录、函数类型、枚举、带标签的联合（下面叫“变体”）、类与接口、泛型（函数的和类的）、任意、永不（只在内部用）。**后置 3 种**：元组、随便两个类型的联合（A|B）、整数当字典键。理由都是“Go 或 Java 表达不了，硬做就得绕回小库，等于没类型”。
2. **数字分成整数和小数。** 整数范围定成 ±9007199254740991（JS 能精确表示的最大整数），加减乘超出范围就报错“整数超出范围”，不悄悄算错；`/` 永远得小数；整除向 0 取整；余数的符号跟被除数；除以 0 报错。这套规矩在 Node、Python、Go、Java 上用 2000 组随机数对拍过，逐字节一致。
3. **类、接口、记录、枚举、变体按名字认（名义化）；函数类型按形状认（结构化）。** 因为 Java 和 PHP 只认名字，按最严的那个统一，Go 和 TS 自然满足；反过来不行。
4. **不标类型照样能用。** 变量、返回值、匿名函数的参数、泛型调用的类型实参、空列表里放什么，全部自动推出来。没标类型的函数参数：自己文件里的函数从所有调用它的地方反推；要导出给别人用的库函数必须标全。验证程序 `p13` 里 5 个函数一个类型都没标，推出来的 Go / Java 代码照样是原生类型。
5. **“任意”遇到确定类型：检查，不对就报错**（不再悄悄转换）。旧文档不受影响，靠“规矩版本”区分：旧文档＝版本 1，行为一个字不变；新建的文档＝版本 2，用上面这套严格规矩。**这条要霜霜拍板。**
6. **槽的形状不加新的**，还是圆头和六边形两种。类型不对**允许放下**，但标红并给“一键修”。390 宽上默认不显示类型标签，点一下积木才在底部说明条里显示。第 6 节给了 10 条提示语原文。
7. **映射表**见第 7 节。表达不了的地方各有办法：Go 没有可空基本类型 → 指针；Go / Java 没有联合 → 只做带标签的；PHP 没有泛型 → 只在设计期查；Java 没有类型别名 → 展开；Go 没有继承 → 接口＋内嵌结构体＋一个指回自己的字段（验证过）。
8. **运行时检查一共 9 处**（第 8 节），每处的错误文字五种语言用同一句。原型里四种语言实测一致，PHP 没跑。
9. **兼容**：`LType` 从“一个标签加一个里面的类型”长成“标签加一串类型参数加名字”；老的 10 个标签原样保留。新增 18 条校验规则，另起 **T 开头**（T01–T18）。文件级返工量估计见第 10 节，语言核心这一层大约 15–20 个工作日（估计，没有实测依据）。
10. **生成策略**：只有“原生写法对所有输入都和小库结果一样”的运算才写原生（小数的加减乘、比较、是否运算、文字拼接）；整数的加减乘、所有除法、下标、文字比大小都走带类型的小库小函数。这样“开不开类型优化结果一样”是规则保证的，不是靠运气。

**验证做了什么**：16 个能跑的小程序＋4 组故意写错的例子（24 处错）。每个程序事先手写预期输出和手工推断结果，再按映射表手写 Node、Python、带原生类型的 Go 和 Java，真编译真跑，四份输出逐字节对比。另写了一个约 1100 行的推断原型脚本，自动推断结果和手工结果对比。做了两轮：

- **第一轮**发现 16 个问题（Java 编不过 2 次、Go 编不过 1 次、我自己手工推断错 1 处、预期写错 1 处、规则没说清 3 处……），当时全跑 72 项通过、7 项不符。
- **第二轮**改了设计（加“代码名”、补 3 条推断规则、定“容器装进任意＝快照”），重写受影响的 5 个程序、新加 1 个，最后一次全跑（2026-11-25 20:17 开始）**84 项全部通过、0 项不符**。

**没做到的**：TypeScript 和 PHP 一行没跑（机器上没有，也不许装）；第二梯队六种语言的对照表全部没核对；推断原型没覆盖元组、可选参数、“是某类”的收窄、库的导出；“稍后的结果〈T〉”只给了映射，没验证。

**缺口 14 条**（GAP-B-1 到 14），**要改骨架 2 处**，**要霜霜拍板 3 件**，都在文末清单里。

## 1. 现在是什么样（读代码看到的）

- `lib/lang/types.dart`：10 个标签（任意、数字、文字、是否、空、列表、字典、函数、对象、稍后的结果）加一个“可以是空”。合并规则是“说不清一律任意”，冲突规则是“有一边是任意就不算冲突”。
- `lib/lang/analyze.dart`、`analyze_module.dart`：推断走两遍，变量类型＝所有赋值合并；**没标类型的参数一律任意**；匿名函数的返回类型不看上下文；读外层变量一律任意；没有“判断过就收窄”。
- `lib/lang/ast.dart`：参数、返回值、字段上能存类型标注，但**只存不用**。
- `lib/lang/gen_go.dart`、`gen_java.dart`：值一律 `any` / `Object`，运算一律 `lc.Add(…)`。所以现在生成的 Go 和 Java“看起来不像 Go 和 Java”。
- `lib/lowcode/logic_validate_types.dart`（规则 G10）：只有 数字 / 是否 / 文字 / 任意 四种，确定对不上才报。
- `lib/blocks/block_drag.dart`：槽只有圆头和六边形两种形状；不是“是否”的东西放进六边形槽**只是警告，不拒绝**。
- 现有的值的规矩（`lib/backend/backend_ir.dart`）：除以 0 得 0、算不出来得 0、文字自动变数字。这是“宽松”的一套，旧文档都靠它。

问题出在哪：类型只有“标签”没有“里面是什么”（列表里放的什么不知道）、没有泛型、没有记录、不会从用法反推，所以生成强类型语言时只能全部退回 `any`。

### 2.2 整数和小数：为什么分、规矩是什么

**为什么必须分**：Go 的 `int64` 和 `float64`、Java 的 `long` 和 `double` 不能混着算，下标必须是整数。不分的话，“第 i 项”这种最普通的积木在 Go 里也得走小库。

**难点**：五种语言的整数各不相同——

| | 整数有多大 | 加减乘超了会怎样 | 整数 / 整数 | 余数的符号 | 除以 0 |
| --- | --- | --- | --- | --- | --- |
| JS | 没有整数，只有双精度小数，精确到 ±(2^53−1) | 悄悄变得不精确 | 得小数 | 跟被除数（未核对文档，本机实测） | 得无穷大 |
| Python | 没有上限 | 不会超 | `/` 得小数，`//` 向下取整 | 跟**除数** | 报错 |
| Go | 64 位 | 悄悄绕回去 | 向 0 取整 | 跟被除数 | 整数崩溃，小数得无穷大 |
| Java | 64 位 | 悄悄绕回去 | 向 0 取整 | 跟被除数 | 整数报错，小数得无穷大 |
| PHP | 64 位 | 悄悄变成小数 | 能整除得整数，否则得小数 | 跟被除数 | 报错 |

（来源见文末；JS 和 PHP 的几项只在第三方页面或本机看到，已标明。）

**定下来的规矩**（严格规矩，即规矩版本 2）：

1. **整数的范围是 −9007199254740991 到 9007199254740991。** 这是 JS 能精确表示的范围。范围取最小的那个语言，其他语言才能跟它一致。
2. **整数的加、减、乘：结果超出范围就报错“整数超出范围”。** 不悄悄算错。四种语言各写一个小函数：先算，再查范围。加减在 Go / Java 的 64 位整数里不会溢出，先算再查就行；乘法会溢出（两个范围内的数相乘最多约 8.1×10^31），所以 Go / Java 先用小数估一下大小，差得远直接报错，接近的再做整数乘法后查范围（原型里这么写的，`p01` 试了边界，`p15` 随机对拍过）。
3. **`/` 永远得小数**（`7 / 2 = 3.5`，`6 / 3 = 2`）。两边是整数就先变成小数再除。这样不用记“整数除法会丢小数”这件坑事。
4. **“整除”**向 0 取整（`-7 整除 2 = -3`）；**“余”**的符号跟被除数（`-7 余 2 = -1`）。选它是因为 Go、Java、JS、PHP 四家天生如此，只有 Python 要多写一个小函数。
5. **除以 0 一律报错“除以 0”**，包括小数除以 0。理由：小数除以 0 得“无穷大”对新手没有任何用处，只会让错误晚一点、在别处冒出来。
6. **小数的加、减、乘按双精度原样算**，不检查。算出无穷大或“不是数”时，写出来统一是 `无穷大`、`-无穷大`、`不是数`。
7. **整数用在要小数的地方自动变过去**（“加宽”）；反过来必须用“取整”积木。整数和小数混算，结果是小数。
8. **整数只是“写程序时知道的事”**：装进“任意”以后它就是一个普通数字；从“任意”里拿出来当整数用时检查一次（必须是数字、没有小数部分、在范围里）。这样 JSON 里的 `12` 和 `12.0` 是同一个东西，不会因为“这个 12 到底是整数还是小数”打架。
9. **数字的写法**（变成文字时）：整数原样写；小数最多写 12 位有效数字、去掉末尾的 0（所以 `0.1 + 0.2` 写出来是 `0.3`，`7 / 3` 写出来是 `2.33333333333`）。这条沿用现有规矩，只把“多大以内算整数原样写”的界线从 10^15 改成整数范围。**注意**：这条我自己都写错过一次预期（见第 12 节 F11），写库的人更容易忘，标准库里要有一个“原样写出小数”的函数给需要的人用（GAP-B-8）。
10. 位运算后置。

**验证**：`p01-numbers`（手挑的边界）和 `p15-fuzz`（2000 组伪随机数，整数加减乘、整除、余，小数加减乘除，其中 36 组除以 0），四种语言校验和一致。

### 2.3 文字

按“码点”算（一个汉字、一个表情都算一个字），沿用现有规矩。**文字比大小、排序按码点顺序。** 这一条 JS 和 Java 自带的比较做不到（它们按另一种内部编码比，`ｚ` 和 `😀` 的先后会反过来），必须走小库——`p04`、`p07` 里专门放了这两个字验证。

### 2.4 列表和字典

- **列表〈T〉**：位置从 0 数。**取第 i 项越界就报错**，类型是 T 而不是 T?（否则每次取项都要判空，没法用）；另给一块“取第 i 项，没有就是空”。
- **列表不能“向上变”**：列表〈整数〉不能当列表〈小数〉用。因为列表能改——要是允许，别人往里放一个 2.5，原来那头就坏了。要转就用“映射”造一个新的。
- **字典〈V〉**：第一版键只许文字。理由：JSON 的键只能是文字；JS 的对象、PHP 的数组对“数字当键”各有各的怪规矩；Go 的 `map` 遍历顺序不固定。内部存成“字典〈文字, V〉”，以后放开不用改存盘格式。
- **取字典里的值得到 V?**（可能没有这个键）。和列表相反，因为“键不在”是正常情况，“越界”是写错了。
- **遍历字典按键的码点从小到大**（沿用现有规矩）。Go 要先取键再排序，Java 用带比较器的 `TreeMap`。

### 2.5 记录

- 必须先声明、起名字（“用户：名字 文字，年龄 整数”）。**不做没名字的记录类型**——没声明就用花括号写的，还是字典〈任意〉。理由：Go、Java、PHP 的记录都得有名字，匿名的要靠生成器起怪名字，报错时用户看不懂。
- **建好以后不能改**，要改用“复制并改”（得到一份新的）。理由：这样 Go 里按值传的结构体、Java 的 `record`、别的语言里按引用传的对象，行为才一样——都“改不到别人手里那份”。
- **相等按内容比**。各语言自带的比较规矩不一样（第 12 节 F3），所以四种语言都生成自己的比较函数。
- 不可变是“浅”的：记录里有个列表字段，那个列表还是能加东西（GAP-B-14）。

### 2.6 联合：只做三种

1. **可空**（T 或 空）。
2. **枚举**（几个固定名字之一）。
3. **变体**（带标签的联合）：“形状＝圆(半径) 或 矩形(宽, 高) 或 点”。配一块“分情况”积木，**必须每种情况都写到**，或者写“其余”。

**不做“随便两个类型的联合”（整数|文字）**。理由：Go 和 Java 里没有对应的东西，只能退回 `any` / `Object` 加运行时判断，那就是“任意”——不如直接让用户用“任意”加“是不是文字”判断。TS 的库里大量用到这种联合，那是“TS 专属库的原生绑定”要解决的事（GAP-B-12 相关），不放进语言核心。

### 2.7 泛型

- **泛型函数**：`第一个〈T〉(列表〈T〉) → T?`。**调用的人永远不用写〈…〉**，全靠推断。定义的人（写库的人）必须把签名标全。
- **泛型类、泛型记录**：`栈〈T〉`、`状态〈T〉`。新建的时候通常也不用写〈…〉（`新 状态(0)` 自动是 状态〈整数〉）；实在没线索时（`新 栈()` 而且后面也没往里放东西）才要写。
- **约束只有三种**：“能比大小”（整数、小数、文字）、“能当字典的键”（第一版只有文字，留着位置）、“实现了某接口”。
- **类的方法不许自己再带类型参数**。理由：Go 到 1.26 为止都不支持（Go 官方博客说 1.27 才加），本机是 1.25。需要的话写成普通泛型函数（GAP-B-10）。
- PHP 没有泛型：类型参数在 PHP 里全部擦掉，只在设计期检查。

### 2.8 类和接口

- 单继承。**类默认不能被继承**，要勾“可以被继承”。理由：Go 没有继承，能被继承的类在 Go 里要多生成一层（见 7.3）；默认关掉，大多数类就是一个普通结构体。
- 接口必须写明“实现了某接口”（Java、PHP 要求；Go、TS 不要求但写了也不矛盾）。

### 2.9 任意、永不

- **任意**保留，是“渐进式”的出口：旧文档、JSON 解析结果、宿主给的数据都是任意。
- **永不**只在内部用，用户看不到。两个用处：一是“一定会抛错”的式子；二是**已经报过错的式子**记成永不，后面碰到它的检查都不再报——保证一处错只说一句（第 12 节 F14）。

### 2.10 函数的参数：可选参数做，剩余参数后置

- **可选参数**（带默认值的）：只在**有名字的函数和方法的声明**上做。调用时少给的，由生成器在调用处把默认值补上——这样 Go、Java 这种没有默认参数的语言也不用特殊处理。**函数类型里不带可选参数**：`(整数, 文字) → 是否` 就是两个，不多不少。
- **剩余参数**（“后面随便几个”）后置：先用列表代替。理由：传给函数类型时各语言规矩差太多（Go 的 `...T`、Java 的数组、Python 的元组）。
- 这两条**原型都没验证**（GAP-B-13）。

## 3. 按名字认还是按形状认（问题 2）

| 东西 | 怎么认 | 理由 |
| --- | --- | --- |
| 类、接口 | 名字 | Java、PHP 只认名字 |
| 记录、枚举、变体 | 名字 | 同上；而且按名字认，报错时能说“这里要『用户』”而不是一长串字段 |
| 函数类型 | 形状 | 匿名函数没名字，只能按“收什么、返回什么”认；五种语言都能表达（Java 靠小库里的几个接口） |
| 列表、字典、可空 | 形状 | 它们本来就是“壳＋里面的类型” |

**统一规矩怎么翻**：

- 翻到 **Java / PHP**（按名字认）：直接对应。函数类型在 Java 里用小库的 `Fn0 / Fn1 / Fn2 / Act0 / Act1 / Act2` 接口（验证过）；PHP 用 `\Closure`，参数和返回类型表达不了，只在设计期查。
- 翻到 **Go / TS**（按形状认）：我们的规矩比它们严，所以生成的代码一定能编过；多出来的“不许”由我们的检查器拦，不靠它们的编译器。Go 的接口不用写“实现了”，生成时照常生成方法就行；为了不让“碰巧方法一样”的两个类被 Go 当成同一个接口，变体的每个分支加一个不导出的标记方法（`p09` 里的 `is形状()`）。

**记录的字面量例外**：写 `新建 用户(名字: …, 年龄: …)` 时按字段名对上就行，这是“按形状填”，但得到的类型是有名字的。

## 4. 推断做到什么程度（问题 3）

原则：**能从上下文看出来的，绝不让用户标。** 用的是“从两头往中间推”的局部推断，不做全程序的方程求解——后者报错时说不出人话（“类型变量 t17 和 t23 对不上”）。

### 4.1 规则

1. **变量**：类型＝它所有被赋的值的类型合并。合并规则：
   - 整数 ⊔ 小数 ＝ 小数；T ⊔ 空 ＝ T?；
   - 类 ⊔ 类 ＝ 最近的公共父类；没有公共父类但**正好共同实现一个接口**，就是那个接口；否则任意；
   - 两个里面类型不同的列表（都已确定）＝任意；
   - 其他对不上的 ＝ 任意。
2. **返回值**：没标就是所有“返回”的值合并；一个“返回”都没有就是空。递归函数从“永不”起步，反复算到不变。
3. **匿名函数的参数**：没标就看上下文（它被放在一个要 `(整数) → 文字` 的地方，参数就是整数）；**没有上下文就是任意**。
4. **泛型调用**（比如“映射”）：
   - 先看**不是匿名函数的参数**，把类型变量定下来；
   - 再带着定下来的类型去看匿名函数，匿名函数的返回类型再定剩下的类型变量；
   - 数字类的类型变量按合并来定（先看到整数、后看到小数，就是小数）。**变宽了以后，带着变宽后的类型再看一遍匿名函数**（第一轮发现的，见 F13）。
5. **空列表 `[]`、空字典、没写〈…〉的泛型类**：里面的类型先记成“待定”，由这个变量后面的“加项”“存”“方法调用”定下来。到最后都没线索，按任意，并给一条提醒（T12）。
6. **列表字面量里有匿名函数**：先看别的项，拿它们的类型当匿名函数的上下文。
7. **分支合并**：“如果 / 否则”两边给同一个变量赋值，按规则 1 合并。
8. **可空的收窄**：只对**局部变量和参数**做（字段、下标不做——它们可能在两句话之间被别人改掉）。
   - 认得的判断：`不是空`、`是空`、`≠ 空`、`＝ 空`，以及它们的“且”“或”“非”；
   - “如果 是空 就返回 / 抛出”之后，后面都算不是空；
   - 变量被重新赋了一个可能是空的值，收窄失效；
   - 循环体里的收窄不带到循环外面；
   - **带进匿名函数**：这个变量在整个函数里从没被“改”过才带；被改过的不带（等匿名函数真跑起来时可能又是空了）（F16）。
9. **没标类型的函数参数**——**决定：分两种**。
   - **自己文件里用的函数**：从**所有调用它的地方**的实参类型合并反推（反复算到不变）。没人调用的，按任意。
   - **要导出给别人用的（库的函数、“我的积木”进了库的）**：没标就是任意，并给警告 T13“导出的函数请把参数类型标全”。
   - 理由：全算任意，不标类型的人写出来的 Go 永远是 `any`，类型系统对他等于不存在；全靠反推，库的类型会随着“谁调用了它”变来变去，库就没法单独检查、单独发布。
10. **一处错只说一句**：报过错的式子类型记成“永不”，后面不再连带报。

### 4.1.1 实现时定下来、原型里没写明的几处（2026-11-26）

- **“重复 i 从 a 到 b”的循环变量**：a、b、步长都是整数就是整数，只要有一个小数就是小数（原型一律按整数）。
- **乘方**的结果恒为小数（2 的 -1 次方不是整数）；要整数自己套“取整”。
- **同名的泛型类型合并**（两个“栈〈整数〉”）结果还是“栈〈整数〉”；原型会把〈…〉丢掉变成光秃秃的“栈”，那是原型的毛病。
- **试着做 / 出错时**里的那个“错误”变量，这一期先按“文字”算；核心 2 有了错误对象再换。
- **变量表的先后**：Dart 实现里循环变量排在循环体里的变量前面，原型排在后面。对照测试只比内容、不比先后。
- 结果是**按节点对象**记的。同一个节点对象在树里出现两次（`const` 写的常量容易这样）只能记住一处，分析结果里的 `shared` 会把它们列出来，生成器用之前要保证是空的。

### 4.2 验证

- `p13-untyped`：5 个函数一个类型都没标，推出来分别是 `(列表〈整数〉) → 小数`、`(文字, 整数) → 文字`、`(小数, 整数) → 小数`、`(整数) → 整数`、`(任意) → 文字`，对应的 Go 是 `func 平均(xs *lc.List[int64]) float64` 这样的原生签名。
- `p03-lists`、`p14-generic-class`：匿名函数的参数、空列表、`新 栈()`、`新 状态(0)` 这些地方没标，都推对了。
- 推断原型 `infer.py` 对 16 个程序自动推出共 155 行结果，和手工结果对比：第一轮有不一致（其中 1 处是**我手工推错了**，原型是对的；另有规则没说清造成的误报和手写清单漏行，见第 12 节），第二轮全部一致。

## 5. 渐进式怎么和强类型语言共存（问题 4）

### 5.1 决定：严格检查，不对就报错；旧文档靠“规矩版本”保持不变

现有设计稿（v4 第 4.3 节）说“任意遇到确定类型，生成一次宽松转换 `lc.Num(x)`”。**我建议改成检查**：

| | 宽松转换（现在的） | 检查（建议） |
| --- | --- | --- |
| `"abc"` 放进要整数的地方 | 变成 0，继续跑 | 报错“这里要整数，拿到的是文字” |
| 好处 | 永远不崩 | 错误在发生的地方就暴露 |
| 坏处 | 错误被藏起来，在很远的地方以“结果不对”的样子出现 | 多一种会报的错 |

理由：霜霜要的是“像样的强类型”。强类型的意思就是“类型不对的值到不了要它的地方”。宽松转换正好相反——它保证的是“到了以后悄悄变成别的”。

**但旧文档不能变。** 所以需要一个开关：

- 每个文档带一个**规矩版本**。旧文档没有这个字段，算 **1**：现有行为一个字不变（全是任意、全走小库、除以 0 得 0、文字自动变数字）。
- 新建的文档是 **2**：用本文的严格规矩。
- 版本 1 → 2 是一个手动动作（“升级到严格规矩”），升级时给一份“哪些地方行为会变”的清单；不能自动降回去。
- ~~版本 1 的文档里类型标注照样能写、照样检查（给提示），但**不影响生成的代码**。~~
  **实现时改了（2026-11-26）**：版本 1 的文档**完全不跑** T 开头的规则，校验结果和以前逐字相同。原因：任务要求“旧文档的校验结果一个字不变”，而且用测试钉住了（`test/rules_v1_frozen_test.dart`）；多出一条提醒也算变了。想看类型提示的人点“升级到严格规矩”。
- **存在哪（实现）**：文档最外层的 `rules` 字段（整数）。是 1 就不写这个字段，旧文档存出来和以前一个字节不差。常量和“新建的文档用哪个版本”的开关在 `lib/lang/rules.dart`。

### 5.2 版本 2 里“任意”的规矩

1. **确定类型 → 任意**：随便放，不用检查。
2. **任意 → 确定类型**：自动生成一次检查（不用用户摆积木），不对就报错。想自己处理错误的，用“当成〈类型〉”积木包在“试着做”里。
3. **任意和任意之间算术**：也检查（“加法的两边要数字，拿到的是文字”），不悄悄转换。
4. **“连起来”（拼文字）收任何类型**，不算错。
5. **列表、字典过“任意”的边界**（第二轮定的，`p16` 验证）：
   - 列表〈整数〉 → 任意：**拍一份快照**（复制一份，变成“任意里的样子”）；
   - 任意 → 列表〈整数〉：**逐项检查，得到新的一份**；哪一项不对，报“列表的位置 3：这里要整数，拿到的是文字”；
   - 任意 → 列表〈任意〉：只看“是不是列表”，**还是同一个**。
   - 为什么要复制：Go 里 `*List[int64]` 和 `*List[any]` 是两种东西，没法是“同一个”；JS 和 Python 里倒是可以，但那样从“任意”那头往里塞一个文字，带类型的那头就坏了，而且四种语言行为不一样。复制是唯一能让四种语言一致的简单办法。
   - 代价和补救见 GAP-B-4。

### 5.3 “标不标类型，结果一样吗”

- 同一份程序，**开不开原生类型的生成，结果一定一样**——这是第 11 节的规则保证的。
- 同一份逻辑，**标了类型和没标**：正常跑完时结果一样。两个例外要说清楚：
  - 标成整数（或被推成整数）的，超出范围会报“整数超出范围”；走“任意”的那条路按小数算、不报。
  - 列表经过“任意”会被复制（5.2 第 5 条）。

## 6. 槽的形状、放不进去怎么办、提示语（问题 5）

### 6.1 形状：不加

还是两种：**圆头＝值，六边形＝是否**。不给整数、文字、列表各做一种形状。

理由：(1) 类型有十几种还带参数（列表〈用户〉），形状表达不了；(2) 手机上积木本来就小，再分形状认不出来；(3) Scratch 那一路也只分这两种形状，其余靠颜色和文字（只学了这个思路）。

**颜色**：积木的颜色继续表示“它属于哪一类积木”（运算、文字、列表…），不拿来表示类型——一个颜色两个意思会乱。

**槽里的小标记**（新加，很轻）：空槽里用灰色小字显示它要什么（现在已经有占位文字，沿用），比如 `数`、`字`、`表`。只在槽空着的时候显示，放了东西就没了。

### 6.2 放不进去：允许放下，标红，给一键修

**决定：不拒绝放下。** 理由：

1. **类型是推出来的，会变。** 现在对不上的，改了另一处就对上了；拒绝放下的话，用户得按“正确的顺序”搭，这违背搭积木的直觉。
2. **手机上拖一次成本高。** 拖过去弹回来，用户不知道为什么。放下去标红、说人话，他知道哪里不对。
3. **现状就是这样**：六边形槽放了别的东西现在也只是警告。
4. 标红的积木不让生成代码、不让运行（沿用现在“有错不导出”的规矩），所以不会“带着错跑起来”。

**只有一种情况拒绝放下**：形状本身不对——语句积木往值槽里放。这是现在就有的规矩。

**一键修**（点标红的积木，底部说明条里出按钮）：

| 情况 | 一键修做什么 |
| --- | --- |
| 要文字，给的是数字 | 外面包一层“变成文字” |
| 要整数，给的是小数 | 外面包一层“取整” |
| 要整数，给的是文字 | 外面包一层“变成整数（变不了就是空）”，再提示要处理空 |
| 给的可能是空 | 外面包一层“是空就用 ▢” |
| 要“是否”，给的是数字 | 换成“▢ ≠ 0” |
| “分情况”少了几种 | 把缺的情况补上（空的） |
| 新建记录缺字段 | 把缺的字段补上（空槽） |

### 6.3 390 宽上类型怎么显示

- **默认什么都不显示。** 积木上已经很挤了。
- **点一下积木**（现在点一下是选中）：底部说明条多一行，例如 `总和：整数` 或 `找年龄：(字典〈整数〉, 文字) → 整数?`。一行放不下就横向滚，不换行（守“一行只做一件事”）。
- **有类型错误的积木**：红色描边＋右上角一个小红点；点开在说明条里显示提示语和一键修按钮。
- **“我的积木”的定义帽子**上，参数后面可以点出一个小下拉标类型；没标的不显示任何东西。
- 类型名一律用中文（整数、列表〈文字〉），不出现 `int64`、`List<String>`。

### 6.4 十条典型提示语（原文）

写法的规矩：先说**这里要什么**，再说**放进来的是什么**；不出现“类型”“不兼容”“期望”这些词；能说出名字的说名字。前 8 条是推断原型实际打印出来的原文（见 `e01`–`e04`）。

1. 「重复」的第 2 个参数要整数，放进来的是文字
2. 减法的两边要数字，这里有一边是文字
3. 这里要“是/否”，放进来的是整数
4. 「加倍」的第 1 个参数要整数，「v」可能是空，要先判断“不是空”
5. “分情况”还少了：黄（或者加一个“其余”）
6. 新建「点位」还缺：y
7. 「最大」要的是能比大小的东西（数字或文字），点位不能比大小
8. 「猫」说自己是「会叫」，但是没有「叫」这个方法
9. 记录「点位」建好以后不能改，用“复制并改”
10. 「空的」里放什么还看不出来，先当成“任意”（这条是提醒，不是错）

运行时的错误文字见第 8 节。

| PHP | 列表和字典是同一种 `array` | 小库里要有办法分清“空列表”和“空字典” | 没跑，未核对 |

### 7.3 Go 里的类怎么做

- **不能被继承的类**（默认）：就是一个 struct 加方法，变量类型是 `*类名`。这是地道的 Go。
- **能被继承的类**：生成三样东西——一个接口（变量的类型）、一个放字段的“体”struct、体里一个指回最外层对象的 `self` 字段。子类把父类的体内嵌进来。父类的方法里调用“自己的方法”一律写成 `o.self.方法()`，这样调到的是子类重写的那个。`p08` 里“动物.介绍()”调到“狗.叫声()”验证了这一点。
- 这比现有设计稿（v4 第 3.7 节）说的“Go 的类全走小库的对象模型”好：字段是真字段、方法是真方法，Go 的编译器能查类型。代价是“能被继承的类”生成的代码多一层，所以才默认关掉继承。

## 8. 必须在运行时检查的地方（问题 7）

| --- | --- | --- | --- |

## 9. 类型和“库”的关系（问题 8）

1. **库导出的每个函数、方法、类、记录，签名必须标全**（参数和返回值）。没标的按任意，并给警告 T13。理由见 4.1 第 9 条：库要能单独检查。库**内部**不导出的函数照样可以不标。
2. **积木外观带类型**：“我的积木”的每个槽对应一个参数，槽的形状由参数类型定（是否 → 六边形，其余 → 圆头），空槽里的灰色小字也从类型来。返回“是否”的积木自己是六边形，返回别的是圆头，返回空的是语句积木。这条和现有“我的积木三种调用外观”对得上。
3. **原生绑定的签名必须写全，一个任意都不许省**（真的是任意就明写“任意”）。理由：原生绑定是类型系统看不见里面的地方，签名是唯一的依据。运行时按第 8 节在出口查一次，防止绑定写错。同一个绑定在五种语言里的实现不同，但签名只有一份。
4. **用户库里的类型怎么导出**：记录、枚举、变体、类、接口、类型别名都可以勾“导出”。导出的类型：
   - 必须有**代码名**（拉丁字母开头，只含字母数字）。给人看的名字照样可以是中文。原因是 Java 的类型名会变成文件名、Go 的中文名出不了包（F1、F7）。编辑器可以自动起一个（拼音或 `T1`），允许改（GAP-B-1）。
   - 导出的函数签名里用到的类型也必须导出，否则报 T13。
   - **类型别名**：Go、TS、Python 有对应的写法，Java 没有 → Java 里在每个用到的地方展开。别名只是另一个名字，不是新类型（GAP-B-3）。
5. **库的版本和类型**：改了导出签名算“不兼容的改动”。这条归 C 部分（库系统），我这里只提出来。
6. **库声明自己用哪个规矩版本**。版本 1 的文档调用版本 2 的库：参数在进库的地方按第 8 节查；反过来，版本 2 的文档调用版本 1 的库，拿回来的一律当任意。

## 11. 生成策略（问题 10）

**一条总规矩：只有“原生写法对所有可能的输入，结果都和小库一模一样”的地方才写原生。**

| 运算 | 类型都确定时生成什么 | 为什么 |
| --- | --- | --- |
| 小数 + − × | 原生 `a + b` | 五种语言都是同一个双精度标准，结果必然一样 |
| 整数 + − × | 小库 `iadd(a, b)`（带类型的小函数，Go 里是 `func IAdd(a, b int64) int64`） | 要查范围 |
| `/`、整除、余 | 小库 `fdiv / idiv / imod` | 要查除以 0；Python 的规矩不同 |
| 数字比大小、相等 | 原生 | 一样 |
| 文字相等 | 原生（Java 用 `.equals`） | 一样 |
| 文字比大小 | 小库 | JS、Java 不是按码点 |
| 是否的 且 / 或 / 非 | 原生 | 一样 |
| 文字拼接 | 两边都是文字时原生；有数字时先用小库“变成文字”再拼 | 数字的写法是我们自己的规矩 |
| 列表取项、改项 | 小库 `at / setAt` | 越界的错误文字要一样 |
| 字典取值 | 小库或原生都行，结果一样；原型用的小库 | —— |
| 记录取字段、调方法、调函数 | 原生 | —— |
| 记录相等 | 生成的比较函数 | 各语言自带的不一样 |
| 任何一边是任意 | 走“任意”版的小库函数（`dadd` 等） | —— |

- **变量和函数的声明**：类型确定的写原生类型（`var 总 int64`、`long 总`），任意的写 `any` / `Object`。
- **规矩版本 1 的文档**：永远全走现有小库，生成的代码和现在一个字不差。
- **“开不开类型优化，结果一样”怎么保证**：上表里“原生”的每一项都是“原生＝小库”的情况，所以把它们换回小库（不开优化）结果不变。`p15-fuzz` 用 2000 组随机数把“原生类型的路”和“任意的路”对拍了一遍：四种语言、两条路，校验和都是 973361409，不同的次数是 0（对拍的数都在范围里；超范围时两条路本来就不同，见 5.3）。
- 走“带类型的小库小函数”不等于回到 `any`：`lc.IAdd(a, b)` 的参数和返回值都是 `int64`，Go 的编译器照样查类型，也容易被内联。生成的代码读起来是 `lc.IAdd(总, x)` 而不是 `总 + x`，这是为“各语言一致”付的代价。

### 12.1 做法

- **16 个程序**（`p01`–`p16`）。每个目录有：源程序 `prog.lc`、手工推断结果 `types.txt`、事先写的预期输出 `expect.txt`、按映射表手写的 `main.js`、`main.py`、`go/main.go`（原生类型）、`Main.java`（原生类型）、`README.md`。
- **4 组故意写错的**（`e01`–`e04`，共 24 处）：源程序＋手写的“应该报什么”。
- **推断原型** `infer.py`（约 1100 行 Python）：自动推断和报错，结果和手写的对比。覆盖和没覆盖的规则见 `types/README.md`。
- **四种语言的原型小库** `_prelude/`。
- `run_all.sh` 一键全跑：每个程序 6 项（四种语言各自等不等于预期、四份是不是逐字节相同、自动推断等不等于手写），每组错例 1 项。
- 版本：node v24.22.1、Python 3.12.3、go1.25.0、javac 21.0.13.1。Go 只用标准库、不联网。

### 12.3 第二轮（改设计 → 重写 → 2026-11-25 20:17 全跑：84 项通过，0 项不符）

- **改了设计**：加“代码名”（F1、F7）；“分情况”后面补抛错、Java 放在里面（F2）；记录比较一律自己生成（F3）；泛型推断“变宽后再看一遍”（F13）；“一处错只说一句”（F14）；收窄带进匿名函数改成“从没被改过才带”（F16）。
- **重写了**：`p13` 的 Go、Java、Python 和手写清单（F12）；`p14`、`p15` 的手写清单（F15）；`infer.py`（F13、F14、F16）；`run_all.sh`。
- **第二轮新发现的一件事**：回头看“任意的边界”时发现第一轮根本没碰“确定类型的**列表**装进任意”——Go 里 `*List[int64]` 不能直接当 `*List[any]`。于是定了 5.2 第 5 条“快照”规矩，新加 `p16`，四种语言各加了三个小库函数，跑出来一致。
- **第二轮之后还留着的**：快照规矩的代价（GAP-B-4）没有验证过拦截规则；`p15` 的预期不是手算的（2000 组算不动），它的预期文件是跑出来的结果——它验的是“四种语言一样、两条路一样”，不是“等于手算值”；其余 15 个程序的预期都是事先手写的。

### 12.4 这次验证**不能**说明什么

- 四种语言的代码是**我照着映射表手写的**，不是生成器生成的。它说明“映射表写得出能编过、结果一致的代码”，不说明“生成器写得出来”。
- TypeScript、PHP 没跑。
- 推断原型和产品里的检查器是两份代码，产品实现时要拿这 16＋4 个例子重新对一遍。
- 没有在手机上跑过任何东西；槽的形状、标红、一键修、说明条都只是设计，没有做界面原型。

## 给协调者的清单

### 发现的缺口

- **GAP-B-1** 类型和导出函数缺“代码名”（拉丁字母的名字）。影响 L3 库、L1 的类 / 记录声明。建议：声明上加一个字段，编辑器自动起、可改。
- **GAP-B-2** “稍后的结果〈T〉”只有映射、没有验证，Python / Go / Java / PHP 落成什么都没定。影响 L1。建议：跟异步那部分一起定，定完补 2–3 个验证程序。
- **GAP-B-3** Java 没有类型别名，函数类型别名只能逐处展开，生成的 Java 会很长。影响 Java 生成。建议：接受；或者给每个别名生成一个专用接口（没试）。
- **GAP-B-4** “列表装进任意＝快照”的副作用：同一个没标类型的函数，参数被推成列表〈整数〉时改得到调用者的列表，被推成任意时改不到。影响 L1 语义。建议：加 T14 警告拦“往任意里的列表加东西”；T14 没实现、没验证。
- **GAP-B-5** JSON：解析结果是任意；需要标准库提供“按记录类型读 JSON”。另外 Java 标准库里没有 JSON 解析（未核对官方文档），小库得自带。影响 L2。
- **GAP-B-6** 宿主数据的入口检查：原生绑定的出口要按签名自动查一次，这需要原生绑定的格式里签名是机器可读的。影响 L0。
- **GAP-B-7** TypeScript、PHP 的映射没跑过。建议：下一步在有 tsc、php 的环境里把 16 个程序各补两份。
- **GAP-B-8** 小数写出来只有 12 位有效数字，需要一个“原样写出”的标准库函数。影响 L2。
- **GAP-B-9** 错误在原型里简化成了“一句文字”。真正的错误值（错误的种类、带原因、自定义错误类）没有设计类型。影响 L1 / L2。
- **GAP-B-10** 类的方法不能自带类型参数（Go 1.27 才支持）。影响写库的人。建议：先用普通泛型函数代替，等 Go 版本上来再放开。
- **GAP-B-11** “是 某类”判断后的收窄、向下转型（T15、第 8 节第 9 条）有规则没验证。
- **GAP-B-12** TS 专属库里大量“随便的联合”（`string | number`）在语言核心里没有对应，绑定时只能写任意。影响前端库（D 部分）。
- **GAP-B-13** 可选参数、剩余参数、元组没验证；剩余参数和元组后置。
- **GAP-B-14** 记录的“不能改”是浅的：字段里的列表还能改。建议：先接受并写进说明；要深的不可变得再设计“不可变列表”。

### 和“设计骨架”不一致、需要改骨架的地方

1. **骨架里“类型渐进式：任意＝动态值，旧文档行为不变”这一条本身成立，但 v4 设计稿第 4.3 节配套的“边界上生成一次宽松转换”不成立**——它让类型不对的值悄悄变成别的，和“强类型”相反。建议改成：加“规矩版本”，版本 1 保持宽松转换（旧文档不变），版本 2 改成检查。
2. **“开 / 不开类型优化，结果一样”要收窄说法**：成立的是“同一份程序，生成原生还是走小库，结果一样”；不成立的是“同一份逻辑，标类型和不标类型，结果一样”——有两个例外（整数超范围会报错、列表过任意会复制，见 5.3）。建议骨架里把这句改成前一种说法。
3. （不是骨架，是 v4 设计稿）第 3.7 节“Go 的类走小库对象模型”“不做泛型类”建议都改：Go 的类用 7.3 的做法，泛型类第一版就做——两样都验证过（`p08`、`p14`）。

### 需要霜霜拍板的问题

1. **要不要分“规矩版本”，新文档用严格规矩**（类型不对就报错、除以 0 报错、整数超范围报错），旧文档原样不变？——建议：要。不分的话只能二选一：要么旧文档行为变，要么新的类型系统继续“悄悄转换”。
2. **类型不对的积木：允许放下并标红＋一键修，还是直接拒绝放下？**——建议：允许放下。
3. **记录建好以后不能改，要改用“复制并改”**，可以吗？——建议：可以。好处是各语言行为一致、不会“改了一处别处跟着变”；代价是多一块积木、手感上多一步。

### 没核对 / 没跑成 / 看不出来的

- **没跑**：TypeScript、PHP 的全部映射；第二梯队六种语言；任何手机上的东西；界面。
- **没核对官方文档**（只凭本机实测或第三方页面或我的了解）：
  - JS：`%` 的符号跟被除数（本机实测）；`Map` 保持插入顺序。
  - PHP：除以 0 抛错（第三方页面，且其中一页说法矛盾）；整数溢出变小数；`ksort` 的顺序；可空类型、联合类型、`mixed`、没有泛型。
  - Java：`record` 和 `sealed` 各是哪一版进来的（第三方说 16 和 17；本机 JDK 21 实测都能用）；标准库没有 JSON 解析。
  - TS：`unknown`、可辨识联合。
  - Python：`X | None` 的写法、`dataclass(frozen=True)`、`def f[T]`、`match`（本机 3.12.3 实测都能跑，没查文档）。
  - Go：`cmp.Ordered`（本机实测能编）；map 遍历顺序不固定；有符号整数溢出“绕回”那句（官方规范页的搜索摘要被截断，只在镜像上看到）。
  - 第 7.4 节整张表。
- **估计、不是实测**：第 10.2 节的行数和天数。
- **看不出来的**：`lib/blocks/` 里做“标红＋一键修＋说明条显示类型”要动多少，我只读了拖放那一处，留给 E 部分。
- **原型没覆盖的规则**：T13、T14、T15、T17、T18；“是 某类”的收窄；可选参数；库的导出；规矩版本 1 和 2 互相调用。
