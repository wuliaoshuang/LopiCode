## 0. 结论摘要

1. **数清楚了**：九类一共 **264** 条特性。分级：①核心 **214** 条（要动语言核心的 104 条，只加小库函数或规矩的 110 条）；②宿主专属 9 条；③原生片段兜底 1 条；④不做 40 条（每条写了理由）。
2. **①的 214 条里**：现在核心已经有的 **120** 条；设计稿有、没实现的 **8** 条；**完全没有的 86 条**（编号 GAP-A1-1 到 86，清单在 12.1）。86 条里 30 条要动语言核心，56 条只是加小库函数或把规矩写明。
3. **最大的几块缺口**：整数类型；记录、枚举、元组、集合四种新类型；空值安全（“要是空就用”“空就算了”）；解构；按样子分情况；生成器和“可遍历的”；文字插值；位运算；整套正则；整套日期时间；数字格式化和保留小数位。
4. **现在的核心有一个好底子**：所有运算都走小库函数、不用各语言自带的运算符，所以各语言在优先级、除法、取余、舍入、转文字上的几十处差异（本文跑出来一大批）都碰不到。新东西照这个路子加就行。

八个难点的建议（各有一节，在第 13 节）：

5. **数字**：分“整数 / 小数”，但只在类型上分，运行时还是一种 64 位小数；整数范围 ±(2^53−1)，出界报错不绕回；“÷”永远得小数，“整除”向下取整；位运算按 32 位。这样六种语言才可能一位不差。
6. **文字长度**：保持按码点。它是唯一不靠数据表、六种语言都能算得一样的单位。另给“看起来有几个字”的函数；网页光标位置的换算放浏览器库。
7. **相等**：建议默认的“等于”改严（类型不同就不相等），另给“是同一个”和“看起来一样”两块。现在的规矩里外不一致（1 等于 "1"，但 [1] 不等于 ["1"]）。**这条改现有行为，要拍板。**
8. **真假值**：保持现状（空、否、0、空文字算否，其余算是）并写成明文。它正好是 JS、Python、PHP 都同意的那一部分。
9. **空值安全**：两种值积木。“要是空就用”是新节点；“空就算了”是给取字段、取项、调用加一个开关。没有这两个写法的语言（Python、Go、Java）用小库函数加“把右边包成函数”降级，现有的 Go 三目就是这个做法。
10. **生成器**：统一用“推”的做法（生成器＝收一个回调的函数，回调返回“否”就停），六种语言同一套，不依赖任何语言自带的 yield。**跑过**：Node、Python、Java、Go 四份输出一致。做不到“我来要下一个”，那个先不做。
11. **正则**：两层。标准库放“公共子集”（没有前看回看、反向引用、\p），小库负责检查和转写；完整正则放各语言的宿主库。已经跑出 4 处子集内的差异（如 `a$` 对 "a\n"，Python、Java 匹配而 JS、Go 不匹配），都有办法抹平。
12. **日期时间**：拆开。纯算术能算对的（时刻、时长、固定偏移、标准格式、加减天和月）放标准库；要靠外部数据的（按地名的时区、夏令时、按语言习惯的写法）放库。

和骨架的出入：

13. 骨架的四级里，①建议明分两档（动语法树 / 只加小库），工作量差一个数量级。
14. ②“宿主专属”建议放宽成“同一套积木，但不承诺各语言结果一致”，正则完整版、时区、大整数都属于这种。

要霜霜拍板的 4 条（详见“给协调者的清单”）：“等于”改不改严；除以 0 和算出无穷大是得 0 还是报错；数字转文字只留 12 位要不要保持；核心不做十进制小数和大整数行不行。

## 3. 变量与作用域（S）

条目来源：ECMAScript“声明与作用域”、Python 语言参考“命名与绑定”、Go 规范“Declarations and scope”、Java 语言规范第 6 章（名字）和第 4.12 节（变量）、PHP 手册“变量范围”。

### 3.1 语言表

| 编号·特性 | JavaScript | TypeScript | Python | Go | Java | PHP | 对照 |
|---|---|---|---|---|---|---|---|
| S-01 声明变量的写法 | 有 let、var；非严格模式下不声明直接赋值会变全局 | 同 JS | 不一样：没有声明关键字（let 是语法错·跑），赋值就是声明 | 有 var、:= | 有“类型 名字”或 var（跑过） | 不一样：没有声明，$x 一赋值就有（未核对） | Ruby 赋值即声明；其余有关键字 |

| S-05 模块级（文件级）变量 | 有：模块里的顶层声明只在本模块；老式脚本里顶层 var 会进全局 | 同 JS | 有 | 有：包级变量 | 没有·未：只能是类的 static 字段 | 不一样：文件顶层就是全局（未核对） | 都有或用静态字段 |

| S-09 闭包能不能改外层变量 | 能（跑过） | 同 JS | 不一样：能读；要改得写 nonlocal（关键字表有·官） | 能（跑过） | 不能·跑：只能抓住“之后不再改”的变量 | 不一样：匿名函数要用 use 点名，默认按值，写 & 才能改；fn 箭头函数自动按值（未核对） | Swift、C#、Kotlin、Dart、Ruby 能；Rust 分借用和移走 |

| S-12 解构声明（一句话把列表、记录拆成几个变量） | 有：数组解构、对象解构、带默认值、带“剩下的” | 同 JS | 有：a, *b = c（跑过）；没有按键名拆字典的写法（未核对） | 不一样：只有接多返回值 a, b := f()（跑过） | 不一样：只有 record 模式（跑过） | 有 [$a, $b] = …、['k' => $v] = …（未核对） | Kotlin、Rust、Swift、Dart、C#、Ruby 有 |
| S-13 没用到的变量、没赋值就读，编译器管不管 | 不管 | 可选开关管 | 不管 | 管：没用到的局部变量编译不过（跑过） | 管一半：没赋值就读编译不过 | 不管 | Rust、Swift、Kotlin、Dart 警告 |
| S-14 变量中途能不能换类型 | 能 | 不能 | 能 | 不能 | 不能 | 能 | Ruby 能；其余不能 |
| S-15 删除变量 | 不一样：delete 只删属性 | 同 JS | 有 del（关键字表有·官） | 没有·官（关键字表没有） | 没有·未 | 有 unset（未核对） | 多数没有 |
| S-16 名字规则（分不分大小写、前缀、首字母含义） | 分大小写，可用中文 | 同 JS | 同 | 首字母大写＝对包外公开 | 分大小写 | 变量带 $；函数名、类名不分大小写（未核对） | Ruby 首字母大写＝常量 |

## 4. 运算（O）

条目来源：MDN 运算符优先级表、Python 3.15 词法页运算符表、Go 规范运算符表、Java 语言规范 27 版第 15 章目录（15.14–15.26）、PHP 手册运算符优先级表（只看到手册源文件的修改记录，原页没打开）。

### 4.1 语言表

| 编号·特性 | JavaScript | TypeScript | Python | Go | Java | PHP | 对照 |
|---|---|---|---|---|---|---|---|
| O-01 加、减、乘 | 有；+ 遇到文字变拼接 | 同 JS | 有 | 有；两边类型必须一样（跑过） | 有 | 有；+ 只做数字 | 都有 |
| O-02 除法 | 有：永远得小数，7/2=3.5（跑过） | 同 JS | 有：/ 永远得小数（跑过） | 不一样：整数相除只留整数部分，7/2=3（跑过；规范写“向零截断”·官） | 不一样：同 Go（跑过） | 不一样：整除得整数，否则小数（未核对） | Ruby、Rust、C#、Kotlin、Swift 同 Go；Dart 的 / 得小数 |

## 13. 八个难点

### 13.1 数字要不要分“整数 / 小数”

**建议：分，但只在类型上分，运行时还是一种数。**

- “整数”是“数字”里的一部分：值没有小数部分，而且在 ±(2^53−1) 以内。3 和 3.0 是同一个值。六种语言的小库里都还是用 64 位小数装。
- 为什么不用各语言自带的整数：算超了以后，Go、Java 绕回去变负数，PHP 悄悄变成小数，Python 永远不超，JS 根本没有 64 位整数（上面都跑过或标了未核对）。四种行为没法对齐。
- 为什么这样能逐字节一致：64 位小数的加、减、乘、除、开方、向下取整，六种语言都遵守同一个标准、结果一位不差；在 ±(2^53−1) 以内，整数的加减乘在小数里是完全精确的。所以只要小库每次算完检查“还是不是整数、有没有出界”，结果必然一样。
- 具体规矩：
  1. “÷”永远得小数（7÷2=3.5）。要整数用“整除”，**向下取整**（-7 整除 2 得 -4）。小库不能只写 `floor(a/b)`：先除再向下取整，然后用 `a − q×b` 验一下，不对就修正一格（大数相除时小数除法可能刚好进位）。
  2. 取余保留现在的（符号跟被除数，-7 余 3 得 -1），另加“向下取余”（符号跟除数，得 2）。两个都给，是因为各有各的用处，而且“整除 × 除数 + 向下取余 = 被除数”能成立。
  3. 整数加减乘出界就报错“数太大了”，不绕回。
  4. 整数可以自动当小数用；小数要变整数必须过“取整”积木（四选一：向下、向上、四舍五入、去掉小数部分）。
  5. 位运算单独规定按 32 位算（和 JS 一样），因为这是唯一六种语言都能便宜地做到一致的宽度。
- 没标类型的积木不受影响：行为和现在完全一样。
- 没做的验证：我没有在六种语言里把“先除再修正”的整除写出来对跑。JS 和 Python 里试了几个接近上限的数，直接 `floor(a/b)` 和精确结果一致（跑过），但这不能证明所有情况都对，所以才建议加修正那一步。

### 13.2 文字的长度和下标按什么算

**建议：保持按码点。另外给两样东西：按“看到的字”算的函数，和浏览器专用的码元换算。**

- 按码元（JS、Java 的原生算法）不行：Go、PHP 是按字节的，Python 是按码点的，一个表情符号在 JS 里长度是 2、在 Go 里是 4、在 Python 里是 1（都跑过）。
- 按“看到的字”（字素）当默认也不行：它要一张很大的 Unicode 数据表，各语言自带的表版本不同，Python、Go 的标准库干脆没有。同一段积木在不同语言上会算出不同的长度。
- 码点是唯一一个六种语言不靠数据表就能算得一模一样的单位。代价有两个，都能接受：
  1. “一家三口”那种组合表情按码点是 5 个字（跑过）。所以要给 T-04 那块“看起来有几个字”，小库自带同一份简化规则。
  2. JS、Java 里“取第 i 个字”要从头数，慢。小库对长文字的循环应先拆成“字的列表”再走（C-17 的“对文字的每个字”就这么生成）。
- 网页上的光标位置、选区是按码元的：放在浏览器宿主库里做换算（T-02），不进核心。

### 13.3 相等的统一规矩

**建议：三块积木，默认的那块改严。这一条改了现有行为，需要拍板。**

现在的“等于”是：类型一样直接比（列表、字典转成 JSON 比），类型不一样就都转成文字再比。问题：

- 1 等于 "1" 是“是”，但 [1] 等于 ["1"] 是“否”（列表是按 JSON 比的）。同一条规矩里外不一致。
- “类型不同也算相等”正是 JS、PHP 里最出名的坑。

建议改成：

| 积木 | 规矩 |
|---|---|
| (a) 等于 (b) | 类型不同就是“否”。数字按值（3 和 3.0 相等）；文字要每个码点都一样；列表、元组、字典、记录按内容一层层比；对象、函数看是不是同一个；空只等于空 |
| (a) 和 (b) 是同一个 | 只看是不是同一个东西（给列表、字典、对象用） |
| (a) 看起来和 (b) 一样 | 现在的宽松规矩：都转成文字再比。给“输入框里的文字和数字比”这种场合用 |

集合的元素和字典的键只许数字、文字、是否，所以不需要“用户自己规定相等和哈希”（L-24 不做）。

要是不想改现有行为，退一步的方案是：保留现在的“等于”，另加“完全等于”。缺点是默认的那块还是容易出错。

### 13.4 真假值的统一规矩

**建议：保持现在的规矩，并把它写成明文。**

- 现在的规矩：空、否、0、空文字算“否”，其余都算“是”（包括空列表、空字典、文字 "0"）。
- 这正好是 JS、Python、PHP 三种“什么都能当条件”的语言都同意的那一部分：空列表在 JS 里算是、在 Python 和 PHP 里算否；"0" 在 PHP 里算否、别处算是（JS、Python 跑过，PHP 未核对）。有争议的值一律算“是”，规矩最短。
- 加了类型以后再补两条：
  1. 条件口的类型是“是否”。接上来的值类型已知且不是“是否”时，编辑器自动套一块看得见的“(x) 当真”，而不是在生成代码里悄悄转。
  2. “并且 / 或者”的结果永远是“是否”（现状）。JS、Python 里“a 或者 b 返回 a 本身”的用法，由“要是空就用”承担。
- Go、Java 条件必须是 bool：一律生成小库的 truthy，类型已知是“是否”时直接用。

### 13.5 空值安全（?. 和 ??）怎么做成积木

**建议：做成两种值积木，落到一个新节点和四个已有节点上的一个标记。**

- **(x) 要是空就用 (y)** → 新节点 LCoalesce(左, 右)。右边只在左边是空时才算。
  - JS、PHP 直接生成 `??`。
  - Python、Go、Java 没有：生成小库函数 `orElse(左, 把右边包成的函数)`。左边作为参数只算一次，右边包成函数所以不会提前算。Go 现在的 Pick 就是这个做法（已看过代码）。Java 里被包进去的变量要走“一格盒子”，现有机制已经有了。
- **(x) 的 [字段]（空就算了）**、**(x) 的第 (i) 项（空就算了）**、**调用 (x) 的 [方法]（空就算了）** → 不新增节点，给 LField、LIndex、LSend、LCall 加一个“空就算了”标记。
  - 取字段、取项：生成小库函数 `safeGet(x, 键)`，x 是空就返回空。
  - 调方法：参数不能提前算，所以参数表也包成函数。
- 积木长相：在普通的“(x) 的 [字段]”积木上长按，出一个“空就算了”的开关，打开后积木边上多一个小问号。不另做一排积木，免得面板翻倍。
- 和类型的配合（归类型系统部分落实）：
  - 带“空就算了”的积木，结果类型是“可空的 T”；“要是空就用”把“可空”去掉。
  - 对“可空”的值直接取字段，检查器报错，并给两个一键修法：打开“空就算了”，或外面包一层“如果 (x) 不是空”。
  - 在“如果 (x) 不是空”里面，x 自动当成不可空。
- 现成的好处：小库的“取第 i 项”“取键”读不到本来就返回空，所以“(字典) 的 [键] 要是空就用 (默认值)”马上就能用。
- “我保证不是空”（O-22）单做一块，是空就报错并指出是哪块积木。

### 13.6 生成器 / 迭代在没有生成器的语言里怎么降级

**建议：核心里的“可遍历的”统一用“推”的做法，六种语言都这么生成；不依赖任何语言自带的生成器。**

- 做法：一个“可遍历的”就是“收一个回调的函数”。它每产出一个值就调一次回调；回调返回“否”表示“够了，别再给了”。“交出 (值)”生成 `if (!回调(值)) return;`。
- “对 (可遍历的) 的每一项”把循环体包成回调：正常走完返回“是”，“跳出”返回“否”，“跳过这一圈”返回“是”。循环体里的“返回”要多一个标志和一个存返回值的格子，出来以后再真的返回。
- 这正是 Go 规范里“对函数做 range”的形状（规范原文已核对），所以 Go 新版可以直接用原生的 `for v := range`，标志这些编译器代劳。Java 没有生成器，但有闭包就够了。
- **跑过**：同一段逻辑（自然数 → 平方 → 只留奇数 → 取前 4 个；再加一个“找到第一个大于 10 的就从函数里返回”）在 Node 24、Python 3.12、JDK 21、Go 1.25 上各写了一份，四份输出都是 `1,9,25,49 12`。脚本在 `/tmp/v5-A1/gen/`。PHP 没跑。
- 这个做法做不到的事：**“我来要下一个”**（拉）和**两路同时走**（配对两个无限的序列）。建议：
  - 有限的序列：先“收成列表”再配对。
  - 无限序列的“拉”：先不做（④）。真要做，Java、Go 得用线程，资源不好收。
- 为什么不在 JS、Python、PHP 上用它们自带的 yield：那样同一块积木在不同语言上是两套机制，出了差异很难查；统一一套，才谈得上逐字节一致。

### 13.7 正则：定“公共子集”还是各语言专属

**建议：两层。标准库里放一个“公共子集”，六种语言结果一致；各语言的完整正则放在宿主库里，谁用谁负责。**

公共子集里有：普通字符、点号、字符组 `[a-z]` `[^…]`、`\d \w \s \b`（只认 ASCII）、`^ $`、量词 `* + ? {n,m}` 和它们的懒惰版、分组、不捕获的分组、命名分组 `(?<名>…)`、“或”、三个标志（不分大小写、多行、点号匹配换行）。

公共子集里没有：前看和回看、反向引用（Go 没有，跑过）、`\p{…}`（Python 标准库没有，跑过）、以及其他少见写法。

小库要做的事：

1. **检查**：模式不在子集里，搭积木时就报错（模式是写死的文字时），运行时也查一遍（模式是拼出来的时候）。
2. **转写**：命名分组在 Python 里写成 `(?P<名>…)`；替换里的 `${名}` 在 Python 里写成 `\g<名>`；Go 的标志写进模式开头；PHP 加分隔符。
3. **抹平几个已经跑出来的差异**：

| 试的东西 | JS | Python | Java | Go | 小库怎么统一 |
|---|---|---|---|---|---|
| `a$` 对 "a\n" | 不匹配 | **匹配** | **匹配** | 不匹配 | 转写成“绝对末尾”（Python `\Z`、Java `\z`，都跑过得“不匹配”） |
| `^.$` 对一个表情符号 | 不加 u 标志不匹配，加了才匹配 | 匹配 | 匹配 | 匹配 | JS 一律加 u 标志 |
| `\d` 对全角数字“３” | 不匹配 | **匹配** | 不匹配 | 不匹配 | Python 加 ASCII 标志（跑过，加了就不匹配） |
| `\w` 对“中” | 不匹配 | **匹配** | 不匹配 | 不匹配 | 同上 |
| `(a\|ab)(c\|bcd)` 对 "abcd" | abcd | abcd | abcd | abcd | 一致 |

4. 位置一律按码点返回（JS、Java 要从码元换算）。

为什么不只做“各语言专属”：库作者写的东西（比如“检查邮箱格式”）要能在六种语言上都用，必须有一个大家都认的子集。

为什么不自己写一个正则引擎放进小库：六份实现、速度慢。但如果以后一致性测试发现子集里还有抹不平的差异，这是最后的退路。

没做的验证：PHP 没跑。上面只试了 8 个模式，不算一致性测试；设计落地时要有一组“模式 × 输入”的表在各语言真跑。

### 13.8 日期时间放标准库还是库

**建议：拆开。“纯算术就能算对的”放标准库；“要靠外部数据的”放库。**

| 放标准库（小库，六种语言逐字节一致） | 放库（宿主专属，不保证各语言一致） |
|---|---|
| 时刻（从 1970 年起的毫秒，整数）、现在 | 按地名的时区（Asia/Shanghai） |
| 时长（毫秒数）和单位换算 | 夏令时 |
| 按固定偏移（如 +08:00）把时刻拆成年月日时分秒、再合回去 | 按语言习惯写日期（“2026年11月25日 星期三”） |
| 标准格式的读和写 | 宽松地猜各种日期写法 |
| 日期加减天、加减月（月底夹住）、相差几天、星期几 | 农历等非公历 |
| 用积木拼出来的格式化 | |

- 左边这些只是整数运算（年月日和“第几天”互相换算是一个固定的公式），六种语言的小库各抄一份就一定一致，完全不调各语言自带的时间库。各语言自带的东西差别太大：月份从 0 还是从 1 起、星期从哪天起、1 月 31 日加一个月是 2 月 28 日（Java，跑过）还是 3 月 3 日（Go，跑过）、五种互不相通的格式写法。
- 右边这些都要靠一份会更新的数据（时区规则一年改好几次），各语言、各系统带的版本不同，硬放进标准库就守不住“逐字节一致”。
- 中国用户最常见的需求（按北京时间显示）用固定偏移 +08:00 就够了，左边已经覆盖。
- “现在”天生每次不同：小库里要留一个测试时能塞进固定时刻的口子。
- JS 的新时间接口 Temporal 不依赖：说它在 Safari 正式版里还没有（第三方说法，未核对）。

### 发现的缺口

- 共 **86** 条“完全没有的①”，编号 GAP-A1-1 到 GAP-A1-86，逐条见 12.1（每条有：缺什么、哪一层、怎么补）。其中 30 条要动语言核心（L1），56 条只加小库函数或写明规矩（L2）。
- 另有 12 组“已经有但要补一点”的，见 12.2。

### 和“设计骨架”不一致、建议改骨架的地方

1. **骨架第 2 条（四级）不够分**：①里其实有两种——要动语法树的（L1）和只加小库函数的（L2），工作量差一个数量级。建议在①下面明写 L1 / L2 两档，本文已经这么标了。
2. **骨架第 2 条的②“宿主专属”含义要放宽**：正则的完整版、按地名的时区、大整数这类，不是某个“宿主”独有，而是“每种语言各有各的、结果不保证一致”。建议把②定义成“对外是同一套积木，但不承诺各语言结果一致”，和①的“逐字节一致”对着讲。
3. **骨架的统一用词里没有“整数”以外的这几个**：字节串、集合、时刻、可遍历的。建议加进用词表。
4. 骨架“类型渐进式”和本文没有冲突；本文所有涉及类型的建议（整数是数字的子集、可空、联合）都假定“不标就是任意、行为和现在一样”。

### 需要霜霜拍板的（4 条）

1. **“等于”要不要改严**（13.3）。选项：A 改严，类型不同就不相等，另给一块“看起来一样”（建议）；B 不改，另加“完全等于”。A 会改变现有积木的行为。
2. **除以 0、算出无穷大时怎么办**（N-04、N-05、N-09）。现在都悄悄得 0。选项：A 保持得 0（不会崩，但错了不容易发现）；B 改成报错（建议：整数运算报错，小数运算保持得 0——整数出错多半是真 bug，小数多半是显示用）。
3. **数字转文字只留 12 位**（N-18）。好处是 0.1+0.2 显示 0.3；代价是写成文字再读回来可能差一点点。选项：A 保持，另加“完整写出”给存盘和传输用（建议）；B 改成完整写出。
4. **核心不做十进制小数和大整数**（N-12、N-13）。建议：算钱用“整数的分”；大整数做成单独的库。如果她的用户里算钱的场景多，可以把十进制提到标准库，代价是六份实现。
