# 库的落盘格式（第 1 版）

> 积木第 5 版·库 1（第三轮 A1）定的。实现在 `lib/lang/lib_model.dart`（读）、`lib_check.dart`（查）、`lib_apply.dart`（用）、`lc_text.dart`（模块文件的写法）。
> 内置库（“接口服务”，`lib/backend/lib_service.dart`）和将来用户自己写的库是**同一种格式、同一个读入器**；差别只有第 9 节那三处。
> 设计在 C 分册（`C-library-system.md`）；和它不一样的地方集中写在第 10 节。

## 1. 一个库是什么

库＝一个文件夹：一份清单、一个或几个模块（真正干活的函数、类、类型）、一张积木表（画布上长什么样、对着模块里的什么）。

```
我的库/
  lib.json            清单（必须有）
  modules/xxx.lc      模块：语言核心写的定义（第 4 节）
  blocks.json         积木表（第 5 节），可以有几个
  native/…            手写代码（第 8 节；这一版读得进来但用不了）
```

读入器吃的是“相对路径 → 文件内容”这样一张表（`libRead(files, builtin: …)`），不管它是从磁盘、压缩包还是应用里带的文字来的。
**任何输入都不抛异常**：有问题就记在库的“问题”表里，有问题的库不能用。

## 2. 清单 `lib.json`

| 字段 | 必须 | 说明 |
|---|---|---|
| `kind` | 是 | 固定 `"lopicode-lib"` |
| `format` | 否 | 格式版本，现在是 1；比 1 大的不收 |
| `id` | 是 | `作者/库名`，两段都是小写字母、数字、连字符，字母开头，每段最多 32 个字 |
| `name` | 否 | 给人看的名字（最多 24 个字），没写用库名 |
| `version` | 否 | 版本号文字 |
| `summary` | 否 | 一句话说明（最多 80 个字） |
| `rules` | 否 | 规矩版本，只能是 2（库一律照严格规矩写） |
| `modules` | 是 | `[{"file": "modules/a.lc", "name": "模块名"}]`；一个文件里正好一个模块，名字要和文件里写的一样 |
| `blocks` | 否 | 积木表文件的路径列表 |
| `types` | 否 | 这个库给出来的类型：`{"name", "module", "hint"}`；必须是那个模块里**公开**的类型 |
| `settings` | 否 | 设置项（第 7 节） |
| `init` | 否 | “准备”时刻要做的语句（文字写法，第 6.5 节） |
| `start` | 否 | “最后启动”时刻要做的语句 |
| `provides` | 否 | 整个库一直给着的隐含东西：`{"名字": "变量名"}`（变量在 `init` 里新建） |
| `autoUse` | 否 | 哪类文档自动带上它（只有内置库写了才算数） |
| `native` | 否 | `{"allowed": true}`＝带手写代码（第 8 节） |

## 3. 模块里不许有什么

- 不许有“程序开始时”（`(主 …)`）：库不是程序。要在开头、结尾做事，用清单的 `init`、`start`。
- 不许直接声明宿主接口（`(宿主 …)`）——只有内置库可以（第 9 节）。用户库要碰外面的世界，只能用内置库给的积木和函数。

## 4. 模块文件的写法（`.lc`）

模块用“语法树的文字写法”写：一层层括号，头一个词说这是什么。它和画布上的积木是一一对应的（每种括号对着语言核心的一个节点），
只是写成了文字。写法的全表就是 `lib/lang/lc_text.dart` 里那个读入器；常用的：

```
(模块 小工具
  (公开 (函数 加倍 ((x 整数)) -> 整数 (返回 (* x 2))))      ; 包一层“公开”＝别人能用
  (公开 (记录 口袋 (名 文字) (件数 整数)))
  (函数 帮手 ((s 文字)) -> 文字 (返回 (连 s "！"))))          ; 没包＝只有库自己能用
```

- 声明：`函数` `记录` `枚举` `变体` `接口` `类` `别名` `变量`；外面包 `(公开 …)` 就是公开的。
- 语句：`设` `常` `改` `如果` `当` `每个` `每对` `数` `返回` `抛出` `试` `打印` `做` `加项` `存` `分情况` …
- 式子：数、`"文字"`、`是` `否` `空`、名字、`(调 函数 实参…)` `(发 对象 方法 实参…)` `(新 类 实参…)` `(新记 记录 (字段 值)…)`
  `(. 对象 字段)` `(列 …)` `(典 (键 值)…)` `(标 类型 式子)` `(转 类型 式子)` `(λ (参数…) 式子)` `(λ块 (参数…) 语句…)` 和各种运算。
- 类型：`整数` `小数` `文字` `是否` `空` `任意` `(列表 T)` `(字典 T)` `(可空 T)` `(函数 (参数类型…) 返回类型)` `(要等函数 …)`，或者类型的名字。
- **“要不要等”不用标**（核心 3 起）：函数、方法、匿名函数要不要等，检查器自己推。模块里写的 `要等函数` `要等方法` `要等λ` 还认，
  意思是“不管里面有没有要等的事，都当它要等”，一般用不着；老的库文件不用改。
  反过来可以写 `不等函数` `不等方法`（接口方法在返回类型后面写 `不等`）＝**规定不许等**，里面有要等的事会报 T29。
  函数**类型**上：`(函数 …)`＝没说（要等的、不等的都收）；`(要等函数 …)`＝这个位置收可能要等的函数；`(不等函数 …)`＝只收不用等的，
  放进要等的函数报 T30。库的回调口想清楚要不要让人在里面等：边遍历边改自己数据的那种写 `不等函数`，别的不用写。
- 要等的事的写法：`(开始做块 语句…)` `(等 t)` `(等最多 t 毫秒)` `(等全部 列表)` `(等最先 列表)` `(取消 t)` `(被取消了吗)` `(一次一个 名字 语句…)`；
  类型 `(稍后 T)`。规矩见 B-gen-notes.md 第 16 节（PHP 不一样的地方在 16.6）。
- `;` 到行尾是注释。
- **文字里不做转义**：写了反斜杠就是反斜杠，文字里放不了双引号。（上一轮的样例靠这个规矩，没改。要用到引号、换行的地方，现在只能用小库函数拼。）

读不了的时候给一句话（“不认识的式子：…”或“写法不对（括号不配对…）”），不抛异常。

## 5. 积木表 `blocks.json`

```json
{"blocks": [
  {"id": "double", "how": "call", "of": "加倍", "args": ["x"],
   "look": {"name": "加倍", "shape": "value", "template": "{x} 的两倍"}}
]}
```

| 字段 | 说明 |
|---|---|
| `id` | 积木编号（库里不重复） |
| `module` | 对着哪个模块；库只有一个模块时可以不写 |
| `category` | 放在积木盒的哪一组 |
| `look` | 外观：名字、形状（`value` 值 / `statement` 语句 / `cap` 收尾 / `hat` 帽子）、模板、槽、颜色、提示——和“我的积木”的外观是同一种写法 |
| `slotKinds` | 槽的种类，没写的都是“放值”：`literal` 只能填写死的字 / `assign` “放进变量” / `mouth` 口（里面放一串积木） |
| `how` | 这块积木对着什么：四选一，见下 |
| `of` | `call`：函数名；`static`：`类名.方法名`；`method`：方法名 |
| `args` | 调用时实参怎么排（`call` `static` `method` 用；`method` 的第一个是对象） |
| `expand` | 模板（`how` 是 `expand` 时） |
| `into` | 调用型的语句积木：结果放进哪个 `assign` 槽 |
| `needs` | 要用到哪些隐含的东西（名字） |
| `provides` | 给口里的积木递什么：`{"名字": "模板里的变量名"}` |
| `legacy` | 旧名对照（只有内置库能写，第 9 节） |

### 5.1 四种办法

1. **`call`——对着一个公开函数**。实参个数要和函数对得上。
2. **`static`——对着一个类自己的方法**（`类名.方法名`）。
3. **`method`——对着一个对象的方法**。第一个实参是对象。
4. **`expand`——原地展开**。积木就是一小段模板，用的时候把模板抄到用的地方，把洞填上。帽子、带口的积木只能用这种。

前三种是“调用型”：值积木就是这次调用；语句积木——写了 `into` 就把结果放进那个变量，形状是“收尾”就是“返回 调用的结果”，否则只调不要结果。

`args` 的每一项可以是：

| 写法 | 意思 |
|---|---|
| `"槽名"` | 用这个槽里填的东西 |
| `{"context": "名字"}` | 用隐含的东西（要同时写进 `needs`） |
| `{"setting": "编号"}` | 用设置项的值 |
| `{"preset": 值}` | 写死的值（同一个函数换个默认值就是另一块积木） |

## 6. 模板里的洞

模板是第 4 节的文字写法（可以好几句），多了五种洞：

| 洞 | 意思 |
|---|---|
| `(槽 名)` | 这个槽里填的式子 |
| `(隐含 名)` | 隐含的东西（6.2） |
| `(设置 编号)` | 设置项的值（第 7 节） |
| `(口 名 (收尾 语句…))` | 口里的那串积木原样放这里（6.4）；`收尾` 可以不写 |
| `(放进 槽名 式子)` | 把式子的值放进用户在“放进变量”槽里选的变量（6.3） |

### 6.1 规矩

- **同一个槽在模板里只许出现一次**。要用两次，先 `(设 临时 (槽 名))` 存起来再用——不然用户填的式子会被算两遍。读库的时候就查，查到就是问题。
- 模板里新建的名字（`设` `常` `每个` 的变量、匿名函数的参数…）用的时候**自动改名**，不会和用户的变量、别的展开撞上。
- 模板不许用自己（不许递归）；洞要对着种类对的槽（`口` 对 `mouth`，`放进` 对 `assign`）。

### 6.2 隐含的东西

帽子（或任何带口的积木）可以给口里的积木**递东西**，用户看不见也不用接线：`"provides": {"请求": "这次请求"}`——模板里那个叫“这次请求”的变量，
口里的积木用 `(隐含 请求)` 或 `{"context": "请求"}` 就拿到了。要用的积木在 `needs` 里写上名字；
**不在给它的积木下面用，会被拦下并说清楚**（“「路径参数」要放在给「请求」的积木里面”）。
整个库一直给着的东西（比如路由表）写在清单的 `provides`，在 `init` 里新建。

### 6.3 放进变量

`slotKinds` 里标成 `assign` 的槽，用户在里面选一个变量。调用型用 `into` 指它；展开型在模板里写 `(放进 槽名 式子)`。用户没选变量时，式子照算、结果不要。

### 6.4 口里能放“返回”

口里的积木是**原样放进模板**的（不是包成一个函数再调），所以口里的“返回”“跳出”就是它看上去的意思。
`(收尾 …)` 是口里走完没有离开时接着做的；口里一定会返回的话，收尾就不接了（免得生成“走不到的代码”）。

### 6.5 两个时刻

- `init`：程序开头，在用户的东西之前。库在这里新建它一直给着的东西。
- `start`：程序最后，在用户的东西都登记完之后。“接口服务”在这里开端口。

两个时刻里只能用 `(设置 …)` 这一种洞，不改名（`init` 里新建的变量就是清单 `provides` 指的那个）。几个库：`init` 按排的顺序，`start` 反过来。

## 7. 设置项

```json
{"id": "port", "name": "端口", "type": "整数", "default": 8080, "min": 1, "max": 65535, "hint": "…"}
```

类型用第 4 节的类型写法；默认值只能是空、是否、数、文字，或它们的列表。值存在用了这个库的那份文档里；生成的时候 `(设置 编号)` 换成那个值的字面量。
**密钥不放设置项**（它会进存盘文件和生成的代码），走环境变量。

## 8. 原生绑定（手写代码）

两层：

1. **宿主接口**——语言核心之外、五种语言各有一份实现的那 14 个口子（开服务、读写文件、读环境变量…，`lib/lang/host_v2.dart`）。
   模块里 `(宿主 名字 (参数…) -> 返回)` 声明、`(宿 名字 实参…)` 调用。**只有内置库能声明**。这一层这一版是通的，“接口服务”库就靠它。
2. **库自己带的手写代码**（`native/` 文件夹，每种语言一份函数体）。这一版**读得进来、但不会放进生成的工程**：
   清单没写 `native.allowed` 就带了 `native/` 文件 → 报问题；写了 → 也报“这一版还不会把手写代码放进生成的工程”。
   留给“用户自己写库”那一段接着做（要先有审查界面和开关，见 C 分册 8.6）。

## 9. 内置库比用户库多出来的三处

读入器是同一个，只是传 `builtin: true` 时多放行三样：

1. 模块里能直接声明宿主接口。
2. 积木能写旧名对照 `"legacy": {"fn": "dbGet", "args": ["collection", "id"]}`：旧文档里叫这个名字的积木 / 小库函数，就是这块积木；
   `args` 按旧的参数顺序写槽名，`@名字` 表示那一位是隐含的东西（旧小库把“这次请求”当第一个参数传）。设置项能写 `legacyKey`（旧文档顶层的哪个键）。
3. `autoUse` 生效（某类文档自动带上）。

用户库写了这些：1 报问题，2、3 报问题 / 不算数。

## 10. 上限（自定）

一个库最多 32 个模块、400 块积木、64 个设置项；单个文件最多 40 万字。超过的不收。

## 11. 和 C 分册不一样的地方

| C 分册原来的打算 | 现在 | 为什么 |
|---|---|---|
| 模块定义存成积木的 op/e 写法（JSON） | 存成语法树的文字写法（`.lc`） | 内置库要用的好些节点（标类型 / 转类型、带种类的“出错时”、宿主调用）还没有对应的积木；文字写法一一对着语言核心的节点，现在就全。用户在画布上搭出来的库，由“用户自己写库”那一段翻成这种写法存盘 |
| 积木外观外包一层，`of` 靠前缀区分 | 单独一张 `blocks.json`，`how` 四选一明着写 | 不用猜前缀，读坏了好说清楚是哪一样不对 |
| 模板里的洞是 `{"e": "slot"}` | `(槽 名)` 这样的文字洞 | 跟着上一条 |
| 同一个槽出现两次：自动存临时值 | 读库时拦下，让作者自己先存 | 自动存会悄悄改变算的先后；拦下更不容易出怪事 |
| 库的三个时刻（模块变量初始化、init、start） | `init`、`start` 两个；模块顶上的变量照语言核心的规矩自己初始化 | 第一个本来就是语言核心管的 |
| 手写函数体的原生绑定 | 只读入、如实拒绝 | 见第 8 节 |

# 用户自己写库（库 2）加的部分

## 12. 文字的转义规矩和写出器

读入器是 `lib/lang/lc_text.dart`，写出器是 `lib/lang/lc_write.dart`，两边的写法一一对上。

- 文字里**没有**双引号、反斜杠、换行、回车的：照老写法 `"…"` 原样写。老写法不做转义，所以以前的样例和内置库一个字不用改。
- 文字里**有**这四样之一的：写成 `(字 "…")`，引号中间 `\\`、`\"`、`\n`、`\r`、`\t` 是转义；不认识的转义原样留着那个字。
- “看是哪种情况”收尾的那一口，文字写法里叫 `(其余 …)`（这是落盘格式里的字，不改；界面上一律叫“其他情况”）。
- 别的模块的名字写成“模块名.名字”这种带记号的名字（`lQualified`），库里用了别的库的积木、展开出来的名字就带着它，落盘再读回来不会认错人。
- 写不了的东西（名字里有空格、括号……）写出器会说原因，不出文件。

## 13. 库文档：画布上的库存在哪、长什么样

库在画布上就是一份后端积木文档，顶层多一个 `library`：

```json
"library": {
  "id": "shuang/flow", "version": "1.0.0", "author": "霜霜", "summary": "…",
  "settings": [{"id": "次数", "label": "最多试几次", "type": "int", "default": 3}],
  "defs": [{"id": "retry", "how": "expand", "fn": "f3", "look": {"name": "多试几次", "text": "最多试 {次数} 次"},
            "shape": "stmt", "mouths": ["里面"], "provides": {"第几次": "n"}, "params": {"次数": {"from": "slot"}}}]
}
```

- `how` 四选一：`call`（调函数）、`method`（调对象的方法，多一个叫“对象”的槽）、`static`（调类自己的方法）、`expand`（原地展开，也就是设计里的“模板”）。
- 参数从哪来（`params.<名>.from`）：`slot`（积木上的槽）、`implicit`（外层帽子递进来的隐含的东西）、`setting`（库的设置项）。
- `into: true`：调用型积木多一个叫“结果”的“放进变量”槽。
- `mouths`：口的名字，最多 2 个；`provides`：这块积木递给口里的东西（名字 → 函数里的哪个变量）。
- 库的定义画布上多两块积木：`libMouth`（做口里的积木）、`libPut`（把结果交给用的人选的变量），只在原地展开的定义里有意义。
- 库文档存盘时不生成后端工程，而是出库文件夹（下一节）；出完自己读一遍、查一遍，查不过就不给文件、把原因列出来。

用库的文档顶层多 `uses`（用了哪些库、每个库的设置项填了什么）和 `hats`（库的帽子积木开头的串）。库积木在文档里写 `lib:作者段/库名#积木编号`——认的是库标识和积木编号，所以库里改函数名、改积木上的字，用的文档都不用跟着改。三样都是没有就不写键，没碰库的旧文档读进来再存出去一个字节不差。

## 14. 库在项目里怎么放

```
blocks/libs.json                  项目里有哪些库（标识、版本、从哪来、内容的校验值）
blocks/作者段/库名/lib.json        清单
blocks/作者段/库名/blocks.json     积木表
blocks/作者段/库名/modules/*.lc    模块
blocks/作者段/库名/source/backend.lc.json   画布原件（有它才能回画布接着改、才能“复制一份来改”）
```

清单比第 2 节多出来的键：`author`、`origin`（从谁复制来的）、`requires`（靠哪些别的库，最多 16 个）、`native.waits`（手写函数里哪些“要等”，最多 64 个，只读进来显示）。
作者段 `lopi`、`local` 是应用自己留着的，别的库不许用。模块名前面带库标识（`作者段/库名` 或 `作者段/库名:模块名`），所以两个库的模块、生成出来的文件都不重名。

## 15. 导出文件 `.lopilib`

就是库文件夹打成的一个 zip，放在 `exports/库-名字-版本.lopilib`。文件按名字排好、时间固定，同样的库打出来一个字节不差。

拆包时的防护：整个文件最多 8MB、最多 512 个文件、单个解出来最多 1MB（清单 256KB）、解出来总量最多 16MB；文件名里有 `..`、以 `/` 开头、带盘符或反斜杠的整包不要；只留清单、积木表、`modules/`、`source/`、`native/`。不从网址导入，不执行包里的任何东西。

导入前先出预览：名字、标识、版本、作者、每块积木、要用到的宿主能力、靠哪些库、有没有手写代码（有就列出文件、可以点开看）。

**手写代码这一版做到“如实显示并拒绝启用”**：带 `native/` 的库预览页说清楚不能导入，“导入”按钮是灰的。差的是三样：五种语言各自怎么把手写文件接进生成的工程；手写函数的类型和“要不要等”怎么声明、怎么查（`native.waits` 现在只显示）；运行环境里怎么隔开。

## 16. 多个库同时用时名字怎么不撞

| 语言 | 库的模块变成什么 | 例子（库 `shuang/flow`） |
|---|---|---|
| Node | 一个文件，名字带库标识 | `m_shuang_u2f_flow.js` |
| Python | 一个文件，`import` 的就是这个文件名 | `m_shuang_u2f_flow.py` |
| PHP | 一个文件；函数、类哪个文件都看得见，两个模块里同名的在合并那一步自动改名 | `m_shuang_u2f_flow.php` |
| Go | 同一个包里的一个文件；同名的在合并那一步自动改名 | `m_shuang_u2f_flow_lc.go` |
| Java | 一个 `final class`，别的模块用它的东西写“类名.名字”，**不再靠类一个接一个继承** | `M_shuang_5fu2f_5fflow.java` |

Go 没有给每个库单开一个包：同名的东西合并时已经自动改名、不会撞（验收里“三个库同用、故意同名”五种语言真跑一致），单开包要改工程目录和启动命令，这一版不动。没公开的名字别的库用不到——这是检查阶段拦的（T 系列的“没公开”那条），生成的代码不再拦一遍。

## 17. 和 C 分册不一样的地方（库 2）

| C 分册的打算 | 现在 | 为什么 |
|---|---|---|
| 应用级“我的库”＋侧边栏“积木库”页 | 只有项目里的库（`blocks/`），入口在后端积木页“更多”›“积木库” | 先把“写库→用库→导出导入”整条路走通；跨项目用靠导出文件 |
| 新建库三步（名字→给谁用→放哪） | 两步（名字、标识） | 这一版只有后端库、只放项目里，后两步没有可选的 |
| 内置库“复制一份来改” | 不能：内置“接口服务”没有画布原件，又直接用宿主接口（用户库不许） | 能做的是新建库叠在它上面（验收里的“待办”库就是） |
| 手写代码：默认关、看了代码同意才启用 | 如实显示并拒绝启用 | 见第 15 节 |
| 设置项带最小、最大值 | 只有整数、文字、是/否三种，没有范围 | 界面上没做填范围的地方 |
