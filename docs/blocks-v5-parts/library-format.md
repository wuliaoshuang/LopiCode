# 库的落盘格式（第 1 版）

> 积木第 5 版·库 1（第三轮 A1）定的。实现在 `lib/lang/lib_model.dart`（读）、`lib_check.dart`（查）、`lib_apply.dart`（用）、`lc_text.dart`（模块文件的写法）。
> 内置库（“接口服务”，`lib/backend/lib_service.dart`）和将来用户自己写的库是**同一种格式、同一个读入器**；差别只有第 9 节那三处。
> 设计在 C 分册（`C-library-system.md`）；和它不一样的地方集中写在第 10 节。

## 1. 一个库是什么

库＝一个文件夹：一份清单、一个或几个模块（真正干活的函数、类、类型）、一张积木表（画布上长什么样、对着模块里的什么）。

```
我的库/
  lib.json            清单（必须有）
  modules/xxx.lc      模块：语言核心写的定义（第 4 节）
  blocks.json         积木表（第 5 节），可以有几个
  native/…            手写代码（第 8 节；这一版读得进来但用不了）
```

读入器吃的是“相对路径 → 文件内容”这样一张表（`libRead(files, builtin: …)`），不管它是从磁盘、压缩包还是应用里带的文字来的。
**任何输入都不抛异常**：有问题就记在库的“问题”表里，有问题的库不能用。

## 2. 清单 `lib.json`

| 字段 | 必须 | 说明 |
|---|---|---|
| `kind` | 是 | 固定 `"lopicode-lib"` |
| `format` | 否 | 格式版本，现在是 1；比 1 大的不收 |
| `id` | 是 | `作者/库名`，两段都是小写字母、数字、连字符，字母开头，每段最多 32 个字 |
| `name` | 否 | 给人看的名字（最多 24 个字），没写用库名 |
| `version` | 否 | 版本号文字 |
| `summary` | 否 | 一句话说明（最多 80 个字） |
| `rules` | 否 | 规矩版本，只能是 2（库一律照严格规矩写） |
| `modules` | 是 | `[{"file": "modules/a.lc", "name": "模块名"}]`；一个文件里正好一个模块，名字要和文件里写的一样 |
| `blocks` | 否 | 积木表文件的路径列表 |
| `types` | 否 | 这个库给出来的类型：`{"name", "module", "hint"}`；必须是那个模块里**公开**的类型 |
| `settings` | 否 | 设置项（第 7 节） |
| `init` | 否 | “准备”时刻要做的语句（文字写法，第 6.5 节） |
| `start` | 否 | “最后启动”时刻要做的语句 |
| `provides` | 否 | 整个库一直给着的隐含东西：`{"名字": "变量名"}`（变量在 `init` 里新建） |
| `autoUse` | 否 | 哪类文档自动带上它（只有内置库写了才算数） |
| `native` | 否 | `{"allowed": true}`＝带手写代码（第 8 节） |

## 3. 模块里不许有什么

- 不许有“程序开始时”（`(主 …)`）：库不是程序。要在开头、结尾做事，用清单的 `init`、`start`。
- 不许直接声明宿主接口（`(宿主 …)`）——只有内置库可以（第 9 节）。用户库要碰外面的世界，只能用内置库给的积木和函数。

## 4. 模块文件的写法（`.lc`）

模块用“语法树的文字写法”写：一层层括号，头一个词说这是什么。它和画布上的积木是一一对应的（每种括号对着语言核心的一个节点），
只是写成了文字。写法的全表就是 `lib/lang/lc_text.dart` 里那个读入器；常用的：

```
(模块 小工具
  (公开 (函数 加倍 ((x 整数)) -> 整数 (返回 (* x 2))))      ; 包一层“公开”＝别人能用
  (公开 (记录 口袋 (名 文字) (件数 整数)))
  (函数 帮手 ((s 文字)) -> 文字 (返回 (连 s "！"))))          ; 没包＝只有库自己能用
```

- 声明：`函数` `记录` `枚举` `变体` `接口` `类` `别名` `变量`；外面包 `(公开 …)` 就是公开的。
- 语句：`设` `常` `改` `如果` `当` `每个` `每对` `数` `返回` `抛出` `试` `打印` `做` `加项` `存` `分情况` …
- 式子：数、`"文字"`、`是` `否` `空`、名字、`(调 函数 实参…)` `(发 对象 方法 实参…)` `(新 类 实参…)` `(新记 记录 (字段 值)…)`
  `(. 对象 字段)` `(列 …)` `(典 (键 值)…)` `(标 类型 式子)` `(转 类型 式子)` `(λ (参数…) 式子)` `(λ块 (参数…) 语句…)` 和各种运算。
- 类型：`整数` `小数` `文字` `是否` `空` `任意` `(列表 T)` `(字典 T)` `(可空 T)` `(函数 (参数类型…) 返回类型)` `(要等函数 …)`，或者类型的名字。
- **“要不要等”不用标**（核心 3 起）：函数、方法、匿名函数要不要等，检查器自己推。模块里写的 `要等函数` `要等方法` `要等λ` 还认，
  意思是“不管里面有没有要等的事，都当它要等”，一般用不着；老的库文件不用改。
  反过来可以写 `不等函数` `不等方法`（接口方法在返回类型后面写 `不等`）＝**规定不许等**，里面有要等的事会报 T29。
  函数**类型**上：`(函数 …)`＝没说（要等的、不等的都收）；`(要等函数 …)`＝这个位置收可能要等的函数；`(不等函数 …)`＝只收不用等的，
  放进要等的函数报 T30。库的回调口想清楚要不要让人在里面等：边遍历边改自己数据的那种写 `不等函数`，别的不用写。
- 要等的事的写法：`(开始做块 语句…)` `(等 t)` `(等最多 t 毫秒)` `(等全部 列表)` `(等最先 列表)` `(取消 t)` `(被取消了吗)` `(一次一个 名字 语句…)`；
  类型 `(稍后 T)`。规矩见 B-gen-notes.md 第 16 节（PHP 不一样的地方在 16.6）。
- `;` 到行尾是注释。
- **文字里不做转义**：写了反斜杠就是反斜杠，文字里放不了双引号。（上一轮的样例靠这个规矩，没改。要用到引号、换行的地方，现在只能用小库函数拼。）

读不了的时候给一句话（“不认识的式子：…”或“写法不对（括号不配对…）”），不抛异常。

## 5. 积木表 `blocks.json`

```json
{"blocks": [
  {"id": "double", "how": "call", "of": "加倍", "args": ["x"],
   "look": {"name": "加倍", "shape": "value", "template": "{x} 的两倍"}}
]}
```

| 字段 | 说明 |
|---|---|
| `id` | 积木编号（库里不重复） |
| `module` | 对着哪个模块；库只有一个模块时可以不写 |
| `category` | 放在积木盒的哪一组 |
| `look` | 外观：名字、形状（`value` 值 / `statement` 语句 / `cap` 收尾 / `hat` 帽子）、模板、槽、颜色、提示——和“我的积木”的外观是同一种写法 |
| `slotKinds` | 槽的种类，没写的都是“放值”：`literal` 只能填写死的字 / `assign` “放进变量” / `mouth` 口（里面放一串积木） |
| `how` | 这块积木对着什么：四选一，见下 |
| `of` | `call`：函数名；`static`：`类名.方法名`；`method`：方法名 |
| `args` | 调用时实参怎么排（`call` `static` `method` 用；`method` 的第一个是对象） |
| `expand` | 模板（`how` 是 `expand` 时） |
| `into` | 调用型的语句积木：结果放进哪个 `assign` 槽 |
| `needs` | 要用到哪些隐含的东西（名字） |
| `provides` | 给口里的积木递什么：`{"名字": "模板里的变量名"}` |
| `legacy` | 旧名对照（只有内置库能写，第 9 节） |

### 5.1 四种办法

1. **`call`——对着一个公开函数**。实参个数要和函数对得上。
2. **`static`——对着一个类自己的方法**（`类名.方法名`）。
3. **`method`——对着一个对象的方法**。第一个实参是对象。
4. **`expand`——原地展开**。积木就是一小段模板，用的时候把模板抄到用的地方，把洞填上。帽子、带口的积木只能用这种。

前三种是“调用型”：值积木就是这次调用；语句积木——写了 `into` 就把结果放进那个变量，形状是“收尾”就是“返回 调用的结果”，否则只调不要结果。

`args` 的每一项可以是：

| 写法 | 意思 |
|---|---|
| `"槽名"` | 用这个槽里填的东西 |
| `{"context": "名字"}` | 用隐含的东西（要同时写进 `needs`） |
| `{"setting": "编号"}` | 用设置项的值 |
| `{"preset": 值}` | 写死的值（同一个函数换个默认值就是另一块积木） |

## 6. 模板里的洞

模板是第 4 节的文字写法（可以好几句），多了五种洞：

| 洞 | 意思 |
|---|---|
| `(槽 名)` | 这个槽里填的式子 |
| `(隐含 名)` | 隐含的东西（6.2） |
| `(设置 编号)` | 设置项的值（第 7 节） |
| `(口 名 (收尾 语句…))` | 口里的那串积木原样放这里（6.4）；`收尾` 可以不写 |
| `(放进 槽名 式子)` | 把式子的值放进用户在“放进变量”槽里选的变量（6.3） |

### 6.1 规矩

- **同一个槽在模板里只许出现一次**。要用两次，先 `(设 临时 (槽 名))` 存起来再用——不然用户填的式子会被算两遍。读库的时候就查，查到就是问题。
- 模板里新建的名字（`设` `常` `每个` 的变量、匿名函数的参数…）用的时候**自动改名**，不会和用户的变量、别的展开撞上。
- 模板不许用自己（不许递归）；洞要对着种类对的槽（`口` 对 `mouth`，`放进` 对 `assign`）。

### 6.2 隐含的东西

帽子（或任何带口的积木）可以给口里的积木**递东西**，用户看不见也不用接线：`"provides": {"请求": "这次请求"}`——模板里那个叫“这次请求”的变量，
口里的积木用 `(隐含 请求)` 或 `{"context": "请求"}` 就拿到了。要用的积木在 `needs` 里写上名字；
**不在给它的积木下面用，会被拦下并说清楚**（“「路径参数」要放在给「请求」的积木里面”）。
整个库一直给着的东西（比如路由表）写在清单的 `provides`，在 `init` 里新建。

### 6.3 放进变量

`slotKinds` 里标成 `assign` 的槽，用户在里面选一个变量。调用型用 `into` 指它；展开型在模板里写 `(放进 槽名 式子)`。用户没选变量时，式子照算、结果不要。

### 6.4 口里能放“返回”

口里的积木是**原样放进模板**的（不是包成一个函数再调），所以口里的“返回”“跳出”就是它看上去的意思。
`(收尾 …)` 是口里走完没有离开时接着做的；口里一定会返回的话，收尾就不接了（免得生成“走不到的代码”）。

### 6.5 两个时刻

- `init`：程序开头，在用户的东西之前。库在这里新建它一直给着的东西。
- `start`：程序最后，在用户的东西都登记完之后。“接口服务”在这里开端口。

两个时刻里只能用 `(设置 …)` 这一种洞，不改名（`init` 里新建的变量就是清单 `provides` 指的那个）。几个库：`init` 按排的顺序，`start` 反过来。

## 7. 设置项

```json
{"id": "port", "name": "端口", "type": "整数", "default": 8080, "min": 1, "max": 65535, "hint": "…"}
```

类型用第 4 节的类型写法；默认值只能是空、是否、数、文字，或它们的列表。值存在用了这个库的那份文档里；生成的时候 `(设置 编号)` 换成那个值的字面量。
**密钥不放设置项**（它会进存盘文件和生成的代码），走环境变量。

## 8. 原生绑定（手写代码）

两层：

1. **宿主接口**——语言核心之外、五种语言各有一份实现的那 14 个口子（开服务、读写文件、读环境变量…，`lib/lang/host_v2.dart`）。
   模块里 `(宿主 名字 (参数…) -> 返回)` 声明、`(宿 名字 实参…)` 调用。**只有内置库能声明**。这一层这一版是通的，“接口服务”库就靠它。
2. **库自己带的手写代码**（`native/` 文件夹，每种语言一份函数）。第四轮起接通了：默认关，全应用的开关开着、这个库的这一份代码她看过并确认了才会放进生成的工程。格式和规矩见第 20 节。
   （第三轮这里写的是“读得进来、但不会放进生成的工程”，已经过时。）

用户的库要直接声明宿主接口，必须在清单的 `hosts` 里一个不落地写明（第 19 节）；没写的照旧报问题。

## 9. 内置库比用户库多出来的三处

读入器是同一个，只是传 `builtin: true` 时多放行三样：

1. 模块里能直接声明宿主接口。
2. 积木能写旧名对照 `"legacy": {"fn": "dbGet", "args": ["collection", "id"]}`：旧文档里叫这个名字的积木 / 小库函数，就是这块积木；
   `args` 按旧的参数顺序写槽名，`@名字` 表示那一位是隐含的东西（旧小库把“这次请求”当第一个参数传）。设置项能写 `legacyKey`（旧文档顶层的哪个键）。
3. `autoUse` 生效（某类文档自动带上）。

用户库写了这些：1 报问题，2、3 报问题 / 不算数。

## 10. 上限（自定）

一个库最多 32 个模块、400 块积木、64 个设置项；单个文件最多 40 万字。超过的不收。

## 11. 和 C 分册不一样的地方

| C 分册原来的打算 | 现在 | 为什么 |
|---|---|---|
| 模块定义存成积木的 op/e 写法（JSON） | 存成语法树的文字写法（`.lc`） | 内置库要用的好些节点（标类型 / 转类型、带种类的“出错时”、宿主调用）还没有对应的积木；文字写法一一对着语言核心的节点，现在就全。用户在画布上搭出来的库，由“用户自己写库”那一段翻成这种写法存盘 |
| 积木外观外包一层，`of` 靠前缀区分 | 单独一张 `blocks.json`，`how` 四选一明着写 | 不用猜前缀，读坏了好说清楚是哪一样不对 |
| 模板里的洞是 `{"e": "slot"}` | `(槽 名)` 这样的文字洞 | 跟着上一条 |
| 同一个槽出现两次：自动存临时值 | 读库时拦下，让作者自己先存 | 自动存会悄悄改变算的先后；拦下更不容易出怪事 |
| 库的三个时刻（模块变量初始化、init、start） | `init`、`start` 两个；模块顶上的变量照语言核心的规矩自己初始化 | 第一个本来就是语言核心管的 |
| 手写函数体的原生绑定 | 只读入、如实拒绝 | 见第 8 节 |

# 用户自己写库（库 2）加的部分

## 12. 文字的转义规矩和写出器

读入器是 `lib/lang/lc_text.dart`，写出器是 `lib/lang/lc_write.dart`，两边的写法一一对上。

- 文字里**没有**双引号、反斜杠、换行、回车的：照老写法 `"…"` 原样写。老写法不做转义，所以以前的样例和内置库一个字不用改。
- 文字里**有**这四样之一的：写成 `(字 "…")`，引号中间 `\\`、`\"`、`\n`、`\r`、`\t` 是转义；不认识的转义原样留着那个字。
- “看是哪种情况”收尾的那一口，文字写法里叫 `(其余 …)`（这是落盘格式里的字，不改；界面上一律叫“其他情况”）。
- 别的模块的名字写成“模块名.名字”这种带记号的名字（`lQualified`），库里用了别的库的积木、展开出来的名字就带着它，落盘再读回来不会认错人。
- 写不了的东西（名字里有空格、括号……）写出器会说原因，不出文件。

## 13. 库文档：画布上的库存在哪、长什么样

库在画布上就是一份后端积木文档，顶层多一个 `library`：

```json
"library": {
  "id": "shuang/flow", "version": "1.0.0", "author": "霜霜", "summary": "…",
  "settings": [{"id": "次数", "label": "最多试几次", "type": "int", "default": 3}],
  "defs": [{"id": "retry", "how": "expand", "fn": "f3", "look": {"name": "多试几次", "text": "最多试 {次数} 次"},
            "shape": "stmt", "mouths": ["里面"], "provides": {"第几次": "n"}, "params": {"次数": {"from": "slot"}}}]
}
```

- `how` 四选一：`call`（调函数）、`method`（调对象的方法，多一个叫“对象”的槽）、`static`（调类自己的方法）、`expand`（原地展开，也就是设计里的“模板”）。
- 参数从哪来（`params.<名>.from`）：`slot`（积木上的槽）、`implicit`（外层帽子递进来的隐含的东西）、`setting`（库的设置项）。
- `into: true`：调用型积木多一个叫“结果”的“放进变量”槽。
- `mouths`：口的名字，最多 2 个；`provides`：这块积木递给口里的东西（名字 → 函数里的哪个变量）。
- 库的定义画布上多两块积木：`libMouth`（做口里的积木）、`libPut`（把结果交给用的人选的变量），只在原地展开的定义里有意义。
- 库文档存盘时不生成后端工程，而是出库文件夹（下一节）；出完自己读一遍、查一遍，查不过就不给文件、把原因列出来。

用库的文档顶层多 `uses`（用了哪些库、每个库的设置项填了什么）和 `hats`（库的帽子积木开头的串）。库积木在文档里写 `lib:作者段/库名#积木编号`——认的是库标识和积木编号，所以库里改函数名、改积木上的字，用的文档都不用跟着改。三样都是没有就不写键，没碰库的旧文档读进来再存出去一个字节不差。

## 14. 库在项目里怎么放

```
blocks/libs.json                  项目里有哪些库（标识、版本、从哪来、内容的校验值）
blocks/作者段/库名/lib.json        清单
blocks/作者段/库名/blocks.json     积木表
blocks/作者段/库名/modules/*.lc    模块
blocks/作者段/库名/source/backend.lc.json   画布原件（有它才能回画布接着改、才能“复制一份来改”）
```

清单比第 2 节多出来的键：`author`、`origin`（从谁复制来的）、`requires`（靠哪些别的库，最多 16 个）、`native.waits`（手写函数里哪些“要等”，最多 64 个，只读进来显示）。
作者段 `lopi`、`local` 是应用自己留着的，别的库不许用。模块名前面带库标识（`作者段/库名` 或 `作者段/库名:模块名`），所以两个库的模块、生成出来的文件都不重名。

## 15. 导出文件 `.lopilib`

就是库文件夹打成的一个 zip，放在 `exports/库-名字-版本.lopilib`。文件按名字排好、时间固定，同样的库打出来一个字节不差。

拆包时的防护：整个文件最多 8MB、最多 512 个文件、单个解出来最多 1MB（清单 256KB）、解出来总量最多 16MB；文件名里有 `..`、以 `/` 开头、带盘符或反斜杠的整包不要；只留清单、积木表、`modules/`、`source/`、`native/`。不从网址导入，不执行包里的任何东西。

导入前先出预览：名字、标识、版本、作者、每块积木、要用到的宿主能力、靠哪些库、有没有手写代码（有就列出文件、可以点开看）。

**手写代码**：第三轮做到“如实显示并拒绝启用”；第四轮给出了启用的路（第 20 节）。开关关着时仍然是如实显示、拒绝导入。

## 16. 多个库同时用时名字怎么不撞

| 语言 | 库的模块变成什么 | 例子（库 `shuang/flow`） |
|---|---|---|
| Node | 一个文件，名字带库标识 | `m_shuang_u2f_flow.js` |
| Python | 一个文件，`import` 的就是这个文件名 | `m_shuang_u2f_flow.py` |
| PHP | 一个文件；函数、类哪个文件都看得见，两个模块里同名的在合并那一步自动改名 | `m_shuang_u2f_flow.php` |
| Go | 同一个包里的一个文件；同名的在合并那一步自动改名 | `m_shuang_u2f_flow_lc.go` |
| Java | 一个 `final class`，别的模块用它的东西写“类名.名字”，**不再靠类一个接一个继承** | `M_shuang_5fu2f_5fflow.java` |

Go 没有给每个库单开一个包：同名的东西合并时已经自动改名、不会撞（验收里“三个库同用、故意同名”五种语言真跑一致），单开包要改工程目录和启动命令，这一版不动。没公开的名字别的库用不到——这是检查阶段拦的（T 系列的“没公开”那条），生成的代码不再拦一遍。

# 第四轮（线 A·A1）加的部分

## 18. 库“给谁用”

清单多一个键 `for`：`backend`（后端）、`frontend`（前端）、`both`（后端和前端都行）。**没写＝后端**——这个键之前的库都是后端的，旧文件读进来不改写、再存出去一个字节不差（后端的库存盘时不写这个键）。

| 写的是 | 读库时查什么 |
|---|---|
| `both` | 不许直接用宿主接口、不许带手写代码、不许靠“接口服务”——只用语言核心的库才两边都能用 |
| `frontend` | 不许用后端的宿主接口、不许带手写代码、不许靠“接口服务”（前端自己的宿主接口和“页面”库由前端 1 接进来） |
| `backend` | 没有额外限制 |

用的时候：文档自己知道它是哪一边的（`LibUser.libSide`，后端积木文档＝后端）。给谁用对不上的库——库面板里“在这份文档里用它”的开关是灰的、下面写着原因；
检查阶段和生成阶段也各拦一次（文件被人手改成用上了也过不去）。新建库多一步“这个库给谁用”（三选一，默认是当前这份文档那一边）。导入预览页有一行“给谁用”。

文档无关的那一层在 `lib/lowcode/lib_blocks.dart`：`LibUser`（一份“会用库的文档”要答的几个问题）、`LibTable`（库积木表）、`libCategories`（积木盒分组）。
后端文档是第一个使用者（`backend_lib_table.dart` 只剩薄薄一层），前端 1 的页面逻辑文档是第二个。

## 19. 顶替自带库：“接口服务”复制一份来改

> **2026-11-27 中途包：这一处默认关。** 复制件直接用宿主接口，而“自己的库在清单里写明后可以直接用宿主接口”由 `lib/lang/rules.dart` 的 `kUserLibHostEnabled`（界面和读库读的是 `userLibHostEntry`）管着，现在是关，等霜霜点头再开。关着时：自带“接口服务”面板上没有可点的“复制一份来改”，换成一行灰字“这一版还不能复制自带的接口服务库来改”；不是应用自带的库只要模块里直接声明了宿主接口（清单里写没写明都一样），读出来就是问题“这一版自己的库还不能直接碰宿主接口，只有应用自带的库可以”，导入预览如实显示并拒绝。应用自带的“接口服务”“页面”库不受影响。

清单多三个键：

| 键 | 说明 |
|---|---|
| `replaces` | 顶替哪个自带库。现在只认 `lopi/service`。写了它的库不能当普通库“用上”，只能被文档指定去顶替 |
| `hosts` | 这个库直接用了哪些宿主接口，**一个不落地**写出来；模块里声明了、这里没写的 → 读库就是问题。导入预览页把它们用人话列在“要注意的”里 |
| `origin` | 从谁复制来的（标识和版本），只是记一笔 |

写了 `replaces` 的库多放行两样原来只有自带库能做的事：旧名对照（`legacy`、`legacyKey`）——没有它旧文档里的接口积木找不到人。`autoUse` 仍然不放行。

用它的文档顶层多一个键 `serviceLib`（库标识；没有就不写，旧文档一个字节不变）。指定以后：接口、请求、回应、数据集合这些积木（含旧名字的）、端口这些设置项都走这个库；
自带的那个这份文档里不再带。指定的库不在项目里、读不了、清单没写 `replaces` → 检查阶段说原因，生成不出来。
有库顶替了“接口服务”、同一份文档里别的库却还靠着自带的那个（`requires: lopi/service`）→ 拦下（两边的“请求”是两个模块里的两样东西，接不上）。

复制件怎么不和原库撞名：模块名换成库标识（生成的文件名跟着换）、启动时用的路由表变量换成“路由表_标识”、记录类型挂在新模块名下面。原库和复制件同时在项目里、甚至各被一份文档用着都不撞。

**为什么复制出来的是文字写法、不是画布上的原样**（认真评估过，结论是这一段做不成画布的）：

1. 自带库不是从画布上搭出来的，没有画布原件；要给复制件画布原件，得把 298 行的模块文字**反过来翻成积木**。应用里只有“积木 → 文字”的写出器，没有反方向的。
2. 就算写一个反向的翻法，模块里有三类东西现在没有对应的积木：“看它是哪一类值”（`是类`，17 处）、“当成某种类型用”（`转`，22 处）和“标上类型”（`标`，18 处）——
   这是处理“任意”类型的值（请求内容、JSON）必需的，几乎每个函数都有；还有直接调宿主接口（`宿`，11 处，7 个接口）、带“要等”的函数类型（2 处）。
   也就是说不是“碰宿主接口的那几个函数留在文字里、其余上画布”能切开的：不碰宿主接口的函数里也到处是前三种。
3. 一个库“一部分模块在画布上、一部分是文字”这种混合形态现在的库文档也不支持（有画布原件的库，文字全部由画布出）。

要做成画布的，前提是三件事：给 `是类` / `转` / `标` 做积木、做“原生绑定积木”（直接调宿主接口的那种；前端 1·上本来就要做）、做“文字 → 积木”的反向翻法。
> **2026-11-28 补（第四轮·A3b）：三件前提都有了，但复制件还没改成画布版。** 三个类型积木和原生绑定积木在 A3b 上半做了；“文字 → 积木”的反向翻法在 A3b 下半做了（`lib/backend/backend_from_text.dart`），自带的两个库现在能在画布上**只读地看**（库面板里“在画布上看（只读）”）：“接口服务”40 个函数 230 句全部翻成了积木，其中 34 处某个值没有对应积木、照文字原样放着。上面第 2 条里的数字是当时的，现在的缺口见 D 分册“落地说明（第四轮·A3b 下半）”。
> 复制件改成画布版还差三件没定：类型别名在积木文档里放哪；清单里 `autoUse`、`init`、`start`、`provides` 这些自带库专用字段复制件怎么带；一块展开成好几句的积木表模板复制后谁维护。

前两件做完以后第三件才有意义。在那之前，“复制一份来改”得到的是能打开、能改、能用的**文字写法**的库：

- 库面板里“改库的文字”：列出清单、积木表、模块三个文件，点开是一整页的编辑框（代码字号跟着全应用的设置）；
- 顶上“检查”（只查不存）和“存”。存之前一定先查：括号、引号、JSON 写坏了说**第几行**；读库查出来的问题（类型对不上、积木对不上函数……）点得出名字的补一句“这个文件第几行附近”；查不过不存，原文件不动；
- 库的标识不能在这里改；带画布原件的库不走这条路（在画布上改）。

行号是另外扫一遍文字得来的（`lib/lang/lc_locate.dart`），读库的那一套没有改。类型检查查出来、又点不出名字的问题说不出行——这种只说原因。

## 20. 库里的手写代码

> **2026-11-27 中途包：这一处默认关。** 由 `lib/lang/rules.dart` 的 `kLibNativeCodeEnabled`（各处读的是 `libNativeCodeEntry`）管着，等霜霜点头再开。关着时：设置 › 能力 里没有“积木库的手写代码”那一行；`LibNativeTrust` 一律当成没开（私有目录里存过“开着”和确认记录也不算数）；带手写代码的库导入预览照样列出文件、能点开看全文，但不能导入；已经在项目里的照旧“有问题、用不了”，库面板里只给“看手写代码”；提示语统一是“这一版还不能启用带手写代码的库”，不指向任何入口。下面 20.3 写的启用的路只在开着时成立。

### 20.1 格式

```json
"native": {
  "allowed": true,
  "functions": [
    {"name": "join", "params": ["文字", "整数"], "returns": "文字", "waits": false,
     "files": {"node": "native/join.js", "python": "native/join.py", "php": "native/join.php", "go": "native/join.go", "java": "native/join.java"}}
  ]
}
```

- 每个手写函数在清单里**逐个声明**：名字（英文字母开头，字母、数字、下划线，最多 32 个字）、参数类型、返回类型、要不要等、每种语言对着 `native/` 里哪个文件。一个库最多 32 个。
- 参数和返回只能是 文字、整数、小数、是否（不能可空），最多 8 个参数。别的东西先变成文字（比如 JSON）再交过去。
- 模块里用 `(宿主 手写.<库标识>.<函数名> (参数…) -> 返回)` 声明、`(宿 手写.<库标识>.<函数名> 实参…)` 调用。
- 读库时查：`native/` 里每个文件都要在清单里登记到某个函数名下（没登记的文件 → 问题）；清单里有的函数模块里要有声明、模块里声明的清单里要有；
  **两边的参数个数、类型、返回类型要一样**（对不上 → 问题）；每个文件要是规定的样子（下表“必须出现”那一列——只是防写错文件，不是安全检查）；
  “都行”和“只给前端”的库不许带。
- 调用的地方照声明的类型查（给整数的地方给了文字 → 检查阶段拦）；声明“要等”的，调用处由系统自己加等、外面那个函数跟着变成要等的（和“要等的事”同一套）。
- 第三轮的 `native.waits` 名单不再读（要不要等写在每个函数自己的 `waits` 上）。

### 20.2 五种语言各自怎么接进生成的工程

文件原样放进工程、和主文件放在一起，文件名是 `LcN_<库标识>_<函数名>.<后缀>`（标识里的 `/` 换成 `__`、`-` 换成 `_`）；文件里的占位名字 `__NAME__` 换成这个名字。

| 语言 | 文件要写成 | 必须出现 | 调用处生成 |
|---|---|---|---|
| Node | `module.exports = function (参数…) { … };` | `module.exports` | `require("./名字.js")(实参…)` |
| Python | `def run(参数…):` | `def run(` | `__import__("名字").run(实参…)` |
| PHP | `<?php return function (参数…) { … };` | `return ` | `($GLOBALS['名字'] ??= require __DIR__ . '/名字.php')(实参…)` |
| Go | `package main` ⏎ `func __NAME__(参数…) 返回类型 { … }` | `__NAME__` | `名字(实参…)`（同一个包） |
| Java | `final class __NAME__ { static 返回类型 run(参数…) { … } }` | `__NAME__` | `名字.run(实参…)` |

实参、返回值照声明的类型转好了再交（整数在 Node 里是 BigInt、Go 里是 `int64`、Java 里是 `long`）。
哪个函数没有某种语言的文件：那种语言不生成，说明是哪个库的哪个函数缺；别的语言照常。

### 20.3 启用的路（每一道）

1. **全应用一个开关**“允许库里的手写代码”（设置 › 能力 › 积木库的手写代码），**默认关**。打开要过一道确认框（危险色按钮“我明白，打开”），框里是下面 20.4 那段话；关掉不用确认。
2. **每个库单独确认**：开关开着时，导入预览页列出每个手写文件、点开看全文，底下勾“我看过这些代码了，知道它会跟着工程一起运行”，勾了“导入”才亮。开关关着：不能导入（只能看）。
3. **记的是这一份代码**：确认记录＝（项目、库标识）→ 清单和 `native/` 全部文件的 SHA-256。库的手写代码或清单变了一个字就对不上，这个库立刻用不了，
   要到库面板里“看手写代码并确认”重新看、重新勾。
4. **关掉开关＝全部作废**：所有确认一起清掉，再打开要一个一个重新确认。
5. 确认记录存在**应用自己的私有目录**（应用支持目录下的 `lib_native_trust.json`），不在任何项目文件夹里——项目文件夹是 Agent 能写的地方，记在那里等于 Agent 能替她点头。
   Agent 的读写文件工具被路径守卫挡在项目文件夹里，够不到它；Agent 的终端命令平时在 Ubuntu 环境里跑，那里面没有挂这个目录，也看不到它。
   **没挡死的一处**：Ubuntu 环境起不来、终端退回手机本机 shell 的时候，命令是以应用自己的身份跑的，理论上摸得到应用私有目录里的任何文件（包括这个和设置文件）——
   这是终端退回本机 shell 本来就有的事，不是这次新开的口子，但它意味着“确认记录 Agent 绝对改不了”这句话不能说。界面以外应用里没有别的入口改它。存盘走 `writeJsonAtomic` / `readJsonFile`，文件坏了＝关着、一个都没确认过。
6. 没放行的库照样读得出来、看得到，只是带一条问题、用不了；生成阶段拿不到它的手写文件。

没有变的：不从网址导入；导出包的上限（整包 8MB、512 个文件、单个 1MB、总量 16MB、路径规矩）一条没松；应用自己**不执行**手写代码——它只是被写进生成的工程，工程运行时才跑。

### 20.4 没隔开的是什么（界面上写的就是这段，不许写得比这安全）

> 手写代码不是积木，应用看不懂它，也不检查它。它会原样写进生成的工程；工程一运行，它就跟着运行，和工程里别的代码在同一个进程里、权限一样：
> 能读写这个工程碰得到的所有文件、能联网、能读环境变量（里面可能有密钥）、能起别的程序。应用没有把它单独关起来，“超时取消”也管不到它里面。只放你自己逐行看过、信得过的代码。

补充（实现上的事实）：

- 在手机上运行工程是在应用自带的 Ubuntu 环境里（PRoot），那是整个工程的运行环境，不是给手写代码单开的；手写代码和工程里别的代码看到的东西一样。
- 把工程推到 GitHub、SSH 主机去构建和运行时，手写代码跟着去，在那边有那边给工程的全部权限。
- 读库时对手写文件做的“样子检查”只是防写错文件，拦不住恶意代码。
- Go、Java 的手写文件和生成的代码一起编译：写错了整个工程编不过（报错在编译器的输出里）；Node、Python、PHP 是调用到的时候才加载。

## 21. 和 C 分册、和第三轮不一样的地方（第四轮·A1）

| 原来 | 现在 | 为什么 |
|---|---|---|
| 第三轮：新建库两步，没有“给谁用” | 三步：名字、标识、给谁用 | 前端的库要来了；清单里先分清 |
| 第三轮：自带“接口服务”不能复制来改 | 能：得到文字写法的库，“改库的文字”里改，文档里“用它顶替” | 见第 19 节；画布原样做不成的原因也在那里 |
| C 分册 8.6：手写代码默认关、看了代码同意才启用 | 做成了两道：全应用开关＋每库每份代码确认（按内容校验值记） | 一道开关不够——开过一次以后，后来导入的库不该自动放行 |
| C 分册 8.6 设想的“原生片段”（积木里直接嵌一小段目标语言） | 没做这种；只有“清单里声明的手写函数” | 片段没有类型声明、没法在检查阶段查；函数有 |
| 第三轮 `native.waits` 名单 | 每个函数自己的 `waits` | 和类型声明放在一起，一处说清 |
| 用户库不许直接声明宿主接口 | 清单 `hosts` 里一个不落写明就可以 | 复制自带库来改必须能用；导入的人在预览页看得到它碰了哪些宿主能力 |

## 22. 只给前端的库可以用前端的宿主接口（第四轮·A2）

> **2026-11-27 中途包：这一处默认关。** 和第 19 节同一个开关（`lib/lang/rules.dart` 的 `kUserLibHostEnabled` / `userLibHostEntry`），等霜霜点头再开。关着时只给前端的自己的库直接用前端的宿主接口同样是问题、用不了；自带的“页面”库照常。

清单里 `for` 写 `frontend` 的库，可以在清单 `hosts` 里写明并在模块里声明**前端的**宿主接口（表在 `lib/lang/host_front.dart`）：

- 乙类 20 个原生绑定：`timer.after / every / cancel / frame`、`net.request / abortNew / abort`、`storage.read / write / remove / keys`、
  `loc.now / push / replace / go / onPop / assign`、`page.alert / confirm`、`win.on`。
- 甲类 9 个页面宿主接口：`page.state.new / read / write / derived / watch`、`page.ui.read / write / on / life`。
- 后端前端都有的那几个（打印、现在的时刻、歇一会儿、随机字节）。

边界（读库时就查，不过的库用不了）：

- 只给前端的库**不许**用后端的宿主接口，**不许**带手写代码（浏览器目标不接手写代码）。
- `for` 写 `both`（都行）的库照旧：不许任何宿主接口、不许手写代码，只用语言核心。
- 只给后端的库用了前端才有的接口，报问题。
- `compat.*` 那 6 个“旧规矩”接口只许自带的“页面”库声明，用户的库不许。
- 后端文档里不许启用只给前端的库；页面逻辑里不许启用只给后端的库、不许启用“顶替后端自带库”的库、不许启用带手写代码的库。

宿主接口的签名以表里的为准：声明写得和表里不一样，类型检查报错。

## 23. 自带的前端库和“靠着它们的库”（第四轮·A4）

应用自带的前端库一共 6 个，都是“给谁用＝前端”、作者段 `lopi/`、不带手写代码、内容是语言核心写的模块＋宿主接口声明：

| 标识 | 名字 | 怎么用上 | 直接碰的宿主接口 |
| --- | --- | --- | --- |
| `lopi/page` | 页面 | 前端的文档自动用上（不用点） | 见第 22 节 |
| `lopi/timer` | 定时 | 积木库… › 定时 › 在这份文档里用它 | `timer.after / every / cancel / frame`、`time.now` |
| `lopi/http` | 请求 | 同上 | `net.request`、`time.now`、`time.sleep`、`page.state.new / write` |
| `lopi/storage` | 本地保存 | 同上 | `storage.read / write / remove / keys`、`page.state.new / read / write / watch` |
| `lopi/store` | 状态仓库 | 同上 | `page.state.new / read / write / watch`、`storage.read / write` |
| `lopi/bus` | 事件总线 | 同上 | 一个都不碰（纯语言核心） |

规矩：

- 后五个叫“要用才用的自带库”（`lib/lowcode/lib_front_builtin.dart` 的 `kLcFrontBuiltins`）。前端的文档（页面逻辑、给前端用的库）的 `loaded` 里永远有它们，
  不用项目里有、不占“一个项目最多 64 个库”的数；要在文档的 `uses` 里写上才算用上（页面文件里存在 `logic.uses`）。不是前端的文档 `uses` 里不许有它们。
- 五个之间互不依赖：各自直接声明自己要的宿主接口。所以用上一个不会连带要求用上另一个。
- 都能“在画布上看（只读）”：模块文字照 A3b 的路翻成积木。模块里的变量（`(变量 名 类型 初始值)`）这一段起也翻得过来——进文档的 `core.globals`，
  汉字起的名字换成 `g1、g2…`（和局部名字换成 `v1、v2…` 同一个道理）；初始值没有对应积木的那个变量不带过来，并在明细里说。

**自己写的库靠着自带前端库**：

- 库的画布原件 `uses` 里写上（界面上＝在库的画布里“积木库…”把它打开），就能用它的积木。出库文件时写进清单 `requires`（“页面”库不写，它是自动带的）。
- 导入预览里一句“要靠应用自带的“X”库（用这个库的时候，在“积木库…”里把它也打开）”，不算“项目里还没有”；预览时的类型检查把它们（和“页面”库）放进依赖一起查。
- 用这个库的页面逻辑必须把它靠的自带库也用上，没用上＝问题：“库「甲」要靠库「状态仓库」，请把「状态仓库」也用上”，检查拦、导出不出这一页的逻辑。
  （不替用户自动打开：打开一个库会让积木盒多一页，这件事要她自己知道。）
- 自己的库**直接**碰宿主接口照旧由 `userLibHostEntry` 管着（默认关＝读库时就是问题）。靠着自带库去碰不算直接碰：碰的那一下发生在自带库的模块里，
  自带库公开什么、怎么碰是应用定的。

**语言核心新补的九样积木**（严格规矩才有；`lib/backend/backend_blocks_strict.dart`）：个数 `sizeOf`、拼起来 `joinText`、整除 `intDiv`、看类型 `isTypeNamed`、
变成整数 `toInt`、像不像数 `isNumeric`、网址解码 `urlDecode`、拆成码点 `codePoints`；匿名函数的参数能标类型（表达式对象里的 `ptypes`，和 `params` 等长，没标的是空字，全没标就不存这一项）。
