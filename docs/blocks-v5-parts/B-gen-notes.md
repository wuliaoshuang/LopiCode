## 2. 值在各语言里长什么样

| 积木里的类型 | Node | Python | PHP | Go | Java |
|---|---|---|---|---|---|
| 整数 | number，每次运算后查是不是安全整数（小库 `chk`） | int | int | `int64` | `long`（泛型位、可空用 `Long`） |
| 小数 | number | float | float | `float64` | `double` / `Double` |
| 文字 | string（按码点处理） | str | string（自己按 UTF-8 拆码点，不靠 mbstring） | `string` | `String`（按码点） |
| 列表〈T〉 | Array | list | 包成对象 | `*lc.List[T]` | `ArrayList<T>` |
| 字典〈V〉 | Map | dict | 包成对象 | `lc.Dict[V]` | 按码点排序的 `TreeMap<String,V>` |
| 可空 T | null | None | null | 基本类型 / 记录 / 枚举 / 类型变量用 `*T`，本来就是引用的不变 | 盒装类型，null |
| 记录 | 生成的 class（继承 `Rec`） | 类实例 | 类实例 | struct（按值） | `record … implements Lc.Rec` |
| 枚举 | 生成的 class（继承 `Enum`，冻结） | 类实例 | 类实例 | 有名的 `int64` | `enum … implements Lc.Named` |
| 变体 | 每种情况一个 class（继承 `Variant`） | 类实例 | 类实例 | 接口＋每种情况一个 struct | 接口＋每种情况一个 record |
| 类 | class | class | class | 不可继承＝`*T_x`；可继承＝接口 `T_x`＋“体”`B_x`＋`self`（B 分册 7.3） | `static class`，创建走静态 `lcNew_<类>`，不用 Java 构造函数 |
| 函数值 | 函数 | 函数 | 闭包 | `func(...)` | `Lc.Fn0…Fn4` / `Lc.Act0…Act4`（最多 4 个参数） |
| 任意 | 原样 | 数字一律 float | 数字一律 float | `any` | `Object`（数字一律 `Double`） |

名字：Go、Java 里类型名一律写成 ASCII（Java 是 `T_<十六进制码点>`），免得编译器对中文标识符有不同意见。
Java 里被匿名函数捕获又会被改的局部变量装进 `Lc.Ref`。

## 3. 严格语义（五种语言同一句报错）

类型不对、除以 0、整数超范围、位置越界、空值直接用、小数变不成整数：都报错，句子五种语言逐字相同
（比如 `除以 0`、`整数超出范围`、`位置 5 超出了列表的范围（共 3 项）`、`这里的值是空，不能直接用`）。
没被“试着做”接住的错，最后打印 `出错：<那句话>`。整除向 0 取整；“等于”不偷偷转换；文字比大小按码点。
`log` 先攒着，`run(main)` 最后一次写出。

9 种运行时检查点：检查器在 `checks` / `coercionOf` 里标出来的位置，生成器在那儿调小库的 `asInt` / `asText` / `must` / `at` 等；
检查器已经证明用不着的地方不加。

## 4. 借了核心 2 的哪些最小部分（为了 p08、p11、p14 能跑）

- p08（类）：字段和默认值、“创建时”、方法、单继承、调父类的创建和方法、“是不是”。接口只做了声明和“实现了”的标记。
- p11（错误）：第一轮只按“一句文字消息”抛和接。**核心 2 第 1 段（2026-11-26）已换成错误对象**，见第 9 节；p11 原型的写法没改，读入时把“读 e”翻成“e 的消息”，输出不变。
- p14（泛型类）：带类型变量的类和它的方法。
- 还没有（遇到会明说“还没有”，不会生成错代码）：Go、Java 里“继承一个带类型变量的类”；Go 里“方法自己再带类型变量”（Go 语言本身不允许）。

## 5. 和后端（服务器积木）的关系——现在接到哪

- 校验：`validateBackend` 对规矩版本 2 的文档多跑一遍类型检查（`lib/backend/backend_validate_types.dart`），问题对回积木。版本 1 的文档不进。
- 生成：**后端文档的生成还走版本 1 的生成器**。版本 2 的生成器遇到宿主语句（返回响应、数据集合…）、宿主名字（“这次请求”）、
  原生小段会抛“还不能”。要接上，得先定宿主绑定的签名（设计 GAP-B-6），并让服务器小库的值和严格小库的值对得上
  （PHP 的列表 / 字典一边是数组一边是对象；Go 一边是 `any` 一边是原生类型；Java 一边 `Double` 一边 `long`）。这属于“库 1”的事。
- 所以开关 `kLangRulesForNewDocs` 这一段**没有翻成 2**：翻了的话新文档会“按严格规矩查、按老规矩跑”，两头对不上。

### 5.1 翻开关前还差什么（2026-11-26 实测）

把现有四份样本文档改成版本 2 过一遍校验（`test/backend_validate_types_test.dart` 钉着）：

- 新建文档的默认内容（入门样本）、一致性样本、“我的积木”样本：一条不多。
- 第 4 版新积木样本：多出 10 条错（T01 八条、T06 一条、T07 一条）。大多是样本故意混着放类型（整数列表里加文字 / 小数、
  字典的键用整数、给文字取负、把文字放进要列表或字典的格子），严格规矩下本来就该报。有一条是老积木和版本 2 的签名对不上：
  “数列 从 到 步长”老积木传 3 个参数，版本 2 的签名只有 2 个 → 这块积木在版本 2 下一拖出来就报错（T07）。
- 老积木会翻出来、但版本 2 签名表（`kLangRtV2`）里还没有的小库函数：abs、max、min、random、copy、template、toNumber、toText、
  toBool、isType、listInsert、listRemove、listSort、listEach、dictMerge、dictPairs、dictRemove。检查器对它们按“参数任意、结果任意”，
  不会误报；版本 2 的生成器遇到会明说“还没有”。其中 abs / max / min 和带步长的数列要“整数进整数出、小数进小数出”，
  现在的签名表一个名字只能写一种参数，表达不了——得先定是拆成两个名字还是给签名表加“数字”这种约束（设计上没写）。

### 5.2 和界面段（分支 v5-typeui）的临时桥怎么对

- 界面段的 `backend_type_bridge.dart`：`beTypeCheck(doc)` → `BeTypeCheck`（整份结果＋每条问题落到哪一格 `BeSlotRef`，带式子里的位置和一键修），
  靠它那边在翻译器里加的 `origins` 表和“没用到第 4 版积木的接口也翻”（`all`）。
- 这一段的 `backend_validate_types.dart`：`beTypeFindings(doc, route)` / `beFuncTypeFindings(doc, table, f)` → `BeLangFinding`
  （规则号、是不是错、提示语、哪一块、哪个参数、怎么改），只靠原有的来源表；只查用到第 4 版积木的接口和“我的积木”。
- 差别：这边粒度到“哪块积木的哪个参数”，不到式子里的位置；只用旧积木的接口这边不查；文档变量和“这次请求”两边都当“任意”；
  同一格上已有类型问题时两边都不再显示 G10。
- 合并建议：以界面段的 `beTypeCheck` 为准（它更细），把这边 `beTypeFindings` 的函数体换成“调 `beTypeCheck`、把 `BeTypeFinding` 转成
  `BeLangFinding`”，`validateBackend` 里的两处调用不用动；`test/backend_validate_types_test.dart` 里的条数要按合并后的结果重对一遍。

## 7. 合并对接以后（2026-11-26，分支 v5-r1）

这一节以后以这里为准，上面 5、5.1、5.2 里“两边各查各的”“条数 10 条”的说法作废。

### 7.1 类型检查只跑一处

- 只有 `lib/backend/backend_type_bridge.dart` 的 `beTypeCheck(doc)` 跑后端文档的类型检查；`beTypeCheckShared(doc)` 是带“内容没变就不重查”的同一个东西
  （只记最近一份，按“同一个文档对象＋存盘文字一样”认）。
- `lib/backend/backend_validate_types.dart` 的 `beTypeFindings` / `beFuncTypeFindings` 现在只是把那份结果按接口 / 按“我的积木”分开、
  换成 `BeLangFinding`。`validateBackend` 里那两处调用没动。`BeLangFinding` 多了一个可选的 `exprPath`（参数里的哪个位置）。
- 进校验结果的：检查结果里“错 / 警告”两级；“提醒”（T12）不进，只在编辑器里显示。T08（名字找不到）整个不报——老规则已经报了。
- 所以和合并前相比：只用旧积木的接口现在也查；老的“运算 / 比较”“不是”查类型时翻成语言核心的式子（`typed`）；
  同一块同一个参数里的几处问题各算各的（以前同一个参数里只留一条）；同一个位置上有类型问题时，老的 G10 让位（位置不同的 G10 留着）。

### 7.2 界面上不出现两次

`backend_type_host.dart` 的 `withTypeIssues`：先把校验结果里的 T 规则全部拿掉，再把检查结果（带“式子里的位置”和一键修）整批放进去。
两边是同一份检查结果，所以不会多、不会少、不会有两种说法。钉子：`test/backend_validate_types_test.dart` 最后两条。

### 7.4 合并时修的一处检查器误报

`LTypeWorld.unify`：函数类型的参数位置是“反着”的。以前“映射(整数的列表, 一个肯收任意的函数)”会把 T 撑宽成“任意”，
然后报“第 1 个参数要列表〈任意〉，放进来的是列表〈整数〉”。现在类型变量已经从别的参数定下来时，函数的参数位置不再去撑宽它
（函数肯收更宽的东西本来就合法，后面的 `ok` 按反着的方向查）；还没定下来的照旧从这里定。返回位置不变。

### 7.5 安全闸：严格规矩的后端文档现在不生成

事实（2026-11-26，Node 真跑）：一份 `rules: 2` 的后端文档走版本 1 的生成器——
- 三块严格积木放在旧积木的格子里（比如“返回 200 和数据 {a: 把 "12" 变成整数}”）：整个值生成成 `null`，接口照样回 200，校验一条不报；
- 放在新积木的语句里（“新建变量 n = 把 "12" 变成整数”）：那个接口整段不生成，留一行注释，访问回 500“这个接口里有还不支持的积木”；
- `1 ÷ 0` 还是得 0（校验的提示也还是老话“运行时结果会是 0”）。

所以加了两个常量（`lib/lang/rules.dart`）：
- `kLangStrictBackendGen = false`：为 false 时严格规矩的后端文档**不生成**（`regenerateBackend` 返回 `strictPending`，一个文件都不写，
  说明是 `kBeStrictGenPending`）、**不让启动**、“看代码”里是那句说明而不是老办法翻出来的代码。有错误时还是先说有几个错误。
- `kStrictRulesUpgradeEnabled = false`：为 false 时“⋯”菜单里没有“升级到严格规矩…”。界面读的是 `backend_screen.dart` 的
  `beStrictUpgradeEntry`（测试里打开来测升级那条路）。

“库 1”把后端接上版本 2 生成的时候：两个都改成 true，`kLangRulesForNewDocs` 那时再看要不要翻。


## 9. 错误是对象（核心 2 第 1 段，2026-11-26，分支 v5r2-core）

文件：`errors.dart`（内置错误类的那段语法树、种类归类表）、`typecheck_err.dart`（检查）、`gen2_err.dart`（五种语言共用的骨架）、各语言生成器里的 `tryFrame / throwObjLines / errObjCode / rethrowLines / errKindCode / errSupport` 六个小钩子、各小库里的 `LcError`（加了 `obj`）和 `errKind`。

- **内置错误类不是手写在小库里的**：“错误”（字段“消息”，可继承）和六个内置种类（找不到、类型不对、数值不对、超时、取消了、读写失败）是一段语法树（`langErrorPrelude()`），检查器把它们并进声明表，生成器在程序**用到错误时**（有“抛出 / 试着做”、有继承“错误”的类、有类型里提到它们）把它们排在用户声明前面一起生成。所以五种语言里它们和用户的类是同一种东西——**第 2 段改类的生成（Go 内嵌＋接口＋指回自己）时它们自动跟着走，不用另写**。没用到错误的程序生成结果和以前逐字一样。
- **抛**：`抛出 (一句话)` ＝ 先新建一个“错误”再抛；`抛出 (错误对象)` 直接抛。外面都包一层小库的 `LcError(那句话, 对象)`（各语言的异常必须是特定的类）。那句话是**抛的那一刻**对象的“消息”；没接住时打印的就是它。
- **接**：接住 `LcError` → 拆出对象（`errObj`）→ 从上往下一节节用“是不是这个类”判断 → 第一节对上的把对象放进变量、跑那一节 → 都没对上原样再抛（Node `throw E`、Python `raise`、PHP `throw $E`、Java `throw E`、Go `panic(E)`）。接“错误”或者没写种类＝兜底，生成成最后的 `else`。只有一节兜底且没起名字时不拆对象。
- **小库自己报的错**（除以 0、越界…）抛的时候没有对象，只有一句话；**接住的时候**才按 `errKind(那句话)` 归到一个内置种类、造出对象并记在 `LcError.obj` 上（所以原样再抛、外层再接，拿到的是同一个对象）。归类表在 `errors.dart` 的 `kErrKindOfMessage`，五个小库各抄了一份一样的：含“除以 0”“整数超出范围”“变不成整数”→数值不对；含“超出了”→找不到；含“拿到的是”“值是空”→类型不对；其余→错误。“怎么按种类名造对象”由生成的程序在开头登记（Node / Python / PHP：`errSetup(函数)`；Go / Java：程序里生成一个 `lcErrObj` 函数）。
- **`e 的种类`**：检查器把它当成错误对象上一个只读的文字字段，生成成取类名（Node / Python / PHP `kindOf`，Go `LcName()`，Java `lcName()`）。
- **错误变量的类型**：变量自己的类型是各节种类合起来的最近公共父类；在某一节里读它按这一节的种类看（检查器给那个 `LName` 记 `opOf == 'narrow'`，Go / Java 生成一次向下转，另外三种不用转）。节里给它重新放了东西就不再这样看。
- **Go**：`lc.Error` 加了 `Obj any`；新的 `lc.TryE` 交回整个 `Error`（老的 `lc.Try` 留给小库内部用）；“最后”还是 `defer`。**Java**：`_completes` 按各节算“后面到不到得了”。
- **没接住**：照旧先把攒的输出写出去、最后一行 `出错：<那句话>`，然后**退出码 1**（以前是 0）。五种语言一致。测试支持 `Gen2Run.exitCode`。
- **没做、有意不做**：错误的“原因”（错误链）、单独的“原样再抛出”积木（`抛出 e` 就是）——F1 的结论是“加了没用上，先不进核心”。接口不能当“出错时”的种类。

## 10. 模块（核心 2 第 1 段）

文件：`link.dart`（`linkProgram`：检查＋合并）、`rename.dart`（给顶层名字改名的整树重建器）、`gen2_all.dart` 的 `gen2ProgramFiles`、`typecheck.dart` 的 `checkProgramTypes`。规则 M01–M08 在 `type_issue.dart` 的 `kModuleRules`。

- `LProgram(modules, entry)`。每个 `LModule` 有 `name`、`uses`（用到了谁）、`decls`（顶层声明，带“公开”）、`body`（只有入口能有）。
- 检查：名字不重样（M01）；入口、`uses` 里的名字都得有（M02）；不许绕圈，报错把圈画出来并给固定解法，入口也不能被别人用（M03）；非入口不能有“程序开始时”（M04）；用了没列进 `uses` 的（M05）、没公开的（M06）、两个被用模块公开了同名的（M07，自己有同名的用自己的）；顶上变量的初值直接用到同模块里排在后面的变量（M08）。
- 启动顺序：被用到的先（深度优先、同层按程序里的先后），模块里按声明先后，入口最后跑“程序开始时”。
- **合并成一个模块再走老路**：声明按启动顺序排；全程序里只出现一次的顶层名字不动，撞名的改叫“模块名·名字”（改名器分得清被局部变量、参数、类型参数挡住的名字）。合并后的模块交给 `checkModuleTypes` 和原来的五个生成器——所以模块级变量的初始化就是原来“全局变量在 main 开头按声明顺序赋值”那一套，顺序由合并顺序保证。
- **一个模块一个文件**（2026-11-27，库 1 下半；`gen2_split.dart`、各生成器的 `programFiles()`）。检查那一半一点没动：还是 `linkProgram` 先查、先合成一个模块、过类型检查（检查和生成看的是同一份）；只在最后写文件时，照“合并以后每个顶层名字原来是哪个模块的”把顶层声明分到各自的文件里。只有一个模块有东西的程序还是一个文件，和以前一个字不差。
  - 文件：主文件（入口模块的声明＋“程序开始时”）；内置错误种类单独一份（`lc_kinds.*`，Java 是 `LcKinds.java`；用到了错误才有）；别的模块按启动顺序各一份。
  - 文件名：`m_模块名.后缀`，Go 是 `m_模块名_lc.go`（Go 把 `_test.go`、`_linux.go` 这类结尾当成特殊文件，模块名正好这样结尾会被悄悄跳过，所以最后垫一个 `_lc`），Java 是 `M_模块名.java`（类名只用英文字母、数字、下划线，汉字写成码点）。模块名里英文字母、数字、下划线、常用汉字原样，别的字符写成 `_u码点_`；两个模块收拾完只差大小写的，后一个加序号（有的系统文件名不分大小写）。
  - **启动顺序没有另生成入口**：模块级变量的赋值还是全放在主程序开头、按启动顺序排（和合成一个文件时一样），各模块文件里只有声明，引进来的时候不跑用户的代码。所以当初担心的“分文件以后要另生成一个按顺序准备各模块的入口”不需要。
  - 各语言怎么让别的文件看得见：

    | 语言 | 模块文件 | 类型、函数 | 别的模块的变量 |
    |---|---|---|---|
    | Node | CommonJS，最后 `module.exports = {…}` | `const { 名字… } = require("./m_x.js")` | 交出去的是一对 `get / set`，用的地方写 `lcM_x.g_变量`——读到、改到的都是那个文件里的变量 |
    | Python | 一个 `.py` | `from m_x import 名字…` | 写 `lcM_x.g_变量`（`import m_x as lcM_x`；`from … import` 拿到的只是当时的值，不能用）；函数里的 `global` 只声明自己文件的 |
    | PHP | 一个 `.php`，只由主文件 `require_once` | 函数、类哪个文件都看得见 | 最外层的变量本来就是全局的，照旧 `global` |
    | Go | 同在 `main` 包的一个 `.go` | 同包直接看得见 | 同包直接看得见 |
    | Java | 一个类文件，里面都是 static | 类一个接一个继承下来（`M_乙 extends M_甲`、`Main extends 最后一个`），子类直接看得见父类的 static 成员和里面的类 | 同左 |

  - Java 用“继承一串”是因为没有包名的类不能 `import static`，而给生成的代码加包名要改目录结构和启动命令；这样写代码里的名字一个都不用改。（Java 的这条规矩没去翻官方原文，**未核对**；javac `-Xlint:all -Werror` 真编译过。）
  - 一个文件要引进来的是启动顺序里排在它前面的**全部**模块，不只是它“用到了谁”里写的那几个：它的代码里会出现隔了一层的模块的类型（比如“看是哪种情况”展开出来的各种情况）。能不能用早在合并前查完了，这里多引不放宽任何规矩。
  - Go 的模块文件没用到小库就不写 `import "lcprog/lc"`（Go 不许引了不用）。
  - 没公开的名字也会被交出去 / 引进来（Node、Python）：公开不公开是检查阶段拦的，生成的代码不再拦一遍。
  - 验收：`test/lang_gen2_split_test.dart`（文件名单、难缠的模块名、别的模块的变量读到现在的值，五种语言真跑）；m01–m05、c13、小框架 39 条、严格版 135 条都是走分文件这条路过的。
- 已知边角：撞名改了名的类，运行时看到的名字（`种类`、把对象变成文字）是“模块名·类名”；M08 只查初值式子里直接写的名字，经过函数间接读到的查不出（那时读到的是这种类型的零值 / 空）；变体的“情况”名、字段名、方法名不是顶层名字，不参与改名。

## 11. 类与接口（核心 2 第 2 段，2026-11-26，分支 v5r2-core）

### 11.2 这一段定下来的做法（和 A2 分册不一样的地方单列在 11.5）

- **类本身的成员降成模块级的声明。** 类本身的字段＝一个模块级变量，类本身的方法＝一个模块级函数，名字是“类名.成员名”（`lStaticName`）。检查器在收集声明时就这样登记（`collect()`），生成器的 `decls` 把它们排在自己的类后面，所以五种语言不用各写一套“静态”。类本身的字段的初值和别的模块级变量一起、按声明的先后在程序开始时放（`Gen2Base.startup`）。
- **怎么认“这里说的是类本身”**：没有加新的语法树节点。`LSend(LName(类名), 方法, …)`、`LField(LName(类名), 字段)`、`LTField(LName(类名), 字段)` 里，那个名字没有被变量、函数挡住而且是一个类的名字，就是在说类本身（`classRef`）。检查器在节点上记一个 `static:类名.成员名`，生成器照这个记号走。子类名上能用父类的类成员（`特别编号器 的 下一个` 找到的是 `编号器.下一个`，同一个变量）。
- **内部的字段**＝本类和子类里面能用（设计 C12 的“内部”一档）。类本身的字段也能标内部。只在检查阶段拦（T22），生成的代码里名字不变。
- **默认值**只能是直接写的值（数、文字、是否、空）。在**调用的地方**补，五种语言生成的函数都是“参数给全了”的样子。所以：重写、实现接口时，默认值必须和上面的一模一样（T18、T11）——按接口 / 父类的类型调和按子类的类型调，补出来的才是同一个值。
- **重写 / 实现的方法，参数和返回的类型要和上面的一模一样**（原来 T11 只查个数和返回放不放得进，T18 查“放不放得进”）。原因：Go、Java 里它们是同一个方法，类型差一点就不是重写了。没标类型的参数 / 返回跟着上面的走（`_follow`）。
- **接口不能当“出错时”要接的种类**（保持 A1 的 T19）。理由：接住的东西一定要有“消息”“种类”，这是“错误”这个类给的，接口保证不了；而且 Go、Java 里“按种类接”落成的是“往下转成那个类”，接口上没有对应的错误类可转。要按“实现了某个接口”分，就先接“错误”，再问“是不是那个接口”（验收里有这个例子）。
- **“调父类的创建时”**只能是子类“创建时”的第一句、只能一次；父类的“创建时”要参数时子类必须调（T27，设计 C17）。字段初值的先后没变：父类创建时 → 本类字段初值 → 本类创建时剩下的。

### 11.3 宿主接口和小库

- `host_v2.dart` 的 `kHostV2`：`sys.print(文字, 通道)`、`time.now()`、`store.read(名字)`、`store.update(名字, 函数)`。名字和参数照 C 分册 9.1（**不是**原型里的 `log.error`、`time.ms`、`store.get`）。程序里要先写一句声明（`LNativeDecl`），类型要和表一模一样，对不上在生成时说。
- `sys.print` 的 `out` 通道和“打印”进同一个攒着的输出（程序结束时一次写出，先后不乱）；`err` 通道马上写到标准错误。C 分册说的“写完立刻刷出去”现在只有 `err` 做到——版本 2 的独立程序整个是“攒着最后写”，要等有了一直跑着的服务（核心 3 的 `http.serve`）再一起改。
- 格子：五种语言都是进程里的一张表；存、读都复制（列表、字典一层层复制，别的值原样）；改的函数里再改同一个名字＝出错。**PHP 现在也是进程里的表**，不是 C 分册说的带锁文件：带锁文件是为了“一个请求一个进程”时留得住，这要到有 `http.serve` 才有意义，到时一起做。Go、Java 的表有一把锁，但“正在改”是按名字记的、不分是谁在改——核心 3 有了同时跑的事以后要换成按名字排队。
- 没做的三个要等的（`time.sleep`、`net.fetch`、`http.serve`）和 `sys.env`、`random.bytes`：前三个要“要等的事”（核心 3）；后两个小框架没用到。
- 小库：`isNumeric(任意) → 是否`（整数、小数是；文字去掉两头的空格 / 制表 / 换行以后整段是 `[+-]?(数字+(.数字*)?|.数字+)([eE][+-]?数字+)?` 而且不是无穷大才是；数字只认 0–9）；`urlDecode(文字) → 文字`（`%XX` 按 UTF-8 换回来，“+”不动；`%` 后面不是两个十六进制数字、或者换回来不是合法的 UTF-8＝出错“这段网址编码解不开”）。原型里的 `url.decode` 是宿主接口，这里按 C 分册的判定（纯计算不进宿主）做成小库。`isNull`、`join`、`orElse` 原来就有，够用。

### 11.4 这一段顺手修的（生成器原来就有的问题）

1. **默认值在 Go / Java 里运行时出错**（“这里要整数，拿到的是数字”）：默认值那个节点没经过类型检查，生成器把它当“任意”再转。改成按它字面上是什么来写（`_defaultCode`）。
2. **Go：能被继承的类实现了接口，拿着这个类的值不能当接口用**（编译不过，“missing method lcIs_…”）：类的 Go 接口里没有嵌它实现的接口。已嵌。
3. **Go / Java：函数当另一种样子的函数用编译不过**（比如返回“列表”的匿名函数交给要“返回任意”的参数）：Go 的函数类型、Java 的泛型都不会自己转。`convert` 里加了“包一层”。

### 11.5 和设计分册不一样的地方

- A2 分册 C09 说 Go 把静态成员降成包级变量 / 函数、别的语言用各自的静态：**现在五种语言都降成模块级**（一套办法，少五份代码；外面看不出差别）。
- A2 分册 C12 说内部的成员在 Java / PHP 生成 `protected`、JS / Python 生成 `_名字`、Go 小写：**现在名字不变，只在检查阶段拦**。原因：生成的代码不给人手改，改名只会让五种语言的输出更不一样；合成一个编译单位以后 Go 的大小写也拦不住什么。
- A2 分册 C13（方法也能勾“内部”，`LMethodDecl` 加 `isPrivate`）**这一段没加**：任务清单里只有内部的字段，小框架的 39 个样例也没用到内部的方法。要加的话照 T22 的办法：`privateCheck` 已经是通用的。
- 原型（02-web-framework）里宿主接口的名字和 C 分册 9.1 不一样，以 C 分册为准；A4 把原型搬过来时要改名（对照表在 B-impl-notes“核心 2 第 2 段”一节）。

## 12. “要等”的四样的最小版＋“小框架”39 条验收（核心 2 第 4 段，2026-11-26，分支 v5r2-core）

验收：`test/lang_gen2_framework_test.dart`——“小框架”七个模块＋“小书店”（`test/fixtures/framework/bookshop.lc`，换算表见同目录 README.md）由生成器产出，五种语言真编译、真起服务，原型的 39 条请求和 39 行日志逐字节一样。故意写错的在 `test/lang_gen2_framework_bad_test.dart`。

这一节写的都是**这一段定下来的做法**；设计分册（A2 10.f、C 9.1）写了的照它，没写的在 12.5 单列。

### 12.1 这一轮的范围：明着标，不推断

- 函数、方法、匿名函数上有一个“要等”的记号（`LFuncDecl.waits`、`LSignature.waits`、`LLambda.waits`）；函数类型里“要不要等”的槽位（第一轮留的）现在填上了。**谁要等由写的人明着标**，不自动推。
- 语法树：`LAwait(式子)`＝等一件开始做了的事做完、拿它的结果；`LSpawn`＝开始做一件事。`LSpawn` 这一轮**只认一种样子**：里面就一句“返回 f()”，f 是一个不收参数的函数值（读入器把原型的 `(spawn 语句…)` 包成一个“要等”的匿名函数）。类型是“稍后的结果〈T〉”。
- 宿主接口里要等的两个：`time.sleep`、`http.serve`（`kHostV2Waits`）。
- **生成器的一道保护**（五种语言一样）：要等的事（调要等的函数 / 方法 / 函数值、要等的宿主接口、“等”）出现在没标“要等”的函数里 → 不生成，说“这里有“要等”的事，所在的函数要先标成“要等””。不拦的话 Node 里会悄悄拿到一个 Promise 当结果用，别的四种语言却是对的——五种语言不一样比不生成更糟。这**不是**核心 3 的“自动推断和放错地方的拦截”：检查器这一轮完全不管“要不要等”（接口的实现、重写的方法标得一不一样也不查），提示语也只有这一句。
- 普通函数可以放在要“要等的函数”的地方（“小书店”里不用等的路由就是这样）；反过来检查器这一轮也不拦（核心 3 的事）。

### 12.2 四样在五种语言里怎么落

| | Node | Python | PHP | Go | Java |
|---|---|---|---|---|---|
| 标了“要等”的函数 | `async` 函数；调它的地方 `(await …)` | 普通函数（靠线程，不用 asyncio） | 普通函数 | 普通函数 | 普通方法 / lambda |
| 开始做 | `lc.spawn(f)`：调 f 拿到 Promise（先挂一个空的 catch，免得“没人接”的警告） | `spawn(f)`：开一条守护线程跑 f，结果 / 错误记在任务对象里 | `LcHost::spawn(f)`：**当场做完**，结果 / 错误记着 | `lc.Spawn(f)`：开一个 goroutine，结果经通道交回；错误（panic）接住记着 | `LcHost.spawn(f)`：开一条虚拟线程 |
| 等 | `(await 任务)` | `wait(任务)`：等线程结束，有错重新抛 | `LcHost::wait(任务)`：直接取，有错重新抛 | `lc.Wait(任务)` | `LcHost.await(任务)` |
| `time.sleep` | 等一个定时器（Promise） | `time.sleep`（停当前线程） | `usleep`（停这个请求） | `time.Sleep` | `Thread.sleep` |
| `http.serve` | `node:http` | `http.server.ThreadingHTTPServer`（一个请求一条线程） | `php -S 主机:端口 main.php`（PHP 自带的服务），程序每个请求从头跑一遍，`hostServe` 只处理眼前这一个请求 | `net/http` | `com.sun.net.httpserver.HttpServer`＋虚拟线程 |

A2 10.f 写的是“Python 线程池＋Future”，这里是“一件事一条守护线程”（没有池子的大小要定，结果一样）；其余和 10.f 一样。Java 的虚拟线程要 JDK 21。

### 12.3 `http.serve` 的细则（五种语言一样，除了标明的）

- 签名按 C 9.1：`http.serve(端口, 主机, 处理函数)`，处理函数是 `要等的函数(字典〈任意〉) → 字典〈任意〉`。端口 0–65535（0＝让系统挑）；占用了出错。
- 请求字典 `{method, path, query, headers, body}`：path 是原样没解码的；query 是问号后面的原样文字（没有就是空文字）；头的名字小写、重名的用“, ”连；内容不是合法的 UTF-8 当空。
- 留在宿主里的：内容超过 1MB 回 413 `{"error":"请求内容太大"}`，不进处理函数；处理函数抛错、交回的不是字典、status 不是 100–599 的整数 → 500 `{"error":"服务器内部出错"}`，原因写到标准错误。
- 响应：头按名字排序写出去；程序给的 Content-Length 不要，宿主按内容的字节数补；204、304、1xx 和 HEAD 不写内容；不用分块传输。
- 开始监听以后宿主打印一行 `后端已启动：http://主机:端口`（**PHP 没有这一行**：服务是 `php -S` 起的，不经过程序）。
- 搬到库里的（照 9.1）：端口先看 `PORT`、主机看 `HOST`——在“小框架”的“路由”模块里，用新加的 `sys.env`。

### 12.4 改掉了 11.3 记的三处出入

1. `sys.print` 的 `out` 通道和“打印”：五种语言都改成**写一行马上刷出去**（多线程的三种带一把锁）。程序从头到尾什么都没写的话结束时补一个空行（原来的约定，老样例的期望输出不变）。
2. PHP 的格子：命令行直接跑还是进程里的表；在 `php -S` 的服务里是**带锁的文件**（系统临时目录下 `lcstore-<服务进程号>-<服务开始时刻>.dat`，`flock` 独占锁＋`serialize`），顺手清掉已经不在的服务留下的文件。
3. Python / Go / Java 的格子：一个名字一把锁，别的线同时改同一个名字**排队**；同一条线在“改法”里再改同一个名字还是报错（不然会自己等自己）。Node 是单线程，只有“重入报错”这一种情况。

### 12.5 分册没写、这一段定下来的（要霜霜知道）

1. PHP 开服务的办法是 `php -S`，所以：没有启动提示行；程序在命令行下直接跑到 `http.serve` 会出错并说该怎么启动；PHP 自带的服务一次只处理一个请求，“只停当前这一件事”在 PHP 上就是“停这个请求”（9.1 原话）。对外发的时候它只适合开发用，正式部署要另配（库 1 / 部署那边的事）。
2. PHP 的“开始做”是当场做完：`/parallel` 的结果一样（3），但两件事是一前一后做的，耗时是相加不是取大。
3. “小书店”的请求数从模块顶上的变量挪进了格子（PHP 每个请求从头跑，变量留不住）。这是对原型示例的一处改动，五种语言用同一份。
4. Go 的格子要知道“是不是同一条线在重入”：Go 没有公开的线编号，用 `runtime.Stack` 开头那行里的编号。这是取巧的办法（Go 官方不鼓励依赖它），只用在“重入报错”这一处；核心 3 做“一次只让一个做”时建议换成显式传下去的记号。
5. `LSpawn` 只认“返回 f()”一种样子（12.1）。
6. 生成器的那道保护（12.1）。
7. 启动提示行由宿主打（不是库）。
8. 没接住的错：主程序是“要等”的也一样——打印“出错：…”、退出码 1。

### 12.6 这一段顺手修的（生成器原来就有的问题）

- Go、Java：不交回东西的函数放到要“交回任意的函数”的地方（`/boom` 那样只抛错的处理函数），包的那一层原来把“没有值”当值用，编译不过。现在是“做完交回空”。
- Go：带“试着做”的函数，最后一句已经是“返回 / 抛出”时后面还多一句走不到的 `panic`，`go vet` 报“unreachable code”。现在不多写了；“小框架”整套 `go vet` 不报（`test/lang_gen2_gofmt_test.dart`）。

### 12.7 gofmt

- 小库 `lc/lc.go`、`lc/host.go`：已经改到 gofmt 干净，有测试看着。
- `main.go`：缩进从两个空格改成了制表符（原因就是生成器共用的缩进单位是两个空格，Go 没改）。剩下和 gofmt 不一样的是：结构体字段和连着的单行函数的**列对齐**、声明之间的空行、`if ((…))` 多出来的括号、写在一行里的 `func() { 甲; 乙 }()`。“小书店”的 main.go 上有 66 处。
- 没接着改的原因：列对齐要照 gofmt 的算法重算每一组的宽度，等于在生成器里重写半个 gofmt，而且要跟着 Go 版本变；不影响编译、运行和 `go vet`。**留给霜霜定**，建议：不追求生成器直接产出 gofmt 干净的代码；要好看的话在“有 Go 的地方”（构建机、手机 Ubuntu 里装了 Go 以后）生成完顺手跑一次 `gofmt -w`。

## 14. 宿主接口补到 14 个（核心 2 第 5 段）

这是 5 步里的第 1 步。清单（`lib/lang/host_v2.dart` 的 `kHostV2`）：原有 7 个（sys.print、sys.env、time.now、time.sleep、store.read、store.update、http.serve）＋这一段 7 个：random.bytes、net.fetch、file.read、file.write、file.exists、file.list、file.remove。C 分册 9.1 的 8 个＋9.2 的 5 个都齐了（time.sleep 是上一段为“要等”加的，不在 C 的清单里）。测试 `test/lang_gen2_host_io_test.dart`：五种语言真跑；net.fetch 只打测试自己在 127.0.0.1 随机端口上起的服务，另拿一个没人听的端口测“连不上”。

签名：`random.bytes(整数) → 列表〈整数〉`；`net.fetch(方式 文字, 网址 文字, 头 字典〈文字〉, 内容 可空文字, 超时毫秒 整数) → 字典〈任意〉`（要等）；`file.read(文字) → 文字`、`file.write(文字, 文字) → 空`、`file.exists(文字) → 是否`、`file.list(文字) → 列表〈文字〉`、`file.remove(文字) → 空`。

**net.fetch 细则（五种语言一样）**
- 请求：方式只认大写的 GET、HEAD、POST、PUT、PATCH、DELETE、OPTIONS；超时毫秒必须大于 0；请求头里的 host、content-length、connection、expect、upgrade 不发；没给 User-Agent 就发 `LopiCode`；GET、HEAD 不发内容；发内容又没给 Content-Type 就用 `text/plain; charset=utf-8`；跟着跳转走；网址先做百分号转义（办法同版本 1），# 后面的不发。
- 回应：`{status, headers, body}`。不管状态码是几都算“回来了”（404、500 不是出错）。status 是数字；headers 的名字小写、重名的用“, ”连；body 按 UTF-8 读，坏的地方换成 U+FFFD，**开头的 BOM 不去**（版本 1 的 fetch 去一个——留给库去做）；回应多大没设上限；主机名带 @ 的不拦（版本 1 拦——留给库）。
- 出错的话（都是“读写失败”那一类）：`请求不了：网址要以 http:// 或 https:// 开头`、`请求不了：不认识的方式「X」`、`请求不了：超时毫秒要大于 0`、`请求超时了`、`请求不了：连不上`。
- 各语言用的：Node 自带的 fetch＋AbortSignal.timeout；Python urllib.request（HTTPError 当回应读）；PHP http 流（fopen；本机 PHP 没有 curl 扩展，所以不靠它）；Go net/http；Java java.net.http.HttpClient。

**文件细则**：路径只能是工程文件夹（进程当前所在的文件夹）里的相对路径，绝对路径、盘符、带 `..` 的一律报“路径不对：只能用工程文件夹里面的相对路径”；写是先写临时文件（目标名＋`.lctmp`＋进程号）再改名；file.exists 对文件夹也回“是”；file.list 只列一层、按码点排序；消息：`读不了文件：没有「p」`、`读不了文件：「p」`、`读不了文件：「p」不是 UTF-8 文字`、`写不了文件：「p」`、`列不了文件夹：「p」`、`删不了文件：「p」`。

**random.bytes**：个数 1 到 1024，不在范围里报“随机字节的个数要在 1 到 1024 之间”；用的是各语言的安全随机源。

**没验证的**：请求头、回应头的值里带非 ASCII 字符时五种语言是不是一样（测试用的 Dart 小服务发不了这种头，没测成）；https（测试不联网）；回应特别大的时候。

## 16. 核心 3：“要等的事”（第三轮 A3，2026-11-27，分支 v5r3-lang）

霜霜定的是“‘要等的事’自动推、不让用户管”。这一段把第 12 节“明着标”的最小版换成了推出来的，并补齐了超时、取消、
“一次只让一个做”、“稍后的结果”的三种等法。验收：`test/lang_gen2_waits_test.dart`（12 个样例五种语言真跑）、
`test/lang_waits_infer_test.dart`（推断各形状＋故意写错的）、`test/backend_wait_blocks_test.dart`（积木文档）。

### 16.1 推断（`lib/lang/typecheck_wait.dart`，并在类型检查的同一轮里）

“要等的事”有五种：**等**（等一个稍后的结果）、调**要等的宿主接口**（等一会儿、开服务、请求别的网址）、调**要等的小库函数**
（等最多、等全部、等最先的一个、进“一次只让一个做”）、调**要等的函数 / 方法**、调**可能要等的函数值**。

- 一个函数（方法、匿名函数、帽子里的处理函数都一样）里面有要等的事，它就是要等的；调它的也跟着是。只增不减，转到不再变为止，
  所以递归、互相调用、跨模块都收敛（跨模块是先合成一个程序再推的）。
- 匿名函数、“开始做”里面的事算它们自己的，不算外面那个函数的；**调**那个匿名函数、**等**那个结果才算外面的。
- 方法：子类重写的要等，父类同名的那个也算要等（拿着父类类型调它的人要等得对）；实现接口的方法要等，接口的那个方法也算要等。
- 函数类型上有三种说法：**可能要等**、**规定不许等**、**没说**。作者写的 `(函数 …)` 是“没说”：放得进要等的函数，也放得进不等的。
  要等的函数值一旦放进过“没说”的位置（或者“任意”），全程序里调“没说”的函数值都按可能要等算（保守，只影响 Node 多写几个 `await`）。
- 把自己的参数原样交给“规定不许等”的位置（比如自己写了个“每个都做”，里面把参数交给小库的“映射”），这个参数也就只收不用等的函数。
  这条是从小框架的 `仓库.改库(名, 改法)` 来的：不推这一层，写得对的程序会被误拦。
- 手标的还认：`要等函数` `要等方法` `要等λ` 照样算要等（没有要等的事也算）。新加了反过来的 `不等函数` `不等方法`、接口方法第 4 项写 `不等`
  ＝规定不许等，里面有要等的事就报 T29。库的文字写法怎么用它们见 library-format.md 第 4 节。内置库“接口服务”里原来 5 处手标都去掉了，全靠推。

### 16.2 三条新规则（都是错误，检查阶段拦，五种语言都不生成）

| 规则 | 什么时候 | 一键修 |
|---|---|---|
| T29 | 不能等的地方有要等的事：类的“创建时”、字段初始值、规定不许等的函数 / 方法、实现或重写了规定不许等的方法 | 那一句单独成句时：改成“开始做”（不等它做完） |
| T30 | 要等的（或说不准的）函数放进了只收不用等的函数的地方：小库的口（映射、筛选、归并、找、每个都、有一个、逐个）、“改格子”的改法、标了“不等函数”的参数 | 匿名函数里要等的那句单独成句时：改成“开始做” |
| T31 | “等”后面不是“稍后的结果” | 去掉“等” |

提示语都是说人话的中文，并说出“是因为里面哪一句要等”。积木上没有“要等”的标记，只在类型问题里出现。

### 16.3 新能力（不加语法树节点，都是小库函数）

| 写法 | 小库函数 | 规矩 |
|---|---|---|
| `(开始做块 语句…)` | — | 里面随便几句话，马上开始做；结果是“稍后的结果〈里面返回的类型〉”。里面的“返回”只结束这件事。出的错先记着，等它时才抛 |
| `(等 t)` | — | 等它做完拿结果；可以等好几次 |
| `(等最多 t 毫秒)` | `awaitMax` | 到时候没做完＝“超时”错误（消息“等了 N 毫秒还没做完”）；**那件事自己接着做**，以后还能等到。≤0＝马上看一眼 |
| `(等全部 列表)` | `awaitAll` | 全做完才交回，结果按列表顺序。有一件出错（或等的人自己被取消）＝还没做完的都取消，把错抛出来。空列表＝空列表 |
| `(等最先 列表)` | `awaitAny` | 谁先做完（成了或出错）用谁的；别的接着做。空列表＝出错 |
| `(取消 t)` | `cancel` | 给那件事打个记号并叫醒它：它到下一个要等的地方抛“取消了”（消息“这件事被取消了”），“最后总要”照跑。已做完的不受影响；取消两次没关系。取消一件正在等别人的事，被等的那件不受影响 |
| `(被取消了吗)` | `cancelled` | 正在做的这件事有没有被取消 |
| `(一次一个 名字 语句…)` | `lockEnter` / `lockLeave` | 同名的一段同时只有一件事在里面，别的排队，**先来先进**；出错也会让出来（翻成“进去＋试着做…最后总要出来”）。**不能重入**：自己在里面再进同名的＝出错（不然会自己等自己）。排队时被取消＝退出队伍 |

“超时”“取消了”是内置的两个错误种类（上一轮就留了名字，这一轮才真的会抛），能按种类接。

### 16.4 每件事一条“线”

取消、“一次只让一个做”、格子都要认“现在是哪件事在做”。主程序是一条线，每次“开始做”一条，服务里每个请求一条。

| 语言 | 线记在哪 | 等的办法 |
|---|---|---|
| Node | `AsyncLocalStorage`（跟着 `await` 走） | 一个公共的“叫醒”名单，Promise |
| Python | 线程自己的小本子（`threading.local`） | 一把公共的 `Condition` |
| Java | `ThreadLocal`（虚拟线程） | 一把公共的锁＋`Condition`（`LcTask.java`） |
| Go | **显式传**：每个生成的函数、方法、匿名函数、函数类型第一个参数都是 `lt *lc.Line` | 一把公共的锁＋一个“关掉就全体叫醒”的 channel（`lc/task.go`） |
| PHP | 没有同时做，见 16.6 | — |

- **Go 不再用 `runtime.Stack` 认线**（上一轮格子靠它）。代价是生成的 Go 代码每个函数多一个参数；好处是不靠解析调试输出、快、确定。
  `gofmt` 照过。接口方法、小库的高阶函数、`DynCall` 都带这个参数。
- **Node 主程序做完就退出**（写完输出以后 `process.exit`）：还没做完的“开始做”不再往下做——和另外四种语言一致
  （它们本来就是主线结束就退）。开了服务的程序不受影响（“开服务”那一句永远不结束）。这是行为变化。

### 16.5 库里的处理函数

内置库“当收到请求”帽子里的处理函数原来固定写成“要等的匿名函数”，现在就是普通匿名函数，要不要等是推出来的。
路由表里“处理函数”那个**类型**还写着“可能要等”（它是个口：收要等的、也收不等的），这不是手标某个函数。
严格版 135 条、另加 7 条、74 条五种语言重跑全过。

和总设计 6.3“库的回调默认不许等”的出入：现在是“作者没写就推；写了‘不等’才不许”。小库自己的高阶函数和“改格子”的改法是写了不许等的。
理由：用户库的回调大多只是被调一下，默认不许等会把“在处理函数里请求别的网址”这种正常写法全拦掉；真不能等的地方（库里边遍历边改）让库作者写一句“不等函数”。

### 16.6 PHP：如实的语义（和别的语言不一样的地方）

PHP 没有“同时做”：一个请求（或一次命令行运行）从头到尾一条路走完；`php -S` 开几个工作进程，进程之间没有共享内存。
所以 **“开始做”在 PHP 里就是当场把那件事从头做到尾**，做完才回来。这一点不假装。别的靠“两件事同时在跑”才有意义的东西，PHP 按
**“假如它们是同时做的，时间上会怎样”算出来**（`rt2_php_task.dart`）：

- 每件事记着“我做到第几毫秒了”：等一会儿、请求别的网址花掉的时间往上加；纯计算不算时间。“开始做”的那件事从开始它的人当时的毫秒数起算。
- **等**：把自己的毫秒数拨到那件事做完的时候。
- **等，最多 N 毫秒**：那件事做完的时候比“现在＋N”晚＝抛“超时”。**真的时间一点没省**（那件事早就当场做完了，花的时间已经花了）；
  省下来的只是“程序接下来走哪条路”和别的语言一样。
- **等最先的一个**：按算出来谁先做完。**等全部**：一件出错＝按算出来的时间，那时还没做完的记成被取消。
- **取消**：那件事按算出来的时间“这会儿还没做完”＝记成“被取消了”，以后等它拿到“取消了”错误、拿不到它的结果。
  **但它做过的事（打印、改格子、写文件、发请求）都已经发生了，收不回来**；它自己里面也接不到“取消了”，`被取消了吗` 在 PHP 里恒为“否”。
- **一次只让一个做**：一个请求里本来就是一件一件做的，同名重入照样报错；开了服务时用**带锁的文件**（格子文件旁边，每个名字一个），
  几个工作进程之间真的排队。命令行下不用锁。还有一种别的语言没有的情况：开始这件事的那一边正占着同名的段——别的语言会排队等它出来，
  PHP 里它要等这件事做完才能往下走，永远等不到，所以直接报错说明。

结果：12 个样例里 9 个 PHP 和别的语言**同一份期望**（时间算得对，走的路就一样）；3 个另有期望（`.expect.php`），不同都在“那件事自己的打印 / 改动”上：

| 样例 | 别的语言 | PHP |
|---|---|---|
| w03 三件事同时做，各自做完时打印 | 按做完的先后打印 | 按开始的先后打印（都在“都开始了”之前） |
| w08 取消一件边做边打印的事 | 打印两圈就停，里面接到“取消了” | 五圈都打印、都记了账，里面接不到；外面等它照样拿到“取消了” |
| w12 主程序先做完 | 后台那件事后面的打印不出来 | 后台那件事早做完了，打印都在 |

和 A2 分册 P15“PHP 不会超时”的出入：改成了“会超时，按算出来的时间”。理由：不然同一段“超时了就走另一条路”的积木，PHP 和别的语言走的路不一样，
而这是能算对的。

### 16.7 这一段顺手修的

- 生成器原来的保护“没标要等的函数里有要等的事→不生成”删掉了（现在推得出来，不会有这种情况）。
- `LSpawn` 原来只认“返回 f()”，现在是随便几句话；旧写法 `(开始做 f)` 还认，翻成同一个东西。
- Go 小库的 `lcErrObj`、接口方法声明、高阶函数都补上了线参数。
