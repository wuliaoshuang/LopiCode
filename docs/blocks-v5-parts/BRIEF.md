## 二、背景：这个项目和霜霜的要求

LopiCode 是一个 Flutter 写的手机应用（屏幕按 390×844 设计），让人在手机上靠 Agent 和“搭积木”做代码项目。工程在 `~/workspace/lopicode`（master `cc7c7e2`），工程规矩见 `AGENTS.md`。

积木这条线到现在的状态（细节读 `docs/blocks-v4-language-design.md`，1548 行，含第 1、2 阶段的实施记录；以及 `docs/blocks-v3-design.md`、`docs/lowcode-v2-design.md`）：

- **编辑器** `lib/blocks/`（34 个文件）：拼图式积木画布，只认一个 `BlockHost` 接口，不认识“前端/后端”。
- **后端积木** `lib/backend/`（55 个文件）：一份 `backend.lc.json`，生成 Node / Python / Go / Java / PHP 五种语言的零依赖小工程；
  路由、请求、响应、数据集合这些是**每种语言手写在“运行时小库”里的**（`runtime_*.dart`），不是积木搭的。
- **语言核心** `lib/lang/`（19 个文件，约 4300 行）：第 4 版新加的与语言无关的语法树、名字解析、类型推断（很薄）、五种语言的生成器。
  第 1 阶段（值、变量、运算、流程、55 个小库函数）和第 2 阶段（函数、匿名函数、闭包、“我的积木”）已做完，**只接到了后端积木页**。
  类、错误处理、异步、模块、库都还只是设计稿，没实现。类型现在的做法：Go / Java 里一律 `any` / `Object`，运算全走小库（`lc.add(a, b)`），标的类型只存不用。
- **前端低代码** `lib/lowcode/`（54 个文件）：页面模型（节点树＋样式）、画布编辑器、样式面板、自定义组件（带属性、没有插槽、没有数据绑定）、
  页面逻辑积木（`logic_*`，10 种语句 9 种值，直接翻成 JavaScript，还没接语言核心）、导出 HTML / Vue 3 / React。

**霜霜 2026-11-25 19:34 的要求（逐条都要落到文档里）**：

1. 第 3 阶段“把现有后端积木改写成库”要做，而且**要允许用户自己写库**。
2. **前端也要有库**：要有组件库，还要有 JS 库。前端可视化编辑器要再升级——她说现在“有一些简陋，而且有点难用”。
3. 前端逻辑的编写要**标准化**：要掌握 JavaScript 的一切知识以及它在前端（浏览器）里的应用；除了 Node.js 那一套积木逻辑，前端环境的积木逻辑也要研发，尽量复用已有的语言核心。
4. **封装思想**：除了语言基础和基础库以外，所有其它能力都必须是用基础积木封装出来的。所以基础要打牢。要回答：给出的这些积木能不能完整地组建成一个库？能不能完成一个完整流程？
5. **要多次验证、多次测试。**
6. **把所有语言的特性全部拉出来穷举**——各语言大差不差，翻译时多费点步骤而已，是能穷举完的。
7. 大部分语言强调强类型，**类型系统必须做好**。她说现在这一套“还是太过简陋，就是因为前期没考虑清楚”，所以这次**大部分工作要花在前期思考上**。

她以前定过、仍然有效的：手机是唯一目标（390×844，一行只做一件事，挤不下的收进菜单）；积木“要像积木、要好玩”；内置库只读加“复制一份来改”；
没验证的要说清楚；汇报里不许把“没做的”列一下就算交代。

## 三、设计骨架（协调者定的起点——你发现它不对，要在你那份里明说“骨架第 n 条不成立，因为…，建议改成…”）

1. **四层**：
   - L0 **宿主原生接口**：一小撮没法用积木搭的能力（开 HTTP 服务、碰 DOM、发网络请求、读写存储、时间、打印…），每种目标语言各写一段真代码实现。越少越好。
   - L1 **语言核心**：值、变量、运算、流程、函数、类与接口、模块、错误处理、异步、类型。就是一门“与具体语言无关的小语言”，积木只是它的语法树的一种编辑外观；语法树是唯一真相，生成器只吃树。
   - L2 **标准库**（也叫“小库”）：值的规矩（转换、比较、数字写法）和文字 / 列表 / 字典 / 数学 / JSON / 时间这些最常用的操作。各语言手写一份，保证同一份积木在各语言里跑出来**逐字节一样**。
   - L3 **库**：除上面三层以外的一切（路由、中间件、数据集合、页面控件操作、状态管理、组件、表单校验……）。**内置库和用户库是同一种格式**，都是用 L1 的积木＋L2 搭出来的，只在最底下通过“原生绑定”碰 L0。组件库＝带“组件”的库。
2. **特性分四级**（穷举表用）：① 核心——做成积木，所有目标语言都能翻（原生 / 降级生成 / 小库兜底）；② 宿主专属——只在某种语言或环境的库里出现（比如 JS 的原型链、Proxy；Go 的通道；Rust 的所有权）；③ 原生片段兜底——不做成积木，留一个“手写一小段代码”的出口；④ 不做——写明理由。
3. **类型是渐进式的**：`任意`＝动态值，旧文档里的东西全是 `任意`，行为不变；标了类型或能推断出来的地方，校验更严、生成各语言的原生类型。类型系统要像样（可空、泛型、函数类型、记录、联合、类与接口），不是现在的十种标签。
4. **目标语言**：第一梯队 JavaScript（浏览器、Node 分开看）/ TypeScript / Python / Go / Java / PHP；第二梯队（“以后要能接”，这一轮只做对照、不做生成）C# / Kotlin / Rust / Ruby / Dart / Swift。
5. **统一用词**（全文一致，别各起各的名字）：数字（细分 整数 / 小数，要不要分由类型部分定）、文字、是否、空、列表、字典、记录、元组、函数、匿名函数、类、接口、枚举、任意、可空、联合、泛型、模块、库、标准库（小库）、宿主原生接口、原生绑定、原生片段、槽（放值的格子）、口（放积木的 C 形开口）、帽子（一串的开头）、语句积木、值积木、是否积木（六边形）、“我的积木”（自定义积木）。
