# D · 前端（浏览器环境）的积木逻辑

> 作者：D。写于 2026-11-25。只是设计稿，产品代码一行没动。
> 读法：第 0 节是结论；第 1 节是现状（带文件名和行号）；第 2–9 节是八个决定；第 10 节是缺口；最后是给协调者的清单和核对过的来源。
> 文中“跑过”的都写了怎么跑、结果是什么；“没跑”“未核对”的都照实标了。

## 0. 结论摘要

1. **现状比想的更薄**：页面逻辑只有 10 种语句、9 种值、3 种事件（点击、输入、页面加载）、3 种变量类型；没有函数、列表、字典、数据绑定；自定义组件只有属性，没有事件、插槽、状态、逻辑。三种产物（普通网页 / Vue / React）骨子里都是“命令式改控件”，Vue 和 React 只是把“被积木碰到的控件属性”登记成状态再绑上去（第 1 节）。
2. **浏览器的能力分两类，这是整份设计的地基**：
   - **甲类＝归框架管的界面**（控件的文字、显隐、列表、输入框的值、控件事件、组件）。三种产物写法完全不同，必须走**语义级**的宿主接口，一个接口三份实现。
   - **乙类＝不归框架管的浏览器能力**（定时器、请求、本地存储、地址栏与历史、剪贴板、窗口事件……）。三种产物里是**同一段 JavaScript**，一个接口一份实现。
   所以“原生接口尽量少”的做法是：甲类只留 9 个，乙类第一批 20 个，其余全用积木封装成库（第 2 节）。
3. **状态与绑定选 b：细粒度响应式（状态＋派生＋“当…变了”）**。理由：它是三种产物的最大公约数——Vue 直接对上 `ref / computed / watch`；React 用官方给外部仓库准备的 `useSyncExternalStore`；普通网页自带一段很小的运行时（草稿 17 行，正式版要加“重复”和归属，估计一两百行）。a（现状）写不出列表和派生；c（整块重画）在普通网页里要自己做差量更新，在 Vue 里是反着框架用（第 4 节）。
4. **积木语义钉死三条**：①改状态**立刻生效**，下一块读到的就是新值（和现在一样）；②派生值**读的时候**才算、算过记住；③控件上的绑定和“当…变了”**攒到这一轮做完再统一跑一次**。这三条我在 Node 里用小运行时草稿跑通了 10 项检查（第 4.6 节、附录 A）。
5. **绑定不是积木，是控件上的一项设置**：文字、显示/隐藏、在不在、列表重复（必须给“每项的标识”）、类名开关、样式、输入框双向绑定。逻辑里只管改状态，不再到处“把某控件的文字设为”。这就是霜霜要的“标准化”的核心：**状态是唯一的真相，界面是状态算出来的**（第 3、4 节）。
6. **组件模型补全**：属性（用完整类型系统）、事件、插槽（默认 / 具名 / 带数据）、状态、派生、方法、生命周期（只给“放上页面以后”“拿走之前”两个，不给“更新以后”）。三种产物的对应表见第 5 节。普通网页现在是把组件实例“展开”成一堆控件，要改成“每个组件一个工厂函数”。
7. **语言核心几乎全部复用**（值、变量、运算、流程、函数、列表字典、类、错误、异步）；但语言核心现在只做到第 2 阶段，**前端要用的原生绑定、类、错误处理、异步都还没实现**，而且唯一的 JS 生成器是 Node 专用写法（`require`），浏览器用不了（第 6 节）。
8. **新旧两套“转数字 / 转文字”规矩不一致，我跑出来了**：`"0x10"` 页面算 16、核心算 0；不换行空格开头的 `" 5"` 页面算 5、核心算 0；`1e21` 页面写成 `1e+21`、核心写成 `1e21`；“重复 2.5 次”页面做 3 遍、核心做 2 遍。所以迁移时**旧积木继续用旧规矩**，新积木用核心规矩（第 6.3、7 节）。
9. **现有 19 种积木逐个有去处**（第 7 节对照表），旧 `page.lc.json` 一个字不改就能开；第一步**保留旧生成器**给“只用了旧积木的页面”，新生成器只在用到新功能时启用，等两条路在 Node 里逐条比对一致后再合并。
10. **“没写逻辑的页面导出逐字不变”保得住**：规矩改成“没有积木、没有绑定、没有带逻辑的组件 → 不产 logic.js、不加 script 标签”。
11. **内置前端库 10 个**（页面、定时、请求、本地保存、状态仓库、事件总线、路由、表单校验、动画、国际化），第 8 节给了“状态仓库”和“路由”两个库的完整写法。两个库的伪代码我手工改写成 JS 在假宿主里跑了 16 项，发现并补了 1 个漏洞（8.5）。
12. **验证**：现在的手写假 DOM 够测“事件接没接上、属性改没改、顺序对不对”，测不了冒泡、默认行为、表单校验、历史记录、输入法、渲染时机；Vue / React 产物在这台机器上**一次都没真编译过**，这是最大的风险（第 9 节）。
13. **缺口 32 个**（GAP-D-1 … 32，第 10 节）。最要紧的 6 个：浏览器 JS 生成目标（1）、原生绑定按“语言×宿主”分实现（2）、帽子型积木登记与自动收尾（3、9）、事件回调里的异步规矩（5）、状态里的列表“原地改不触发更新”（7）、事件对象的类型随事件名变（20）。
14. **和骨架、和 C 的出入**：骨架四层成立；有两处要补——“宿主”要再分一维（同是浏览器 JS，还分普通网页 / Vue / React）；C 建议的“7 个通用碰 JS 对象接口”我建议只做兜底、不做主干（理由见 2.6）。

**需要霜霜拍板的 3 件**（详见文末）：①要不要允许在开发机上装 Vue、React 和打包工具做真编译验证（建议：要）；②React 产物要“行为和网页完全一样”还是“写法地道”（建议：行为一样）；③“更新以后”这个生命周期不给（建议：不给，用“当…变了”代替）。

**没核对 / 没跑的**（详见文末）：Vue 的 computed / watch / v-model / defineEmits / 带数据的插槽 / 生命周期只见到第三方转述，官方页没打开；React 的列表 key、受控输入同上；动画、剪贴板、通知、地理位置、IndexedDB、Cookie、WebSocket、Worker 的接口细节全部未核对；Vue / React 产物没编译、没运行；所有示例库没被任何程序读过。

### 1.2 怎么翻成 JavaScript

- 翻译器是 `JsLogicWriter`（`logic_js_core.dart` 127 行起），它不直接写“变量在哪、控件怎么改”，而是问一个叫 `JsTarget` 的东西要四句话：读变量、写变量、读控件属性、写控件属性，外加“事件的值”（同文件 79–96 行）。
- `JsTarget` 现在有三个：
  - **普通网页** `DomJsTarget`（`logic_js.dart` 19–51 行）：变量放在一个 `state` 对象里；控件用 `document.querySelector(".n-"+编号)` 找（`lcEl`，54–95 行）；显示隐藏改 `style.display`；事件用 `addEventListener`。
  - **Vue** `VueJsTarget`（`export_vue.dart` 53–86 行）：变量、以及“被积木碰到的控件属性”都做成 `ref`；模板里用 `v-show`、`:style`、`@click`、`{{ }}`、`:value`（121–169 行）。
  - **React** `ReactJsTarget`（`export_react.dart` 52 行起）：文件头 6–12 行解释了为什么**不用** `useState` 放变量——因为“下次重画才生效”，会破坏“上一块刚改、下一块就读到”——所以变量放在 `useRef({...}).current` 里，每次写完调一下 `lcRefresh()`（一个只用来触发重画的计数）。
- 小工具（`logic_js_core.dart` 100–124 行）：`lcNum`（转数字，转不了当 0）、`lcText`（数字保留 12 位有效数字）、`lcEq`（比较时把数字和文字拉平）、`lcEventValue`。
- 细节（后面迁移要用）：算术一律先转数字，除和取余的结果再过一遍 `lcNum`（约 208–213 行）；“设变量”会按变量声明的类型转一下；“等一会儿”翻成 `setTimeout`（279–281 行）；“打印”直接 `console.log(值)`，不转文字（286 行）；“请求网址”用 `.then(成功, 失败)` 两个参数的写法，状态码不是 2xx 当失败（295–316 行）；不认识的积木翻成一行注释，不崩。
- 整份 `logic.js` 的结构（`logic_js.dart` 122–189 行）：文件头 → `const state` → 小工具 → 每个事件一个有名字的函数 → `lcStart` → 等文档就绪后启动。**逻辑为空时返回空字符串**（124 行）。
- 有“错误”级的校验问题时，不更新 `logic.js`，框架导出也被拦（`logic_gate.dart` 11–15 行）。校验规则表在 `logic_rules.dart` 24–82 行（G 共用、P 页面专有、S 后端、L 语言核心、B “我的积木”外观）。

### 1.3 页面节点和组件

- 页面是一棵节点树（`model.dart` 22 行起 `LcNode`：编号、类型、属性、孩子、样式、`bind`）。控件类型 12 种（185–219 行）。**“列表”控件的内容是写死的字符串数组**。
- 节点上的 `bind` 现在只用于“组件定义里的控件，把某个属性接到组件的属性上”，能接的只有 5 种（106 行 `bindableProps`）。
- 自定义组件（`component_model.dart` 35–89 行）：只有编号、名字、属性表、根节点。属性类型只有文字、数字、颜色、是否（14 行）。**没有事件、没有插槽、没有状态、没有逻辑。**
- `component_ops.dart` 297–306 行：要存成组件的那块控件如果被积木引用了，**直接拒绝**，理由写的是“组件定义里的控件不支持积木逻辑”。
- 导出普通网页时，组件实例被“展开”成普通控件（`component_ops.dart` 221 行 `expandedTree`，`export_html.dart` 96 行调用）；导出 Vue 用 `defineProps`（`export_vue.dart` 315 行）。

### 1.4 导出时逻辑怎么落进去

- 普通网页（`export_html.dart` 49–115 行）：每个控件带 class `lc-<类型> n-<编号>`（55 行）；有逻辑才在末尾加一句引用 `logic.js` 的 `<script>`，注释原话“没有逻辑的页面一个字节都不多”（97–99 行）。
- Vue：`<script setup>` ＋ `<style scoped>`（`export_vue.dart` 207–224 行），页面加载的积木放进 `onMounted`（295 行）。文件头 13 行写明“没有用真正的 Vue 编译器编译过”。
- React：`useEffect(…, [])` 跑页面加载的积木，并注明严格模式下开发时会跑两次（约 331–341 行）；输入框用 `onChange`（267–268 行）。18 行写明没用 Babel 编译过。
- 三者共用 `export_framework_common.dart`：`LcPropStates`（187 行）就是那本“哪些控件属性被积木碰到了”的登记簿。

### 1.5 语言核心现在到哪了

- 语法树节点很全（`lib/lang/ast.dart`：模块、变量、函数、类、接口、原生声明、各种语句、列表字典字面量、取字段、调方法、新建对象、匿名函数、等待、开始做、原生片段……）。
- 但**生成器只做到第 2 阶段**（`rt.dart` 21 行 `kLangStage = 2`）：`gen.dart` 358–360 行对“取字段 / 调方法 / 新建对象 / 是不是某类 / 自己 / 等待 / 开始做”直接报“不支持”；`gen_func.dart` 315 行对变量和函数以外的声明报“不支持”（原生声明记为第 3 阶段，其余第 5 阶段）。
- 小库函数约 55 个以上（`rt.dart` 89–186 行：类型、数学、文字、列表含映射 / 过滤 / 累计、字典、JSON、范围）。
- JS 生成器只有 `gen_node.dart`（88 行），产物开头是 `require("./lc_lang.js")`——这是 Node 的写法，**浏览器里直接用不了**。
- 类型（`types.dart`）有十种“种类”，但生成时全按“任意”处理。

**前端能直接复用多少**：语法树、校验、积木编辑器、小库的 JS 实现（内容是普通 JS，不依赖 Node）可以复用；生成器的“出口包装”要新做一份；类、错误、异步、原生绑定是前后端共同的欠账。

### 1.6 现在怎么验证

- `test/lowcode_logic_js_test.dart`（1082 行）：在 Node 里跑，用的是**手写的极小假 DOM**（87–136 行）：按 class 找元素；`addEventListener` 只是记下来；`alert`、`console`、`setTimeout`、`fetch`、`location` 全是“只记账”的假货；测试里手动 `fire()` 触发事件。另有 `node --check` 查语法。没装 Node 时这些用例跳过。409 行还有一个“换一种 target 写法”的用例，证明翻译器确实能换宿主。
- `test/lowcode_logic_export_test.dart`（143 行）：没逻辑就没 `<script>`；有逻辑就引用 `logic.js`；存盘、删除、有错误时不更新。
- Vue 和 React 的产物：只有文字层面的检查，没有真编译、没有真运行（三处源码注释和 `docs/lowcode-v2-design.md` 的“做完之后补记”都这么写）。

## 2. 决定一：浏览器宿主的最小原生接口

### 2.1 先分两类（这一步最要紧）

判断一个浏览器能力怎么接，先问一句：**这块东西，Vue / React 管不管？**

| | 甲类：归框架管的界面 | 乙类：不归框架管的浏览器能力 |
| --- | --- | --- |
| 是什么 | 页面上每个控件的文字、值、显隐、样式、有没有、重复几份；控件上的事件；组件 | 定时器、网络请求、本地存储、地址栏与历史、剪贴板、窗口大小与滚动、通知、定位…… |
| 三种产物的写法 | **完全不同**：普通网页直接改元素；Vue 改 `ref`、模板自己跟着变；React 改状态、整个函数重跑 | **完全一样**：都是那一句 JavaScript（`setTimeout(...)`、`fetch(...)`、`localStorage.getItem(...)`） |
| 怎么接 | 语义级宿主接口，**一个接口三份实现**（现在 `JsTarget` 的三个子类干的就是这件事） | 原生绑定，**一个接口一份实现** |
| 为什么不能混 | 在 Vue / React 里绕过框架直接改它管的元素，下次重画会被盖掉或者出错（这是两家文档反复强调的，原话我**未核对**） | — |

这个分法带来三个好处：甲类接口可以压到很少（9 个）；乙类接口不用写三遍；“假宿主”好做——测试时甲类换成假页面、乙类换成假浏览器对象，库的积木一行不用改。

### 2.2 甲类：页面宿主接口（9 个，三份实现）

名字是给实现的人看的内部名，用户看到的是积木。

| # | 接口 | 参数 → 返回 | 语义细则 |
| --- | --- | --- | --- |
| 1 | `状态.新建` | (初值: T) → 状态‹T› | 造一个“会通知”的格子。页面级的在页面启动时造一次；组件里的每个实例各造一份。 |
| 2 | `状态.读` | (状态‹T›) → T | 读当前值。在“派生”“绑定”“当…变了”里读，会被记下“我依赖它”。 |
| 3 | `状态.写` | (状态‹T›, 新值: T) | **立刻生效**；和旧值一样（按 JS 的 `Object.is` 比）就什么都不做；不一样就通知依赖它的派生和绑定“你旧了”。 |
| 4 | `状态.派生` | (算法: () → T) → 派生‹T› | 读的时候才算；依赖没变就用上次的结果；不许在算法里改状态（校验拦）。 |
| 5 | `状态.监听` | (取值: () → T, 回调: (新值, 旧值) → 空) → 取消函数 | 取值结果变了才叫回调；一轮里变多次只叫一次，拿到的是最后的值；登记时默认不先叫一次（可选“马上先做一次”）。 |
| 6 | `界面.读` | (控件, 属性名) → 任意 | 读控件现在的文字 / 值 / 是否显示等。**保留是为了旧积木**；新写法里读状态，不读控件。 |
| 7 | `界面.写` | (控件, 属性名, 值) | 同上，为旧积木保留。一个属性如果已经绑定到式子上，再用它写＝校验错误（“这个属性已经跟着状态变了”）。 |
| 8 | `界面.当事件` | (控件, 事件名, 回调: (事件) → 空, 选项) → 取消函数 | 选项：只做一次、不拦默认行为的承诺。事件对象是一份**记录**，不是浏览器原对象（见 2.4）。 |
| 9 | `界面.生命周期` | (哪个: 放上以后 / 拿走之前, 回调) | 页面的“放上以后”＝现在的“页面加载时”。组件里每个实例各叫一次。 |

外加一个**第二批**的：`界面.真元素(控件) → 元素 或 空`（要调 `focus()`、量尺寸、拿画布时才需要；放上页面之前是空）。

**绑定不在这张表里**。绑定是页面文档里控件上的一项设置，由导出器翻成对应写法（Vue 的模板指令、React 的 JSX 式子、普通网页的一段“状态变了就改元素”），不是运行时调用的接口。见第 4 节。

**不给的**：创建 / 插入 / 删除任意元素。理由：控件“有没有”“重复几份”用绑定声明（“在不在”“列表重复”），三种产物都有地道写法；让积木自己造元素，在 Vue / React 里没有对应物。真有这个需要（比如在一个容器里画图表），走“真元素”＋JS 专属库，并且那个容器要标成“这块我自己管”。

三份实现各是什么：

| 接口 | 普通网页 | Vue 3 | React |
| --- | --- | --- | --- |
| 状态.新建 / 读 / 写 | 自带小运行时（草稿见附录 A） | `ref(初值)` / `.value` | 自带小运行时（放在组件外面）＋ `useSyncExternalStore` 订阅 |
| 状态.派生 | 小运行时的派生 | `computed(() => …)` | 小运行时的派生 |
| 状态.监听 | 小运行时的监听 | `watch(取值, 回调)` | 小运行时的监听 |
| 界面.读 / 写 | `lcGet / lcSet`（现在的） | 读写登记簿里的 `ref`（现在的） | 读写 `lcUi`（现在的）；迁到新模型后是读写状态 |
| 界面.当事件 | `addEventListener` | 模板里 `@事件名` | JSX 里 `on事件名` |
| 界面.生命周期 | 文档就绪后 / 被拿走时 | `onMounted` / `onBeforeUnmount` | `useEffect(() => { …; return 收尾 }, [])` |

`ref`、模板自动解包、依赖追踪：vuejs.org 已核对。`useSyncExternalStore(订阅, 取快照)` 的签名和“快照没变必须返回同一个值”：react.dev 官方子域已核对。`useEffect` 的“返回收尾函数”“严格模式下开发时多跑一轮 开→收→开”：react.dev 已核对。`computed`、`watch`、`onMounted`、`onBeforeUnmount`：只见到第三方转述，**官方页未核对**。

### 2.4 事件对象里能取什么

回调拿到的不是浏览器原对象，是一份记录（这样三种产物一致，也能给类型）：

| 字段 | 类型 | 哪些事件有 |
| --- | --- | --- |
| 值 | 文字 | 输入、改变（就是现在的“事件的值”） |
| 勾上了 | 是否 | 勾选框的改变 |
| 键 | 文字 | 按键 |
| 横坐标、纵坐标 | 数字 | 点击、指针、触摸 |
| 触发的控件 | 控件 | 所有（事件委托时用） |
| `阻止默认行为()` | 动作 | 所有。**必须在回调里第一个“等”之前调**，之后调没用（GAP-D-5） |
| `别再往上传()` | 动作 | 所有 |

冒泡和捕获：只给“冒泡阶段监听”这一种，不暴露捕获阶段。理由：捕获阶段的用途（抢在子控件之前拦截）在积木里几乎用不上；React 的事件是它自己合成的，和原生的传播细节不完全一样（**未核对**），少暴露一点少一处不一致。

### 2.5 第二批、可以封装成库的、先不做的

| 能力 | 归哪 | 说明 |
| --- | --- | --- |
| 防抖、节流 | **库**（“定时”库） | `定时.过后`＋`定时.取消` 就能用积木写出来 |
| 睡一会儿（“等 毫秒”） | **语言核心** | 核心已有；浏览器实现＝等一个 `定时.过后` |
| 请求的重试、缓存、去重、JSON 自动转 | **库**（“请求”库） | 在 `网络.请求` 上封装 |
| 路由（按地址显示哪一页） | **库** | 在“地址”那 6 个接口上封装，见 8.4 |
| 表单取值、校验 | **库** | 取值靠输入框的双向绑定；校验是纯计算。浏览器自带的约束校验（`checkValidity` 等）**不用**——它的提示气泡样式各浏览器不一样，而且三种产物接法不同（未核对） |
| 表单提交 | 甲类事件 | “表单”控件的“提交”事件＋`阻止默认行为()`。需要新控件类型，交给 E |
| CSS 过渡 | **不是接口** | 是样式；逻辑里只要切换类名（绑定“类名开关”）。“过渡做完了”事件走 `界面.当事件` |
| Web Animations（脚本控制的动画） | 第二批，`界面.真元素`＋JS 专属库 | 接口细节未核对 |
| Cookie | 第二批 | 一读一写两个原生绑定（整串文字），拆解拼装用积木写。服务器设成“脚本读不到”的那种本来就读不到（未核对） |
| IndexedDB | 第二批，做成“带原生实现的库” | 接口是事件式的、有事务和版本升级，直接映射成积木太碎；做成“大容量的键值存储”几个积木就够。未核对 |
| 剪贴板 | 第二批 | 写、读各一个，都是异步。**要求安全上下文和用户许可（未核对）**——霜霜现在的服务器都是 `http://` 明文，很可能用不了，要真机验 |
| 通知、地理位置 | 第二批 | 同样涉及许可和安全上下文，未核对 |
| 看一个控件有没有滚进屏幕（懒加载、无限滚动） | 第二批 | `IntersectionObserver`，未核对。图片懒加载先用 HTML 自带的 `loading="lazy"`（未核对），那是属性不是逻辑 |
| 媒体（音频、视频） | 第二批 | 播放、暂停是元素的方法，走 `界面.真元素`；状态（在不在播、进度）走事件 |
| Canvas（画布） | 第二批，JS 专属库 | 画图指令很多，属于“一个专门的库”，不进最小集 |
| WebSocket | 第二批，做成库 | 连、发、关三个原生绑定＋三个事件；C 的判定流程里它也是“库带原生绑定” |
| Worker（后台线程） | **先不做** | 要单独一份脚本文件、只能传消息；积木里“同时做”已经够日常用。等真有算得很重的需求再说 |
| Service Worker、推送、WebRTC、WebGL、蓝牙、USB | **不做** | 离“手机上搭页面”太远，而且多数要求 https |

### 2.6 和 C 的建议怎么对上

C 在摘要第 9 条建议：浏览器的最小集是“一组通用的‘碰 JS 对象’接口（7 个）”，DOM、定时器、存储、地址栏都在它上面用积木封装，Vue / React 的“改控件”走语义级接口由我细化。（我读到 C 的文件时它只写到第 2 节，7 个接口的细则我没看到。）

我的意见：**语义级接口那一半完全同意（就是 2.2）；“通用碰 JS 对象”建议只做兜底，不做主干。** 理由：

1. **类型**：`调用(对象, "getItem", [键])` 这种写法，名字是字符串，返回值是“任意”，类型系统帮不上忙。有名字的原生绑定（`存储.读(区, 键) → 可空‹文字›`）类型是全的。霜霜明确要“类型系统必须做好”。
2. **假宿主**：按名字替换 20 个接口很容易；替换“任意 JS 对象的任意方法”要造一整个假浏览器。
3. **权限**：能调任意 JS 对象的任意方法，等于能手写代码。按 C 自己的第 8 条，这在用户库里默认是关着的。那内置库走这条路就没有额外好处——内置库本来就由我们写原生实现。
4. **它仍然有用**：做成“JS 专属库”里的 4 块积木（取全局对象、读属性、写属性、调方法），和“手写代码”同一个开关、同一个“手写”角标，给会的人兜底。归到特性四级里的 ③。

这一条需要协调者在 C、D 之间定一下（见文末清单）。

## 3. 决定二：JavaScript 在前端的知识地图（“标准写法”）

每一行是一件前端里常见的事。**“标准做法”那一列就是规范**——积木盒只提供这一种写法，不提供别的路。

“层”的写法：核心＝语言核心已有或计划有；小库＝标准库；页面库 / 某某库＝内置库里的积木；设置＝控件上的一项设置（不是积木）；不做＝理由在后面。

### 3.1 运行模型

| 事 | 标准做法 | 层 | 积木 / 设置长什么样 |
| --- | --- | --- | --- |
| 事件驱动 | 页面平时不跑任何代码，“有事发生才做”。所有逻辑都从一个帽子开始 | 页面库 | `当 [按钮1] 被点击 { … }`、`当页面放上以后 { … }`、`当 (状态 关键词) 变了 (新值) (旧值) { … }` |
| 一次只做一件 | 页面只有一条线，一段积木跑完才轮到下一段；一段积木里不“等”的话，中间不会被别的事件插进来 | 核心（说明书里写清楚） | 无积木。MDN 已核对：每轮至多一个任务 → 清空所有微任务 → 需要时重画 |
| 界面什么时候变 | 改状态立刻生效；屏幕等这一段积木跑完才重画。所以“先改成‘加载中’，再算很久”——加载中不会显示出来，中间必须“等”一下 | 页面库 | `[让界面先更新一下]`（等到下一帧）。实现＝等一个 `定时.下一帧` |
| 等 | `[等 毫秒]`、`(等 (请求…))`：这一段停在这里，**别的事件照常响应**，等到了接着往下 | 核心（3.10） | 核心的“等” |
| 同一个事件又来了 | 上一次还在“等”的时候又点了一下：默认**照常再开一份**（和 JS 一样）。帽子上可以改成“忽略新的”“取消旧的”“排队” | 页面库（GAP-D-5） | 帽子上的一个小下拉，默认不显示 |
| 没人接的错误 | 帽子里的积木出了错又没被“试试看”接住：统一交给 `当页面出错时 (错误) { }`；没写这个帽子就打印到控制台 | 页面库 | `当页面出错时 (错误) { … }` |

### 3.2 界面

| 事 | 标准做法 | 层 | 积木 / 设置 |
| --- | --- | --- | --- |
| 改界面 | **不直接改控件，改状态**；控件的属性绑在状态或式子上 | 设置＋页面库 | 控件属性旁边的“绑定”钮 → 选状态或拼一个式子；逻辑里 `[把 状态 计数 设为 (…)]` |
| 条件显示 | 两种，意思不同，必须分清：**“显示 / 隐藏”**（东西还在，只是看不见，输入框里的字还留着）和 **“在不在”**（不在就真的没有，里面的组件会被拿走、再出现是新的） | 设置 | 控件上“显示条件”“存在条件”各一格 |
| 列表渲染 | 控件上设“重复”：数据来源（一个列表式子）、每项叫什么、第几项叫什么、**每项的标识**（必填）。标识用来在列表变了以后认出“谁还是谁”，这样只动变了的那几项，输入到一半的格子也不会串 | 设置 | “重复”面板四格。标识缺省给“第几项”并出**警告**（“列表会增删或排序时请换成每项自己的编号”） |
| 差量更新 | 用户不用管。Vue / React 自己做；普通网页由页面宿主按“标识”做（留、挪、加、删） | 宿主实现 | 无积木 |
| 类名 / 样式 | 类名是“开关”：`选中了 ← (当前项 = 这一项)`；样式是“值”：`背景色 ← (…)` | 设置 | 样式面板每一格旁边的“绑定”钮（界面交给 E） |
| 输入框 | **双向绑定到一个状态**：打字改状态，改状态也改框里的字。不要自己监听输入再手动回写 | 设置 | 输入框的“值”一格选一个状态 |
| 事件委托 | 用户不用管。“重复”出来的每一份里放事件帽子，帽子能直接拿到“这一项”。生成时页面宿主可以只在外层挂一个监听（优化，行为一样） | 宿主实现 | `当 [删除钮] 被点击（这一项）{ … }` |
| 直接碰元素 | 尽量不碰。确实要（让输入框获得焦点、滚到某处、量大小）用页面库里有名字的积木，不给“任意改元素” | 页面库（第二批） | `[让 [输入框1] 获得焦点]`、`[滚到 [控件] ]`、`([控件] 的宽)` |
| 把文字放进页面 | 一律当**纯文字**放，不当 HTML 解析。不提供“设成一段 HTML” | 页面库 | 无。理由：把用户输入当 HTML 塞进页面是最常见的安全漏洞来源（`textContent` 与 `innerHTML` 的差别，MDN 未核对） |

### 3.3 状态

| 事 | 标准做法 | 层 | 积木 |
| --- | --- | --- | --- |
| 状态 | 会让界面变的数据才是状态；只在一段积木里用的是普通变量 | 页面库 | 状态面板里声明；`(状态 x)`、`[把 状态 x 设为 …]`、`[把 状态 x 增加 …]` |
| 派生 | 能从别的状态算出来的**不要另存一份**，声明成派生值 | 页面库 | 状态面板里“派生”：`总价 ＝ (把 (状态 购物车) 每项的 小计 加起来)` |
| 状态里的列表和字典 | **整份换新，不原地改**（三种产物只有这样才都能发现“变了”） | 页面库＋校验 | `[往 状态 待办 末尾加 (…)]`、`[从 状态 待办 去掉 满足 (…) 的]`、`[把 状态 待办 里 标识是 (…) 的那项的 完成 设为 (…)]`——这些积木内部都是“抄一份、改、整份设回去” |
| 监听变化 | 只用来做“对外的事”（存盘、发请求、打印）。**想让另一个状态跟着变，用派生，不用监听** | 页面库＋校验 | `当 (式子) 变了 (新值) (旧值) { … }`；在里面直接改别的状态出**警告** |
| 跨页面 / 跨组件共享 | 放进“状态仓库” | 状态仓库库 | 见 8.3 |

## 4. 决定三：状态与数据绑定

### 4.1 三条路的比较

约束是：同一份积木要能翻成**普通网页、Vue 3、React** 三种产物，而且三种跑起来行为一样。

| | a. 命令式改控件（现状） | b. 细粒度响应式（状态＋派生＋监听） | c. 状态变了整块重画 |
| --- | --- | --- | --- |
| 用户怎么想 | “点了以后，把这个文字改成那个” | “这个文字＝计数×2；点了以后计数加 1” | “界面是状态的函数；状态变了全部重算” |
| 普通网页 | 最简单，现在就是 | 要自带一段小运行时（草稿 17 行，附录 A 跑通了；正式版估计一两百行） | 要自己做“新旧界面比对、只改不同处”——等于自己写半个 React |
| Vue 3 | 反着框架用：现在是把被碰到的属性偷偷登记成 `ref` | **就是 Vue 自己的模型**（`ref / computed / watch`） | 反着用：Vue 是按依赖精确更新的，不是整块重画 |
| React | 反着框架用：现在靠 `useRef`＋手动刷新 | 状态放组件外面，用 `useSyncExternalStore` 订阅——这是 React 官方给“外部仓库”留的正路 | **就是 React 自己的模型** |
| 列表 | 写不出来（要能造元素） | 绑定“重复”，三种产物都有地道写法 | 同左 |
| 派生值 | 没有，每处都要手动同步，容易漏 | 有 | 有（重画时现算） |
| “先写后读立刻生效” | 是 | 是（状态是我们自己的格子） | React 的 `useState` 做不到（react.dev 官方子域原话：设置状态不改变已经在跑的代码里的变量，而是请求重画）；要保住就得退回 b 的做法 |
| 旧积木能不能原样留着 | 能 | 能（“改控件属性”保留为宿主接口 6、7） | 难（旧积木直接改控件，重画会盖掉） |

**决定：选 b。** 一句话理由：b 在 Vue 里是原生的，在 React 里有官方正路，在普通网页里代价是一段很小的运行时；c 在三种里只有 React 是原生的，而且恰恰在 React 里保不住“先写后读”。a 留作旧积木的兼容，不再往上加功能。

风险照实说：React 那条路（外部仓库＋`useSyncExternalStore`）写出来的代码**不是 React 新手教程里的样子**（教程里是 `useState`）。行为对、官方支持，但“看着不地道”。这是文末要霜霜拍板的第 ② 件。

### 4.2 三条语义（钉死）

1. **改状态立刻生效。** `[把 x 设为 1]` 后面紧跟的 `(状态 x)` 读到 1。和现在的页面变量一样，旧页面不受影响。
2. **派生值读的时候才算，算过记住。** 依赖的状态没变就不重算；变了也不马上算，等有人读。所以派生值永远是新的，不会读到“半新半旧”。
3. **绑定和“当…变了”攒着，这一段积木跑完再统一跑一次。** 一段积木里把同一个状态改三次，屏幕只更新一次，“当…变了”只叫一次，拿到的是最后的值。

第 3 条在三种产物里的落地：普通网页和 React 用小运行时，攒到微任务里跑（微任务在本轮任务结束后、重画之前清空，MDN 已核对）；Vue 的 `watch` 默认也是攒着的（“界面更新不是同步的，攒到下一拍”这句我只见到镜像站转述，**vuejs.org 未核对**；`watch` 回调相对于界面更新的先后顺序也**未核对**——所以规矩里写“不要在‘当…变了’里假定界面已经更新”，要等就用 `[让界面先更新一下]`）。

两条保险：
- “当…变了”里又改了它自己看的状态，互相触发超过 100 轮 → 报错停下，不卡死页面（附录 A 第 7 项跑过）。
- 派生值互相绕圈 → 读的时候报错（附录 A 第 8 项跑过）；编辑时校验也能先拦住（静态看依赖图）。

### 4.3 积木

**声明**（在状态面板里，不在画布上——和现在的变量面板同一个位置）：

| 种类 | 填什么 | 备注 |
| --- | --- | --- |
| 状态 | 名字、类型（完整类型系统）、初值 | 现在的三种变量自动就是状态 |
| 派生 | 名字、一个式子（类型自动推出） | 式子里不能有“改状态”“请求”等动作（校验） |

**画布上的积木**：

| 积木 | 形状 | 说明 |
| --- | --- | --- |
| `(状态 x)` / `(派生 y)` | 值 | 读 |
| `[把 状态 x 设为 (…)]` | 语句 | 写。派生不能写 |
| `[把 状态 x 增加 (…)]` | 语句 | 数字专用 |
| `[把 状态 x 的 字段路径 设为 (…)]` | 语句 | 状态是记录 / 字典时，改里面一格。内部＝抄一份、改、整份设回去（GAP-D-10） |
| `[往 状态 x 末尾加 (…)]`、`[从 状态 x 去掉第 (n) 项]`、`[从 状态 x 去掉满足 (条件) 的]`、`[把 状态 x 里满足 (条件) 的换成 (…)]`、`[把 状态 x 排序 按 (…)]` | 语句 | 状态是列表时用。内部同上 |
| `当 (式子) 变了 (新值) (旧值) { … }` | 帽子 | 监听。可选“一开始先做一次” |
| `[一起改 { … }]` | 语句带口 | 一般用不到（一段积木本来就是攒着的）；跨了“等”又想让两次改动一起生效时用。第二批 |

**一个要紧的坑和它的拦法**（GAP-D-7）：语言核心的列表是可以原地改的（“往列表末尾加”直接改那个列表）。如果用户写

```
设 临时 为 (状态 待办)
[往 (临时) 末尾加 "买菜"]        ← 原地改了状态里那个列表，但没人知道它变了
```

界面不会更新（React 里是因为快照要求不可变、按 `Object.is` 比——react.dev 官方子域已核对；Vue 里因为是深层响应反而**会**更新——于是三种产物行为不一样，这最糟）。拦法两层：
- 类型：`(状态 x)` 读出来的列表 / 字典 / 记录是**只读**的，把它喂给“原地改”的积木＝校验错误，提示“要改状态里的列表，用‘往 状态 … 末尾加’”。
- 兜底：开发预览时小运行时把读出来的列表冻住（`Object.freeze`），原地改会直接报错；导出的正式产物不冻。Vue 产物里状态用“浅层”的 `shallowRef`，让它和另外两种一致（`shallowRef` **未核对**）。

### 4.4 控件属性怎么绑

绑定写在页面文档里控件节点上（格式见 4.7），界面怎么点出来交给 E。逻辑上一共 8 种：

| 绑定 | 填什么 | 意思 |
| --- | --- | --- |
| 文字 | 一个式子 | 控件的文字＝式子的值（按“转文字”的规矩） |
| 属性 | 属性名＋式子 | 图片地址、占位文字、是否禁用、链接等 |
| 显示条件 | 是否式子 | 不成立时看不见，但东西还在 |
| 存在条件 | 是否式子 | 不成立时真的没有 |
| 重复 | 列表式子、项的名字、序号的名字、标识式子 | 这个控件（连同里面的）按列表每项来一份；里面的绑定和帽子都能用“这一项”“第几项” |
| 类名开关 | 类名＋是否式子（可多条） | 成立就加上这个类名 |
| 样式 | 样式名＋式子（可多条） | 背景色、文字色、宽高等 |
| 双向 | 一个状态（或状态里的一格） | 输入框、勾选框、下拉：用户改 → 写状态；状态改 → 改控件 |

规矩：
- 一个属性要么写死、要么绑定、要么被旧积木“改控件属性”直接改，**三选一**。绑了又去直接改＝校验错误。
- 绑定的式子必须没有副作用（不能有请求、不能改状态）。
- “重复”必须有标识；用“第几项”当标识时出警告（React 官方对用序号当 key 的告诫我只见到第三方转述，**未核对**；Vue 同）。
- 双向绑定的输入框，中文输入法拼字拼到一半时要不要写状态：Vue 的 `v-model` 据说会等拼完（**未核对**），React 的 `onChange` 据说每敲一下都触发（**未核对**）。这里三种产物很可能不一致，**只能真机验**。

### 4.5 三种产物各生成什么

以“计数器：一个文字显示‘两倍是 N’，一个按钮加 1，一个待办列表”为例。**以下三段都是手写的示意，没有编译、没有运行。**

**普通网页**（`logic.js` 里；`lc.状态`、`lc.派生`、`lc.绑` 是自带小运行时）：

```js
const count = lc.state(0);
const todos = lc.state([]);
const dbl   = lc.derived(() => count.get() * 2);

lc.bindText(".n-t1", () => "两倍是 " + lcText(dbl.get()));
lc.bindShow(".n-empty", () => todos.get().length === 0);
lc.bindEach(".n-row", () => todos.get(), (it) => it.id, (row, it) => {   // 每项一份；it 是取这一项的函数
  row.bindText(".n-rowText", () => it().title);
  row.on(".n-del", "click", () => todos.set(todos.get().filter((x) => x.id !== it().id)));
});
lc.on(".n-b1", "click", () => count.set(count.get() + 1));
```

“重复”的模板在 HTML 里放进一个 `<template>` 元素，`bindEach` 按标识做留、挪、加、删。（`<template>` 的行为**未核对**。）

**Vue 3**（单文件组件）：

```vue
<script setup>
import { ref, shallowRef, computed } from "vue";
const count = ref(0);
const todos = shallowRef([]);
const dbl = computed(() => count.value * 2);
function onB1Click() { count.value = count.value + 1; }
function onDel(it)   { todos.value = todos.value.filter((x) => x.id !== it.id); }
</script>
<template>
  <span class="n-t1">两倍是 {{ lcText(dbl) }}</span>
  <div class="n-empty" v-show="todos.length === 0">还没有</div>
  <div class="n-row" v-for="it in todos" :key="it.id">
    <span class="n-rowText">{{ it.title }}</span>
    <button class="n-del" @click="onDel(it)">删</button>
  </div>
  <button class="n-b1" @click="onB1Click">加 1</button>
</template>
```

对应关系：文字 → `{{ }}`；属性 → `:名字`；显示条件 → `v-show`；存在条件 → `v-if`；重复 → `v-for`＋`:key`；类名开关 → `:class`；样式 → `:style`；双向 → `v-model`；监听 → `watch`。其中 `ref`、模板自动解包已核对；`v-show / v-if / v-for / :key / v-model / computed / watch / shallowRef` 的官方页**未核对**（只见第三方转述）。

**React**：

```jsx
import { useSyncExternalStore } from "react";
import { lc } from "./lc-rx.js";                 // 同一份小运行时
const count = lc.state(0), todos = lc.state([]);
const dbl = lc.derived(() => count.get() * 2);
const page = lc.snapshotOf({ count, todos, dbl }); // 订阅函数＋“没变就返回同一个对象”的快照

export default function Page() {
  const s = useSyncExternalStore(page.subscribe, page.getSnapshot);
  return (<>
    <span className="n-t1">两倍是 {lcText(s.dbl)}</span>
    <div className="n-empty" style={{ display: s.todos.length === 0 ? undefined : "none" }}>还没有</div>
    {s.todos.map((it) => (
      <div className="n-row" key={it.id}>
        <span className="n-rowText">{it.title}</span>
        <button className="n-del" onClick={() => todos.set(todos.get().filter((x) => x.id !== it.id))}>删</button>
      </div>))}
    <button className="n-b1" onClick={() => count.set(count.get() + 1)}>加 1</button>
  </>);
}
```

对应关系：文字 / 属性 → `{式子}`；显示条件 → 行内样式；存在条件 → `{条件 && <…/>}`；重复 → `.map`＋`key`；类名 → `className` 拼字符串；双向 → `value`＋`onChange` 写状态；监听 → 小运行时的监听（不用 `useEffect`）。

为什么这么写：`useSyncExternalStore` 的订阅函数要定义在组件外、快照没变必须返回同一个值、快照必须不可变——这三条官方都写了（已核对），所以状态放在组件外、列表整份换新正好满足。和现在的 `useRef`＋`lcRefresh()` 比：效果一样，但这是官方正路，严格模式和并发渲染下更有保障（“更有保障”是我的推断，**没跑**）。

**页面级状态放在组件外面有一个后果**：同一个页面组件在一个应用里出现两次，会共用一份状态。页面本来只出现一次，没问题；**组件**不能这么放，组件的状态必须每个实例一份（第 5 节）。

### 4.7 页面文档要加的字段（只加不改）

```
节点（LcNode）新增，全部可缺省：
  binds:    { "text": <式子>, "src": <式子>, … }          文字和属性
  showIf:   <是否式子>                                     显示条件
  renderIf: <是否式子>                                     存在条件

  variables 每项多一个可选 "kind": "state"（缺省）| "derived"，derived 带 "expr"；"type" 放开成完整类型写法
```

## 5. 决定四：组件

### 5.1 模型（给全；界面怎么编辑交给 E）

```
组件定义
  编号、名字、图标、说明
  属性[]      名字、类型（完整类型系统）、默认值、必填？            ← 现在只有名字＋四种类型＋默认值
  双向属性[]  名字、类型                                           ← “值”这类：外面给进来，里面也能改
  事件[]      名字、参数[]（名字、类型）                           ← 新
  插槽[]      名字（“默认”或自己起）、带出去的数据[]（名字、类型）、没人填时的备用内容（一棵节点树）   ← 新
  状态[] / 派生[]                                                  ← 新，每个实例一份
  逻辑        帽子（控件事件、生命周期、当…变了、当属性变了）、函数（“方法”）   ← 新，用同一套语言核心
  公开方法[]  哪几个函数允许外面调                                  ← 新，第二批
  根          一棵节点树（节点上可以有第 4 节的各种绑定；绑定的式子里能读属性、状态、派生）
  样式隔离    开（默认）/ 关

组件实例（页面或别的组件里的一个节点，type = component）
  属性值      每个属性：写死的值，或一个式子（绑定）
  双向        每个双向属性：接到外面的哪个状态
  事件处理    外面的帽子：当 [这个实例] 发出 [事件名] (参数…) { … }
  插槽内容    每个插槽名下一组子节点；带数据的插槽里，这些子节点的绑定可以读“带出来的数据”
```

组件里的积木（只在组件定义里能用，靠位置约束限制）：

| 积木 | 说明 |
| --- | --- |
| `(属性 标题)` | 读属性。**属性只读**，不许改（数据从上往下） |
| `[发出 [事件名] (参数…)]` | 往外发事件（消息从下往上） |
| `(双向 值)`、`[把 双向 值 设为 (…)]` | 双向属性；写＝通知外面改 |
| `当放上页面以后 { … }`、`当拿走之前 { … }` | 生命周期 |
| `当 (属性 x) 变了 (新值) (旧值) { … }` | 就是“当…变了”，不另造 |
| 状态、派生的那一套 | 同第 4 节，但每个实例一份 |

### 5.2 三种产物的对应

**以下对应里，Vue 的 `defineProps` 以外的各项、React 的 `children` / 把函数当属性传，官方页都未核对（只见第三方转述）；三种产物都没编译、没运行。**

| 模型里的东西 | 普通网页 | Vue 3 | React |
| --- | --- | --- | --- |
| 组件本身 | 一个工厂函数 `lcComp_名字(根元素, 属性, 插槽, 发出)`，每个实例调一次；HTML 里组件的结构放进 `<template>` | 一个 `.vue` 文件 | 一个函数组件 |
| 属性 | 传进来的是“取值函数”，这样外面变了里面跟着变 | `defineProps({ 名: { type, default } })` | 函数的参数 |
| 事件 | 属性里的回调函数 | `defineEmits([…])`＋`emit("名", 参数)`；外面 `@名` | 名字叫 `on名` 的回调属性 |
| 双向属性 | 一对：取值函数＋回调 | `defineModel()`（3.4 起）；或 `modelValue` 属性＋`update:modelValue` 事件 | `value`＋`onChange` 一对属性 |
| 默认插槽 | 工厂把外面给的那段节点插到标记处 | `<slot />` | `props.children` |
| 具名插槽 | 同上，按名字 | `<slot name="头" />`；外面 `<template #头>` | 一个名字叫“头”的属性，值是一段 JSX |
| 带数据的插槽 | 外面给的是“拿到数据后造节点”的函数 | `<slot :项="it" />`；外面 `<template #default="{ 项 }">` | 一个函数属性：`渲染项={(it) => <…/>}` |
| 状态 | 工厂函数里的局部状态（小运行时） | `ref` | **每个实例一个小仓库**：`useState(() => 新建仓库())[0]`（保证只建一次）＋`useSyncExternalStore` |
| 方法 | 工厂里的函数 | `<script setup>` 里的函数 | 组件函数里的函数 |
| 公开方法（外面调里面） | 工厂返回的对象 | `defineExpose` | `useImperativeHandle` |
| 创建时 | 工厂函数体 | `<script setup>` 的顶层代码 | 建小仓库的那一刻 |
| 放上页面以后 | 插进文档以后 | `onMounted` | `useEffect(() => { …; return 收尾; }, [])` |
| 拿走之前 | 被“存在条件”或“重复”拿走时，宿主负责叫 | `onBeforeUnmount` | 上面那个 `useEffect` 返回的收尾函数 |
| 更新以后 | **不提供** | （`onUpdated`） | （不带依赖的 `useEffect`） |
| 样式隔离 | 类名带组件编号前缀 | `<style scoped>`（现在已经在用） | 类名带组件编号前缀（不用 CSS Modules，那要打包工具配合） |

三个要解释的决定：

1. **不给“更新以后”**。三家差太多：Vue 是“这个组件的界面因为状态变化更新完以后”，React 是“每次重画提交以后”，普通网页根本没有“组件更新”这回事。而它的正当用途几乎都能用“当 (某个状态) 变了”更准确地表达。少一个容易写出死循环的口子。（文末拍板 ③）
2. **“放上以后”做的事必须能收尾**。React 严格模式在开发时会故意多跑一轮“开 → 收 → 开”来查漏（react.dev 已核对）。所以规矩是：在组件里登记的监听、定时器、窗口事件、请求，**宿主自动记账，拿走时自动收**（GAP-D-9）。用户不用写收尾，也就不会漏。这条对三种产物都有好处：普通网页里“重复”拿掉一项时同样要收。
3. **Vue 的插槽内容在外面那个组件的作用域里求值，而且里面组件的 `scoped` 样式管不到插槽内容**（vuejs.org 已核对）。我们的模型照这个定：插槽内容里的绑定读的是**外面**的状态（加上插槽带出来的数据），样式归外面。另两种产物照此实现。

### 5.3 和现有 `component_model` 的差距与迁移

| 现在 | 目标 | 迁移 |
| --- | --- | --- |
| 属性类型 4 种（文字、数字、颜色、是否） | 完整类型系统 | 旧的四种原样有效；“颜色”＝文字类型＋“用取色器编辑”的提示 |
| 没有事件、插槽、状态、逻辑 | 都有 | 新字段缺省为空，旧组件读出来就是“一个只有属性的组件”，行为不变 |
| 定义里的控件被积木引用就不让存成组件（`component_ops.dart` 297–306） | 允许；那些积木跟着搬进组件的逻辑里 | “存成组件”时：只引用组件内部控件和内部状态的帽子 → 搬进去；引用了外面变量的 → 提示“这几块用到了页面的东西，要先改成属性或事件”，不自动猜 |
| 普通网页导出时把实例展开成普通控件（`expandedTree`） | 工厂函数＋`<template>` | **没有逻辑、没有插槽、没有状态的旧组件继续走展开**（导出结果逐字不变）；用了新功能的才走工厂 |
| 节点上的 `bind` 只能把 5 种属性接到组件属性 | 第 4 节的通用绑定 | 旧 `bind` 读成新绑定的简写（4.7） |
| 嵌套最多 8 层 | 不变 | — |
| 组件不能放进“重复”里各带各的状态 | 能 | 靠“每个实例一份状态”，无迁移问题 |

还缺的两样（记为缺口）：**动态选组件**（“路由出口”要按名字决定显示哪个组件，GAP-D-17）；**组件库的打包**（组件随库发布，归 C 的库格式，我这边只要求库清单里“组件”一栏能带上本节的完整定义）。

## 6. 决定五：和语言核心的关系

### 6.1 直接复用的

| 语言核心里的 | 前端怎么用 | 现在做没做 |
| --- | --- | --- |
| 值（数字、文字、是否、空、列表、字典）和字面量 | 原样 | 第 1 阶段，已做 |
| 局部变量、赋值 | 原样。**页面变量不再是“模块变量”，是“状态”**（6.2 第 2 条） | 已做 |
| 运算、比较、逻辑 | 新积木原样用；旧积木保留旧规矩（6.3） | 已做 |
| 如果、重复、当…时重复、逐项、跳出 | 原样 | 已做 |
| 函数、匿名函数、闭包、“我的积木” | 原样。事件帽子的回调就是一个匿名函数 | 第 2 阶段，已做（只接了后端页） |
| 列表、字典的小库函数（映射、过滤、累计、排序……） | 原样。状态里的列表配“只读”规矩（4.3） | 已做 |
| 类、接口 | 原样（库里用得多：路由器、仓库都是类） | **没做**（第 5 阶段） |
| 错误（抛、试试看） | 原样；再加“没人接的错误”的去处（3.1） | **没做** |
| 异步（等、开始做、同时做、过…以后做） | 原样，但规矩有浏览器特有的补充（6.2 第 1 条） | **没做**（第 6 阶段） |
| 模块 | 原样，但拼装方式三种产物各不同（6.4） | **没做** |
| 原生绑定 | 整个前端的地基 | **没做**（第 3 阶段） |
| 校验规则机制、积木编辑器、读法文字 | 原样 | 已做 |

结论：**设计上能复用九成以上；实现上，前端真正要用的后五样一样都还没做。** 所以前端这条线排不到最前面，必须等原生绑定（第 3 阶段）和异步至少做出来。

### 6.2 浏览器里不一样的 / 要新增的

1. **异步是“不等它”的事件模型。**
   - 后端：一个请求进来，一串积木从头跑到尾，“等”就是停下来等，没有别人插队的问题。
   - 浏览器：一顶帽子里“等”的时候，**别的帽子照常能跑**，而且**同一顶帽子可能再被触发一次**。状态是大家共用的，“等”回来以后状态可能已经被别人改了。
   - 所以要补四条规矩：①帽子的回调自动当成异步函数（用户不标），出的错统一交给“当页面出错时”；②`阻止默认行为()` 必须在第一个“等”之前，之后放＝校验错误；③帽子可选“同一个事件又来了怎么办”（默认照常再开）；④组件被拿走以后，它里面还在“等”的积木回来时**不再往下做**（靠取消令牌，GAP-D-6）。
   - 旧积木“等一会儿”是“只管里面的、后面不等”，它对应核心的 `[过…以后做 { }]`，不是 `[等 毫秒]`。两个都保留，名字和样子要能一眼分清。
2. **没有“每次请求一份变量”。** 后端的模块变量是进程级的格子、要考虑并发（C 的 `store.update`）；页面只有一条线，没有并发写的问题，但有“界面要跟着变”的问题。所以页面的“模块级变量”一律是**状态**；不想让界面跟着变的，用局部变量或者“我的积木”里的变量。
3. **需要一个“浏览器 JS”生成目标**（GAP-D-1）。现在唯一的 JS 生成器 `gen_node.dart` 开头就是 `require("./lc_lang.js")`，还用 `lc.fn / lc.call` 包函数值。浏览器目标要：不用 `require`；小库内联或者用 ES 模块导入；没有 `process`、`Buffer`。式子、语句、函数的翻译可以和 Node 目标共用，只是“文件怎么包、小库怎么来、宿主接口怎么叫”不同。
4. **“宿主”要多一维**（GAP-D-2）。C 的原生绑定按语言给实现（`node`、`python`、`browser`……）。甲类接口需要的是：同为浏览器 JS，再分 `browser`（普通网页）、`browser-vue`、`browser-react` 三份。乙类只要 `browser` 一份，另两种自动沿用。
5. **帽子要有“登记时机”和“归谁管”**（GAP-D-3、9）。后端的帽子在启动时登记一次、永不取消。前端的帽子：页面里的在页面启动时登记；组件里的在每个实例放上页面时登记、拿走时自动取消；“重复”里面的每一份各登记各的。
6. **绑定的式子是“没有副作用的式子”**，需要语言核心能判断一个式子纯不纯（C 的原生绑定声明里已经有 `pure` 字段，够用；用户写的函数要靠推断：函数体里没有写状态、没有调不纯的东西）。

### 6.3 新旧“转数字 / 转文字”不一致（跑过）

页面逻辑的小工具（`lcNum`、`lcText`）和语言核心的小库（`toNum`、`fmtNum`，在 `lib/backend/runtime_node.dart` 36–53 行）规矩不同。我把两边的函数原样抄进一个脚本对比（`/tmp/v5-D/cmp.js`、`/tmp/v5-D/diff2.js`，`node` 直接跑，2026-11-25）：

| 输入 | 页面（旧） | 语言核心（新） |
| --- | --- | --- |
| 转数字 `"0x10"` | 16 | 0 |
| 转数字 `"0b11"` | 3 | 0 |
| 转数字 `"0o17"` | 15 | 0 |
| 转数字 不换行空格＋`5` | 5 | 0 |
| 转数字 全角空格＋`5` | 5 | 0 |
| 转数字 换页符＋`5` | 5 | 0 |
| 转文字 `1e21` | `1e+21` | `1e21` |
| 转文字 `1e-7` | `1e-7` | `0.0000001` |
| 转文字 `123456789012345680` | `123456789012000000` | `1.23456789012e17` |
| 转文字 `2 的 53 次方` | `9007199254740000` | `9.00719925474e15` |
| 转文字 `1500000000000000` | `1500000000000000` | `1.5e15` |
| 重复 `"2.5"` 次 | 3 遍 | 2 遍（核心的 `times` 先去掉小数，`runtime_node.dart` 179–181 行） |

一样的：`"5"`、`" 5 "`、`"1e3"`、空文字、`"abc"`、`"5."`、`".5"`、`"+5"`、`"12abc"`、`"Infinity"`、`"1_000"`、是 / 否、空；`0.1+0.2` 都写成 `0.3`；`1/3` 都是 `0.333333333333`；`1e-8` 都是 `1e-8`。

另外看代码看出来的不同（没逐条跑）：页面的“等于”是“类型一样直接比，不一样都转成文字再比”（`logic_js_core.dart` `lcEq`）；核心的 `eq` 规矩在 `runtime_node.dart` 106 行，我没逐条对。页面“设变量”会按变量声明的类型转一下；页面“打印”不转文字，直接把值交给 `console.log`。

**决定**：
- 旧积木（旧文档里的 `bin`、`join`、`repeat`、`setVar`……）继续用旧规矩，实现就是把 `lcNum / lcText / lcEq` 这三个函数原样留在“页面”库里当兼容函数。**行为逐字不变。**
- 新拖出来的积木一律是语言核心的，用核心规矩。前后端从此一致。
- 积木盒里只放新的。旧文档里的旧积木照常显示、照常能改参数，角上不加任何标记（对用户来说它们没坏）；提供一个“换成新版积木”的菜单项，换之前说明上表这些边角差别。
- 不建议“悄悄统一成核心规矩”：差别都在边角，但“重复 2.5 次从 3 遍变 2 遍”这种是看得见的。

### 6.4 模块怎么拼进产物

| 产物 | 拼法 |
| --- | --- |
| 普通网页 | **仍然只有一个 `logic.js`**，HTML 里仍然只有那一句 `<script>`。里面依次是：小库（只带用到的函数）→ 小运行时（用到状态绑定才带）→ 用到的库的模块（各包在自己的函数作用域里，第 4 版 3.8 已定）→ 组件工厂 → 页面自己的模块 → 启动。不拆多文件的理由：拆了就要在 HTML 里按顺序多写几句 `<script>`，或者用 ES 模块（手机上用 `file://` 直接打开时 ES 模块会被拦——**未核对**，要真机验） |
| Vue | 页面和每个组件各一个 `.vue`；库的模块各一个 `.js`（ES 模块，`export`）；小库一个 `lc-lang.js`。`.vue` 里 `import` 它们 |
| React | 页面和每个组件各一个 `.jsx`；其余同 Vue，外加小运行时 `lc-rx.js` |

小库现在的文字放在 `lib/backend/runtime_node*.dart`，是给 Node 写的一整份。前端要的是“同样的函数、不带 Node 的出口、能只取用到的那几个”（GAP-D-11）。

### 6.5 JavaScript 专属的东西怎么办

原则：**用户要的是“做成这件事”，不是“用上这个语法”**。一个 JS 特性，如果语言核心里已经有同样用途的积木，就不单独暴露；如果是生成器写代码时用得上的，生成器自己用；真有独特用途的进“JS 专属库”（特性四级里的 ②，只在目标是 JS 时出现）；其余不做。

| JS 的东西 | 处理 | 理由 |
| --- | --- | --- |
| 原型链 | 不做 | 类已经够用；生成的代码用 `class` |
| `this` 的各种绑定规矩 | 不暴露 | 生成器一律用箭头函数和类方法，用户永远碰不到“this 丢了” |
| `var`、提升、`==`、`with`、`eval`、标签语句 | 不做、不生成 | 都是坑；生成器只用 `let / const / ===` |
| 解构、展开、可选链、空值合并、模板字符串 | 生成器内部用 | 用户侧对应的是“取字段”“连起来”“安全取（可空类型）”“没有就用” |
| 闭包、高阶函数 | 核心已有 | |
| Promise、async / await | 核心的“等 / 开始做 / 同时做” | 不暴露 Promise 对象本身 |
| 迭代器协议、`for…of` | 生成器内部用 | 核心的“逐项”就翻成它 |
| 生成器函数（`function*`）、异步迭代 | 不做 | 用途窄；真要用走原生片段 |
| Symbol | 不做 | 没有积木层面的用途 |
| Proxy、Reflect | 不做 | 状态模型不依赖它（我们的状态是显式的格子） |
| getter / setter | 归“类”的设计（“算出来的属性”），不是 JS 专属 | 交给负责类的同事 |
| Map、Set | 核心若有“集合”类型就对上；字典继续用普通对象 | 归 A / B |
| WeakMap、WeakRef | 不做 | 内存管理细节，积木层不该操心 |
| 类型化数组、ArrayBuffer、Blob、File | JS 专属库，第二批 | 画布、文件上传、二进制请求才用；依赖“字节串”类型（C 的 GAP-C-9） |
| BigInt | 不做 | 除非类型系统把“整数”单独分出来 |
| 正则 | 归标准库（各语言正则不一样，要定一个公共子集），不是 JS 专属 | 表单校验要用（GAP-D-14） |
| Date、Intl | 时间归标准库；本地化格式走国际化库的原生绑定 | |
| JSON、百分号编码、URL 拆解 | 标准库（纯计算，按 C 的判定） | |
| `structuredClone`（深拷贝）、深比较 | 标准库 | 状态的“抄一份再改”要用（GAP-D-13） |
| 动态 `import()` | 不做（第一轮） | 要打包工具配合 |
| 直接碰任意 JS 对象 | JS 专属库 4 块，默认关（2.6） | 兜底 |

### 6.6 Node 和浏览器怎么分

```
            ┌─────────────── JS 通用（一份）───────────────┐
            │ 语言核心的 JS 翻译（式子、语句、函数、类…）   │
            │ 标准库的 JS 实现（值的规矩、文字、列表、JSON…）│
            │ 通用宿主接口里两边都有的：打印、时间、随机、   │
            │   定时、网络请求（两边都有全局 fetch）        │
            └───────────────────────────────────────────────┘
   ┌──── Node 专属 ────┐                  ┌──── 浏览器专属 ────┐
   │ 开 HTTP 服务       │                  │ 页面宿主 9 个（×3） │
   │ 文件、环境变量     │                  │ 存储、地址与历史    │
   │ 进程级格子（并发） │                  │ 对话框、窗口事件    │
   │ CommonJS 出口      │                  │ 下一帧              │
   └────────────────────┘                  │ 单文件 / ES 模块出口│
                                           └─────────────────────┘
```

“两边都有全局 `fetch`”：本机 Node 24 确实有（上面 2.3 跑过）；Node 从哪个版本开始有，**未核对**。注意第 4 版 6.3 已经指出“前后端同名的请求积木行为不同”——新的 `网络.请求` 两边语义定成一样（只有网络层失败才出错），旧积木各自保留旧行为。

## 7. 决定六：现有页面积木迁到“页面”库

### 7.1 逐个对照（行为必须不变）

**语句 10 种**

| 旧 op | 现在翻成什么 | 新模型里是什么 | 行为怎么保住 |
| --- | --- | --- | --- |
| `setVar` 设变量 | `state.x = 按变量类型转(值)` | 页面库 `[把 状态 x 设为 …]`（兼容版：先按声明类型用旧规矩转） | 兼容版保留“按类型转”；新版靠类型检查，不转 |
| `changeVar` 变量增加 | `state.x = state.x + lcNum(值)`；变量不是数字就跳过 | 页面库 `[把 状态 x 增加 …]`（兼容版用 `lcNum`） | 同上 |
| `setProp` 改控件属性 | `lcSet(控件, 属性, 值)` | 页面库 `[把 [控件] 的 [属性] 设为 …]` → 宿主接口 `界面.写` | 实现就是现在三个 `JsTarget` 的 `writeProp` |
| `if` 如果 | `if (…) { } else { }` | 语言核心的“如果” | 条件的“算不算成立”用旧规矩的兼容函数 |
| `repeat` 重复 | `for`，次数＝`min(lcNum(n), 10000)` | 页面库“重复（旧）”＝展开成核心的循环，次数算法照旧 | 见 6.3：不能直接换成核心的“重复”，小数次数会差一遍 |
| `wait` 等一会儿 | `setTimeout(里面的, max(0, 毫秒))`，后面不等 | 语言核心 `[过 … 以后做 { }]` | 语义本来就一样（第 4 版 6.3 已对上） |
| `alert` 弹提示 | `alert(lcText(值))` | 页面库 `[弹提示 …]` → `页面.弹提示` | 转文字用旧规矩 |
| `navigate` 去网址 | `location.href = …` | 页面库 `[去网址 …]` → `地址.整页跳转` | — |
| `log` 打印 | `console.log(值)`，不转文字 | 通用“打印”（兼容版：原值直接交出去） | 核心的“打印”如果会先转文字，这里就得留兼容版 |
| `fetch` 请求网址 | `fetch(…).then(成功, 失败)`；非 2xx 当失败；正文按文字读；后面不等 | 页面库“请求网址（旧）”＝一个库里定义的积木：`开始做 { 试试看 { 回应 ← 等 网络.请求; 不成功就出错 } 如果出错 { 失败那串; 结束 }; 存进变量; 成功那串 }` | 注意旧写法里“成功那串”自己出的错**不会**进“失败那串”——所以成功那串要放在“试试看”外面，如上 |

**值 9 种**

| 旧 kind | 新模型里是什么 | 备注 |
| --- | --- | --- |
| `text`、`num`、`bool` | 语言核心的字面量 | — |
| `var` | `(状态 x)` | 页面变量＝状态 |
| `prop` | 页面库 `([控件] 的 [属性])` → `界面.读` | — |
| `event` | 帽子上的参数小块“事件的值” | 第 4 版 6.3 已定；实现照旧 `lcEventValue` |
| `bin` | 页面库的兼容运算（算术先 `lcNum`、除和余再收一次；比较；等于用 `lcEq`；并且 / 或者） | 不能直接换成核心运算（6.3） |
| `not` | 核心“不成立” | JS 的 `!`，规矩和旧的一样 |

三种事件：`click`、`input` → `当 [控件] 被点击 / 输入时`（`界面.当事件`）；`load` → `当页面放上以后`（`界面.生命周期`）。

### 7.2 旧 `page.lc.json` 怎么照常打开

- 文件里的 op 名、kind 名、参数名**一个都不改**。“页面”内置库带一张“旧名对照表”（C 的第 12 条已经定了这个机制），读到 `setProp` 就知道它是页面库里的哪块积木。
- 变量的 `type` 还是那三个词，读出来就是对应的类型；没有 `kind` 字段的就是状态。
- 存回去时：没动过的旧积木原样写回（不改名、不加字段）；用了新功能才升到第 3 版。这样旧版应用打开“只用旧功能的文档”不受影响。
- 坏数据的处理照现在的规矩：逐条跳过，不崩。

### 7.3 三种 `JsTarget` 怎么变成“页面宿主的三份实现”

| 现在 `JsTarget` 的方法 | 变成 |
| --- | --- |
| `readVar` / `writeVar` | `状态.读` / `状态.写` 的三份实现 |
| `readProp` / `writeProp` | `界面.读` / `界面.写` 的三份实现 |
| `eventValue` | 事件记录的“值”字段的三份取法 |
| （各导出器里零散写的）挂事件、页面加载 | `界面.当事件`、`界面.生命周期` 的三份实现 |
| `LcPropStates` 登记簿 | 留着：它回答“哪些控件属性被旧积木直接读写了、所以在 Vue / React 里要有个状态接着” |

也就是说：三个子类里的代码大部分**原样搬家**，从“翻译器的插件”变成“宿主接口的实现”。新增的只是状态的派生 / 监听和各种绑定的翻译。

### 7.4 `logic.js` 的结构变化

```
现在                                   以后（用了新功能的页面）
──────────────────────────             ──────────────────────────────────────────
文件头注释                             文件头注释
const state = {…}                      小库（只带用到的函数；旧积木用到的 lcNum 等也在这）
小工具 lcNum / lcText / lcEq / …       小运行时（有状态绑定才带）

等文档就绪 → lcStart()                 帽子（有名字的函数，名字规则不变）
                                       绑定

```

启动顺序照 C 的“库的三个时刻”（C 的 7.7）。

**稳妥的过渡办法**（建议）：第一步**不动旧生成器**。文档里只有旧积木、没有任何新功能时，继续走现在的 `exportLogicJs`，产物逐字不变，现有 1082 行测试原样全过。文档用到任何新东西才走新生成器。等新生成器写好以后，拿现有测试里的所有旧文档做“两条路对比”：同一份文档两边各生成一份，在 Node 的假页面里跑同一串事件，比较留下的痕迹（改了哪些属性、弹了什么、请求了什么）。全部一致、再加真机抽查过了，才把旧路撤掉。

### 7.5 “没写逻辑的页面导出逐字不变”

现在的判断是“逻辑为空 → `exportLogicJs` 返回空串 → 不加 `<script>`”（`logic_js.dart` 124 行、`export_html.dart` 97–99 行）。新规矩把“逻辑为空”的定义写全：

> 没有任何帽子、没有任何状态和派生、没有任何节点带绑定、没有用到任何带逻辑 / 状态 / 插槽的组件、没有“用上”任何有 init / start 的库 → 不产 `logic.js`、HTML 里不加 `<script>`、组件照旧展开。

有一个容易漏的：用户“用上”了一个库但一块积木都没拖——如果那个库有“启动时要做的事”，页面就不再是“没逻辑”了。建议：**库只有在至少一块积木被用到时才参与生成**，否则当它不存在。守这条的测试就是现有的 `lowcode_logic_export_test.dart` 第一组，再补“声明了状态但没用到”“用上库但没拖积木”两例。

## 8. 决定七：前端的库

### 8.1 建议内置的 10 个

| 库 | 公开的积木（主要的） | 底下用到 | 批次 |
| --- | --- | --- | --- |
| **页面**（基础，默认用上） | 状态 / 派生 / 当…变了；当控件事件；当页面放上以后 / 出错时；弹提示、问一句、去网址；旧积木的兼容版；（二批）获得焦点、滚到、量大小 | 甲类 9 个；`页面.弹提示 / 问一句`；`地址.整页跳转` | 一 |
| **定时** | 过…以后做、每隔…做、取消；防抖、节流；让界面先更新一下 | `定时.*` 4 个 | 一 |
| **请求** | 请求（方法、网址、头、正文、超时）；取 JSON；`加载`（带“正在加载 / 出错了 / 数据”）；重试；记住几秒 | `网络.*` 3 个；状态接口；标准库 JSON | 一 |
| **本地保存** | 读本地（没有就用…）、存本地、删、清空；“这个状态关掉再开还在” | `存储.*` 4 个；JSON | 一 |
| **状态仓库** | 新建仓库、读、改、订阅、动作；可选持久化 | 状态接口；本地保存库 | 一 |

| **路由** | 路由表、去、换、后退、当前路径 / 参数；“路由出口”组件 | `地址.*` 5 个；状态接口；动态选组件 | 二 |
| **表单校验** | 规则（必填、长度、范围、像邮箱、自己写条件）；校验一格、校验全部；每格的错误文字（派生） | 无原生接口；标准库文字 / 正则 | 二 |
| **动画** | 在…毫秒内把状态变到…；缓动方式；停 | `定时.下一帧`；状态接口 | 二 |
| **国际化** | 语言表、文案（带占位）、换语言；数字 / 日期 / 货币的本地写法 | 状态接口；`Intl` 的原生绑定（未核对） | 二 |

“列表渲染助手”不单独成库：差量更新由宿主做；排序、过滤、分页是标准库的列表函数配派生值。

### 8.2 用户怎么写前端库

和写后端库是同一件事（C 的库格式），前端多三样：

1. 库的 `hosts` 写 `browser`。
2. 库里可以有**库级状态**（整个页面只有一份，比如“当前路由”）和**组件**（第 5 节的完整定义）。
3. 帽子型积木登记的东西**自动记账**：在页面里用，页面关掉时收；在组件里用，组件拿走时收。写库的人只要保证“登记”返回一个取消函数。

用户库**默认只能用积木**在内置库之上封装；要直接碰浏览器对象，得打开库设置里的“允许手写代码”（C 的第 8 条），用 JS 专属库的 4 块或者写原生绑定。

- 类要带泛型参数（`仓库‹T›`），方法也要带（`取‹R›`）——类型系统必须支持。
- `只读‹T›` 这个类型修饰（GAP-D-8）。

- 回调口带两个参数（新、旧）（GAP-D-4）。

- `组件名` 这种类型——“一个指向组件的值”（GAP-D-21 的同类）。
- **库级状态、库级设置、init / start**：C 的 7.6、7.7 已经有“设置项”和“三个时刻”，够用；“库级状态”要补一句：在浏览器里它是状态，不是进程级格子（GAP-D-15）。
- **声明积木**（`路由 "…" 显示 …`）：长得像帽子但没有口，只是启动时登记一条——C 的“一个定义多个外观”能做，但要允许“没有口的帽子”（GAP-D-3）。
- 详情页“等请求回来时已经换了页面”：回来以后往一个已经被拿走的组件里写状态。要靠“组件拿走以后，里面等着的积木不再往下做”（GAP-D-6）。
- 假宿主要会模拟地址栏：加一条历史**不**触发事件、走几步**要**触发事件——假得不对，用例过了也没用。所以假宿主本身也要有一份“它像不像真的”清单，真机上对一遍（第 9 节）。
- “匹配”模块是纯计算，前后端都用得上（C 的示例库 `demo/mini-router` 做的也是这件事）。建议路径匹配抽成一个 `hosts: any` 的公共小库，前后端的路由库都依赖它，不要两份。

### 8.5 这两个库我实际验证了什么

没有“读库、生成代码”的程序，所以积木系统这一层**没法验**。我做的是：把 8.3、8.4 的伪代码**手工改写成 JavaScript**，接上附录 A 的小运行时，配一个假存储和一个假地址栏（加一条历史不触发事件、走几步过后触发事件），在 Node 24 里跑库的用例。脚本 `/tmp/v5-D/libs.js`，命令 `node libs.js`，2026-11-25。16 项：

- 仓库 6 项全过：改了读到新值；改完那一刻还没存盘（监听是攒着的）；关掉再开还在；存的东西形状不对就用初值；取出来的派生值；派生值跟着变。
- 匹配 5 项：带参数、段数不同、中文和空格、根路径 4 项过；第 5 项是我特意加的坏输入（`/s/%E4%ZZ`）。
- 路由 5 项全过：一开始是首页；去了以后页面跟着变、参数对；后退的那一刻还没变；过一拍以后回到详情；没对上时页面是空。

**验证中发现的问题（1 个，已当场改）**：坏的百分号编码会让“解百分号编码”直接出错（JS 里是 `URIError`），而我第一版伪代码没接——用户手改地址栏就能让页面的路由整个坏掉。已在 8.4 的“匹配”里补上“试试看 → 当成没对上”。这也顺带说明一条设计要求：**标准库里“会出错的纯计算函数”必须在积木上看得出它会出错**（C 的原生绑定声明里有 `fails` 字段，积木外观上也要体现）。

**这次验证不说明什么**：手工改写的 JS 不是生成器生成的；假地址栏是我按 MDN 的描述造的，没和真浏览器对过；“路由出口”组件和动态组件完全没验。

### 9.1 四层，从便宜到贵

| 层 | 在哪跑 | 能验什么 | 验不了什么 | 现在有没有 |

### 9.2 假宿主够不够

**够**的（而且应该多用，因为快、稳、不挑机器）：翻译对不对、帽子接没接上、状态和绑定的语义、库的逻辑、旧新两条路的对比、坏数据不崩。

**不够**的，逐条：

| 假的测不出来的 | 为什么 | 用哪层补 |
| --- | --- | --- |
| 事件冒泡、默认行为（点链接会跳、表单会提交、回车会提交） | 假页面的事件是手动触发的，没有传播 | ③ |

| 前进后退、刷新后地址还在不在、井号方式和路径方式的差别 | 假地址栏是按我理解造的 | ③＋真机 |

3. 每个内置库：库自带用例在假宿主里跑（像 8.5 那样，但由生成器生成而不是手工改写）。
4. 应用内自检页（第 ③ 层）：甲类 9 个接口、乙类 20 个接口，各一组断言；假宿主的“像不像”清单也在这里跑。
5. Vue / React：如果霜霜同意装（文末拍板 ①），同一份文档三种产物各起一个页面，用同一份操作脚本点一遍，比较最后页面上的文字。不同意装，就只能如实写“未编译”，并且在导出页面上继续挂着那句提醒。

## 10. 缺口

为了做到上面这些，各层还缺的东西。编号 GAP-D-n；“影响”写的是影响哪一层；最要紧的打了 ★。

### 10.1 语言核心（L1）

| 编号 | 缺什么 | 影响 | 建议怎么补 |
| --- | --- | --- | --- |
| ★ GAP-D-1 | **没有“浏览器 JS”生成目标**。唯一的 JS 生成器是 Node 写法（`require`） | L1 生成器 | JS 生成器拆成“翻译”（共用）和“出口”（Node / 普通网页单文件 / ES 模块）两半 |
| ★ GAP-D-2 | **原生绑定还没实现**（第 3 阶段），而且只按语言分实现；甲类接口要按“语言 × 宿主”分（普通网页 / Vue / React） | L1、L3 | 实现键从 `browser` 扩成 `browser`、`browser-vue`、`browser-react`；后两个缺省沿用 `browser` |
| ★ GAP-D-3 | **帽子型积木的登记**：登记时机（页面启动 / 组件放上 / “重复”的每一份）、返回取消函数、没有口的“声明积木” | L1、L3 | 帽子＝“启动时调一个登记函数，回调口是它的一个参数”；登记函数必须返回取消函数；允许口为空 |
| GAP-D-4 | **回调口带多个参数、带类型、带返回值**（“新值、旧值”；校验函数返回是否；标识函数返回文字） | L1、类型 | 口的声明里写参数表和返回类型；口里出现对应的参数小块 |
| ★ GAP-D-5 | **事件回调里的异步规矩**：自动当异步；没人接的错去哪；`阻止默认行为()` 必须在第一个“等”之前；同一事件又来了怎么办 | L1、校验 | 6.2 第 1 条的四条规矩；校验加一条“等之后不能阻止默认行为” |
| GAP-D-6 | **异步没有“取消”**：请求要能中止；组件拿走以后里面等着的积木不该接着做；防抖要取消上一次 | L1 | “开始做”返回的“稍后的结果”可以被取消；每个帽子的这一次运行带一个隐含的取消令牌，归属的组件拿走时自动取消 |
| ★ GAP-D-7 | **状态里的列表原地改，界面不知道**，而且三种产物表现不一样 | L1、类型、校验 | 读状态得到“只读”的值；原地改的积木不接受只读值；另给“不改原件”的一组（见 10） |

### 和“设计骨架”不一致、需要改骨架的地方

1. **骨架第 1 条（四层）成立，但 L0 要补一维**：“宿主”不只是“浏览器 / Node”，同是浏览器 JS 还分普通网页 / Vue / React。建议骨架写明：L0 接口的实现按“语言 × 宿主变体”给；只有“归框架管的界面”那 9 个接口需要变体，其余一份。
2. **骨架里“JS（浏览器、Node 分开）”要落到生成器上**：现在只有 Node 一个 JS 生成器。建议骨架写明：JS 的“翻译”一份，“出口”三种（CommonJS、单文件、ES 模块）。
3. **第 4 版 6.1 的页面宿主 6 个接口（`dom.find / get / set / on`、`page.onLoad / alert / go`）不够也不准**：`dom.find` 在 Vue / React 里没有意义（控件引用是编译时就定下的，不是运行时去找）；缺状态、派生、监听、生命周期的“拿走之前”。建议换成 2.2 的 9 个；`alert`、`go` 归乙类。
4. **第 4 版 7.2 的计数器例子（“类 组件：状态、画法、根；改状态就重画”）是 c 路线**，和本文选的 b 不一致。建议那个例子改写成“状态＋绑定”的样子。
5. **和 C 的出入**（要协调者定）：C 摘要第 9 条把“7 个通用碰 JS 对象接口”当浏览器的最小集；我建议它只做兜底（JS 专属库、默认关），主干用有名字、有类型的原生绑定。理由见 2.6。
6. **和 E 的两处小出入**（E 的第 7.1 节写明“等 D 的设计来对齐”）：①E 只有一种“显示条件”（为否时不画）；我分成“显示条件”（还在，看不见）和“存在条件”（真的没有）两种，因为对输入框里的内容、组件的状态、生命周期意义不同。②E 的“重复”里标识是可选的；我建议必填、缺省“第几项”并出警告。其余（属性三种来源、默认单向、输入类双向、重复里能用“这一项”“第几个”）一致。
7. **C 的示例库 `demo/mini-router` 和我的路由库都有“路径匹配”**：建议抽成一个前后端共用的纯计算小库。
