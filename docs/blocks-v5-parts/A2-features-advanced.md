# A2 语言特性穷举表（后半）：类、模块、错误、并发、迭代、解构、元编程、内存

## 0. 结论摘要

1. **数量**：8 类一共列了 **199 条**（类 56、模块 22、错误 27、并发 27、迭代 18、解构 16、元编程 16、内存 17）。分级：①核心 99、②宿主专属 8、③原生片段 5、④不做 87。
2. **①的 99 条里，现在真能出代码的只有 20 条**；语法树有节点但生成器没做 27 条（类、错误、异步三块全在这里）；只在 v4 设计稿里有 12 条；**完全没有 40 条**（GAP-A2-1 到 40，见第 11 节）。
3. 已实现的 20 条几乎都是第 1、2 阶段顺带有的规则（遍历、常量、复制、小库）。这半边等于还没开工。
4. **类模型**：单继承＋多接口够用（6 门里只有 Python 有多继承）。访问控制建议两档“公开／内部（本类和子类）”。JS 原型链不暴露。
5. **Go 的类有比“对象＋方法表”更好的办法，跑过了**：只靠结构体嵌入做不到“父类方法里调到子类重写的版本”（Go 官方 FAQ 也这么说）；但“嵌入＋接口＋父结构体里存一个指向自己的接口”做得到，三层继承、调父类都对。建议 Go 改用这种写法。
6. **接口**：核心用名义化（类上写明“实现了哪些接口”）。从名义翻到结构（Go、TS）是丢信息，容易；反过来要猜，难。
7. **枚举、带数据的枚举**：建议都进核心，做成同一个东西，配一块“看(x)是哪种情况”。不然骨架里的“枚举”“联合”类型没有声明它们的积木。6 门语言各有落法（见 10.c），**都没跑**。
8. **记录**＝键固定、每个键有类型的字典；和字典是两种类型，可互转；没有方法、按内容比较。
9. **错误处理**：统一成“抛出／接住”可行。**“试着做”的口里有返回/跳出/跳过时，Go 用“怎么出来的标记”走得通，跑过了**（含“最后总要”照常执行、处理段里再抛）。Go 的 err 只在原生绑定边界上转换。建议分析器现在就记下“每个函数会不会抛”，以后 Rust 的 Result 要用。
10. 两个现成的问题：`LThrow` 只能带一句消息（接住再抛、错误链都做不了）；小库现在已经会抛错，但用户还没有“试着做”能接。建议错误处理往前排。
11. **异步**：“用户不标 async、生成器自己推”保留。代价主要在 JS/TS：会传染；**把会等的函数当回调交给小库或原生库会出错、类的“创建时”里不能等**——这两处 v4 没写到。Python 用线程方案，Go、Java（要 JDK 21）几乎没代价。
12. **PHP 没有并发**：建议不要禁用“开始做”，改成“立刻做完”，结果相同只是不同时；否则用了并发的库在 PHP 整个不能用。没验证。
13. **建议进核心的并发三样**：超时（“等…最多…毫秒”）、取消、一块最小的“一次只让一个做”。最后这块 v4 说不做；但小库自己加锁保不住“读—改—写”三步，会出现“Node 里对、Go 里偶尔错”。
14. **模块**：沿用 v4 的落法；补三条——库落成目录/包、模块之间不许绕圈（积木层查、把圈画出来）、非入口模块顶层不许跑代码。
15. **装饰器／注解**：只靠原生片段不够（它包不住用户用积木搭的函数和类）。建议核心加一个很轻的“标注”：贴在声明上的“名字＋参数”，每种语言怎么落由提供它的库写（贴在前面／登记调用／字段标签三种）。核心不认识任何框架。
16. **所有权／指针**：第一梯队可以完全不暴露。为以后的 Rust 预留参数的“只读／会改／拿走”标记、只读字段、“能不能跨线程”、“会不会抛”“会不会等”这几样分析结果，现在都不显示。
17. **需要霜霜拍板的只有 2 个**：PHP 和 TS 还算不算第一梯队（本机都跑不了）；带数据的枚举、“看是哪种情况”、标注这三样新概念进不进核心。我的建议都是“进／留，但先把环境装上、排在类和错误之后”。
18. **和骨架的出入**：第 1 条 L1 清单要补“枚举与记录、匹配、标注”；第 2 条①的标准对 PHP 并发要放宽成“结果相同即可”；第 3 条类型清单漏了枚举；第 5 条用词建议加“标注、稍后的结果、错误、选项”。另有 8 处 v4 设计稿的决定建议改，见文末。
19. **如实说明**：真跑过的只有两个 Go 实验（本机 go 1.25.0，不是当前的 1.27.4）。TypeScript、PHP 一行没跑（本机没有）。10.b、c、d、f、h、i 里各语言的落法都是纸面的。
20. **核对情况**：第一梯队“没有 X”的断言，对过官方文档的约 18 条（Go 9、Python 2、Java 3、PHP 3、TS 1），表里标〔核〕；其余标〔未核〕。“对照”一列（C#/Kotlin/Rust/Ruby/Dart/Swift）整列没核对。ES2026、JDK 27、C# 15 的内容只有二手来源。
21. 199 这个数取决于我拆的粒度；比例（①里五分之一已实现、五分之二完全没有）比绝对数可靠。

**格子里的写法**

- 语言格：`有`／`没有`／`不一样：…`（＝“有但不一样”）。JS 一格里浏览器和 Node 有差别时写“浏览器…／Node…”。
- `〔核〕`＝这条“没有”对过官方文档（出处见文末“核对过的来源”）；`〔未核〕`＝按我的了解写的，没对过官方文档。没有标记的“有”是按常识写的，没有逐条核对。
- “对照”一列（C#/Kotlin/Rust/Ruby/Dart/Swift）**整列都没核对**，只供参考。
- “现在积木核心”一格开头的四种状态：
  - `已实现`：生成器能出代码（后面括号里是节点名或小库函数名）；
  - `有节点`：`lib/lang/ast.dart` 里有这个节点，但生成器碰到就报“还没做”；
  - `仅设计`：只在 `docs/blocks-v4-language-design.md` 里写了，代码里没有；
  - `没有`：设计稿和代码里都没有（或设计稿明说不做）。
- “打算怎么表示”一格开头是分级：①核心 ②宿主专属 ③原生片段兜底 ④不做。
- 现状依据：2026-11-25 读的 master（cc7c7e2）。`kLangStage = 2`；能力表 `kLangFeatures` 里 `classes`、`errors`、`async` 三项都是“以后做”。

## 10. 九个难点

### 10.a 类模型统一成什么

**建议：核心就是“单继承＋多个接口”，访问控制两档（公开／内部），不暴露原型链。Go 不再用小库的“对象＋方法表”，改成生成“结构体嵌入＋接口＋存一个指向自己的接口”。**

为什么单继承＋多接口够：第一梯队 6 门里，JS、TS、Java、PHP 的类都是单继承（Java 已核对官方教程；其余未核对），只有 Python 允许多个父类（已核对），Go 没有继承（已核对）。多继承进核心，5 门都要降级；不进核心，只有 Python 少用一个本来就少用的能力。混入、特质、接口默认方法同理（各只有 1–2 门有），用“字段里放另一个对象”代替。

为什么访问控制是“公开／内部（本类和子类）”而不是“公开／私有（只有本类）”：用户写子类时最自然的需求是读父类的字段；“只有本类”这一档在 Java、PHP 会让子类读不到，在 JS（`#`）也读不到，而 Python、Go 根本没有这一档。把第二档定成“本类和子类”，6 门都翻得过去（Java/PHP/TS 用 protected，其余靠起名约定＋积木层检查）。代价：做不到“连子类都不让碰”，我认为对积木用户不重要。

**Go：结构体嵌入＋接口，能不能做到“父类方法里调到子类重写的版本”——只靠嵌入不能，加一个 self 接口能。跑过。**

- 官方说法（Go FAQ，已核对）：动态分派只能通过接口；结构体上的方法永远是静态决定的。
- 实验 1（跑过：本机 go 1.25.0，`go run`，只用标准库，文件在 /tmp/v5-A2/exp1/main.go，临时目录会丢，要点抄在下面）：

```go
// 写法一：只嵌入
type Animal struct{ Name string }
func (a *Animal) Sound() string { return "……" }
func (a *Animal) Intro() string { return a.Name + " 叫：" + a.Sound() }
type Dog struct{ Animal }
func (d *Dog) Sound() string { return "汪" }
// 写法二：父结构体里存一个接口类型的“自己”，方法之间互相调都经过它
type AnimalI interface{ Sound() string; Intro() string }
type Animal2 struct{ Name string; self AnimalI }
func (a *Animal2) Intro() string { return a.Name + " 叫：" + a.self.Sound() }
func NewDog2(n string) *Dog2 { d := &Dog2{}; d.Name = n; d.self = d; return d }
```

  跑出来的输出：

```
写法一 直接调: 汪
写法一 父方法里: 阿黄 叫：……          ← 父方法里调到的是父类自己的，不是“重写”的
写法二: 某兽 叫：……
写法二: [狗] 阿黄 叫：汪               ← 子类 Intro 先调父类 Intro，父类里又调到子类的 Sound
写法二: [狗] 小黄 叫：嘤               ← 三层继承也对
小黄有Sound方法: true  小黄是*Dog2: false   ← 孙子类不能被认成“是 Dog2”
```

- 结论和生成规则：
  1. 每个类生成一个结构体（嵌入父类的结构体）＋一个接口（列出本类和祖先的全部方法）＋一个 `New类名` 函数（负责把 self 设成最外层对象）。
  2. 方法体里“让这个对象做(方法)”一律生成 `x.self.方法()`；“调父类的(方法)”生成 `x.父类名.方法()`。
  3. 变量、参数的类型用接口，不用结构体指针——这样放得进子类对象。
  4. “是…吗”不能用 Go 的类型断言（实验最后一行：孙子类不是 `*Dog2`）。办法：每个类额外生成一个只有它和它的子孙才有的空方法（比如 `isDog2()`），判断时断言“有没有这个方法”。**这一条我只推理了，没跑。**
  5. 字段读写：本类方法里直接读；类外面要读公开字段时，接口里没有字段，要么生成取值/设值方法，要么类外一律走方法。**没跑**，属于做的时候要定的细节。
- 和小库“对象＋方法表”比：生成的 Go 是正常人看得懂的结构体和接口，有编译期类型检查，接 Go 的原生库（它们要的是结构体和接口）也顺；代价是每个类多一个接口、一个构造函数、一个 self 字段。小库方案只在“类型一个都没标”的动态模式下更省事。**建议：标了类型走新写法，没标类型的字段和参数用 `any`，仍是同一套写法，不再保留方法表。** 这和骨架里“Go 用小库对象模型”（沿用 v4 设计稿 3.7）不一致，见文末清单。

JS 的原型链：不暴露。JS 的 class 写法已经覆盖核心要的全部能力；原型链多出来的（运行时改类、给内置类型加方法）在其它 5 门没有对应，属于 ② 宿主专属，以后要用就放进 JS 专用的库。

### 10.b 接口：名义化还是结构化

**建议：核心用名义化——类上明写“实现了哪些接口”。**

- 为什么：Java、PHP 不写 implements 就不算实现（名义化），必须有这条信息才生成得出来；Go、TS 按结构对（已核对），多写这条信息没有坏处——生成时丢掉即可。反过来如果核心是结构化的，生成 Java/PHP 时要全程序扫一遍“哪个类碰巧满足哪个接口”再补 implements，还会碰上“满足了但作者没这个意思”。从名义化翻到结构化是丢信息，容易；反过来是猜信息，难。
- 对用户也更清楚：类卡片上有一栏“实现了：可关闭、可逐个取”，缺方法时积木直接标红提示缺哪个。
- 各语言怎么翻：

| 语言 | 接口声明 | 类上的“实现了” | 检查在哪做 |
|---|---|---|---|
| TS | `interface` | `implements` 照写 | 积木层＋tsc |
| Java | `interface` | `implements` | 积木层＋javac |
| PHP | `interface` | `implements` | 积木层＋运行时 |
| Go | `interface` | 不写；另生成一行 `var _ 接口 = (*类)(nil)` 让编译器帮查 | 积木层＋编译器 |
| Python | 不生成（或生成 `Protocol` 仅作标注） | 不写 | 只有积木层 |
| JS | 不生成 | 不写 | 只有积木层 |

- “(x)是(接口)吗”在 JS、Python 里没有运行时信息可查：生成器给每个类写一张“我实现了哪些接口”的名字表，小库按表查。**没跑。**
- 原生绑定进来的外部类型（比如 Go 库里的类型碰巧有 `Close()`）：由绑定的作者声明它“实现了可关闭”，不自动按结构认。

### 10.c 枚举和“带数据的枚举”要不要进核心

**建议：都进核心，做成同一个东西——枚举的每个选项可以不带数据，也可以带几个有名字的字段。配套一块“看(x)是哪种情况”（D11–D13、D15）。**

- 为什么进：骨架的类型里有“枚举”和“联合”，没有声明它们的积木，类型就是空的。写库时“状态只能是这几种之一”“结果要么是成功带值、要么是失败带原因”极常见；现在只能用文字（写错不报）或字典（少字段不报）。它也是以后接 Rust 时最对得上的东西。
- 为什么合成一个：简单枚举就是“每个选项都不带数据”的特例，一张卡片、一个节点（LEnumDecl，选项带可选的 fields）、一种匹配积木。
- 各语言怎么翻：

| 语言 | 简单枚举 | 带数据的枚举 | “看是哪种情况” |
|---|---|---|---|
| TS | 几个文字之一的联合类型（不用 `enum`：它生成额外的运行时代码） | 可辨识联合：每种一个带 `kind` 字段的对象类型 | `switch (x.kind)` |
| JS | 一个冻结的对象，值是文字 | 带 `kind` 字段的普通对象＋每种一个构造函数 | `switch (x.kind)` |
| Python | `enum.Enum` | 每种一个 `@dataclass`，再一个联合类型标注 | `match`（3.10 起；本机 3.12 能跑） |
| Go | 命名的 `string` 类型＋一组常量 | 一个带私有标记方法的接口＋每种一个结构体 | 类型 switch |
| Java | `enum` | `sealed interface`＋每种一个 `record` | `switch` 模式匹配（21 起；本机 JDK 21 能跑） |
| PHP | `enum`（8.1，带文字值） | 一个抽象类＋每种一个只读子类（PHP 的枚举选项不能各带各的数据，未核对） | `instanceof` 链 |

- 简单枚举的值统一用**文字**做底（而不是数字）：打印、转 JSON、存数据库时 6 门语言结果一样，也好排查。
- 穷尽检查放在积木层做（D15），不依赖各语言。
- **以上各语言的写法都没跑过**，只有“各语言有没有这个原生能力”对了一部分官方文档（Go 没有带数据的枚举、PHP 枚举的形态）。建议做之前先像 v4 那样手写一份 6 语言的对照程序跑一遍。

### 10.d 记录/数据类 和 字典 的关系

**建议：记录＝“键是固定的、每个键有类型的字典”。两者在积木上长得像，但是两种类型，可以互相转换。**

- 字典：键是运行时才知道的文字，值类型都一样（或“任意”）。用“取(字典)的(键)”，键是一个槽。
- 记录：有名字，字段写死在声明里，每个字段有自己的类型。用“(记录)的(字段)”，字段是下拉，写错名字当场报。按内容比较；可以勾“只读”。没有方法、没有继承（要方法就用类）。
- 和类的区别：记录没有“创建时”、没有方法、没有父类，比较看内容；类比较看“是不是同一个”。
- 转换：小库“(记录)变成字典”“用(字典)填(记录)”（和 C50 是同一对积木），缺字段或类型不对就抛错。JSON 进来先是字典，填进记录后才有类型——这是类型系统和外部数据的接口处。
- 生成：

| 语言 | 记录落成 |
|---|---|
| TS | `interface`（或 `type`）＋对象字面量 |
| JS | 普通对象 |
| Python | `@dataclass` |
| Go | 结构体（用指针传，保持“同一份”） |
| Java | 可改的生成一个普通类；只读的生成 `record` |
| PHP | 带构造器提升的类；只读的加 `readonly` |

- 不建议“没标类型时把记录偷偷落成字典”：同一个积木程序在标没标类型时跑出不同的东西，排查会很难。记录一旦声明就总是按上表生成。
- 和骨架的关系：骨架统一用词里“字典”“记录”都有，这里只是把边界定下来，没有冲突。

### 10.e 错误统一成“抛出／接住”以后，Go 和 Rust 怎么翻

**建议：核心只有“抛出／接住”。Go 现在整体用 panic/recover 翻（已跑通，含口里有返回/跳出）；Go 的 err 返回值只在原生绑定的边界上转换；分析器从现在起就记下“每个函数会不会抛”，给以后的 Rust 和“像 Go 的 Go”用。**

**“试着做”的口里有返回/跳出/跳过时 Go 怎么办——“怎么出来的标记”走得通。跑过。**

- 实验 2（跑过：本机 go 1.25.0，/tmp/v5-A2/exp2/main.go）。做法：三个口各包成一个返回整数的匿名函数，整数表示“怎么出来的”（0 正常、1 返回、2 跳出循环、3 跳过这次）；要返回的值先写进外层的一个变量；小库 `try` 用 `recover` 接错误、用 `defer` 保证“最后总要”；调用处紧跟着三行判断。

```go
how := try(func() int {            // 试着做
    if x < 0 { panic(&lcError{"负数"}) }
    if x == 0 { return exitContinue }
    if x == 99 { return exitBreak }
    if x == target { ret = "找到"; return exitReturn }
    return exitNormal
}, func(e *lcError) int { … }, func() { … })   // 出错了 / 最后总要
if how == exitReturn { return ret }
if how == exitBreak { break }
if how == exitContinue { continue }
```

- 跑了四次调用，覆盖下面这些情况，输出都符合预期：口里正常走完、口里“跳过”（“最后总要”仍然执行，口后面的语句不执行）、口里抛错被接住后继续下一轮、口里“返回”（函数带着值结束）、口里“跳出”（循环结束）、“出错了”的口里“返回”、“出错了”的口里再抛新错误（“最后总要”先执行，新错误带着原因传到外层）。
- 没覆盖到、要在真做时补测的：两层“试着做”套着且内层“跳出”的是外层循环；“最后总要”的口里自己又有返回/抛错；口里改外层的变量被闭包捕获时 Go 1.22 起每轮循环一个新变量的影响（本实验里 `x` 是只读用的）。
- 只在需要时才用标记：口里没有返回/跳出/跳过（分析器能看出来）时，直接生成不带标记的简单形式。

**Go 的 err 返回值**：不做成积木。原生绑定里写的 Go 片段如果返回 `(值, err)`，绑定的外壳生成 `if err != nil { panic(包成核心的错误) }`；反方向（把积木函数交给 Go 库当回调，库期望返回 err）由外壳 `recover` 后转回 err。用户看到的永远是抛出。代价：生成的 Go 不地道（Go 官方不提倡拿 panic 当普通错误处理，FAQ 已核对），性能也比返回 err 差。这是为“6 门语言行为一致”付的价钱。

**以后的出路（给 Rust 预留，也能让 Go 变地道）**：Rust 不能靠 panic 做普通错误处理，必须翻成 `Result` 和 `?`。这要求生成器知道每个函数“会不会抛”。所以建议现在就让分析器推出并保存这个信息（E10）——不让用户标，自动传染，和“会不会等”（P20）是同一套算法。有了它：

| | 会抛的函数 | 调用处 | 试着做 |
|---|---|---|---|
| Go（地道模式，以后可选） | 多返回一个 `error` | `v, err := f(); if err != nil { return …, err }` | 口里每次调用后判断 err，跳到处理段 |
| Rust（以后） | 返回 `Result<T, 错误>` | `f()?` | 口包成返回 Result 的闭包或带标签的块，再 `match` |

这两列都**没跑过**，只是说明预留的信息够用。

另外两件必须一起定的：
- LThrow 现在只能带一句消息，接住再抛、错误链、自定义错误类都做不了，要改成带“错误对象”（E03/E18/E19）。
- 小库现在已经会抛错（比如往不是列表的东西里加项），而用户还没有“试着做”——等于现在的积木程序遇到这些错只能直接崩。错误处理应当排在类之前或同时做（自定义错误类除外，它依赖类）。

### 10.f 异步：“等＝拿到结果再往下走，用户不标 async”的代价

**建议：保留这个统一；Python 用线程方案；补上“一次只让一个做”、取消、超时三样进核心；PHP 不禁用“开始做”，改成“立刻做完”。**

各语言的代价：

| 语言 | “等”翻成什么 | 代价 |
|---|---|---|
| JS／TS | `await`；所有“会等”的函数自动变 `async`，调用它们的地方自动加 `await` | ①传染：一个底层函数用了“等”，一路往上全变 async。②**把会等的函数交给不会等的地方当回调**（小库的 listMap、排序的比较函数、原生库的回调）会出错——拿到的是 Promise 不是值。小库凡是收函数的操作都要有“会等”的版本（一项一项按顺序等），原生绑定要声明“这个回调参数许不许等”，不许就在积木层报错。③类的“创建时”不能是 async：口里有“等”要报错并提示改成静态方法。④多了很多次让出，慢一点。**②③是 v4 设计稿没写到的。** |
| Python | 线程池＋Future，“等”就是阻塞这条线程 | 没有传染，写法最简单。代价：每个“开始做”占一条线程；真并行（或被切走）带来数据竞争，所以需要 P11；接 FastAPI 这类基于 asyncio 的框架时，框架要的是 `async def`，只能由绑定在线程和事件循环之间转一道。不选 asyncio 的原因：它有和 JS 一样的传染，而且 Python 里大量常用库是阻塞式的，混用更麻烦。 |
| Go | 普通调用；“开始做”是 `go`＋通道 | 几乎没有代价。注意 E24：每个 goroutine 里要接住错误，否则整个程序崩。 |
| Java | 虚拟线程，“等”是阻塞调用 | 要求 JDK 21 以上（本机正好 21）。老版本没有降级方案——建议直接写明“Java 目标最低 21”。 |
| PHP | 没有 | 设计稿是禁用“开始做／等／定时器”。我建议：“开始做”＝立刻做完并得到一个已经好了的结果，“等”直接取值，“同时做”按顺序做——程序结果相同，只是不同时。定时器、取消仍然没有意义（禁用或什么都不做）。理由：否则任何用了“同时做”的库在 PHP 整个不能用。**没验证**（本机没有 php）。 |

浏览器和 Node 的不同：

| | 浏览器 | Node |
|---|---|---|
| 主线卡住的后果 | 页面不动、点不了、不重画 | 这个进程里所有请求都卡住 |
| “等(毫秒)” | 只能是定时的 Promise | 同左（`node:timers/promises` 有现成的） |
| 真并行 | Web Worker，数据要复制着传 | worker_threads，同样隔离 |
| 取消 | `AbortController`（运行环境给的） | 也有 |
| 没人接的错误 | window 的事件，页面照常 | 没人接的 Promise 拒绝会让进程退出（未核对） |
| 入口 | 事件（页面打开、点击）；没有“程序结束” | 顶层代码；事件循环空了就退出 |

对设计的影响：网页宿主里“一直循环不等”会卡死页面，积木层应当在网页宿主下对“循环里没有任何等”的无限循环给警告；E23 的宿主帽子在两个宿主里含义不同，所以归②。

要不要“锁”进核心：要一个最小的（P11）。小库自己加锁只能保证“往列表里加一项”这种单次操作不坏；“读出来、加一、写回去”是三步，Python（线程）、Go、Java 都可能在中间被插进来，结果就是计数少了。这种错在 JS 里不出现（两步之间没有“等”就不会被插队），所以同一段积木会“在 Node 里对、在 Go 里偶尔错”——正是霜霜最不想要的那种不一致。给一块“一次只让一个做{…}”就能补上。**没写程序验证**，是按各语言的并发模型推出来的。

取消和超时要不要进核心：要，但做小。
- 超时：`等(结果)，最多(毫秒)`，超了抛“超时”错误。请求外部接口不带超时是写后端最常见的毛病，这个必须有。
- 取消：`取消(稍后的结果)`＋口里可查的`被取消了吗`；“等(毫秒)”和小库的等待点被取消时抛“取消了”错误。各语言底下：JS 用 AbortController 传下去，Python 用一个事件标记，Go 用 context，Java 用线程中断。**没跑。**
- “同时做这几件”一件出错时取消其余的，就靠这个机制。
- 不做：通道、select、原子量、线程本地变量。

### 10.g 模块／包落成什么文件结构，循环依赖

**建议：沿用 v4 设计稿 3.8 的落法，补三条：库落成目录/包；模块之间禁止绕圈；非入口模块的顶层不许跑代码。**

| 语言 | 用户工程里的一个模块 | 一个库 | 导入 |
|---|---|---|---|
| Node | 一个 `.js` 文件（CommonJS） | 一个目录，一个 `index.js` 作对外清单 | `require` |
| 网页 | 所有模块按依赖顺序拼进一个 `logic.js` | 同样拼进去；外部 JS 库用 script 标签 | 没有 |
| TS | 一个 `.ts` 文件 | 一个目录 | `import`（**没跑，本机没有 tsc**） |
| Python | 一个 `.py` 文件 | 一个包目录 | `import` |
| Go | 同一个包里的一个 `.go` 文件，名字加模块前缀 | 一个子目录＝一个 Go 包 | 同包不用导入；库用 `import` |
| Java | 一个类文件，顶层函数是 static | 一个 Java 包 | `import` |
| PHP | 一个 `.php` 文件，名字加前缀 | 一个目录＋命名空间 | `require_once` |

> **2026-11-26 更正（核心 2 第 1 段实现时，偏离了上表“用户工程里的一个模块”那一列）**：现在五种后端语言都像“网页”那一行一样落——**所有模块按依赖顺序合成一个编译单位**（一个主文件＋小库），撞名的顶层名字改叫“模块名·名字”（就是表里 Go、PHP 的“名字加模块前缀”，只是只在撞名时才加）。语言层的规矩（公开、用到了谁、不许绕圈、启动顺序）都在合并前查完，行为和分文件一样，五种语言真跑一致。
> 为什么没有一模块一文件：（1）Node、Python 分文件以后，别的模块要**改**一个模块公开的变量，得给每个变量加一层存取函数（`require` / `import` 拿到的是值的拷贝或者只读绑定），这是一套新的生成办法；（2）启动顺序要由生成的代码自己保证（M11 更正），分文件以后还得另生成一个“按顺序准备各模块”的入口；（3）文件怎么分和“库落成目录 / 包”是同一件事，应该在“库 1”一起定，现在先定会返工。
> 以后：在“库 1”做库的落盘时，把“一个库一个目录 / 包”和“库里一个模块一个文件”一起做；`linkProgram` 的检查、启动顺序、改名表（`LLinked.order / names`）到时候原样可用，只换最后“合并成一个模块”这一步。

循环依赖：
- 为什么禁止：Go 的包之间绕圈直接编译不过（未核对到官方原文）；JS、Python 允许但会读到“还没准备好”的东西，而且两者表现还不一样。唯一 6 门都安全的规则就是不许绕圈。
- 怎么不难受：检查放在积木层，报错时把圈画出来（A→B→A），并给出固定的解法——“把两边都要用的东西挪到第三个模块”。
- Go 的工程内模块因为落在同一个包里，其实绕圈也能编译；但别的语言不行，所以规则还是统一禁止。
- 库和库之间同样禁止绕圈。

顶层代码：非入口模块如果顶层能跑任意语句，“谁先被导入谁先跑”在各语言不一样（Go 按依赖和文件名、Java 按类第一次被用到、JS/Python 按导入顺序）。所以规定：只有入口模块有“程序开始时”；其它模块顶层只有声明，变量初值只许是不调用别的模块的式子（M11）。

> **2026-11-26 更正（核心 2 第 1 段实现时）**：M11 里“变量初值不许调别的模块的函数”放开了。实现是把几个模块按“被用到的先”合成一个编译单位、初始化由生成的代码按这个顺序一句句做（不靠各语言自己的导入顺序），所以初值里调别的模块公开的函数、读它公开的变量，五种语言结果一样（样例 m01、m04、m05 真跑过）。仍然不许的：同一个模块里初值直接用到排在后面的变量（规则 M08）。

v4 设计稿里“模块不许互相用（L10）”的原话更严——它的意思如果是“连单向也不许”，那库就没法分模块了。我按“不许绕圈”理解，请协调者对一下原意。

### 10.h 装饰器／注解：只靠原生片段够不够

**建议：不够。核心加一个很轻的“标注”概念（LAnnotation）：贴在声明上的“名字＋参数”，本身不改行为；怎么落到每种语言由提供这个标注的库来写。**

为什么原生片段不够：原生片段是“一段代码，槽里填值”。但框架要的是把积木写的函数/类本身交出去再包一层：

```python
@app.get("/users/{id}")        # FastAPI：装饰的是用户用积木搭的整个函数
def get_user(id: int): ...
```

```java
@RestController                 // Spring：贴在用户用积木搭的类和方法上
class UserApi { @GetMapping("/users/{id}") User get(@PathVariable int id) {…} }
```

函数体、参数、类型都是积木生成的，原生片段没法把“用户的函数声明”当成自己的一部分。v4 那种做法（每个框架手写一套专用帽子积木）正是霜霜说“不该硬造”的东西。

标注长什么样：
- 积木上：帽子（函数、方法、类）、字段、参数的边上可以挂小标签，比如“网址：GET /users/{id}”。标签从库里拖出来，参数在标签上填。
- 语法树：各种声明多一个 `annotations` 列表，每项是“标注名（来自哪个库）＋参数值”。
- 库里怎么定义一个标注：声明它能贴在哪种声明上、有哪些参数；再给每种目标语言写一条落法，落法只有三种：
  1. **贴在前面**：生成一行写在声明上面——Python 的 `@…`、Java 的 `@…`、PHP 的 `#[…]`、TS 的 `@…`。
  2. **登记调用**：声明照常生成，另外在模块的启动处生成一句调用，把这个函数/类交给框架——Express 的 `app.get("/users/:id", getUser)`、Go 的 `mux.HandleFunc("GET /users/{id}", getUser)`。JS 和 Go 没有能用的装饰器/注解，都走这条。
  3. **字段标签**：只对字段，Go 的 `` `json:"name"` ``。
- 某种语言没写落法：这个标注在那门语言里不可用，库在那门语言里缺这块，积木层明说。

这样“路由”这类概念由库的作者定义一次，6 门语言各落各的写法，核心一个框架的名字都不用认识。核心自己不解释任何标注（包括“重写”“已弃用”都不做成标注）。

要说清的限制：
- 标注只是标签，核心保证不了“贴上以后行为一样”——那是库作者的责任。
- 会改行为的 Python 装饰器（缓存、重试）也能用“贴在前面”落下去，但别的语言没有对应时只能由库作者用“我的积木”包一层来补。
- TS 的装饰器现在有新旧两套（标准版和 `experimentalDecorators`），JS 的装饰器还没进标准（二手来源说法不一，未核对官方），所以 JS/TS 默认走“登记调用”更稳。
- **这一节的各语言落法都没写程序跑过**；FastAPI、Spring、Express 的写法是按我的了解写的，没有对官方文档核对。建议骨架验证阶段拿“一个路由”做一遍 Python（装饰器）＋Go（登记调用）的手写对照。

### 10.i 所有权／指针：第一梯队能不能完全不暴露；给 Rust 预留什么

**建议：第一梯队完全不暴露，也不需要。但核心的几条规则现在就要按“以后翻得成 Rust”的方式定，另外在语法树上预留三个现在不显示的标记位。**

为什么可以完全不暴露：6 门都有自动内存回收。Go 的指针只是生成器的工具（对象、记录一律用指针，保证“同一份”）；PHP 数组“赋值就抄一份”由小库包住（v4 已经这么做；PHP 没真跑过）；Swift 的值类型不在第一梯队。用户只需要知道 O04 那一条规则：数字、文字、是否是值；列表、字典、对象、记录是“同一份”，要抄用“复制一份”。

以后接 Rust 时的难处：核心语义是“到处共享、随便改”，Rust 默认相反。有两条路：
- 笨办法：所有共享的东西生成成 `Rc<RefCell<…>>`（跨线程 `Arc<Mutex<…>>`）。一定翻得过去，但生成的 Rust 又慢又不像 Rust。
- 好办法：分析器证明“这个值其实没被共享/没被改”，就生成普通的所有权和借用。

为了以后走得了好办法，现在预留：
1. **参数的用法标记**（LParam 上，默认“自动”）：只读着用／会改它／拿走它。现在由分析器推，不显示；对第一梯队也有用（“这个函数会改你传进来的列表”可以在积木上提示）。
2. **字段和变量的“只读”**（C11、O07 已经要做）：Rust 默认不可变，知道哪些不变，生成的代码才不用到处加 `mut` 和锁。
3. **“能不能跨线程”**：从“开始做”的口里用到了哪些外面的变量就能推出来；现在 P11/P22 的检查也用得上。
4. **错误会不会抛**（10.e 的 E10）和**函数会不会等**（P20）：Rust 的 `Result` 和 `async` 都要。
5. **规则上不要做的事**：不给“对象之间互相指着成环还指望自动回收”做任何承诺以外的特殊支持（Rust、Swift 都会漏）；不引入“拿到一个变量的引用以后晚点再改它”这类积木（O06）；枚举和记录按内容比较、不可继承（10.c、10.d 已经是这样，正好对应 Rust 的 enum 和 struct）。
6. 类的继承在 Rust 里没有对应：以后只能翻成“结构体里包着父结构体＋特质”，和 10.a 里 Go 的写法是同一个思路——这也是 Go 那套写法值得现在做对的一个原因。

以上是推理，**没有写任何 Rust 代码验证**（本机也没有 Rust）。

## 给协调者的清单

**一、缺口**：GAP-A2-1 到 GAP-A2-40，见第 11 节的表。另外三个不在①里、但挡路的问题：

- 类型种类 `LKind` 只有十种，没有枚举、记录、接口、具体的类、泛型——上面一半的缺口（C25–C31、C48、D11–D15）都要等类型系统那部分。

**二、和骨架不一致、建议改的地方**

- **骨架第 1 条**（L1 的清单是“值、变量、运算、流程、函数、类与接口、模块、错误处理、异步、类型”）不够：按这份穷举，L1 还缺三样没法靠封装得到的东西——枚举与记录（声明）、“看是哪种情况”（匹配）、标注。建议把它们写进 L1 的清单。
- **骨架第 2 条**（①＝“所有目标语言都能翻”）对并发在 PHP 上不成立：PHP 没有“同时”。建议把①的标准写成“降级后**结果相同**即可，不要求同时”，否则并发整块都进不了①。另外：第 2 条举的②的例子（JS 原型链、Proxy、Go 通道、Rust 所有权）我照着分了级（C41、X06、P09、O03），没有异议。
- **骨架第 3 条**（类型要有“可空、泛型、函数类型、记录、联合、类与接口”）漏了枚举：第 5 条的用词里有“枚举”，第 3 条没有。建议补上，并写明“带数据的枚举”就是“联合”的声明方式（10.c）。
- **骨架第 4 条**（第一梯队含 TS、PHP）本身不改，但提醒：本机没有 tsc、没有 php，这两门到现在一行都没真跑过，“第一梯队”目前名不副实（见拍板问题 1）。
- **骨架第 5 条**（统一用词）建议加四个词：**标注**、**稍后的结果**、**错误**、**选项**（枚举里的一种）。

骨架没写、但 v4 设计稿里定过、这次核下来建议改的：

1. “Go 的类用小库‘对象＋方法表’”（3.7）：实验 1 跑出来，结构体嵌入＋接口＋self 能做到父类方法里调到子类重写的版本。建议改成这种写法，生成的 Go 才像 Go。
2. “‘锁’积木不做，小库自己加锁”（3.10）不够：小库只能保证单次操作，保证不了多步，会造成“Node 里对、Go 里偶尔错”。建议加一块最小的“一次只让一个做”。
3. “PHP 里‘开始做／等’禁用”（3.10）：建议改成“立刻做完”，否则用了并发的库在 PHP 整个不可用。
4. “装饰器用原生片段”（3.7）不够：原生片段包不住用户用积木搭的函数/类。建议核心加“标注”。
5. “没有联合”（4.3）：建议枚举（含带数据的）进核心。
6. 访问控制是“公开／私有”（3.7）：建议第二档的含义定成“本类和子类”，否则 Java/PHP/JS 里子类读不到父类字段。
7. “模块不许互相用（L10）”（3.8）：请确认原意是“不许绕圈”还是“完全不许”；我按前者写的。
8. 自动推 async（3.10）有两处没写到的坑：会等的函数被当回调交给小库/原生库；类的“创建时”里不能等。
9. “不做 getter/setter、运算符重载、多重继承、内部类”（3.7）：核下来同意，不用改。

**三、需要霜霜拍板的（只有 2 个）**

1. **PHP 和 TypeScript 还算不算第一梯队？** 本机没有 php 和 tsc，v4 到现在 PHP 一行没真跑过；并发这块 PHP 又几乎全要降级。
   - 选项 A（建议）：留在第一梯队，但先装上能跑的环境再继续，否则每一条“PHP 怎么翻”都是纸面的。

2. **带数据的枚举、“看是哪种情况”、标注，这三样新概念进不进核心？** 它们是这半边最大的新增（约 10 个缺口），好处是类型系统和接框架才立得住，代价是用户要多学三样东西。
   - 选项 A（建议）：都进，但排在类和错误处理之后。
   - 选项 B：只进简单枚举和标注，带数据的枚举以后再说。
