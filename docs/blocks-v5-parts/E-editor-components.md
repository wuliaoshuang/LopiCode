## 0. 结论摘要

**盘点（第一部分）**

1. 霜霜说“简陋、难用”，没指位置。照她的规矩不猜着整版重做：下面把“有证据的问题”和“要她圈的”分开列。
2. **有证据的“简陋”共 14 处**，最重的五处：
   - 基础组件只有 11 种（`model.dart` 224 行），没有开关、勾选、单选、下拉、图标、标签页、导航栏、弹层、表格；输入框只有“提示文字”一项内容属性。
   - 没有数据绑定、没有列表重复、没有显示条件；列表只是一段写死的文字。
   - 只有一个页面（`page.lc.json` 写死）；“跳转”只能填网址。
   - 自定义组件只有属性，没有事件、插槽、变体，里面也不能写逻辑。
   - 没有断点；宽度预设只是“看一眼”，不保存；样式面板能选“网格”，画布却画不出网格。
3. **有证据的“难用”共 15 处**，最重的五处：
   - 撤销、重做、图层、“⋮”全在屏幕最顶上（截图里约在 60/844 的高度），单手够不着；预览、积木逻辑、自定义组件、导出、改标题全挤在一个“⋮”里。
   - 组件面板只有一行横向滑动，一次只露出五个半，没有搜索、分类、常用。
   - “属性”和“样式”是两套重叠的面板，同一个宽度两边都能改；“属性”里数字只能点加减、不能打字，颜色只有 10 个色块。
   - 不能在画布上直接改文字；图片只能填网址；预览要离开编辑器。
   - 长按时长三处三个值：组件面板 250ms、画布 350ms、积木画布 280ms；搭建页没有任何震动反馈（积木画布有）。
4. **看不出来的 5 处**（真机上卡不卡、手柄和长按的手感、键盘弹起时“属性”面板、点一下添加后看不看得见、从预览回来选中还在不在）——只有真机或补测试才知道，没编结论。
5. **现有截图不够给她圈**：`lc-canvas-*` 那 16 张是旧布局（工具条已经从顶上挪到底部），当前布局只有 `05-搭建-*` 4 张；属性面板、样式面板、图层、组件面板、导出面板一张都没有。测试里有出图的代码，但图没生成过（GAP-E-1）。

**方案（第二部分）**

6. 整体布局：主操作收到屏幕下三分之一。底部一条固定的“工具条”（添加 / 图层 / 撤销 / 重做 / 预览），顶栏只留返回、页面名、“⋮”。选中后工具条换成“这个组件能做的事”。
7. 手势和积木画布统一：单指滑动平移、双指缩放、点一下选中、长按 280ms 拿起；长按不动松手＝弹菜单（复制 / 粘贴 / 重复 / 包成组件 / 删除）。
8. “属性”和“样式”合成一张面板，三页：**常用**（按组件类型给 4–7 项快捷属性）、**样式**（现有九组）、**事件**。
9. 间距、圆角、阴影、字号先给“预设档”（照 refactoring-ui 的刻度），旁边留“自定义”；颜色、字号、间距可以存成主题变量，导出成 CSS 变量。
10. 响应式：手机优先，三档断点（默认 / 平板 ≥768 / 桌面 ≥1024），大档只存“和默认不同的那几条”。
11. 数据绑定界面：每个可绑定的属性行尾一个“绑定”小按钮；列表重复和显示条件各一行。模型由 D 定，我写了我假设的五条。
12. 组件库：内置 48 个组件分 6 类、三档优先级（P0 22 个，其中 11 个现在已有；P1 16 个；P2 10 个）；组件库＝带“组件”的库，写了组件在库里要描述的 12 项信息交给 C。
13. 分 6 期。前两期**不动 `page.lc.json` 格式**（布局、手势、面板合并、就地改字、图层升级）；第 3 期起每期都动格式，动之前要先问霜霜。

**需要霜霜拍板 4 件**（见文末）：文件格式升第 3 版、内置组件第一批清单、主题变量要不要做、截图补拍后请她圈。

### 2.2 改成什么

思路：**手指待在屏幕下三分之一就能干完九成的事**。顶栏只放“很少点”的。和积木编辑器一个骨架（画布铺满 + 底部一个盒 + 顶栏悬浮），她学一次两边都会。

**没选中时**

```
┌──────────────────────────────────────┐
│ ← 首页 ▾ ⋮ │ 顶栏 64，悬浮。标题＝当前页面名，点开＝页面列表
│ 手机 390 · 已保存 │ 标题下一行小字：当前屏宽档 · 保存状态
│ │
│ （画布） │
│ │
│ │
├──────────────────────────────────────┤
│ [图层] [↶] [↷] [▶] │ 工具条，高 56。主操作＝添加
└──────────────────────────────────────┘
```

**选中一个组件时**（工具条上面多一行）

```
│ （画布） │
├──────────────────────────────────────┤
│ 按钮“登录” [常用] [样式] [逻辑] [⋯]│ 选中条，高 48。左边是名字，右边是“对它做的事”
├──────────────────────────────────────┤
│ [图层] [↶] [↷] [▶] │
└──────────────────────────────────────┘
```

- 两行加起来 104 高，比现在（选中条 48 + 提示一行 + 组件一行 64 ≈ 140）还矮，画布多露出一点。
- **工具条**这一行只做“全局的事”；**选中条**这一行只做“这个组件的事”。两行各管一件。
- “逻辑”有字，不再是光秃秃的 ⚡。组件上已有逻辑时按钮带一个小圆点。
- “⋮”里只剩：导出、主题、页面设置（标题）、组件库管理。都是不常点的。
- 缩放比例不再占悬浮小条：双指缩放照旧；“回到适应屏幕”放进画布空白处长按的菜单和“⋮”里。（待圈：她要不要留一个看得见的缩放数字——现在右下角有。）
- 屏宽档从左下悬浮小条挪到顶栏标题下那行小字，点它弹一个底部面板选（见第 6 节）。

**为什么这样**：主操作唯一（添加）；最常用的撤销落在右手拇指自然位置；预览一步到；每行一件事。

### 2.3 “添加”点开：组件盒

和积木盒同一种东西：底部面板，可上下拖高矮，最矮只剩手柄。

```
┌──────────────────────────────────────┐
│ ━━━━ │ 手柄
│ 🔍 搜组件 │ 第 1 行：搜索
│ (常用)(布局)(基础)(表单)(展示)(导航)…│ 第 2 行：分类，横滑；最后是“我的”和各个库
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐ │
│ │文字│ │按钮│ │图片│ │输入│ │ 第 3 行起：一行 4 个，每个约 80×72
│ └────┘ └────┘ └────┘ └────┘ │ 图标 + 名字
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐ │
│ │容器│ │横排│ │竖排│ │卡片│ │
│ └────┘ └────┘ └────┘ └────┘ │
└──────────────────────────────────────┘
```

- 点一下＝加进去（规则不变：选中的是容器就进容器，否则放它后面，没选中放页面最后），**加完自动滚到它并选中它**，面板收到最矮。
- 长按 280ms＝拿起来拖，面板自动收到最矮让出画布。
- “常用”＝最近用过的 8 个，存在项目里。没用过任何东西时显示内置的 8 个起步组件。

## 3. 画布操作与手势

### 3.1 手势表（和积木画布对齐）

| 手势 | 在哪 | 做什么 | 和现在比 |
|---|---|---|---|
| 点一下 | 组件上 | 选中 | 不变 |
| 点一下 | 已选中的文字 / 按钮上 | 就地改字（见 3.4） | 新 |
| 点一下 | 空白处 | 取消选中 | 不变 |
| 单指滑动 | 任何地方（含组件上） | 平移画布 | 不变；和积木一致 |
| 双指捏合 | 任何地方 | 缩放 25%–300% | 不变 |
| 长按 280ms | 组件上 | 拿起（震一下）。**拿起后不动就松手＝弹长按菜单**；动了＝拖动 | 现在 350ms、没菜单、没震动 |
| 长按 280ms | 组件盒里的组件 | 拿起拖进画布 | 现在 250ms |
| 长按 280ms | 空白处 | 弹画布菜单：粘贴、适应屏幕、回到 100% | 新 |
| 拖手柄 | 选中框的手柄 | 改尺寸 | 可按范围 32 → 44 |

“动了没有”的界线用积木画布同一个值：8 像素（`block_editor_canvas_view.dart` 的 `dragSlop`）。

震动照积木画布：拿起一下中等的，经过一个可放的位置一下轻的，放下一下轻的，丢进删除区一下重的。

### 3.2 拖动与插入提示

现在的毛病：一拖，所有空位都冒出来把页面撑变形。改成：

- 拖动时**页面排版不动**。只在手指附近算出“最近的一个可放位置”，在那里画**一条 3 像素的蓝线**（线的方向跟着父容器：竖排里是横线，横排里是竖线）。
- 手指停在一个容器上超过 0.4 秒，容器描一圈蓝边，表示“放进它里面”；空容器直接整块高亮。
- 蓝线旁边一个小标签写“放到 卡片 里 · 第 2 个”，避免嵌套深时不知道放进了哪层。
- 拖着的不是“移动 X”小药丸，而是**组件自己的半透明缩略图**（最大 160 宽）。
- 手指进到上下边缘 64 像素内，画布自动往那边滚，越靠边越快。
- 底部工具条在拖动时换成“拖到这里删除”（和积木盒一样）。

### 3.3 选中、多选

- 单选不变。选中框旁边加一个**“选上一层”小按钮**（↑）：嵌套深时点不到外层容器，现在只能开图层。
- 多选：长按菜单里“多选”，或图层面板里勾选。进了多选模式后，点一下＝加入 / 移出。选中条变成：`已选 3 个 [包成容器] [复制] [删除] [完成]`。
- **多选限制在同一个父容器里的兄弟**。为什么：页面是流式排版，跨容器一起移动没有明确含义；限制后“包成容器”“一起移动”都只有一种做法。选了不同父容器的会提示“只能一起选同一层的”。

### 3.4 就地改文字

- 对象：文字、按钮、输入框的提示文字、列表行标题。
- 触发：点一下已选中的它；或选中条“常用”第一项也是文字框。
- 画布上原地变成输入框，字号字体照原样；画布自动把它滚到键盘上面。
- 键盘上方不加额外工具行（一行只做一件事）；点别处或键盘“完成”＝提交；只记一条撤销。
- 字是绑定来的（第 7 节）时不能就地改，点它提示“这段字来自 变量名”，并给“去改绑定”。

### 3.5 对齐、吸附、参考线

页面是流式排版，没有自由摆放，所以**不做**画图软件那种“拖到哪吸到哪”的对齐线。吸附只用在三处，都是“改尺寸 / 改间距”时：

| 吸什么 | 什么时候 | 表现 |
|---|---|---|
| 刻度值 | 拖手柄改宽高、拖间距 | 靠近 4 的倍数 / 刻度值时停一下、震一下 |
| 兄弟的尺寸 | 拖手柄 | 和某个兄弟一样宽 / 高时，两者之间画一条细线并标“＝” |
| 父容器的一半 / 三分之一 / 占满 | 拖宽度手柄 | 手柄旁显示“50%”“占满”，松手写成百分比而不是像素 |

需要自由摆放的（徽标压在头像角上）走“定位”，那是少数情况，不为它做全套参考线。

### 3.6 尺寸手柄与标签

- 可按范围 44×44；显示仍是小圆点。
- 尺寸标签改放在**选中框内侧右下角**（框太小时放框上方），永远不盖别的字，也不会被屏幕边切掉（贴边时往里挪）。
- 直接拖内 / 外边距：选中时绿色、橙色区域的边可以拖（先按住 280ms，避免和平移抢），旁边显示数值，吸刻度。这是后期项（第 5 期）。

### 3.7 长按菜单

```
┌────────────────────┐
│ 复制 │
│ 粘贴到它后面 │ 剪贴板里有东西才亮
│ 重复一份 │
│ 多选 │
│ ────────────── │
│ 包成容器 │
│ 存成组件 │
│ ────────────── │
│ 删除 │ 红字，放最后
└────────────────────┘
```

- “复制 / 粘贴”用应用内剪贴板，跨容器、跨页面、跨项目（同一次运行内）可用。现在的“复制”改名“重复一份”，名副其实。
- 选中条的“⋯”里是同一份菜单再加“上移 / 下移”，不维护两套。

## 5. 属性与样式面板

### 5.1 两套合成一套

选中条上三个入口，对应同一张底部面板的三页：

```
┌──────────────────────────────────────┐
│ ━━━━ │
│ 按钮“登录” [⋯] │ ⋯：看 CSS、重置样式
│ ( 常用)( 样式)( 事件) │ 三页，不横滑
│──────────────────────────────────────│
│ 文字 [ 登录] 🔗 │ 一行一项；🔗＝绑定（第 7 节）
│ 样子 (实心)(描边)(文字) │ 变体
│ 大小 (小)(中)(大) │
│ 宽度 (随内容)(占满)(自定义) │
│ 颜色 ● 主色 ▾ │
│ 禁用 ○—— │
└──────────────────────────────────────┘
```

- **常用**：按组件类型给 4–7 项（见 5.2）。大多数时候在这一页就改完了。
- **样式**：现有九组原样保留（测试都在），但从“九个横滑页签”改成**一页竖着排的九个可折叠小节**，默认展开动过的和“尺寸、间距”，其余折着。为什么：横滑页签看不到后面有什么；竖排一眼看全，找“阴影”不用猜要滑多远。（这一条是待圈项 #16 的一个方案，她圈了再定。）
- **事件**：这个组件能触发哪些事、各挂了什么逻辑（见第 11 节）。
- 旧“属性”面板取消。重叠项（宽高、边距、圆角、背景、字色、字号）只在一处改。**格式不变**：文件里旧的属性照样认；规则是“新改动一律写进样式，旧属性只读不再新写”。这条要先验证导出结果和原来逐字一样（GAP-E-6）。

### 5.3 数值怎么输入

每个数值项是“预设档 + 自定义”：

```
│ 内边距 (无)(小 8)(中 16)(大 24)(…) │ 点“…”展开：数字框 + 加减 + 单位
```

- 预设档直接点；选中的档实心。值不在档上时“…”亮着并显示数值。
- 自定义里：数字框可打字（旧“属性”面板不能打字的问题就没了），加减步长 1（长按连加），单位菜单。
- 在数字上左右滑动也能微调（每 4 像素加减 1），手不用找小按钮。这是后期项。

| 项 | 档 | 来源 |
|---|---|---|
| 间距 | 0 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 | 书的间距刻度前九档 |
| 字号 | 12 / 14 / 16 / 18 / 20 / 24 / 30 / 36 / 48 | 书的字号刻度 |
| 字重 | 常规 400 / 加粗 600 | 书：只用两种 |
| 行高 | 1 / 1.25 / 1.5 / 2 | 书 |
| 圆角 | 无 0 / 小 6 / 中 10 / 大 16 / 全圆 | `tokens.dart` 的前几档；书说“定一个圆角风格用到底” |
| 阴影 | 无 / 一 / 二 / 三 / 四 / 五 | 书的五级：`0 1px 3px`、`0 4px 6px`、`0 5px 15px`、`0 10px 24px`、`0 15px 35px`，都是黑色两成不透明 |
| 边框 | 无 / 1 / 2 | 书 |
| 文字颜色 | 主要 / 次要 / 更淡 | 书：最多三种文字色 |

为什么要预设档：refactoring-ui 的核心就是“从一套定好的值里选”；新手不知道该填 14 还是 15，给档就不用想，做出来的页面也自然整齐。

### 5.5 主题（全局变量）

入口：⋮ › 主题。一张整页：

```
┌──────────────────────────────────────┐
│ ← 主题 │
│ 颜色 │
│ ● 主色 #2563EB › │
│ ● 文字 #111827 › │
│ ● 次要文字 #6B7280 › │
│ ● 背景 #FFFFFF › │
│ ● 卡片 #F9FAFB › │
│ ● 危险 #DC2626 › │
│ ＋ 加一个颜色 │
│ 字号档 › │
│ 间距档 › │
│ 圆角风格 (直角)(小圆角)(大圆角) │
│ 深色模式的颜色 › │
└──────────────────────────────────────┘
```

- 取色面板最上面多一排“主题色”。选了主题色，组件上记的是**变量名**不是色值；之后改主题，全页一起变。
- 导出成 CSS 自定义属性：在 `:root` 上写 `--color-primary: …`，用的地方写 `var(--color-primary)`（MDN 核对过）。
- 画布现在不认 `var(…)`（`canvas_css.dart` 31 行、`css_color.dart` 94 行），要补：画之前先用主题表把变量换成值。
- **要改格式**：页面文件（或项目级的一个主题文件）多一份主题表。建议放项目级，多页面共用。

### 5.6 状态样式

样式页顶上加一行 `状态 (平时)(按下)(禁用)(聚焦)`。选了“按下”后改的只存成“按下时的差别”。导出成 `:active`、`:disabled`、`:focus`（三个伪类 2026-11-26 对 MDN 核对过，见 `docs/api-notes.md`）。

**做成什么样（第 3 期 B2，GAP-E-11 里“状态样式”那一半）**：

- 存在节点的 `states` 字段里：`{"pressed": {…}, "disabled": {…}, "focused": {…}}`，值是和 `style` 同一种写法的 CSS 声明表，**只存和平时不一样的那几条**；一个状态清空了这个状态就不留，三个都空了 `states` 字段也不留（读写在 `lib/lowcode/states.dart`）。
- 面板：`状态` 一行在样式页最上面（九组页签下面）。写过东西的状态药丸上有个小圆点。选了“平时”以外的，下面出一条浅强调色的提醒“现在改的是“按下”时的样子：只记和平时不一样的地方”，右边“清掉”。这时九组控件显示的是“平时的样子 + 这个状态的差别”，改的都写进这个状态。换一个组件、收起面板都回到“平时”。
- 画布：面板上选着哪个状态，选中的那个组件就照“平时 + 这个状态的差别”画（只是看，不改文件）。
- 导出：网页 / Vue / React 每个状态一条规则 `选择器:active { … }`（`lcStateRules`）。**Flutter 导出不读 `states`**（Flutter 的按下 / 禁用 / 聚焦样式要按组件各写各的 `WidgetStateProperty`，没有一条通用写法，这一版如实不做）。
- “禁用”状态只对浏览器认 `:disabled` 的元素起作用（按钮、输入框、下拉这些表单控件）；给文字、容器设了“禁用”的样子，网页上永远不会生效——面板不拦，画布预览照画。

### 6.1 断点模型

- **手机优先**：不带条件的样式＝默认（手机）。另有两档“更宽时”：平板（≥768）、桌面（≥1024）。数值是我定的（768 沿用现有宽度预设），可在主题里改。

- 导出成 `@media (min-width: 768px) { …}`（写法未对 MDN 核对）。
- 为什么只做“按屏幕宽”，不做“按容器宽”（容器查询，MDN 核对过有这个东西）：模型多一层、画布要自己算容器宽度，第一版不值。留着以后加。

## 7. 数据绑定的界面

### 7.1 我假设的模型（等 D 的设计来对齐）

1. 页面有“状态”（存盘字段名还是 `variables`）：名字、类型、初始值。组件也可以有自己的状态。
2. 一个属性的值有三种来源：写死的值；一个变量（或它里面的某一项，如“用户 的 名字”）；一个式子（一块**值积木**，结果类型要对得上）。
3. 值变了，用到它的界面自动跟着变。默认单向（值 → 界面）。输入类组件的“值”是双向的（用户输入 → 写回变量）。
4. 任何节点可以设“重复”：给一个列表，对每一项画一遍；里面可以用“这一项”“第几个”。可选一个“用哪一项当标识”。
5. 任何节点可以设“显示条件”：一个结果是“是 / 否”的式子；为否时不画。

如果 D 的模型不一样（比如不许式子、只许变量），界面第 2 步少一个选项即可，结构不用改。

### 7.2 属性旁边怎么绑

每个可绑定的属性行尾有个 🔗。没绑时是灰的。点它：

```
┌──────────────────────────────────────┐
│ ━━━━ │
│ “文字”从哪来 │
│ ○ 写死： [ 登录] │
│ ◉ 用一个值 │
│ 🔍 搜变量 │
│ 用户名 文字 │ 名字 + 类型；类型对不上的灰掉并写原因
│ 购物车 › 数量 数字 │
│ 这一项 › 标题 文字 │ 在重复里面才有
│ ＋ 新建变量 │
│ ○ 写个式子 › │ 进一个只能放值积木的小画布
│ │
└──────────────────────────────────────┘
```

绑好以后，属性行变成：

```
│ 文字 ⟦ 用户名 ⟧ 🔗 │ 药丸＝绑定来的；点药丸改；🔗 亮
```

画布上绑定来的文字显示变量的初始值（没有就显示“{用户名}”），左上角一个小 🔗 角标。

类型对不上时**不让选并说原因**（“这里要文字，购物车是列表”），不是选了以后才报错——类型系统在这里直接让用户少走弯路。

### 7.4 显示条件

```
┌──────────────────────────────────────┐
│ 什么时候显示 │
│ ○ 一直显示 │
│ ◉ 当 ⟦ 已登录 ⟧ 为“是” │ 选一个“是否”类型的值

│ │

```

为什么给“简单比较”这一档：十次里八次就是“某值为是”或“某数大于 0”，不该逼人进积木画布。

顶栏“⋮”不放。放在组件盒旁边不合适（不是组件）。建议：**和积木逻辑编辑器共用同一份“状态”面板**（积木编辑器顶栏已有这个入口；第四轮起两边都叫“状态”）；搭建页里从绑定面板的“＋ 新建变量”和“事件”页进。只有一份变量表，两边看到的一样。


## 8. 组件库

### 8.1 先说一条和骨架有出入的地方

骨架说“除语言基础和基础库外，所有能力都靠封装得来”。对组件要分两种，不然说不通：

| 种类 | 是什么 | 例子 | 属于哪层 |
|---|---|---|---|
| **原生组件** | 浏览器 / Flutter 本来就有的控件，没法用更小的东西拼出来 | 文字、图片、按钮、输入框、多行输入、勾选框、单选、开关、滑块、下拉、容器、图标 | L0 宿主原生接口 + 原生绑定 |
| **封装组件** | 用原生组件 + 样式 + 逻辑拼出来的 | 卡片、列表行、表单项、导航栏、标签页、弹窗、提示条、空状态、轮播…… | L3 库 |

为什么要分：每个原生组件要写**好几份画法**——编辑器画布（Flutter 画的近似）、导出网页、导出 Flutter、导出 Vue、导出 React。封装组件只要一份定义（一棵节点树），各个导出自动就有。所以**原生组件越少越好**（下面定 13 个），其余全部封装——这正好符合霜霜“靠封装”的方向，只是底下那十几个得承认是原生的。

### 8.3 用户自建组件

**从画布存**：长按菜单 › 存成组件（现在有）。升级的是存之后能定义的东西。组件编辑页（整页，沿用现在的做法）：

```
┌──────────────────────────────────────┐
│ ← 组件：商品卡片 ⋮ │
│ │
│ （组件的画布） │
│ │
├──────────────────────────────────────┤
│ (属性 3)(事件 1)(插槽 1)(变体 2) │ 选一项，下面弹对应的面板
├──────────────────────────────────────┤
│ [图层] [↶] [↷] [▶] │
└──────────────────────────────────────┘
```

| 要定义的 | 界面 | 说明 |
|---|---|---|
| **属性** | 列表：名字、类型、默认值。类型从现在的四种扩到：文字、数字、是否、颜色、**选项（枚举）、图片、列表、记录、任意** | 类型用全应用同一套类型系统（骨架的渐进类型）。组件里的东西绑到属性，用第 7 节同一个绑定面板 |
| **事件** | 列表：名字、带出去什么值（名字 + 类型）。组件里用一块“发出事件 X”积木触发 | 外面用它时，“事件”页里就多出这个事件 |
| **插槽** | 在组件画布上选一个容器 › “设成插槽”，起名；可以放“没填时显示的默认内容” | 外面用它时，画布上那块是个能往里拖东西的空位。默认插槽 + 具名插槽，思路同 Vue 的插槽（官方文档核对过）。React 那边对应“把内容当属性传进去”（2026-11-26 B3 对 react.dev 核对过，见 `docs/api-notes.md`） |
| **变体** | 一个变体＝一个“选项”类型的属性 + 每个取值对应的一组样式差别。界面：选变体取值 → 照常改样式 → 存成“这个取值时的差别” | 和断点同一个机制（只存差别），省一套代码 |
| **逻辑** | 组件画布里选中东西 › “逻辑”，进积木编辑器，作用范围是这个组件 | 现在组件里不许有逻辑（`component_editor_sheet.dart` 第 5 行）。放开后组件有自己的状态变量 |

### 8.4 组件在库里要描述哪些信息（给 C）

组件库＝带“组件”的库，文件格式由 C 定。每个组件至少要能写下这 12 项：

| # | 信息 | 用在哪 |
|---|---|---|
| 1 | 标识（库内唯一）、显示名、别名（搜索用）、一句话说明 | 组件盒、搜索 |
| 2 | 图标、分类 | 组件盒 |
| 3 | 可见性（公开 / 库内） | 库内的不出现在组件盒 |
| 4 | 属性表：名字、类型、默认值、是否必填、说明、**在“常用”页显不显示及顺序、用什么控件编辑**（预设档 / 开关 / 取色 / 文字框） | 属性面板自动生成 |
| 5 | 事件表：名字、带出的值及类型、说明 | “事件”页、积木盒里的事件帽子 |
| 6 | 插槽表：名字、允许放什么（任意 / 只许某几种）、默认内容、最多几个 | 画布上的空位 |
| 7 | 变体表：哪个属性是变体、每个取值的样式差别 | 属性面板的变体行 |
| 8 | 内容：封装组件＝一棵节点树（含绑定、重复、显示条件）+ 组件内状态 + 逻辑；原生组件＝指向一个原生绑定 | 画布、导出 |
| 9 | 原生组件专用：各目标的画法在哪（画布、网页、Flutter、Vue、React），缺哪个目标要明说 | 导出时缺了就报“这个组件不支持导出成 X” |
| 10 | 能不能当容器、放进哪些父组件才合法（如“页签”只能放在“标签页”里） | 拖放时判断能不能放 |
| 11 | 放到画布时的初始样子（默认属性 + 默认子节点）、编辑器里的预览数据 | 点一下添加 |
| 12 | 依赖：用到本库 / 别的库的哪些组件和积木；库的版本 | 复制、导入、升级 |

对 C 的两个要求：(a) 同一个库里组件和积木能互相引用（组件的逻辑用库里的积木；积木“打开弹窗”操作库里的组件）；(b) 第 4–7 项就是组件的“类型签名”，要进类型检查——给属性绑了类型不对的值，在编辑时就报。

### 8.5 组件盒按库分组

- 分类行：`常用 | 布局 | 基础 | 表单 | 展示 | 导航 | 反馈 | 我的 | <库名>…`。前七个是内置库的分类；“我的”＝这个项目里自建的；后面每个用上的库一个。
- 库多了以后分类行最后一个是“更多库 ▾”。
- 搜索跨所有库，结果里每个组件下面一行小字写来自哪个库。

### 8.6 内置只读 + 复制一份来改

- 内置组件上长按（组件盒里）或实例的“⋯”里：**“复制一份来改”**。复制到“我的”，名字自动加“（我的）”，之后随便改。
- 内置的封装组件可以“看里面”：只读打开组件编辑页，顶上一条提示“内置组件不能直接改 ·”。
- 原生组件没有“里面”，复制得到的是“包了一层的封装组件”（里面放一个原生组件 + 预设好的属性），足够做“我的主按钮”这种事。
- 已经放在画布上的实例不会跟着变成“我的”；提供“把这个页面里的 X 都换成 X（我的）”。

| 性能：“500 个节点平移”的速度测试 | 要有速度测试 | 三道：① 平移时整页的搭建次数不涨（和机器快慢无关，这是主要的一道）；② 平移一下至少比“同一次运行里整页重搭一帧”快 10 倍；③ 兜底：平移一下不超过 200 毫秒。②③ 的“一下”都是 60 下（重搭是 10 下）里的**中位数**，偶尔卡一下不影响结果 | 这台机器只有 1.5 核、还和别的测试抢，绝对毫秒数会飘。实测平移一下 2–30 毫秒、整页重搭一帧 780–3080 毫秒（70–370 倍），所以比例取 10 倍、兜底取 200 毫秒，都留了 6 倍以上的余量 |

**先说 GAP-E-6（“属性”和“样式”合并以后，新改动写到哪儿）**。动手前查到的事实：Flutter 导出（`export_dart.dart`）只读简写属性
（`props`），**完全不读 `style`**；网页、Vue、React 导出两边都读（`style` 盖在 `props` 上面）。所以照 5.1 原来写的“新的修改一律写进
`style`”，网页上看不出区别，但 Flutter 导出会不再跟着变——比合并前退步。实际定的规矩（`lib/lowcode/inspector_write.dart`，
`test/lowcode_inspector_write_test.dart` 逐项对过四种导出）：

- “常用”页的一项，**能用简写属性原样表达、而且这个组件的 `style` 里没有盖住它的条目** → 写简写属性。这样写出来的页面文件和四种导出，
  和合并前的“属性”面板逐字相同。
- `style` 里已经有盖住它的条目（她在“样式”页调过）→ 改 `style` 里那几条（不然改了看不出变化）。
- 清掉 → 两处都清。宽度“撑满”只有简写属性能表达：写的时候把 `style` 里盖着它的去掉。
- “样式”页照旧只写 `style`。
- 简写属性表达不了的常用项（按钮的描边 / 只有字、文字最多几行、图片的填充方式和宽高比、容器的方向和换行、卡片阴影档）只能写 `style`，
  这几项 **Flutter 导出里看不出来**（网页 / Vue / React 正常）。要补齐得让 Flutter 导出也读 `style`，是导出那边的活，不是面板的。

**弹窗在画布上怎么编辑（GAP-E-13，定稿）**

- 弹窗平时不显示。它在页面里的位置上只画一个小标签“弹窗 · 标题 · 点一下编辑”（不占版面以外的地方，导出里没有这个标签）。
- **选中弹窗（点小标签、图层里点它、或者选中它里面的任何组件）＝画布进入“只看这个弹层”**：页面换成一层灰色遮罩，弹窗面板画在正中，能往“内容”“底部”两个插槽里拖组件；画布顶上出一条“正在编辑弹窗：标题 [退出]”。
- 退出的三种办法：点“退出”；选中弹窗外面的组件（比如从图层里点别的）；弹窗被删了。**点遮罩 / 空白不退出**（点空了就退出太容易误触，而且和“点空白取消选中”打架）。
- 点一下添加弹窗：永远加在页面最后（它是整页的东西，不属于哪个容器），加完直接进它的编辑状态。弹层状态下点一下添加别的组件：加进这个弹窗。
- 顶上的横条（这条和“这个页面是新版做的”那条）不盖页面：有横条时页面顶边往下让出横条的高度。
- 底部弹层、轻提示以后做的时候照这一套（同一个 `LcOverlayFocus`，`lib/lowcode/overlay_focus.dart`）。

**网格（GAP-E-2）**

- 容器的样式页 › 布局，第一行“排法 (弹性)(网格)”。选网格：写 `display: grid`，没写过列数先给两列；下面换成 列数（1–12，加减或直接填）、列间距、行间距。换回弹性：去掉 `display` 和列写法（间距留着，两种排法通用）。
- 放在网格里的组件，布局组最上面多一行“跨几列”（写 `grid-column: span N`，1 不写；最多到父容器的列数）。
- 第一版只有“等宽 N 列”（`grid-template-columns: repeat(N, 1fr)`）。文件里是别的写法（各列不一样宽等）：画布按“数出来有几列、每列一样宽”近似画，面板显示数出来的列数并说一句“改了会变成每列一样宽”。
- 画布：按列从左到右、放不下换行，行高取这一行最高的；跨列的占连着的几列，这一行剩下的列不够就换行。拖动时的落点线跟着格子走。

给 B3（自定义组件带插槽）留的位置：

- 插槽的全部计算在 `lib/lowcode/slots.dart`：`lcSlotsOf(node)` 给出一个组件有哪些插槽、`lcSlotChildren`、`lcFallbackSlot`、`lcSettleSlot`（插入 / 移动时收拾 `slot`，`LcDocument.insert / move` 已经在调）、`lcSlotBoxId / lcSplitSlotId`（落点 id `节点id#插槽名`）、`lcInsertAt / lcMoveTo`（搭建页、组件编辑页、多选、图层都走这两个）。B3 只要让 `lcSlotsOf` 对“自定义组件的实例”返回定义里的 `slots`，拖放、多选、包成容器、图层这些就都认了。
- 画布上的插槽落点是 `canvas_render_widgets.dart` 的 `_slot(...)` + `CanvasSlotHint`（空插槽的提示）；落点矩形在 `canvas_dropbox.dart` 的 `lcDropBoxTree`。
- 四种导出里“这个插槽里的子节点”统一用 `slot('名字')` 这个闭包取（`export_web_v3.dart`、`export_dart_v3.dart`）。

### 10.5 第 3 期第 3 段（B3）：自定义组件带插槽——提前做的“定义在页面文件里”版（2026-11-26）

本来插槽排在第 6 期（等库格式）。这次提前做了不依赖库的那一半：组件定义还在页面文件的 `components` 里，格式用第 3 版早就留好的字段，一个字段都没加。

**做了什么**

- 组件编辑页：选中一个容器（容器 / 行 / 列 / 卡片，最外层也行）›“更多操作”›“把内容设成插槽”，起名，可设成默认插槽。
  做法是在这个容器里包一层占位节点：容器自己不变（样式、排法都在），原来的内容成了“没填时显示的默认内容”。
  选中插槽：选中条上两个按钮“改名 / 取消插槽”（插槽没有样子可改，不出“常用 / 样式”）。画布上插槽是一个细边框，顶上一行角标“插槽 · 名字”（角标自己占一行，不盖默认内容；所以编辑页里它比真正用的时候高一行）。
- 名字：她起的名字给人看；代码里用的名字——默认插槽固定 `default`，具名的她起的要是合写法的英文就直接用，否则自动 `s1`、`s2`…。一个组件最多 8 个插槽。
- 页面上：实例里每个插槽是一个落点（`实例id#插槽名`）。没填显示默认内容（照样能往上拖，拖进去默认内容让位）；没填又没有默认内容显示空位小框；
  填进去的就是页面里的普通节点，能选中、改、多选、拖出来。
- 不悄悄丢内容：
  - 改名——所有实例里填的内容跟着改，撤销也跟着改回来。
  - 取消插槽——先说“有几处填了东西、共几个组件”，确认后这些内容**挪到各自那个实例的后面**（同一个容器、紧挨着、先后不变）；实例是另一个组件的最外层时外面包一层容器接住。
  - 别的办法（删掉占位或它外面的容器、撤销“设成插槽”）会让一个有人填着的插槽消失——拦下并说明，让她走“取消插槽”。
  - 删整个组件——确认框写明有几处填了东西；“拆成普通控件留着”时填的内容接在原来插槽的位置上（节点还是原来那几个，id 不变，挂在上面的逻辑还认得）。
- 过了一遍原先按“实例没有子节点”写的地方：复制 / 粘贴 / 重复一份（连填的内容一起带）、多选（同一个实例同一个插槽里的才算同一层）、
  包成容器（包出来的容器留在原插槽里）、拆开、存成组件、图层面板（每行写“在「插槽名」里”，没地方放的写明）、Agent 写页面的工具说明。
- 导出：Vue 定义里 `<slot name>`（里面是默认内容）、用的地方 `<template #名字>`；React 默认插槽走 `children`、具名的当同名属性传 JSX、定义里 `{x ?? (<>默认</>)}`；
  网页和 Flutter 没有“组件”这一层，直接把内容内联到插槽的位置（填了用填的，没填用默认的）。旧页面四种导出逐字节不变（基准没动）。
- 组件里不能有弹窗：点着加、拖着加、粘贴，以及任何别的路子，写回定义这一步统一拦；“存成组件”时选中的东西里有弹窗也拦下并说明。

**和原设计（§8.3）的出入**

- §8.3 写“选一个容器 ›设成插槽”——没说容器自己怎么办。实现是“容器留着、内容变默认内容”，不是“把容器换成插槽”：这样排法、间距不用重设，取消也能原样退回。
- 第 3 版格式文档给占位节点留的是 `props.name`；给人看的名字格式里没单独留字段，用了节点通用的 `name`，存盘时再抄进定义的 `slots[].label`。
- 同一个插槽在定义里只能出现一次（Vue 允许同名多处、React 属性也能用多次，但“填进去的节点 id 不变”就保不住了）。
- 插槽内容不能“回传数据”（Vue 的作用域插槽、React 的函数子节点）：等数据绑定（第 5 期）有了再说。

**和第 6 期“组件库”版的关系**

- 第 6 期要做的是：组件定义搬进库文件（能跨页面、跨项目用，带版本、可以“内置只读＋复制一份来改”），加事件、变体、组件内逻辑。
- 到时**能原样用**的：
  - 占位节点和实例子节点的格式（`type: "slot"`、`props.name`、子节点的 `slot`、定义的 `slots`）。
  - 展开（`lib/lowcode/component_expand.dart` 的 `LcExpander`：只认“拿到一个定义”，不管定义从哪来）。
  - 定义那一头的操作和实例里内容的处置（`component_slots.dart`：设成 / 改名 / 取消、数有几处填了、跟着改名、挪出来、拦截）。
  - 画布画法和落点（`canvas_render_slots.dart`、`slots.dart`）、起名对话框、四种导出里插槽那一段。
- 到时**要改**的：
  - （2026-11-27 第 4 期更新：多页面做在同一个页面文件里、组件定为项目级，下面这三件事已经改成扫这个文件里的**所有页面**，见 §10.6 第八条。跨项目的库还是下面说的问题。）
  - “有几处填了东西 / 跟着改名 / 挪出来”现在只扫当前这一个页面文件（`doc.root` 和 `doc.components`）。定义进了库以后，用它的页面不止一个，
    这三件事要么扫整个项目的页面，要么改成“库里的插槽改名 / 删除算一次不兼容的升级，页面打开时再迁移”。这是第 6 期最要先想清楚的一处。
  - `lcLinkInstances`（把定义的插槽表挂到实例上）现在从 `doc.components` 找定义，要换成从库里找。
  - 组件盒“我的组件”一组要按库分组（§8.5）。

### 10.6 第 4 期第 1 段（B1）：多页面（2026-11-27；补 GAP-E-14）

这一节先是设计（GAP-E-14 当时说“没设计”的那几件事），后面是做完以后和前面几节的出入。主题变量、断点不在这一段。

**一、页面放在哪：还是那一个 `page.lc.json`，不拆成一页一个文件**

第 3 版格式（`docs/lowcode-page-format-v3.md`）早就定了 `pages` 这个字段，并且说了“不再升版本”。照它做：

- **首页**就是文件最外层的 `title` / `root` / `logic`；**别的页**依次放在 `pages` 里，每项 `{id, title, root, logic?}`。
  所以“页面清单”就是“最外层这一页＋`pages`”，先后就是清单的先后，**第一个永远是首页**。
- 最外层多了一个可选的 `id`（首页的页面 id）。只有“项目里不止一页”或者“首页的 id 不是 `p1`”时才写。
  **只有一页的项目，存出来和多页面之前逐字节一样**（没有 `id`、没有 `pages`）。
- 页面 id：`p数字`，全项目不重复，建的时候发、以后不变（改名、排序、换首页都不变）——“去页面”积木和底部导航项记的是它。
  写法 `^[A-Za-z0-9_]{1,24}$`；缺了、写法不对、重了的，打开时补一个新的。
- 节点 id **每页各算各的**（两页都可以有 `root`、`n5`）；新节点的数字全项目往上接，免得复制、粘贴到别的页时撞。
- 逻辑（变量、事件）**每页一份**。自定义组件、以后的主题变量是**项目的**（见下面第六条）。
- “现在在编辑哪一页”**不进文件**（它是编辑器的事）。打开项目先看首页。

为什么不照 §10 表里写的“一个项目多个页面文件”：

1. 格式文档已经定了、并且答应过霜霜“只升这一次”；拆文件就得再定一个“页面清单文件”，等于又一种格式。
2. 一个文件＝一次存盘要么全成要么全不成（现成的“先写临时文件再改名”）。拆成几个文件，“改名一页＋改另一页里指着它的积木”存到一半断电就对不上了。
3. 撤销是整份快照：删一页、连带别的页里的引用，一步就能退回来。
4. Agent 读写页面的工具只认这一个文件，不用教它新的目录规矩。
5. 老版本应用打开新文件：至少首页是好的，别的页原样留着不丢（它不认识 `pages` 就不动它）。

代价：页面很多、很大时这个文件会大。所以定了上限 **30 页**（自定的数；满了“新建页面”变灰）。

**二、旧的单页面工程**

- 打开：就是“只有首页”的项目，不改文件。
- 存：没有加页就没有 `id`、`pages`，别的字段、先后都不变（测试拿第 1、2、3 版的旧文件钉住，逐字节比）。
- 加了一页再删掉：存出来和没加过逐字节一样。
- `pages` 里读不出来的项（没有 `root`、根不是页面、超过 30 页的）：不解释、原样留着、排在读得出来的后面。

**三、页面的操作**

| 操作 | 规矩 |
|---|---|
| 新建 | 空白页，排在最后；名字预填“页面 N”；建好就换过去 |
| 改名 | 最长 30 字，空的算“未命名页面”；只改给人看的名字，id 不变，所以指着它的地方不用改 |
| 复制 | 组件树、逻辑照抄成独立的一份，紧跟在原页后面，名字加“ 副本” |
| 排序 | 上移 / 下移，只在“不是首页的几页”之间；想换首页只能点“设为首页”（免得排序时不小心把首页换了） |
| 设为首页 | 挪到第一位；别的页先后不变 |
| 删除 | 只剩一页不能删。**不连带删别处的引用**：指着它的“去页面”积木和导航项留着，校验标成错误、导出时跳过，让她自己决定改去哪。删之前说清楚里面有几个组件几串逻辑、别的页还有几处指着它。能撤销 |

每个操作一条撤销。整个项目一条撤销线；撤销 / 重做以后人跟到“那一步所在的页”（在别的页时说一句）。只换页不算一步、不存盘。

**四、编辑器里从哪进（390×844）**

- 顶栏右边多一个按钮：纸张图标＋“N 页”；⋮ 菜单第一项也是“页面”。副标题在不止一页时多“第 2/3 页”。
- 点开是底部面板，一页一行：图标、页名、下面一行小字（正在编辑 / 首页 / 几个组件 / 几串逻辑）、行尾 ⋮。
  **点一行＝换到那一页**（面板的主要用途）；这一页能做的别的事都收在行尾 ⋮ 里；最下面一个描边按钮“＋ 新建页面”。
- 每一页各有各的画布状态（缩放、滚到哪儿）；换页以后没有选中的组件。

**五、怎么跳页**

- 积木：新的一块 **“去页面〔页面〕”**（分类“交互”，代码名 `goPage`，参数 `page`＝页面 id）。
- 快捷操作（§11.2）：事件页第一行“点击时去页面”。存法照 §11.2——“点击时”帽子下面只有一块 `goPage`，进积木编辑器能看到能改；又接了别的块就不再算快捷操作。
- 底部导航项：每项多一行“点了去：〔页面〕”，存在导航项的 `page`（第 3 版就留好的字段）。
- 没选、页面已经删掉：校验报错误（`pageNotFound`），那一页的脚本不更新；导出时这一块翻成一行注释跳过。

**六、导出成几个文件、各自怎么跳**

| 导出 | 文件 | 跳页 | 底部导航 |
|---|---|---|---|
| 普通网页（存盘时自动出） | 首页 `index.html` / `style.css` / `logic.js`（和以前一样）；别的页 `page-<页面id>.html` / `.css` / `.js` | 换地址：`location.href = "page-p2.html"` | 去别的页的项点了换地址；当前这页的那一项不能点 |
| Vue 3 | 一个外壳 `LcApp.vue`＋每页一个 `.vue`＋共用的组件 `components/*.vue` 各一份 | 改地址栏 `#/页面id`；外壳听 `hashchange` 换页 | 同上，改的是 `location.hash` |
| React | 外壳 `LcApp.jsx`＋每页一个 `.jsx`/`.css`＋共用组件 | 同 Vue | 同 Vue |
| Flutter | 还是一个文件 `export/page.dart`，里面每页一个类（首页的类排第一） | `Navigator.push`（叠一页，系统返回能回来） | `Navigator.pushReplacement`（换一页，不往上叠） |

- Vue / React **不引路由库**（不替她的工程加依赖）：外壳只有二十来行，注释里写明“想换成正式的路由，把那几句 `location.hash` 换掉”。在她的工程里要挂的是外壳，不是某一页。
- 文件名、类名全项目不撞：页名转不出英文的叫 `LcPage`、`LcPage2`…；页面、组件、外壳重名的后来的加数字。
- 删了页 / 换了首页以后，上一次导出留下的 `page-<id>.*` 没人要了：存盘时清掉（只清开头带着我们标记的，用户自己写的同名文件不碰）。
- 换了首页、新首页的逻辑又有错误（脚本不更新）时，`logic.js` 可能还是上一个首页的：多页时首页脚本第二行带“// 页面：id”，对不上就删，不让一页跑另一页的逻辑。
- **只有一页的项目，四种导出和以前逐字节一样**（导出基准没动）。
- Flutter 这一份的局限没变：积木逻辑不导出。所以只有“快捷操作设的去页面”和底部导航会跳；写在“如果”里面的“去页面”在 Flutter 导出里不起作用。

**七、底部导航怎么跨页共用**

- 文件里**没有**“共用的导航栏”这种东西：导航栏在每一页里都是一个普通组件，各存各的。这样导出、老版本、Agent 看到的都是每页自己那一条，没有“这一条到底归谁”的问题。
- 要几页长得一样：在一页上改好，点导航项那一块最下面的 **“同步到其它页面”**——把这条的导航项、样子、样式（含按下时的样式）抄到**它指向的每一页**
  （那一页已经有导航栏就改第一条，没有就在页面最后加一条），每页的“当前项”设成指向它自己的那一项。做之前说清楚会改哪几页；一次同步一条撤销。
- **不自动联动**：以后再改，别的页不会自己跟着变，要再点一次。好处是哪一页想留点不一样的也可以；坏处是要记得点。
  （真正的“改一处处处变”等组件库那一期：把导航栏存成一个项目级的组件来用，那时才有干净的办法。）

**八、自定义组件属于项目，不属于某一页**

- 定下来：**项目级**。`components` 还在文件最外层，所有页面共用；组件盒“我的组件”在哪一页都是同一批。
- 旧文件：`components` 本来就在最外层，原样读，一个字段都不用挪。
- §10.5“要改的”第一条在这一期兑现了一半：“用了几处 / 删定义时连实例一起处理 / 插槽改名时实例跟着改 / 取消插槽时把内容挪出来”现在**扫所有页面**
  （删定义、清逻辑也是每页清各自的）。跨项目共用、版本、从库里找定义，还是第 6 期的事。

**九、给后面两段留的路（没做，只是不堵）**

- 主题变量（B2）：`theme` 还是文件最外层的字段，本来就是项目级，所有页面共用。四种导出里每页都有自己的样式文件 / 样式块，主题变量要写进**每一页**的
  （网页：每个 `*.css`；Vue / React：建议放外壳或共用的那份基础样式里，一处就够）。
- 断点（B2）：`responsive` 是节点上的字段，跟页面无关。“同步到其它页面”现在只抄 `props`、`style`、`states`，到时要把 `responsive` 也抄上。
- 数据绑定（B3）：变量现在**每页一份**（在各页的 `logic.variables` 里）。跨页共用的数据（比如登录的人）放哪，B3 要先定——
  建议：项目级变量另起一个最外层字段，页面里照旧用名字引用，重名时页面自己的优先。Vue / React 的外壳是放它们的现成位置；普通网页换页会整页重载，跨页的数据得走 `sessionStorage`。
- 页面之间带参数（“去商品详情，带上 id”）没做：`goPage` 的 `args` 以后可以加一个 `params`，现在的写法不挡它。

### 10.7 第 4 期第 2 段（B2）：主题变量＋断点（2026-11-27）

先是定下来的做法，后面是和 §5.5、§6.1、§6.2、§10.6 的出入。数据绑定不在这一段。

**一、主题变量放哪、长什么样**

- 放在页面文件最外层的 `theme`（格式文档早留好的字段）：`{"vars": {名: 值}, "labels": {名: 给人看的名字}}`。整个项目共用——所有页面、所有自定义组件。
- 名字只用小写字母、数字、连字符。开头决定种类：`color-` 颜色、`font-` 字号、`space-` 间距、`radius-` 圆角，别的算“其它”。
  种类决定它在面板里出现在哪：颜色变量只出现在取色面板里，字号变量只出现在字号那一格……不会让人把颜色填进圆角。
- 用的地方写 `var(--名)`，就写在节点的 `style` 里（状态样式、断点差别里也一样）。**不发明新写法**：导出时这句原样就是合法的 CSS。
- 改一个变量的值：只改 `theme.vars` 这一处，用到的地方不用动，画布和导出自然跟着变。
- 改变量的代码名：扫所有页面、所有自定义组件定义的 `style` / `states` / `responsive`，以及别的变量的值，一起改。
- 删变量：用到的地方换成它当时的值（样子不变，只是不再跟着变）；删之前告诉她有几处在用。
- 起步的一套（16 个，点一下加进去）：6 个颜色、4 个字号、3 个间距、3 个圆角。数值取自应用自己的刻度。

**二、从哪进、怎么用**

- 管理：搭建页顶栏 ⋮ ›“主题变量”，一张整页。按种类分节，一行一个变量：值（色块或数值）在最前面，然后是名字和“用了几处”。
  点一行在底部面板里改（名字 → 值 → 代码名），删除在面板左下。一个变量都没有时是空页＋“加一套起步的变量”。
- 用（三个地方，都是“复用现有入口”，没有新开一套界面）：
  1. “常用”页的预设档那几行（字号、间距、圆角……）：点“更多”展开后，最下面一排是这一类的变量牌，点一下就用上。
  2. “样式”页的数值格：单位菜单里多一项“用变量…”。
  3. 取色面板：最上面多一节“主题色”。
- 看得出来自变量：数值格整格换成一块带链环图标的牌子（名字＋现在的值）；颜色按钮前面多一个链环、字写变量的名字；预设档那一行行首是变量牌。
  想换回普通值：点格子右边的 ✕，或在取色面板里另选一个颜色。

**三、断点**

- 三档固定，手机优先：手机（默认，不带条件）、平板（≥768）、桌面（≥1024）。平板的差别在桌面上也生效，桌面的再盖在上面——和导出的媒体查询行为一致。
- 存在节点的 `responsive.<档>.style` 里，只存“和下面几层不一样的那几条”；改回和下面一样，这条就自动去掉。
- 顶栏多一个设备图标按钮（手机 / 平板 / 桌面）。切到平板、桌面：画布把页面按 768 / 1024 宽来排，再整体缩小到 390 的屏里放得下（双指还能放大看细处）；
  图标变成强调色，副标题写“平板 768”。
- 这时“样式”页顶上有一条提示：“现在改的只在平板及更宽的屏上生效：只记和手机不一样的地方。”这一档改过东西时右边有“清掉”（一键清掉这个组件在这一档的全部差别）。
  每一格右边原有的 ✕ 清的是这一档的这一条。没在这一档改过的格子显示的是下面那一层的值，灰字写“跟手机一样”。
- “常用”页在平板、桌面档不写断点差别（它改的是简写属性，所有屏宽共用），顶上的提示说明这一点，并给一个“去样式页”。
- 在画布上拖拖柄改大小：手机档写进平常的样式，平板 / 桌面档写进那一档的差别。
- “屏宽与缩放”面板里的屏宽档（自适应 / 360 / 390 / 768）还是“只是看看”，不切档；在那里挑了宽度就回到手机档。
- “同步到其它页面”（底部导航）把 `responsive` 也抄上了。

**四、四种导出**

| 导出 | 主题变量 | 断点 |
|---|---|---|
| 纯网页 | 每个页面的 css 开头一段 `:root { --名: 值; }` | 每个页面的 css 最后：`@media (min-width: 768px) { … }`、`@media (min-width: 1024px) { … }` |
| Vue 3 | 多页面：外壳 `LcApp.vue` 里一段**不带 scoped** 的 `<style>`；单页面：页面文件里同样一段 | 各页面（和组件）自己的样式块最后，媒体查询 |
| React | 共用的 `lc-base.css` 里 | 各页面（和组件）自己的 css 最后，媒体查询 |
| Flutter | **写死成导出那一刻的值**（认得的那几样：底色、文字颜色、字号、内外边距、圆角、间距、宽高）；文件头有一句说明，改了变量要重新导出 | **不导出**，出来的是手机的样子；文件头有一句说明 |

- 只有项目里**真的有地方用到变量**才写 `:root` 那一段；没用到就不写。所以没用变量、没用断点的页面，导出和以前逐字节一样（基准测试没动）。
- 断点里“这一档把某条去掉了”导出成 `属性: initial`。
- Flutter 的局限为什么这样定：现在的 Flutter 导出是一份不带状态、不依赖外部包的静态页面代码，变量要“活”就得生成一个主题类并让每个值去查它，
  断点要生成按屏宽分支的布局——都是把导出器重写一遍的量。先如实写成“当时的值 / 手机的样子”，并在导出文件的开头讲明（导出面板上没有另外提示）。

**六、已知的局限（如实）**

- 画布是 Flutter 近似画的：变量先换成值再画，带后备值的 `var()` 认得，`calc(var(--x) * 2)` 这种算式画布不会算（没专门测过它在画布上显示成什么）。
- 断点里用 `initial` 去掉一条：对会继承的属性（文字颜色、字号等），真网页上回到的是属性的初始值，不是手机档从外层继承来的值；画布上是“当这条没写”。两边可能不一样。
  平常用不到（要在平板档把手机档写的一条清空才会碰到）。
- 状态样式（按下、禁用、聚焦）不分档。
- 断点只按屏幕宽，不按容器宽。
- 变量的值不检查“用的地方合不合适”（比如把一个字号变量手写进颜色里）：面板不会让你这么选，但手写 CSS 能写出来，写错了那条在网页上不生效。

**七、给下一段（数据绑定）留的路**

- 变量替换和断点合并都在“读样式”这一层（`lcViewNode`）做，节点本身不改。数据绑定要在画布上显示绑定的值时，可以在同一层再套一道，不用动画布。
- `style` 里的值现在可能是 `var(--x)`。绑定如果也要绑样式，别抢 `var(` 这个开头。
- 主题变量是“设计时就定下来的常量”，不是运行时的状态；别把两者混成一个字段。要运行时换主题（深色模式）是另一件事，建议到时在 `theme` 下加“第二套值”，而不是让变量可绑定。

### 10.8 第 5 期（B3）：状态与数据绑定的编辑器侧（2026-11-27；补 GAP-E-16）

这一段只做编辑器侧：模型、面板、画布预览、四种导出。积木怎么读写状态、浏览器目标、前端库是下一轮“前端 1”的事。
字段格式见 `docs/lowcode-page-format-v3.md`“第 5 期 B3 之后的补充说明”，导出写法的核对见 `docs/api-notes.md`。

**状态放哪**

- 页面级状态＝每页原有的那份“变量”（`logic.variables`）。**不另起一份**：同一张表两个入口（积木编辑器里原来叫“变量”，第四轮起两边都叫“状态”；“状态”页里叫“这一页的状态”）。旧页面的变量一个不丢、不用迁移，直接就是页面级状态。
- 项目级状态（跨页共用）放最外层新字段 `state`（数组，每项和变量同一个写法）。照 B1 的建议：页面里有同名的，用页面自己的。
- 种类：文字、数字、是 / 否、列表、记录（后两种是这一期放开的）。初值是对应的 JSON 值。可以是“派生值”（多一个 `derived` 式子，不能直接改）。
  项目级派生值只能读项目级状态。
- 管理入口：搭建页顶栏“⋮”→“状态”。两节（这一页 / 整个项目）；新建、新建派生值、改（名字、类型、初值）、删、看哪里在用、在两层之间挪。
  改名会扫：所有页面的绑定、派生值、积木，以及组件定义；项目级的改名跳过“自己有同名状态”的页面（那一页用的不是它）。
  删除不自动改用到它的地方，由检查标出来（“状态”页顶上列出这一页的问题）。

**8 种绑定落在哪**（都是节点上的可选字段，是控件的设置、不是积木）

| D 分册的叫法 | 字段 | 面板里在哪 |
|---|---|---|
| 文字、属性 | `data.<属性名>` | “常用”页每个能绑的设置行尾一个链环；绑了以后这一行换成一个药丸（写着绑的是什么），药丸上的 ✕ 解除 |
| 显示条件 | `showIf` | “常用”页最下面“数据”一节 |
| 存在条件 | `renderIf` | “数据”›“更多绑定” |
| 重复 | `repeat` | “数据”一节，点开一张单子：列表、这一项叫什么、第几个叫什么、每项的标识、空的时候的一句话、画布先画几份 |
| 类名开关 | `classIf` | “数据”›“更多绑定” |
| 样式 | `styles` | “数据”›“更多绑定” |
| 双向 | `model` | 输入框、多行输入、开关、勾选框、单选组、下拉的“数据”一节第一行“跟状态同步” |

列表组件的“列表项”也能绑（上一轮留的“列表数据源”缺口）：绑一个列表状态。

**绑的是什么（式子怎么填）**：面板提供三种填法——“用一个值”（挑一个状态、记录里的一格、重复带出来的“这一项”）、“拼一段文字”（`你好，{user}`）、
“比较”（左 比较符 右）。存的仍是值积木的存法（来源 `var` 或 `expr`），所以下一期接上值积木画布以后，更复杂的式子不用改格式。

**画布**：按初值预览。绑的文字 / 属性换成按初值算出来的；重复按初值的列表画前几份（默认 3，最多 5），带“重复”角标，副本半透明；
条件按初值不成立的照样占位（不然选不中），调淡并带“条件不成立”角标。

**顺手做的**：样式页“布局”第一行加了“显示”开关（写 `display`；在平板 / 桌面档下关掉只记成那一档的差别——GAP-E-16）；“编辑组件”页顶栏也有切屏宽的按钮。

**四种导出**

- 普通网页：`logic.js` 里自带一小段状态与绑定的运行代码；项目级状态放浏览器的 `sessionStorage`（换页还在，关掉标签页就没）。
- Vue 3：页面级 `ref`、派生 `computed`、项目级在 `lc-state.js` 里一个 `reactive` 对象；模板里用 `v-model`、`v-for`＋`:key`、`v-if`、`v-show`、`:class`、`:style`。
- React：页面级沿用原来的 `lcVars`＋`lcRefresh`，派生值现算；项目级在 `lc-state.js` 里一个组件外的对象，页面用 `useSyncExternalStore` 订着。
- Flutter：不导出逻辑，状态不会变，所以**按初值定下来**（文字算好、重复按初值展开最多 200 份、条件不成立的不出、输入框不写回），文件头写明。
- 没用绑定的页面，四种导出一个字不变（只建了状态、哪儿都没绑也一样）。

**和前面写的有出入的地方**

1. D §4.7 的字段名是 `binds` / `repeat{each,as,…}` / `model{state,path}`；实际用的是格式文档第 3 版早就留好的 `data` / `repeat{list,item,index,key,empty,preview}`，`model` 只存状态名。
   理由：格式文档先定、且已有测试钉着；D 的写法只是草稿。D §4.7 已加一句指到这里。
2. `repeat.empty` 格式文档原写“节点数组”，这一期做成**一句文字**（列表是空的时候显示它）。要放任意控件留给以后。
3. 双向只能绑“一个状态本身”，不能绑“记录里的一格”（D 写的 `path`）。
4. §7.2 说绑定的式子用“值积木小画布”填；这一期没做小画布，用上面三种填法顶着。
5. D 说 React 页面级状态也放外部仓库；这一期页面级沿用已有的 `lcVars`＋`lcRefresh`（改动最小、旧导出不变），只有项目级用外部仓库。要霜霜定。
6. 页面级状态没有另起字段，就是 `logic.variables`（D §4.7 说“variables 每项多一个 kind”，实际用有没有 `derived` 来分）。

**这一期的局限（都写进了导出文件的说明或检查提示里）**

- “重复”出来的每一份里，按钮的事件处理是同一个，处理里拿不到“是哪一项”——留给前端 1。

  积木“设置状态”（原“设置变量”，积木上的字由线 A 改）在 Vue / React 目标里对项目级状态的写法已经接了 `lookup`（`JsLogicWriter(doc, target, lookup: …)`）。

### 10.9 第四轮 B1：底部导航跨页共用、“常用”页分屏宽、Flutter 导出跟上、叫法统一（2026-11-27）

**一、底部导航跨页共用（代替 §10.6 的“手动同步”）**

- 存法（格式文档有补充说明）：页面文件最外层多一个可选的 `shared.bottomNav`，是这条导航栏**唯一的一份**内容（导航项、样子、颜色、样式、状态样式、断点差别、绑定）；
  哪一页显示它，就在那一页的树里放一个带 `shared: true` 的 `bottomNav` 节点，文件里这个节点只写 id 这些记号。没放＝这一页不显示。
  所以“放在页面的哪儿”还是每页自己的事（一般在最后），内容是项目的事。
- 在一页上改它（名字、图标、去哪页、顺序、增删、样子、“样式”页里的东西），所有显示它的页面一起变，不用点同步。
  实现上内存里每页那个节点都带着全内容（画布、面板、四种导出都不用知道“共用”这回事）；每次修改后（记撤销之前）以当前页那条为准抄给别的页。
- 当前项自动算：哪一项“点了去”指着这一页，在这一页上就亮哪一项；没有哪一项指着这一页时亮第一项
  （Flutter 的 `NavigationBar` 必须选中一项，所以没有“都不亮”）。共用的导航栏上，面板里那个选中圈只是给看、点不了。
- 入口：
  - 选中导航栏 ›“常用”› 导航项下面：没共用时一个按钮“改成各页共用…”。各页一样（或只有这一页有）→ 一个确认框说清楚哪几页会换成共用、哪几页会加上；
    各页不一样 → 先出“以哪一页的为准”的单子，写明别的页的会被换掉。
  - 共用以后同一个位置是一条说明“各页共用 · N 个页面在显示…”，下面“这一页不显示”“取消共用…”。
  - 右上角“页面”› 某一页的 ⋮ ›“这一页显示 / 不显示底部导航”（项目里有共用的导航栏才有这一项）；不显示的页在那一行小字里写着。
  - 把共用导航的某一项指到一个还没显示它的页：那一页顺手加上（同一条撤销）。
  - 多页面的项目里第一次放导航栏：从一开始就是共用的。已经有共用的、这一页还没显示时再拖一条进来：就是共用的那一条。
- “改成共用”的规矩：已经有导航栏的页都换成共用的；导航项指着、却还没有导航栏的页在最后加一条；别的页不动。取消共用：各页留着当时的样子，变回各管各的。
- 旧文件（每页各一份）照常打开、不改写；没用共用的文件存出来和以前逐字节一样。原来的“同步到其它页面”按钮没有了（它做的事被“改成各页共用”盖住了）。
- 导出：四种导出每一页里各写一份内容相同的导航（各页亮各自那一项）。**没有**抽成一个公共文件 / 公共组件——抽出来更干净，
  但四个导出器都要多一种“跨页的公共部件”，留给第 6 期组件库一起做。
- 顶部导航栏**没有**做成共用，原因：每页的标题、要不要返回箭头、左右插槽里放的按钮（它们的点击逻辑是每页一份的）通常都不一样，
  整条共用以后几乎每页都要“这一页单独改”，等于要先有“共用＋每页覆盖”的机制，那就是组件库里“实例属性覆盖”的事（第 6 期）。

**二、“常用”页的设置也分屏宽（代替 §10.7 里“常用页改的是所有屏宽共用的”）**

- 规矩：画布切到平板 / 桌面档时，“常用”页里**改样子的**（内外边距、间距、圆角、字号、文字级别、颜色、对齐、分布、方向、换行、宽度、高度、
  按钮的样子 / 大小、图片的填充方式 / 宽高比、阴影、最多几行、加粗）只对这一档及更宽的屏生效；**改内容的**（文字、图片地址、输入框类型、默认值、标签、
  必填 / 禁用、图标、导航项 / 选项、组件实例的属性、绑定）不分屏宽，那一行的名字下面有一行小灰字“不分屏宽”。
- 存法和“样式”页完全一样：记进 `responsive.<档>.style`，只记和下面那层（手机、更窄的档）不一样的条目；手机那份简写属性和 `style` 一个字不动。
  所以画布、四种导出（媒体查询）不用另做，“样式”页在这一档能看到、能接着改“常用”页写的东西，提示条上的“清掉”也是同一个。
- 实现（`inspector_bp_write.dart`）：不是一项一项认，而是在一个临时节点上把这次改动原样跑一遍（临时节点的样式＝这一档看到的那份），
  比较**最终样式**前后差在哪，差出来的记进这一档；改动里不落到样式上的部分照旧写到节点上。新加一种“常用”设置不用再改这里。
  “清掉 / 关掉”在这一档的意思是“这一档不再管它”；要是下面那层的值因此又冒出来（手机上加粗、平板上要不加粗），就明写一个回到没设过的值（`font-weight: 400`、`padding: 0px`…）。
- 显示：这一档的“常用”页显示的是这一档看到的值（对齐、分布、宽度的“占满”按最终样式反推，不看手机的简写属性）。
- “编辑组件”页顶栏的屏宽按钮（§10.8 已有）走的是同一块面板，所以组件定义里也一样分屏宽。
- **状态样式（按下 / 禁用 / 聚焦时）还是不分屏宽**，原因：状态样式现在存成 `states.<状态>` 一张平的表，要分屏宽得新加一层存法（`responsive.<档>.states`），
  画布预览、四种导出（媒体查询里再套 `:active` / `:disabled` / `:focus`）、Flutter 那边的状态样式都要各加一层；这一段先把“常用”页和 Flutter 导出做实，
  这一层没有排进来。面板上照旧明说“‘按下时’的样子不分屏宽：现在改的在手机上也生效”。
- 没有做“显示 / 隐藏”在“常用”页的入口：它在“样式”页›布局第一行（§10.8），那里本来就分屏宽。

**三、Flutter 导出读主题变量、状态与绑定、断点，补上状态样式和网格（代替 §10.7 四、§10.8 里“Flutter 按初值定下来”）**

- 什么时候走新路：项目里用了主题变量、状态与绑定、断点、状态样式、网格中的任何一样，Flutter 导出走“会动的那一路”
  （`export_dart_live*.dart`）；一样都没用的项目走原来的路，导出结果和以前**逐字节一样**（基线没动；九个检入样本里六个没变，
  变的三个是用了变量 / 断点 / 状态样式 / 网格的那三个）。只定义了变量、哪儿都没用也不算。
- 主题变量：文件末尾一个 `LcVars` 类，颜色是 `Color`、长度是 `double`，每个变量一行、注释里写它的中文名和 `--名字`；
  用到变量的地方写 `LcVars.colorPrimary`。改变量表里的一个值，用到的地方全变。不是长度也不是颜色的变量（字体名之类）写成一行注释。
- 状态：有绑定的页面导出成 StatefulWidget；这一页的状态是 State 类里 `s_` 开头的字段（派生的是 getter），跨页共用的在
  `LcAppState` 里（静态字段 + 一个通知器，开着的页面都听着）。在自己的代码里改状态：`update(() => s_xxx = 新值)` /
  `LcAppState.update(() => LcAppState.xxx = 新值)`，界面自己重画。
- 8 种绑定各是怎么出的：

  | 绑定 | Flutter 里 | 说明 |
  | --- | --- | --- |
  | 文字、属性 | 直接读状态的一句式子 | 文字类的都行；“禁用”是把禁用的、没禁用的各生成一份，运行时挑；列表内容是 `for`；图片地址运行时分网上的 / 项目里的 |
  | 显示条件 | 列表里的 `if` | 和存在条件一样出（输入框的字放在状态里，不会因为藏起来丢） |
  | 存在条件 | 列表里的 `if` | |
  | 重复 | 列表里的 `for (final (序号, 这一项) in 列表.indexed)` | “列表是空的时候”那句是另一项 `if (列表.isEmpty)`；没有 200 份的上限了；“每项的标识”没用上（见下） |
  | 类名开关 | **导不出** | 见下 |
  | 样式 | 底色、文字颜色、字号、内外边距、圆角、间距、宽、高 这 10 条认得 | 别的 CSS 属性导不出，逐条写在文件头 |
  | 双向 | 输入框 / 多行输入框（控制器 + `onChanged`）、开关、勾选框、单选组（两种样子）、下拉选择 | 数字状态写回去的是数 |

- 断点：每一档屏宽各有一个 build 方法（`_buildPhone` / `_buildTablet` / `_buildDesktop`），`build` 里按 `MediaQuery` 的宽度
  从宽到窄挑（≥1024、≥768）。每一档的树是按“那一档的最终样式”折回简写属性得到的：字号、颜色、内外边距、圆角、间距、宽高、
  加粗、文字对齐、对齐 / 分布、横排 / 竖排、显示 / 隐藏、网格列数都跟着档变。两档出来一模一样的只留一份。
- 状态样式：按钮“按下 / 禁用”时的底色、文字颜色（`WidgetStateProperty`）；输入框 / 多行输入框“聚焦”时的边框颜色（`focusedBorder`）。
- 网格：等宽 N 列用 `LayoutBuilder` + `Wrap` 排，格子宽度按列数、列间距算，跨列（`span N`）的格子宽 N 格；行间距、列间距分开。
- 实现办法（为什么原来的生成器几乎没动）：生成前先把这一档的样式折回简写属性；值是变量、或者要到运行时才知道的，先放一个
  文档里没出现过的**占位值**（一个数 / 一个颜色 / 一段文字），生成完再把占位值换成真正的那句 Dart，并去掉 `const`。
  生成器里只加了几个接入点（`export_dart_hook.dart`）：节点外面套 `for` / `if`、页面级的栏、网格、双向的读写、图片地址、列表内容。
- **导不出来的，逐条**（导出文件开头也会写）：
  1. **类名开关**：Flutter 里没有“类名”，类名对应的样子在编辑器里现在也没有地方配（“类名开关配样子的地方”是第 6 期的事）。
     试过的路：把它当成“条件成立时叠一份样式”——但没有那份样式可叠。等第 6 期有了配样子的地方，按“条件成立时用另一组简写属性”接进来。
  2. **样式绑定里别的 CSS 属性**（比如 `letter-spacing`、`transform`）：Flutter 这边的生成器只认上面那 10 条，别的没有对得上的写法。
  3. **别的状态样式**（容器 / 卡片 / 文字“按下时”换样子，按钮按下时换圆角、字号…）：Flutter 里只有按钮、输入框有现成的
     “某个状态下换样子”的口子；别的要给每个控件包一层自己记“按下没有”的壳，这一段没有做。
  4. **四边不一样的内外边距 / 圆角、横竖不一样的间距**：生成器一直只认“四边一样”（`EdgeInsets.all`）；写了不一样的那个组件按简写属性里的值出。
  5. **“每项的标识”**：重复出来的每一份没有带 Flutter 的 key。带 key 得包一层 `KeyedSubtree`，而行里的子组件外面那层必须是
     `Expanded` / `Flexible`（中间不能隔东西），两个要求打架；影响是列表增删时每一份里的输入框光标可能跳。
  6. **样式里别的东西**（边框、阴影的细节、定位、过渡…）：和以前一样不读，Flutter 这一份只读能折回简写属性的那几样。
  7. **弹窗的断点**：弹窗按手机那一档的样子出（弹窗里绑的内容会跟着状态变）。
  8. **积木逻辑**：这一份一直不导出（按钮的 `onPressed` 是空的；“去页面”的快捷操作和底部导航除外）。所以状态只会被双向的控件
     和导出代码使用者自己的代码改。页面逻辑怎么翻成 Dart 属于“前端目标语言”那一段（线 A 的前端 1 / 2 只做了 JS / TS）。
- 验证：`test/lowcode_dart_live_test.dart`（13 条）——三个检入样本和导出器输出逐字节一致；在 390 宽和 800 宽（另有 1100 宽）下真的装进界面，
  没有异常、没有溢出；改状态后界面确实变了（打字、点开关 / 勾选框 / 单选 / 下拉、`update(...)`、`LcAppState.update(...)`、弹窗开着时改状态）。

**四、叫法统一成“状态”**

- 界面、积木、文档都叫“状态”；存盘字段名（`variables`、`state`、`{"var": …}`）不改；“主题变量”是另一回事，不改名。
- 编辑器这一侧原本就只叫“状态”（状态页、绑定选择器、面板、检查问题的文字），这次只改了状态页上两句提到“变量”的说明，
  以及本分册里的用词。积木上的字（“设置变量”“变量加上”“变量的值”、积木盒“变量”一类、“页面变量”面板、“新建变量…”、
  检查问题里的“变量 xx 还没有声明”等）归线 A，清单记在进度本“文件分工”下面。
- 没改的一处：导出的 Vue / React / `logic.js` 里的注释还写着“页面变量”——那是导出内容，改了旧页面的导出就不是逐字节一样了，
  而且这几行在线 A 名下的逻辑接入点里。要改得连基线一起重出，留给协调者定。

### 10.10 第四轮 B2：第 6 期·组件库（2026-11-27）

**做了的（手机上找得到入口）**

1. **组件的事件**。编辑组件页 ⋮ ›“事件”：加事件（名字、叫法）；选中组件里的一个控件，在同一张表里点“让它的点击往外发”/“让它的输入往外发”。用组件的页面：选中实例 ›“常用”页多出“组件的事件”一组，一个事件一行，挑一个快捷动作（去页面、打开网址、弹出提示、打开弹窗、关闭弹窗、让一个数字加 1）。
2. **变体**。编辑组件页 ⋮ ›“变体”：加变体（可以分组，比如“样子”“大小”，一组里实例只能选一个）；点一个变体进入“正在改变体”，这时在样式面板改的只记成这个变体的差别，点顶栏“改完变体”回到平时的样子。实例 ›“常用”›“样子”一组里选。
3. **实例属性绑状态、组件自己的状态**。实例 ›“常用”›“属性跟着状态变”一组：每个属性一行，挑一个页面状态。编辑组件页里样式面板的“数据”页现在能用（能挑的是组件的属性和组件自己的状态）；⋮ ›“组件的状态”开的是现成的状态页。组件自己的状态每个实例一份。属性类型多了“列表”（只能绑，不能在面板里填）。
4. **类名开关配样子**。选中控件 › 样式页顶上“状态”一行，多出“类名 xx”的药丸（这个控件有几条类名开关就有几个）；点了以后样式面板改的就是这条类名成立时的样子。纯网页／Vue／React 写成 `.控件.类名 { … }`；Flutter 按“条件成立时用另一组属性”导出（只认底色、文字颜色、字号、内外边距、圆角、间距、宽、高）。
5. **用户自己的组件库**。搭建页 ⋮ ›“组件库”：“把组件存成一个库”（名字、标识 `作者段/库名`、版本、作者、勾选组件）；“从文件导入”（先看预览，点了头才落盘）；每个库 ⋮：导出成文件、再存一版、看里面的组件（里面有“复制一份来改”）、放进组件盒、从项目里拿掉。选中一个自定义组件的实例 › 更多 ›“存进库…”直接开存库那张表并勾上它。组件盒“我的”里：项目自己的一组，然后一个库一组。库里的组件不能直接改：“编辑组件”会问要不要复制一份来改。

**怎么存的**（细节在 docs/lowcode-page-format-v3.md“第四轮 B2 之后的补充说明”）

- 定义上：`events`、`variants`、`state`；定义里的节点上：`emit`；实例上：`variant`、`on`、`data`；类名开关每项多一个 `style`；库里来的定义多一笔 `lib`；文档上 `compLibs` 记这个项目自己做了哪些库。全是可选字段，版本号没动。
- 库在项目里：`components/作者段/库名/`（`lib.json`、`components.json`、`images.json`），登记表 `components/libs.json`——和积木库的 `blocks/libs.json` 并列的一张，写法一样（`format`、`libs: [{id, version, from, sum}]`）。导出文件是积木库同一种 `.lopilib` 包，用的是同一套打包拆包和防护（整包 8MB、512 个文件、单个 1MB、路径不许往外跳、内容必须是文字、不从网址导入）。图片转成 base64 放在 `images.json` 里，一共最多 700KB，超了的不带、在预览里说“没带上”。

**导出怎么落地（和 §8 原设想的出入）**

- 原设想：Vue／React 的组件文件自己带属性、事件（defineEmits／回调属性）、状态。**实际做法**：四种导出在动手前都先过一遍 `lcExportDoc`——页面上只要有“用了新东西”的实例（定义有事件／变体／状态／绑定，或者实例选了变体、接了事件、绑了属性），就把这些实例**摊开进页面**再导出：读属性的地方换成实例给的值或式子；组件状态改名成 `<实例 id>__<状态名>` 提升成页面状态（所以每个实例一份）；“控件往外发＋实例接了动作”合成一条“当那个控件被点击”的页面处理；变体的样式叠在定义样式上。没用新东西的组件照旧出组件文件，旧页面四种导出逐字节不变（基线没重出）。
- 这样做的好处：四种导出一个办法、行为一致，三种形状都真编译真跑过；代价：用了新东西的组件在 Vue／React 里不是一个单独的组件文件，同一个组件用十次就摊开十次。要不要再做成真正的组件文件，留给下一段和霜霜定（见给协调者的清单）。
- 事件带出的数据（`emit.args`）已经存了，但合成的页面处理里拿不到——要等页面逻辑那一侧有“当〔实例〕发出〔事件〕”的帽子（线 A）。

**自定的数**：一个组件最多 12 个事件、4 组变体、每组 8 个、24 个自己的状态、一个事件最多带 6 项数据；名字规矩 `^[A-Za-z][A-Za-z0-9_]{0,23}$`；一个库最多 64 个组件、图片一共 700KB；一个项目最多 64 个组件库；库的名字最多 40 字。

**这一段没排进去的（按任务给的取舍顺序，排在后面的四件）**

- 顶部导航栏共用、导出里把共用导航抽成公共部件：没动。卡在哪：要先给“共用的那一条”定存法（放 `sharedNav` 里再加一种，还是做成一个内置组件的实例＋每页覆盖），四种导出各要一套抽法，旧页面逐字节不变要逐个核；这一段的时间用在了前两条和三遍全流程上。
- 内置封装组件改成库定义、“内置组件库”在界面上出现：没动。先要逐个核“改成定义以后四种导出逐字节不变”，这是硬条件，没核之前不敢动。
- P1 组件（图标按钮、链接、网格、滚动区、步进器、表单项、滑块）：没动。
**“拆开成普通控件”遇到用了新东西的实例**：拆的是当前页上的实例时，它那一份组件状态落成页面状态（名字 `<实例 id>__<状态名>`）、接的事件落成页面处理（指向拆出来以后的那个控件），绑定照旧能用；拆的是别的组件定义里面的实例时只拆结构（定义里没有页面状态可落）。

**给下一段（B3）接着做的顺序**：顶部导航共用（建议沿用 `nav_shared.dart` 的办法：最外层 `shared.topNav` 一份＋每页节点上只留“这一页改了的”标题、返回箭头、左右插槽里的东西）→ 公共部件 → 内置封装组件逐个核“改成定义后四种导出逐字节不变” → P1 组件。

### 11.1 现在

### 11.2 改成

**去**：选中按钮 → 选中条“逻辑”（或面板的“事件”页）：

```
┌──────────────────────────────────────┐
│ ━━━━ │
│ 按钮“登录” │
│ ( 常用)( 样式)( 事件) │
│──────────────────────────────────────│
│ 点击时 3 块积木 › │ 有逻辑：一句话概括，点进去
```

**在那边**：
- 积木编辑器顶栏标题第二行小字写“按钮“登录” · 点击时”，她知道自己在给谁写。

- 按钮在画布上多一个 ⚡ 角标；图层里那行也有。
- 删除带逻辑的组件先问（现在已有，测试“删除被逻辑用到的组件先问”）。改名时积木里跟着变（积木里存的是编号不是名字，本来就不会断）。

**出错往回指**：积木的问题清单里“这块用到的组件已经被删了”→ 点它能跳回搭建页并提示是哪个；“试一试”里运行时报错 → 能跳到那块积木（GAP-E-10）。

### 11.3 和语言核心的关系（给协调者）

- 页面逻辑应该就是“语言核心的积木 + 一个‘页面’库”：事件帽子、“设置属性”、“显示 / 隐藏”、“跳转页面”都是库里的积木，底下是 L0 的浏览器接口。有了数据绑定以后，“设置 X 的文字”这类积木会少用很多——改变量就行。
- 组件的事件 = 库里自动生成的一种帽子（“当 <组件> <事件名> 时”，带出的值是帽子上的可拖出参数）。这要求库格式能表达“组件声明了事件 → 积木盒里出现对应帽子”（8.4 的要求 a）。

### 和设计骨架不一致的地方

1. **“除语言基础和基础库外所有能力都靠封装”对组件不完全成立**。有 13 个原生组件拼不出来，只能是 L0 宿主原生接口 + 原生绑定（8.1）。其余 36 个可以封装。建议骨架里明说“组件库里有一小撮原生组件”。
2. **“组件库＝带组件的库，内置库与用户库同一格式”成立，但有一处不对称**：原生组件需要“各导出目标的画法”，这是用 Dart 写在应用里的，用户库写不了。所以用户库里只能有封装组件。这和积木那边“用户库不能写原生绑定”（如果 C 是这么定的）是同一个道理，建议两边用同一句话说。

4. **目标语言**：前端的导出目标是 网页 / Flutter / Vue / React，和后端的 Node / Python / Go / Java / PHP 不是一回事。骨架如果只有一张“目标语言”表，前端这四个要单列。
