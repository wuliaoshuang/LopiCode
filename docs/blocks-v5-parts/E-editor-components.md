## 0. 结论摘要

**盘点（第一部分）**

1. 霜霜说“简陋、难用”，没指位置。照她的规矩不猜着整版重做：下面把“有证据的问题”和“要她圈的”分开列。
2. **有证据的“简陋”共 14 处**，最重的五处：
   - 基础组件只有 11 种（`model.dart` 224 行），没有开关、勾选、单选、下拉、图标、标签页、导航栏、弹层、表格；输入框只有“提示文字”一项内容属性。
   - 没有数据绑定、没有列表重复、没有显示条件；列表只是一段写死的文字。
   - 只有一个页面（`page.lc.json` 写死）；“跳转”只能填网址。
   - 自定义组件只有属性，没有事件、插槽、变体，里面也不能写逻辑。
   - 没有断点；宽度预设只是“看一眼”，不保存；样式面板能选“网格”，画布却画不出网格。
3. **有证据的“难用”共 15 处**，最重的五处：
   - 撤销、重做、图层、“⋮”全在屏幕最顶上（截图里约在 60/844 的高度），单手够不着；预览、积木逻辑、自定义组件、导出、改标题全挤在一个“⋮”里。
   - 组件面板只有一行横向滑动，一次只露出五个半，没有搜索、分类、常用。
   - “属性”和“样式”是两套重叠的面板，同一个宽度两边都能改；“属性”里数字只能点加减、不能打字，颜色只有 10 个色块。
   - 不能在画布上直接改文字；图片只能填网址；预览要离开编辑器。
   - 长按时长三处三个值：组件面板 250ms、画布 350ms、积木画布 280ms；搭建页没有任何震动反馈（积木画布有）。
4. **看不出来的 5 处**（真机上卡不卡、手柄和长按的手感、键盘弹起时“属性”面板、点一下添加后看不看得见、从预览回来选中还在不在）——只有真机或补测试才知道，没编结论。
5. **现有截图不够给她圈**：`lc-canvas-*` 那 16 张是旧布局（工具条已经从顶上挪到底部），当前布局只有 `05-搭建-*` 4 张；属性面板、样式面板、图层、组件面板、导出面板一张都没有。测试里有出图的代码，但图没生成过（GAP-E-1）。

**方案（第二部分）**

6. 整体布局：主操作收到屏幕下三分之一。底部一条固定的“工具条”（添加 / 图层 / 撤销 / 重做 / 预览），顶栏只留返回、页面名、“⋮”。选中后工具条换成“这个组件能做的事”。
7. 手势和积木画布统一：单指滑动平移、双指缩放、点一下选中、长按 280ms 拿起；长按不动松手＝弹菜单（复制 / 粘贴 / 重复 / 包成组件 / 删除）。
8. “属性”和“样式”合成一张面板，三页：**常用**（按组件类型给 4–7 项快捷属性）、**样式**（现有九组）、**事件**。
9. 间距、圆角、阴影、字号先给“预设档”（照 refactoring-ui 的刻度），旁边留“自定义”；颜色、字号、间距可以存成主题变量，导出成 CSS 变量。
10. 响应式：手机优先，三档断点（默认 / 平板 ≥768 / 桌面 ≥1024），大档只存“和默认不同的那几条”。
11. 数据绑定界面：每个可绑定的属性行尾一个“绑定”小按钮；列表重复和显示条件各一行。模型由 D 定，我写了我假设的五条。
12. 组件库：内置 48 个组件分 6 类、三档优先级（P0 22 个，其中 11 个现在已有；P1 16 个；P2 10 个）；组件库＝带“组件”的库，写了组件在库里要描述的 12 项信息交给 C。
13. 分 6 期。前两期**不动 `page.lc.json` 格式**（布局、手势、面板合并、就地改字、图层升级）；第 3 期起每期都动格式，动之前要先问霜霜。

**需要霜霜拍板 4 件**（见文末）：文件格式升第 3 版、内置组件第一批清单、主题变量要不要做、截图补拍后请她圈。

### 2.2 改成什么

思路：**手指待在屏幕下三分之一就能干完九成的事**。顶栏只放“很少点”的。和积木编辑器一个骨架（画布铺满 + 底部一个盒 + 顶栏悬浮），她学一次两边都会。

**没选中时**

```
┌──────────────────────────────────────┐
│ ← 首页 ▾ ⋮ │ 顶栏 64，悬浮。标题＝当前页面名，点开＝页面列表
│ 手机 390 · 已保存 │ 标题下一行小字：当前屏宽档 · 保存状态
│ │
│ （画布） │
│ │
│ │
├──────────────────────────────────────┤
│ [图层] [↶] [↷] [▶] │ 工具条，高 56。主操作＝添加
└──────────────────────────────────────┘
```

**选中一个组件时**（工具条上面多一行）

```
│ （画布） │
├──────────────────────────────────────┤
│ 按钮“登录” [常用] [样式] [逻辑] [⋯]│ 选中条，高 48。左边是名字，右边是“对它做的事”
├──────────────────────────────────────┤
│ [图层] [↶] [↷] [▶] │
└──────────────────────────────────────┘
```

- 两行加起来 104 高，比现在（选中条 48 + 提示一行 + 组件一行 64 ≈ 140）还矮，画布多露出一点。
- **工具条**这一行只做“全局的事”；**选中条**这一行只做“这个组件的事”。两行各管一件。
- “逻辑”有字，不再是光秃秃的 ⚡。组件上已有逻辑时按钮带一个小圆点。
- “⋮”里只剩：导出、主题、页面设置（标题）、组件库管理。都是不常点的。
- 缩放比例不再占悬浮小条：双指缩放照旧；“回到适应屏幕”放进画布空白处长按的菜单和“⋮”里。（待圈：她要不要留一个看得见的缩放数字——现在右下角有。）
- 屏宽档从左下悬浮小条挪到顶栏标题下那行小字，点它弹一个底部面板选（见第 6 节）。

**为什么这样**：主操作唯一（添加）；最常用的撤销落在右手拇指自然位置；预览一步到；每行一件事。

### 2.3 “添加”点开：组件盒

和积木盒同一种东西：底部面板，可上下拖高矮，最矮只剩手柄。

```
┌──────────────────────────────────────┐
│ ━━━━ │ 手柄
│ 🔍 搜组件 │ 第 1 行：搜索
│ (常用)(布局)(基础)(表单)(展示)(导航)…│ 第 2 行：分类，横滑；最后是“我的”和各个库
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐ │
│ │文字│ │按钮│ │图片│ │输入│ │ 第 3 行起：一行 4 个，每个约 80×72
│ └────┘ └────┘ └────┘ └────┘ │ 图标 + 名字
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐ │
│ │容器│ │横排│ │竖排│ │卡片│ │
│ └────┘ └────┘ └────┘ └────┘ │
└──────────────────────────────────────┘
```

- 点一下＝加进去（规则不变：选中的是容器就进容器，否则放它后面，没选中放页面最后），**加完自动滚到它并选中它**，面板收到最矮。
- 长按 280ms＝拿起来拖，面板自动收到最矮让出画布。
- “常用”＝最近用过的 8 个，存在项目里。没用过任何东西时显示内置的 8 个起步组件。

## 3. 画布操作与手势

### 3.1 手势表（和积木画布对齐）

| 手势 | 在哪 | 做什么 | 和现在比 |
|---|---|---|---|
| 点一下 | 组件上 | 选中 | 不变 |
| 点一下 | 已选中的文字 / 按钮上 | 就地改字（见 3.4） | 新 |
| 点一下 | 空白处 | 取消选中 | 不变 |
| 单指滑动 | 任何地方（含组件上） | 平移画布 | 不变；和积木一致 |
| 双指捏合 | 任何地方 | 缩放 25%–300% | 不变 |
| 长按 280ms | 组件上 | 拿起（震一下）。**拿起后不动就松手＝弹长按菜单**；动了＝拖动 | 现在 350ms、没菜单、没震动 |
| 长按 280ms | 组件盒里的组件 | 拿起拖进画布 | 现在 250ms |
| 长按 280ms | 空白处 | 弹画布菜单：粘贴、适应屏幕、回到 100% | 新 |
| 拖手柄 | 选中框的手柄 | 改尺寸 | 可按范围 32 → 44 |

“动了没有”的界线用积木画布同一个值：8 像素（`block_editor_canvas_view.dart` 的 `dragSlop`）。

震动照积木画布：拿起一下中等的，经过一个可放的位置一下轻的，放下一下轻的，丢进删除区一下重的。

### 3.2 拖动与插入提示

现在的毛病：一拖，所有空位都冒出来把页面撑变形。改成：

- 拖动时**页面排版不动**。只在手指附近算出“最近的一个可放位置”，在那里画**一条 3 像素的蓝线**（线的方向跟着父容器：竖排里是横线，横排里是竖线）。
- 手指停在一个容器上超过 0.4 秒，容器描一圈蓝边，表示“放进它里面”；空容器直接整块高亮。
- 蓝线旁边一个小标签写“放到 卡片 里 · 第 2 个”，避免嵌套深时不知道放进了哪层。
- 拖着的不是“移动 X”小药丸，而是**组件自己的半透明缩略图**（最大 160 宽）。
- 手指进到上下边缘 64 像素内，画布自动往那边滚，越靠边越快。
- 底部工具条在拖动时换成“拖到这里删除”（和积木盒一样）。

### 3.3 选中、多选

- 单选不变。选中框旁边加一个**“选上一层”小按钮**（↑）：嵌套深时点不到外层容器，现在只能开图层。
- 多选：长按菜单里“多选”，或图层面板里勾选。进了多选模式后，点一下＝加入 / 移出。选中条变成：`已选 3 个 [包成容器] [复制] [删除] [完成]`。
- **多选限制在同一个父容器里的兄弟**。为什么：页面是流式排版，跨容器一起移动没有明确含义；限制后“包成容器”“一起移动”都只有一种做法。选了不同父容器的会提示“只能一起选同一层的”。

### 3.4 就地改文字

- 对象：文字、按钮、输入框的提示文字、列表行标题。
- 触发：点一下已选中的它；或选中条“常用”第一项也是文字框。
- 画布上原地变成输入框，字号字体照原样；画布自动把它滚到键盘上面。
- 键盘上方不加额外工具行（一行只做一件事）；点别处或键盘“完成”＝提交；只记一条撤销。
- 字是绑定来的（第 7 节）时不能就地改，点它提示“这段字来自 变量名”，并给“去改绑定”。

### 3.5 对齐、吸附、参考线

页面是流式排版，没有自由摆放，所以**不做**画图软件那种“拖到哪吸到哪”的对齐线。吸附只用在三处，都是“改尺寸 / 改间距”时：

| 吸什么 | 什么时候 | 表现 |
|---|---|---|
| 刻度值 | 拖手柄改宽高、拖间距 | 靠近 4 的倍数 / 刻度值时停一下、震一下 |
| 兄弟的尺寸 | 拖手柄 | 和某个兄弟一样宽 / 高时，两者之间画一条细线并标“＝” |
| 父容器的一半 / 三分之一 / 占满 | 拖宽度手柄 | 手柄旁显示“50%”“占满”，松手写成百分比而不是像素 |

需要自由摆放的（徽标压在头像角上）走“定位”，那是少数情况，不为它做全套参考线。

### 3.6 尺寸手柄与标签

- 可按范围 44×44；显示仍是小圆点。
- 尺寸标签改放在**选中框内侧右下角**（框太小时放框上方），永远不盖别的字，也不会被屏幕边切掉（贴边时往里挪）。
- 直接拖内 / 外边距：选中时绿色、橙色区域的边可以拖（先按住 280ms，避免和平移抢），旁边显示数值，吸刻度。这是后期项（第 5 期）。

### 3.7 长按菜单

```
┌────────────────────┐
│ 复制 │
│ 粘贴到它后面 │ 剪贴板里有东西才亮
│ 重复一份 │
│ 多选 │
│ ────────────── │
│ 包成容器 │
│ 存成组件 │
│ ────────────── │
│ 删除 │ 红字，放最后
└────────────────────┘
```

- “复制 / 粘贴”用应用内剪贴板，跨容器、跨页面、跨项目（同一次运行内）可用。现在的“复制”改名“重复一份”，名副其实。
- 选中条的“⋯”里是同一份菜单再加“上移 / 下移”，不维护两套。

## 5. 属性与样式面板

### 5.1 两套合成一套

选中条上三个入口，对应同一张底部面板的三页：

```
┌──────────────────────────────────────┐
│ ━━━━ │
│ 按钮“登录” [⋯] │ ⋯：看 CSS、重置样式
│ ( 常用)( 样式)( 事件) │ 三页，不横滑
│──────────────────────────────────────│
│ 文字 [ 登录] 🔗 │ 一行一项；🔗＝绑定（第 7 节）
│ 样子 (实心)(描边)(文字) │ 变体
│ 大小 (小)(中)(大) │
│ 宽度 (随内容)(占满)(自定义) │
│ 颜色 ● 主色 ▾ │
│ 禁用 ○—— │
└──────────────────────────────────────┘
```

- **常用**：按组件类型给 4–7 项（见 5.2）。大多数时候在这一页就改完了。
- **样式**：现有九组原样保留（测试都在），但从“九个横滑页签”改成**一页竖着排的九个可折叠小节**，默认展开动过的和“尺寸、间距”，其余折着。为什么：横滑页签看不到后面有什么；竖排一眼看全，找“阴影”不用猜要滑多远。（这一条是待圈项 #16 的一个方案，她圈了再定。）
- **事件**：这个组件能触发哪些事、各挂了什么逻辑（见第 11 节）。
- 旧“属性”面板取消。重叠项（宽高、边距、圆角、背景、字色、字号）只在一处改。**格式不变**：文件里旧的属性照样认；规则是“新改动一律写进样式，旧属性只读不再新写”。这条要先验证导出结果和原来逐字一样（GAP-E-6）。

### 5.3 数值怎么输入

每个数值项是“预设档 + 自定义”：

```
│ 内边距 (无)(小 8)(中 16)(大 24)(…) │ 点“…”展开：数字框 + 加减 + 单位
```

- 预设档直接点；选中的档实心。值不在档上时“…”亮着并显示数值。
- 自定义里：数字框可打字（旧“属性”面板不能打字的问题就没了），加减步长 1（长按连加），单位菜单。
- 在数字上左右滑动也能微调（每 4 像素加减 1），手不用找小按钮。这是后期项。

| 项 | 档 | 来源 |
|---|---|---|
| 间距 | 0 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 | 书的间距刻度前九档 |
| 字号 | 12 / 14 / 16 / 18 / 20 / 24 / 30 / 36 / 48 | 书的字号刻度 |
| 字重 | 常规 400 / 加粗 600 | 书：只用两种 |
| 行高 | 1 / 1.25 / 1.5 / 2 | 书 |
| 圆角 | 无 0 / 小 6 / 中 10 / 大 16 / 全圆 | `tokens.dart` 的前几档；书说“定一个圆角风格用到底” |
| 阴影 | 无 / 一 / 二 / 三 / 四 / 五 | 书的五级：`0 1px 3px`、`0 4px 6px`、`0 5px 15px`、`0 10px 24px`、`0 15px 35px`，都是黑色两成不透明 |

### 5.5 主题（全局变量）

入口：⋮ › 主题。一张整页：

```
┌──────────────────────────────────────┐
│ ← 主题 │
│ 颜色 │
│ ● 主色 #2563EB › │
│ ● 文字 #111827 › │
│ ● 次要文字 #6B7280 › │

│ ＋ 加一个颜色 │
│ 字号档 › │
│ 间距档 › │
│ 圆角风格 (直角)(小圆角)(大圆角) │
│ 深色模式的颜色 › │
└──────────────────────────────────────┘
```

- 取色面板最上面多一排“主题色”。选了主题色，组件上记的是**变量名**不是色值；之后改主题，全页一起变。
- 导出成 CSS 自定义属性：在 `:root` 上写 `--color-primary: …`，用的地方写 `var(--color-primary)`（MDN 核对过）。
- 画布现在不认 `var(…)`（`canvas_css.dart` 31 行、`css_color.dart` 94 行），要补：画之前先用主题表把变量换成值。
- **要改格式**：页面文件（或项目级的一个主题文件）多一份主题表。建议放项目级，多页面共用。

## 6. 响应式布局

### 6.1 断点模型

- **手机优先**：不带条件的样式＝默认（手机）。另有两档“更宽时”：平板（≥768）、桌面（≥1024）。数值是我定的（768 沿用现有宽度预设），可在主题里改。
- 每个节点的样式变成：默认一份 + 每档一份“**只存和默认不同的那几条**”。
- 导出成 `@media (min-width: 768px) { …}`（写法未对 MDN 核对）。
- 为什么只做“按屏幕宽”，不做“按容器宽”（容器查询，MDN 核对过有这个东西）：模型多一层、画布要自己算容器宽度，第一版不值。留着以后加。

### 6.2 界面

点顶栏标题下那行小字：

```
┌──────────────────────────────────────┐
│ ━━━━ │
│ 现在看的屏幕 │
│ ◉ 手机 390 默认样式 │
│ ○ 平板 768 改的只在 ≥768 生效│
│ ○ 桌面 1024 改的只在 ≥1024 生效│
│ ──────────────────────────────────── │
│ 只是看看别的宽度 [ 360 ▾] │ 不切档，只变画布宽
└──────────────────────────────────────┘
```

- 切到“平板”后：画布变 768 宽并自动缩小到放得下；顶栏小字变成“平板 768 · 改动只影响平板及更宽”，颜色用强调色，**时刻提醒她现在改的不是默认**。
- 样式面板里，这一档改过的项前面有个小点；长按它＝“恢复成跟手机一样”。
- 图层的“隐藏”之外，样式里的“显示 / 隐藏”可以按档设（手机隐藏、桌面显示），这是响应式最常用的一招。

## 7. 数据绑定的界面

### 7.1 我假设的模型（等 D 的设计来对齐）

1. 页面有“页面变量”：名字、类型、初始值。组件也可以有自己的状态。
2. 一个属性的值有三种来源：写死的值；一个变量（或它里面的某一项，如“用户 的 名字”）；一个式子（一块**值积木**，结果类型要对得上）。
3. 值变了，用到它的界面自动跟着变。默认单向（值 → 界面）。输入类组件的“值”是双向的（用户输入 → 写回变量）。
4. 任何节点可以设“重复”：给一个列表，对每一项画一遍；里面可以用“这一项”“第几个”。可选一个“用哪一项当标识”。
5. 任何节点可以设“显示条件”：一个结果是“是 / 否”的式子；为否时不画。

如果 D 的模型不一样（比如不许式子、只许变量），界面第 2 步少一个选项即可，结构不用改。

### 7.2 属性旁边怎么绑

每个可绑定的属性行尾有个 🔗。没绑时是灰的。点它：

```
┌──────────────────────────────────────┐
│ ━━━━ │
│ “文字”从哪来 │
│ ○ 写死： [ 登录] │
│ ◉ 用一个值 │
│ 🔍 搜变量 │
│ 用户名 文字 │ 名字 + 类型；类型对不上的灰掉并写原因
│ 购物车 › 数量 数字 │
│ 这一项 › 标题 文字 │ 在重复里面才有
│ ＋ 新建变量 │
│ ○ 写个式子 › │ 进一个只能放值积木的小画布
│ │
└──────────────────────────────────────┘
```

绑好以后，属性行变成：

```
│ 文字 ⟦ 用户名 ⟧ 🔗 │ 药丸＝绑定来的；点药丸改；🔗 亮
```

画布上绑定来的文字显示变量的初始值（没有就显示“{用户名}”），左上角一个小 🔗 角标。

类型对不上时**不让选并说原因**（“这里要文字，购物车是列表”），不是选了以后才报错——类型系统在这里直接让用户少走弯路。

### 7.3 列表重复

选中任何组件 → “常用”页最下面固定两行（所有类型都有）：

```
│ 重复 不重复 › │
│ 显示条件 一直显示 › │
```

点“重复”：

```
┌──────────────────────────────────────┐
│ 重复这个组件 │
│ 对这个列表里的每一项 ⟦ 商品列表 ⟧ │ 只能选类型是“列表”的值
│ 这一项叫 [ 商品] │ 起个名，里面的组件绑定时用
│ 序号叫 [ 序号] │
│ 用哪一项当标识 ⟦ 商品 › 编号 ⟧（可不填）│
│ 没有数据时显示 (什么都不显示)(一个空状态)│
```

画布上：重复的组件画 N 份，第一份可编辑，其余半透明、点不中，右上角 ↻ 角标。

### 7.4 显示条件

```
┌──────────────────────────────────────┐
│ 什么时候显示 │
│ ○ 一直显示 │
│ ◉ 当 ⟦ 已登录 ⟧ 为“是” │ 选一个“是否”类型的值
│ ○ 当 ⟦ 数量 ⟧ (大于 ▾) [ 0] │ 简单比较：等于 / 不等于 / 大于 / 小于 / 为空 / 不为空
│ ○ 写个式子 › │
│ 编辑器里 (照条件)(总是显示) │
│ │
└──────────────────────────────────────┘
```

为什么给“简单比较”这一档：十次里八次就是“某值为是”或“某数大于 0”，不该逼人进积木画布。

### 7.5 变量从哪管

顶栏“⋮”不放。放在组件盒旁边不合适（不是组件）。建议：**和积木逻辑编辑器共用同一份“变量”面板**（积木编辑器顶栏已有“变量”入口）；搭建页里从绑定面板的“＋ 新建变量”和“事件”页进。只有一份变量表，两边看到的一样。


## 8. 组件库

### 8.1 先说一条和骨架有出入的地方

骨架说“除语言基础和基础库外，所有能力都靠封装得来”。对组件要分两种，不然说不通：

| 种类 | 是什么 | 例子 | 属于哪层 |
|---|---|---|---|
| **原生组件** | 浏览器 / Flutter 本来就有的控件，没法用更小的东西拼出来 | 文字、图片、按钮、输入框、多行输入、勾选框、单选、开关、滑块、下拉、容器、图标 | L0 宿主原生接口 + 原生绑定 |
| **封装组件** | 用原生组件 + 样式 + 逻辑拼出来的 | 卡片、列表行、表单项、导航栏、标签页、弹窗、提示条、空状态、轮播…… | L3 库 |

为什么要分：每个原生组件要写**好几份画法**——编辑器画布（Flutter 画的近似）、导出网页、导出 Flutter、导出 Vue、导出 React。封装组件只要一份定义（一棵节点树），各个导出自动就有。所以**原生组件越少越好**（下面定 13 个），其余全部封装——这正好符合霜霜“靠封装”的方向，只是底下那十几个得承认是原生的。

### 8.3 用户自建组件

**从画布存**：长按菜单 › 存成组件（现在有）。升级的是存之后能定义的东西。组件编辑页（整页，沿用现在的做法）：

```
┌──────────────────────────────────────┐
│ ← 组件：商品卡片 ⋮ │
│ │
│ （组件的画布） │
│ │
├──────────────────────────────────────┤
│ (属性 3)(事件 1)(插槽 1)(变体 2) │ 选一项，下面弹对应的面板
├──────────────────────────────────────┤
│ [图层] [↶] [↷] [▶] │
└──────────────────────────────────────┘
```

| 要定义的 | 界面 | 说明 |
|---|---|---|
| **属性** | 列表：名字、类型、默认值。类型从现在的四种扩到：文字、数字、是否、颜色、**选项（枚举）、图片、列表、记录、任意** | 类型用全应用同一套类型系统（骨架的渐进类型）。组件里的东西绑到属性，用第 7 节同一个绑定面板 |
| **事件** | 列表：名字、带出去什么值（名字 + 类型）。组件里用一块“发出事件 X”积木触发 | 外面用它时，“事件”页里就多出这个事件 |
| **插槽** | 在组件画布上选一个容器 › “设成插槽”，起名；可以放“没填时显示的默认内容” | 外面用它时，画布上那块是个能往里拖东西的空位。默认插槽 + 具名插槽，思路同 Vue 的插槽（官方文档核对过）。React 那边对应“把内容当属性传进去”（**未对 react.dev 核对**） |
| **变体** | 一个变体＝一个“选项”类型的属性 + 每个取值对应的一组样式差别。界面：选变体取值 → 照常改样式 → 存成“这个取值时的差别” | 和断点同一个机制（只存差别），省一套代码 |
| **逻辑** | 组件画布里选中东西 › “逻辑”，进积木编辑器，作用范围是这个组件 | 现在组件里不许有逻辑（`component_editor_sheet.dart` 第 5 行）。放开后组件有自己的状态变量 |

### 8.4 组件在库里要描述哪些信息（给 C）

组件库＝带“组件”的库，文件格式由 C 定。每个组件至少要能写下这 12 项：

| # | 信息 | 用在哪 |
|---|---|---|
| 1 | 标识（库内唯一）、显示名、别名（搜索用）、一句话说明 | 组件盒、搜索 |
| 2 | 图标、分类 | 组件盒 |
| 3 | 可见性（公开 / 库内） | 库内的不出现在组件盒 |
| 4 | 属性表：名字、类型、默认值、是否必填、说明、**在“常用”页显不显示及顺序、用什么控件编辑**（预设档 / 开关 / 取色 / 文字框） | 属性面板自动生成 |
| 5 | 事件表：名字、带出的值及类型、说明 | “事件”页、积木盒里的事件帽子 |
| 6 | 插槽表：名字、允许放什么（任意 / 只许某几种）、默认内容、最多几个 | 画布上的空位 |
| 7 | 变体表：哪个属性是变体、每个取值的样式差别 | 属性面板的变体行 |
| 8 | 内容：封装组件＝一棵节点树（含绑定、重复、显示条件）+ 组件内状态 + 逻辑；原生组件＝指向一个原生绑定 | 画布、导出 |
| 9 | 原生组件专用：各目标的画法在哪（画布、网页、Flutter、Vue、React），缺哪个目标要明说 | 导出时缺了就报“这个组件不支持导出成 X” |
| 10 | 能不能当容器、放进哪些父组件才合法（如“页签”只能放在“标签页”里） | 拖放时判断能不能放 |
| 11 | 放到画布时的初始样子（默认属性 + 默认子节点）、编辑器里的预览数据 | 点一下添加 |
| 12 | 依赖：用到本库 / 别的库的哪些组件和积木；库的版本 | 复制、导入、升级 |

对 C 的两个要求：(a) 同一个库里组件和积木能互相引用（组件的逻辑用库里的积木；积木“打开弹窗”操作库里的组件）；(b) 第 4–7 项就是组件的“类型签名”，要进类型检查——给属性绑了类型不对的值，在编辑时就报。

### 8.5 组件盒按库分组

- 分类行：`常用 | 布局 | 基础 | 表单 | 展示 | 导航 | 反馈 | 我的 | <库名>…`。前七个是内置库的分类；“我的”＝这个项目里自建的；后面每个用上的库一个。
- 库多了以后分类行最后一个是“更多库 ▾”。
- 搜索跨所有库，结果里每个组件下面一行小字写来自哪个库。

### 8.6 内置只读 + 复制一份来改

- 内置组件上长按（组件盒里）或实例的“⋯”里：**“复制一份来改”**。复制到“我的”，名字自动加“（我的）”，之后随便改。
- 内置的封装组件可以“看里面”：只读打开组件编辑页，顶上一条提示“内置组件不能直接改 ·”。
- 原生组件没有“里面”，复制得到的是“包了一层的封装组件”（里面放一个原生组件 + 预设好的属性），足够做“我的主按钮”这种事。
- 已经放在画布上的实例不会跟着变成“我的”；提供“把这个页面里的 X 都换成 X（我的）”。

- 点“＋ 加逻辑”：**替她把“当 按钮“登录” 被点击”这个帽子建好**，放在积木画布的空位上，然后跳过去，镜头对准这块帽子，积木盒已打开。她直接往下接积木。
- 事件清单来自组件的事件表（8.4 第 5 项），不再是写死的三种。
- “快捷动作”只给一两个最常见的（跳页面、打开 / 关闭某个弹窗）。它们存成的就是普通积木，进积木编辑器能看到、能改——不是另一套东西。

**在那边**：
- 积木编辑器顶栏标题第二行小字写“按钮“登录” · 点击时”，她知道自己在给谁写。
- 积木里要指某个组件的地方（“设置 X 的文字”）：槽里点开是一个组件列表，用的是图层里的**名字**（这就是为什么图层要能重命名）；旁边一个“去画布上点一个”——跳回画布，点谁就是谁，再跳回来。

**回**：
- 返回键回到搭建页，**选中的还是那个按钮，画布位置和缩放不变，面板停在“事件”页**。
- 按钮在画布上多一个 ⚡ 角标；图层里那行也有。
- 删除带逻辑的组件先问（现在已有，测试“删除被逻辑用到的组件先问”）。改名时积木里跟着变（积木里存的是编号不是名字，本来就不会断）。

**出错往回指**：积木的问题清单里“这块用到的组件已经被删了”→ 点它能跳回搭建页并提示是哪个；“试一试”里运行时报错 → 能跳到那块积木（GAP-E-10）。

### 11.3 和语言核心的关系（给协调者）

- 页面逻辑应该就是“语言核心的积木 + 一个‘页面’库”：事件帽子、“设置属性”、“显示 / 隐藏”、“跳转页面”都是库里的积木，底下是 L0 的浏览器接口。有了数据绑定以后，“设置 X 的文字”这类积木会少用很多——改变量就行。
- 组件的事件 = 库里自动生成的一种帽子（“当 <组件> <事件名> 时”，带出的值是帽子上的可拖出参数）。这要求库格式能表达“组件声明了事件 → 积木盒里出现对应帽子”（8.4 的要求 a）。

### 和设计骨架不一致的地方

1. **“除语言基础和基础库外所有能力都靠封装”对组件不完全成立**。有 13 个原生组件拼不出来，只能是 L0 宿主原生接口 + 原生绑定（8.1）。其余 36 个可以封装。建议骨架里明说“组件库里有一小撮原生组件”。
2. **“组件库＝带组件的库，内置库与用户库同一格式”成立，但有一处不对称**：原生组件需要“各导出目标的画法”，这是用 Dart 写在应用里的，用户库写不了。所以用户库里只能有封装组件。这和积木那边“用户库不能写原生绑定”（如果 C 是这么定的）是同一个道理，建议两边用同一句话说。
3. **渐进类型**：成立，而且组件属性是它第一个看得见的好处（绑定面板里类型不对的直接灰掉）。要求类型系统至少有：文字、数字、是否、颜色、选项（枚举）、列表、记录、任意、“事件带出的值”的写法。颜色和图片是界面特有的类型，语言核心里未必有——请协调者确认放在哪层。
4. **目标语言**：前端的导出目标是 网页 / Flutter / Vue / React，和后端的 Node / Python / Go / Java / PHP 不是一回事。骨架如果只有一张“目标语言”表，前端这四个要单列。
