### 最要紧的八个结论

1. **四层结构成立**：最底下一小撮“宿主原生接口”→ 语言核心积木 → 标准库 → 库。后端最底下只要 **8 个**原生接口（再加 5 个读写文件的）；浏览器是 **9 个界面接口**（普通网页里落成 4 个元素接口＋2 个时机接口）**加 20 个原生绑定**。其余全部是积木搭的。
2. **只靠第 4 版的核心搭不出库**，差的东西都撞出来了：内置的“错误”类（抛出要能带东西）、类和接口要真实现、模块级变量、积木定义要有四种写法、“隐含的东西”（比如积木上没有“请求”这一格，里面却要用）、启动顺序的约定。补上以后第二轮全过。
3. **“一个函数里有没有要等的事”必须进类型系统**。后端、前端、库几处验证各自独立撞到同一个问题：同一段积木 Node 和 Python 结果不一样，前端那次状态库直接崩掉。用户不用自己标，系统自动推；只在放错地方时拦下来。
4. **数字要分整数和小数**。不分的话 Go、Java 里永远只能全走小库，等于没有类型。
5. **新老规矩用“规矩版本”隔开**：旧文档＝版本 1，行为一个字不变；新建的文档＝版本 2，更严（类型不对报错、除以 0 报错、“等于”不再把 1 和 "1" 当成一样）。**这条要你点头。**
6. **错误处理要往前排**。现在标准库已经会报错，用户却没有“试着做”，遇到只能崩。
7. **组件不能百分之百靠封装**：输入框、开关、图片这 13 个最底层的组件拼不出来，只能原生做；其余都用它们拼。
8. **PHP 和 TypeScript 到现在一行都没真跑过**（这台机器没有），Vue 和 React 的导出也从来没真编译过。这是目前最大的一块“没验证”，建议先把环境装上再往下做。

## 一、整体结构与用词

### 1.1 四层

| 层 | 是什么 | 谁来写 | 数量 |
|---|---|---|---|
| L0 宿主原生接口 | 积木搭不出来的能力：开服务、发请求、时钟、随机源、存储格子、改页面控件 | 我们，每种语言各写一段真代码 | 后端 8＋5；浏览器 9＋20（普通网页另有 4＋2）；原生组件 13 个 |
| L1 语言核心 | 值、变量、运算、流程、函数、类与接口、枚举与记录、“看是哪种情况”、模块、错误处理、异步、类型 | 我们；积木只是它的一种外观，语法树才是唯一真相 | 见第二部分 |
| L2 标准库（小库） | 转换、比较、文字、列表、字典、数学、JSON、网址编码、时间计算 | 我们，各语言手写一份，保证结果逐字节一样 | 现有 55 个函数；要加的见 7.2 |
| L3 库 | 其余一切：路由、中间件、数据集合、状态管理、路由、表单校验、组件…… | **内置库和用户库同一种格式**，都用 L1＋L2 的积木搭 | 内置：后端“接口服务”“小框架”；前端 10 个；组件库 |

判定一样东西放哪层，只问一句：**它碰不碰外面的世界**。碰的才进 L0。所以 JSON 互转、百分号编码这类纯计算归标准库，不算宿主接口（第 4 版把它们放在宿主里，这次改了）。

对骨架的三处修正（验证之后改的）：

- **L0 要多一维“宿主变体”**：同是浏览器里的 JS，普通网页、Vue、React 改界面的写法完全不同。只有界面那 9 个接口需要三份实现，其余一份。
- **组件这一侧有一小撮原生的**：13 个原生组件相当于界面上的 L0。
- **“所有目标语言都能翻”的标准放宽成“降级后结果相同即可”**：PHP 没有“同时做”，在 PHP 里“开始做”就是立刻做完，结果一样就算过。

### 1.2 特性分四级

| 级 | 意思 | 承诺 |
|---|---|---|
| ① 核心 | 做成积木或标准库函数。分两档：①甲 要动语言核心；①乙 只加标准库函数或写明规矩（工作量差一个数量级） | 各语言结果**逐字节一样** |
| ② 各语言各有各的 | 对外是同一套积木，但放在专门的库里（完整正则、按地名的时区、JS 原型链、Go 通道） | **不承诺**各语言结果一致 |
| ③ 手写兜底 | 不做成积木，留“手写一小段代码”的出口 | 用的人自己负责 |
| ④ 不做 | 每条写了理由 | — |

### 1.3 统一用词

数字（细分整数、小数）、文字、是否、空、列表、字典、记录、元组、集合、字节串、时刻、函数、匿名函数、类、接口、枚举、选项（枚举里的一种）、变体（每种情况带的东西不同的枚举）、任意、可空、泛型、可遍历的、稍后的结果、错误、标注、模块、库、标准库（小库）、宿主原生接口、原生绑定、槽（放值的格子）、口（放积木的 C 形开口）、帽子（一串的开头）、语句积木、值积木、是否积木（六边形）、“我的积木”。

### 2.2 完全没有的 126 条里，分量最重的

要动语言核心的（前半 30 条＋后半 40 条里的大部分）：

- **新类型**：整数、记录、枚举和变体、泛型（函数的和类的）、字节串；元组、集合、“可遍历的”后置。
- **新积木**：声明记录、声明枚举、“看是哪种情况”（按样子分情况）、解构（拆开放进几个变量）、“要是空就用”、摊开、文字里嵌值、生成器（一个一个地给）、把方法当函数值。
- **给已有积木加开关**：赋值带运算（加上、减去）、取字段 / 取项 / 调用加“空就算了”、循环加“先做后判”和标签、函数加“一个一个地给”。
- **类这一块**：字段只读、方法内部可见、泛型类、字段初始化顺序的规矩、访问控制第二档定成“本类和子类”。
- **错误这一块**：错误要是对象（能带状态码、原因）、按种类接住、“最后总要做”。
- **异步这一块**：超时、取消、最小的“一次只让一个做”。

只加标准库函数或写明规矩的（56 条）：整套正则公共子集、整套时间计算、文字比大小、从后往前找、展平、分组、队列、三角和对数、随机小数、“能不能转成数字”等。

另有 12 组“已经有但要补一点”的（文字现在比不了大小、默认参数只能是字面量等），见 A1 分册 12.2。

### 2.3 几个难点的决定

| 难点 | 决定 | 为什么 | 验证 |
|---|---|---|---|
| 数字 | 类型上分整数、小数；JS 里运行时仍是同一种数。整数范围 ±9007199254740991，加减乘出界报错；`÷` 永远得小数；整除**向 0 取整**；余数符号跟被除数 | Go / Java 里整数和小数是两回事；范围取 JS 能精确表示的上限，六种语言都装得下 | 2000 组随机数在 Node、Python、Go、Java 对拍，逐字节一致 |
| 相等 | 版本 2 里“等于”改严（类型不同就不等），另给“是同一个”和“看起来一样” | 现在里外不一致：1 等于 "1"，但 [1] 不等于 ["1"] | 规矩有，新规矩没跑 |
| 真假值 | 保持现状，写成明文 | 改了旧文档行为会变 | — |
| 空值安全 | “要是空就用”是新积木；“空就算了”是取字段、取项、调用上的一个开关 | Python、Go、Java 没有对应写法，用标准库函数降级 | 后端原型里 `orElse` 跑过 |
| 生成器 | 六种语言统一成“收一个回调的函数”，不依赖任何语言自带的写法 | Go、Java、PHP 的自带写法差别太大 | Node、Python、Java、Go 各写一份跑过，输出一致 |
| 正则 | 标准库只放公共子集；完整正则放“各有各的”库 | 子集内已经跑出 4 处语言差异（如 `a$` 对 "a\n"：Python、Java 匹配，JS、Go 不匹配） | 只试了 8 个模式 |
| 日期时间 | 纯算术能算对的放标准库；靠时区数据的放库 | 时区数据各语言各带各的 | 没跑 |
| 文字长度 | 保持按码点；另给“看起来有几个字” | 改了旧文档行为会变 | 简化规则只是提议，没试 |
| 类在 Go 里 | 结构体内嵌＋接口＋一个指回自己的字段（**取代**第 4 版的“对象＋方法表”） | 生成的 Go 才像 Go，而且能带原生类型 | A2 和 B 各自独立跑通：三层继承、父类方法调到子类重写的版本 |
| 接口 | 按名字认 | Java、PHP 只认名字，按最严的统一 | B 的 16 个程序 |
| 枚举 | 简单枚举和“带数据的枚举”（变体）合成一个声明，配“看是哪种情况” | 五种语言都能表达；没有它类型系统立不住 | B 的 `p09` |
| 异步 | 用户不标“要等”，系统自动推；“要不要等”是函数类型的一部分 | 见 6.3 | 后端、前端原型都撞到 |
| 并发 | 只承诺各语言**最后结果一样**，不承诺先后；PHP 里“开始做”＝立刻做完 | 承诺先后的话 Python、Go、Java 都只能假装一条线轮流做 | PHP 没跑 |
| 标注（注解、装饰器） | 设计上留位置，排在最后一期；这之前接不了 Spring Boot 这类框架 | 原生片段包不住用户用积木搭的类 | 没跑 |
| 所有权、指针 | 第一梯队不暴露，只留位置给以后的 Rust | — | — |

| 函数类型 (A, B) → R | 做 | 还要带上“会不会等” |
| 枚举、变体 | 做 | |
| 类、接口 | 做 | |

验证之后要补进来的三样（别的部分撞出来的）：**字节串**（没有它返回图片、上传文件都做不了）、**“稍后的结果〈T〉”**（现在只有映射、没验证）、**只读**（前端状态里的列表被原地改，界面不知道）。

### 3.2 几条主要规矩

- **按名字认还是按形状认**：类、接口、记录、枚举、变体按名字认；函数类型按形状认。
- **不标类型照样能用**：变量、返回值、匿名函数的参数、空列表里放什么，全部自动推。没标类型的函数参数，自己文件里的从所有调用处反推；**要导出给别人用的库函数必须标全**。
- **“任意”遇到确定类型**：版本 2 里检查，不对就报错；版本 1 保持现在的宽松转换。
- **槽的形状不加新的**，还是圆头和六边形。类型不对**允许放下**，标红并给“一键修”。390 宽上默认不显示类型标签，点一下积木才在底部说明条里显示。
- **什么时候生成原生写法**：只有“原生写法对所有输入都和小库结果一样”的运算才写原生（小数加减乘、比较、是否运算、文字拼接）；整数加减乘、所有除法、下标、文字比大小都走带类型的小库小函数。这样“生成原生还是走小库，结果一样”是规则保证的。
- **标不标类型，结果不保证完全一样**，有两个例外要告诉用户：标成整数后超范围会报错；列表装进“任意”时会复制一份。
- **类型和导出的函数要有一个拉丁字母的“代码名”**：Java 的中文类型名编不过，Go 的中文名出不了包。编辑器自动起，可以改。
- **必须在运行时检查的地方共 9 处**，每处的错误文字五种语言用同一句。

### 3.3 各语言落成什么（摘要）

| 类型 | JS | Python | Go | Java |
|---|---|---|---|---|
| 整数 / 小数 | number | `int` / `float` | `int64` / `float64` | `long` / `double` |
| T? | 值或 null | `T \| None` | 基本类型和记录用指针 | 装箱类型或 null |
| 列表〈T〉 | 数组 | `list[T]` | 小库里的指针包装 | `ArrayList<T>` |
| 字典〈V〉 | `Map` | `dict[str, V]`，遍历前排序 | `map[string]V`，遍历前排序 | 按码点排序的 `TreeMap` |
| 记录 | 冻结的对象 | 冻结的 dataclass | struct | `record` |
| 变体 | 带标签字段的对象 | 每种情况一个 dataclass | 接口＋每种情况一个 struct | `sealed interface`＋`record` |
| 任意 | 任何值 | `Any` | `any` | `Object` |

这四列是按表手写了 16 个程序真跑过的。TypeScript 和 PHP 两列在分册里有，**没跑**。

- 新校验规则另起 T 开头，不占用现有的编号。

## 四、C：封装与库体系

完整内容：[`blocks-v5-parts/C-library-system.md`](blocks-v5-parts/C-library-system.md)（含完整字段表和写全的示例库 `demo/mini-router`）。

### 4.1 库长什么样

- **一个文件夹加一份清单** `lib.json`。内置库、用户库、“我的积木”是同一种格式；“我的积木”就是项目里一个隐含的库。
- **名字**：`作者/库名` 两段小写英文。文档里存的是“库的标识＋积木编号”，所以两个库都有一块叫“回应”也不冲突。
- **版本**：三段数字。一个项目里一个库只留一个版本；不兼容的大改建议换标识。
- **库里能放**：函数、类、常量、类型、积木外观、组件、设置项（比如端口）、启动时要做的事、用例。
- **可见性**：清单里写明“公开了什么”，没公开的别人用不到。
- **不做“一个库同时有后端和页面两部分”**；前后端都能用的纯计算做成“哪边都能用”的库（路径匹配就是这种，后端小路由和前端路由库共用一份）。

### 4.2 一块积木是怎么定义出来的

第 4 版只有“一块积木＝调一个函数”，验证下来不够。定成四种：

| 写法 | 例子 |
|---|---|
| 调一个函数 | “回应 状态码 内容” |
| 调对象的方法 | “给 应用 加中间件” |
| 调类的静态方法 | “新建 路由器” |
| 一段模板（展开成几句） | “把结果放进变量”“口里起个新名字” |

另外三样也是撞出来的：

- **隐含的东西**：积木上没有“请求”这一格，定义里却要用——由外层的帽子积木提供。
- **设置项**：端口、基础网址这类。
- **顺序的约定**：模块变量 → 登记帽子 → 库的准备 → “启动时” → 库的启动（比如开端口）。宿主要保证“启动的事都做完才开始收请求”。

值积木不许带口（手机上画不下），改成语句型。

### 4.3 原生绑定

只有一种机制：**一个签名，加每种语言一段函数体**，生成成一个包装函数。第 4 版的“原生片段”并进来，不另设。签名要机器能读（类型系统要在出口自动查一次）。浏览器里的实现还要按“普通网页 / Vue / React”分。

### 4.4 最小原生接口清单

**后端，第一批 8 个**（改写现有后端积木必须有）：

| 接口 | 做什么 | 为什么搭不出来 |
|---|---|---|
| 打印 | 写一行到输出或错误输出 | 输出是进程和外面之间的口子 |
| 读环境变量 | 没有就得空 | 是操作系统给的 |
| 现在的时间 | 从 1970 年起的毫秒数 | 时钟在外面 |
| 睡一会儿 | 只停当前这件事；要等 | 靠宿主调度 |
| 随机字节 | 来自系统的安全随机源 | 随机源在外面 |
| 发请求 | 404、500 不算出错，由库决定；要等 | 网络在外面 |
| 开服务 | 每来一个请求调一次处理函数 | 同上 |
| 存储格子：读＋“一口气改完” | 在请求之间留得住；改的过程别人插不进来 | PHP 每个请求是新进程；Go、Java 多线程 |

第二批 5 个：读文件、写文件、文件在不在、列文件夹、删文件（只读写文字，路径不许跳出工程文件夹）。

和第 4 版不一样的地方：

- 存储从“读、写”换成“读＋一口气改完”。原因：Go、Java 的服务是多线程的，“读出来→加一条→写回去”两个请求同时做会丢数据。（道理上成立；实测并发 30 个请求没撞出来，60 个那次探针自己卡住，没有结论。）
- “一口气改完”的函数返回“新值和结果”两样（原型里跑通的是这种）。
- JSON 互转、网址编码搬到标准库。原型里网址解码暂时放在宿主，正式做时搬走。
- 开服务多一个“主机”参数；跨域头、`OPTIONS` 这些从宿主搬到库里。
- 请求内容上限 1MB 现在是宿主写死的，要做成库的设置项。

**浏览器**：界面相关 9 个＋普通原生绑定 20 个，见第五部分。库体系分册原本建议用“7 个通用的碰 JS 对象的接口”当最小集；**定为只做兜底**（放在“JS 专属库”里，和“手写代码”同一个开关），主干用有名字、有类型的原生绑定。理由：通用接口的方法名是文字，类型说不出来，和“类型系统必须做好”相反；假宿主也难做。

**决定不放进 L0 的**：JSON、网址编码、Base64（标准库）；哈希（标准库，实现用各语言自带的）；定时任务、静态文件（库）；数据库、密码哈希（带第三方包的库）；起子进程（不做，太危险）；长连接和流式响应（现在的“返回一个完整响应”模型表达不了，这一轮不做）。

### 4.5 用户怎么用库

分册里写了手机上的完整流程：新建库、编辑、导出成一个 `.lopilib` 文件发给别人、导入时先预览里面有什么并做防护、内置库只读加“复制一份来改”、给 Agent 的 6 个工具。库的用例设想在应用自带的网页内核里跑，不用装环境（**没跑过**）。

三个默认决定（有不同想法可以改）：

- 这一轮不做“从网址导入库”，只发文件；在线商店不做。
- Java 下需要第三方包的库不做（要在手机上装 Maven 或 Gradle，太重），这类库在 Java 下变灰。
- 用户库里只能有封装组件，不能新增原生组件（原生组件的画法是写在应用里的）。

### 4.6 迁移

- 旧文档不用改就能开；现有 34 条校验规则逐条有去向。
- 现有后端积木改成库以后**样子不变**。旧文档里“每次请求都从初始值开始的变量”保留，做成帽子积木的“每次进来先做的事”，行为不变。
- 校验规则的声明方式从三种变四种（加“几个槽之间的约束”）。要算的校验只能引用应用里写好的检查器，内置库和用户库一视同仁。

### 4.7 如实

示例库只被读过（是合法的 JSON），**没有被任何程序生成过代码**——现在没有读库的代码。第 14 节的“够不够用”是纸面推演；和后端验证跑出来的结论不同的地方，以跑出来的为准（上面已经对过）。返工量都是估计。

## 五、D 与 E：前端逻辑、组件库、可视化编辑器

完整内容：[`blocks-v5-parts/D-frontend-logic.md`](blocks-v5-parts/D-frontend-logic.md)、[`blocks-v5-parts/E-editor-components.md`](blocks-v5-parts/E-editor-components.md)。

### 5.1 现状（读代码看到的）

页面逻辑只有 10 种语句、9 种值、3 种事件（点击、输入、页面加载）、3 种变量类型；没有函数、列表、字典、数据绑定。自定义组件只有属性。三种导出（普通网页、Vue、React）骨子里都是“到处去改某个控件”。语言核心还没接到页面这边，而且唯一的 JS 生成器是 Node 专用的写法，浏览器里用不了。

### 5.2 浏览器的能力分两类接

先问一句：**这块东西，Vue / React 管不管？**

- **管的（界面）**：控件的文字、显隐、有没有、重复几份、输入框的值、控件上的事件、组件。三种导出写法完全不同，所以用**语义级的接口，一个接口三份实现**。只留 9 个：

| 接口 | 意思 |
|---|---|
| 状态：新建、读、写 | 一个“会通知”的格子。写了**立刻生效** |
| 状态：派生 | 从别的状态算出来的值，**读的时候才算**，没变就用上次的 |
| 状态：监听 | “当某个值变了” |
| 界面：读、写 | 直接读写某个控件——**只为旧积木保留** |
| 界面：当事件 | 控件上的事件 |
| 界面：生命周期 | 放上页面以后、拿走之前 |

- **不管的（其余浏览器能力）**：三种导出里是同一段 JavaScript，所以用**普通原生绑定，一份实现**。第一批 20 个：定时 4 个（过后、每隔、取消、下一帧）、请求 3 个（请求、新中止令牌、中止）、存储 4 个（读、写、删、所有键）、地址 6 个（现在的地址、加一条历史、换掉这条、走几步、当前进后退、整页跳转）、对话框 2 个（弹提示、问一句）、窗口事件 1 个。再加和后端同名的打印、时间、随机。

这取代第 4 版的 6 个页面接口（原来的“按名字找控件”在 Vue / React 里没有意义）。

**验证之后的修正**（见 6.4）：只靠这 9 个，组件用积木写不出来。定为：

- **普通网页**下再给 4 个元素级接口（页面的根、造元素、放进去、拿走）和 2 个时机接口（这一段跑完以后做、让攒着的先跑完）。状态、派生、监听、重复、条件、组件，全部是在它们上面**用积木写的内置库**（“状态库”“画面库”），不是原生代码。这样组件就真的是“封装得来”的，用户库里也能做出像样的组件。
- **导出成 Vue / React** 时，元素归框架管，这 9 个接口和 8 种绑定由导出器翻成框架自己的写法。也就是说，9 个接口是“对外的约定”，普通网页那份实现是积木搭的。
- “发请求”前后端统一成一个接口：任何状态码都拿得到回应。

这一条只在 Node 的假页面里验证过；Vue / React 那一半没有验证。D 分册里“普通网页自带 17 行小运行时”的写法以这里为准。

防抖、节流、重试、路由、表单校验都是在这些上面用积木封装的库。剪贴板、通知、定位、Cookie、大容量存储、长连接放第二批；后台线程先不做。

### 5.3 状态与绑定：标准写法

**状态是唯一的真相，界面是状态算出来的。** 逻辑里只管改状态，不再到处“把某控件的文字设为”。

三条钉死的规矩：

1. 改状态立刻生效，下一块读到的就是新值（和现在一样）。
2. 派生值读的时候才算，算过记住。
3. 控件上的绑定和“当…变了”，攒到这一段积木跑完再统一跑一次。

**绑定不是积木，是控件上的一项设置**，共 8 种：文字、属性、显示条件、存在条件、重复、类名开关、样式、输入框双向。

为什么选这种做法：它是三种导出的最大公约数。Vue 直接对上自带的写法；React 用官方给外部状态准备的接法；普通网页里是一个用积木写的“状态库”（验证原型里 239 行，见 6.4；D 分册附录 A 另有一份 17 行的原生草稿，只作对照）。

两处 D、E 两本分册说法不同、这里定了的：

- **“显示条件”和“存在条件”分成两种**（D 的做法）。前者是“还在，只是看不见”，后者是“真的没有”——对输入框里已经打的字、组件的状态意义不同。编辑器里做成一行两个选项。
- **“重复”必须有“每项的标识”**（D 的做法）。没填时缺省用“第几项”，并给一个警告。

第 4 版 7.2 的计数器例子是“改了状态就整块重画”，和这里不一致，**作废**，按“状态＋绑定”重写。

### 5.4 组件

属性、双向属性、事件、插槽（默认的、有名字的、带数据的）、状态、派生、方法、两个生命周期（放上页面以后、拿走之前）。**不给“更新以后”**：三种导出里它的意思都不一样，而且最容易写出死循环；用“当某个值变了”代替。

导出的 React 代码选“**跑起来和网页版一模一样**”，不选“写法和教程里一样”。两样不能兼得：教程写法里“刚改的值下一块读不到”，和积木的直觉相反。

### 5.5 和语言核心、和现有东西的关系

- **语言核心几乎全部复用**。前端新增的只有：浏览器这个生成目标（JS 的“翻译”一份，“出口”三种）、帽子积木的登记与自动收尾、事件回调里“等”的四条规矩。
- **现有 19 种页面积木逐个有去处**，旧 `page.lc.json` 一个字不改就能开。
- **旧积木继续用旧规矩**。新旧两套“转数字”的规矩跑出来四处不一样（`"0x10"` 页面算 16、核心算 0；“重复 2.5 次”页面做 3 遍、核心做 2 遍，等等）。
- 第一步**保留旧生成器**给只用了旧积木的页面；新生成器只在用到新功能时启用，等两条路逐条比对一致后再合并。
- “没写逻辑的页面导出逐字不变”保得住。

### 5.6 内置前端库 10 个

第一批：页面（基础，默认用上）、定时、请求、本地保存、状态仓库、事件总线。第二批：路由、表单校验、动画、国际化。

用户写前端库和写后端库是同一件事，多三样：标明“浏览器用”；可以有库级状态和组件；帽子积木登记的东西自动记账、到时候自动收尾。

### 5.7 编辑器现状盘点（带证据）

你说“简陋、难用”，没指位置。照你的规矩不猜着整版重做，所以分成三堆：

**有证据的“简陋” 14 处**，最重的五处：

- 基础组件只有 11 种，没有开关、勾选、单选、下拉、图标、标签页、导航栏、弹层、表格。
- 没有数据绑定、没有列表重复、没有显示条件；列表只是一段写死的文字。
- 只有一个页面；“跳转”只能填网址。
- 自定义组件只有属性，没有事件、插槽、变体，里面也不能写逻辑。
- 没有断点；样式面板能选“网格”，画布却画不出网格。

**有证据的“难用” 15 处**，最重的五处：

- 撤销、重做、图层、“⋮”全在屏幕最顶上，单手够不着；预览、积木逻辑、自定义组件、导出全挤在一个“⋮”里。

- “属性”和“样式”是两套重叠的面板；数字只能点加减、不能打字；颜色只有 10 个色块。
- 不能在画布上直接改文字；图片只能填网址；预览要离开编辑器。
- 长按时长三处三个值（250、350、280 毫秒）；搭建页没有震动反馈。

**看不出来的 5 处**（要真机或补测试）：节点多了卡不卡、手柄和长按的手感、键盘弹起时属性面板会不会被挡、点一下添加后新组件在不在看得见的地方、从预览回来选中还在不在。

**需要你在截图上圈**：现有截图不够。当前布局只有 4 张（`05-搭建-*`），属性、样式、图层、组件面板、导出面板一张都没有；另外 16 张是旧布局。要先有人重出一套图，再请你圈。

全部 29 处的证据（哪个文件哪一行、哪张截图）在 E 分册第 1 节。**这一部分只读了代码、测试名字和截图，没有跑任何测试、没有做原型。**

### 5.8 编辑器升级方案

- **布局**：主操作收到屏幕下三分之一。底部一条固定的工具条（添加、图层、撤销、重做、预览），顶栏只留返回、页面名、“⋮”。选中后工具条换成“这个组件能做的事”。
- **手势**和积木画布统一：单指滑动平移、双指缩放、点一下选中、长按 280 毫秒拿起并震动；长按不动松手弹菜单（复制、粘贴、重复、包成组件、删除）。
- **“属性”和“样式”合成一张面板**，三页：常用（按组件类型给 4–7 项）、样式（现有九组）、事件。
- **间距、圆角、阴影、字号给“预设档”**，旁边留“自定义”；颜色、字号、间距可以存成主题变量。
- **响应式**：手机优先，三档（默认、平板、桌面），大档只存“和默认不同的那几条”。
- **数据绑定**：每个能绑定的属性行尾一个“绑定”小按钮；重复和条件各一行。
- **图层**：名字、锁定、隐藏、折叠、拖动排序、多选。
- **“试一试”**：不离开编辑器看真网页（用应用里现成的网页组件）。

都按 390×844、“一行只做一件事”排的。

### 5.9 组件库

内置 48 个组件，分 6 类、三档先后：第一档 22 个（其中 11 个现在已有，新做 11 个：图标、多行输入、开关、勾选框、单选组、下拉选择、列表行、顶部导航栏、底部导航栏、标签页、弹窗）；第二档 16 个；第三档 10 个。

**原生的 13 个**（容器、文字、按钮、图片、图标、输入框、多行输入、开关、勾选框、单选组、下拉选择、滑块，再加页面本身），其余都用它们拼出来。原生组件每个要写好几份画法（画布、网页、Flutter、Vue、React），所以越少越好。

组件库就是“带组件的库”，格式和别的库一样。颜色、图片这类界面特有的类型由“页面”库定义，不进语言核心。

### 6.3 几处验证各自撞到的同一件事：“要不要等”

- 后端：把一个“里面要等”的函数交给标准库的“筛选”，同一段程序 Node 得 `[1,2,3,4]`、Python 得 `[3,4]`。
- 库体系（纸面）：帽子积木的回调里有“等”时，库里调它的那个函数怎么一份积木在五种语言里都对，没有答案。
- 前端：事件回调里的“等”要有规矩（比如“阻止默认行为”必须在第一个“等”之前调）。
- 前端验证：状态库在 Node 里直接算错并崩掉（6.4）。

结论：**“一个函数要不要等”是函数类型的一部分**，由系统自动推断并一路传上去；把“要等的函数”交给“不会等的地方”时，在编辑时拦下来，用大白话说明。另外几条规矩：类的“创建时”里不许等；“一口气改完”的函数里不许等；**库的回调默认不许等**（想等就自己放“开始做”），界面事件和组件事件的处理例外——许等，但宿主不等它。

### 6.4 前端：小库、组件、完整流程（两轮）

详细记录：[`blocks-v5-parts/F2-completeness-frontend.md`](blocks-v5-parts/F2-completeness-frontend.md)。一键全跑：`bash docs/blocks-v5-prototypes/05-full-flow/run_f2.sh`。

做法：三样东西都只许用“语言核心＋标准库＋最小宿主接口”写成文本形式再翻出来真跑。期望输出都是第一次运行前手写的，没有为了通过改过。第 1 轮的失败输出原样留档，每次重跑都会核对“和留档的一样”。

| | 第 1 轮 | 第 2 轮 |
|---|---|---|
| 状态库＋事件总线库（48 条检查） | Node 6/48（中途崩掉），Python 45/48 | Node 48/48，Python 48/48，两边逐字节相同 |
| 组件“待办列表”：属性、事件、插槽（25 条检查，Node 里的假页面） | 13/25 | 25/25 |
| 完整流程：表单 → 请求 → 后端校验 → 存储 → 返回 → 前端更新（15 条检查；后端分别起 Node 服务和 Python 服务，真发 HTTP） | 对两个服务都是 11/15 | 对两个服务都是 15/15，前端输出逐字节相同 |

**第 1 轮发现了什么**：

1. **状态库在 Node 里算错并崩掉，报的还是一句假错误；Python 没事。** 查清的原因：后端那套规矩是“调函数值一律等”，于是连“读一个派生值”都会半路让出，攒着的更新正好插进来。同一份库两种语言行为不同——又是 6.3 那件事，而且这次是最重的一次。
2. **只靠 5.2 那 9 个界面接口，组件用积木写不出来。** 它们不能造元素、放元素、拿走元素。写不出第四行（行数是摆死的）、第二个实例、自己画的插槽、两个生命周期、“拿走”。
3. **后端原型里的“发请求”撑不起前端**：不成功一律得空，前端显示不了服务器说的校验原因，也分不出“重复了”和“连不上”。
4. 标准库没有“是不是同一个”，只有宽松相等和深比较，所以“设成一样的值不触发更新”判不对。

**改了什么**：

- 函数分“不用等的”和“可能要等的”；**库的回调规定为不用等的**。界面事件和组件事件的处理例外：许等，但宿主不等它。
  （2026-11-27 核心 3 落地时改了一点：函数类型有三种说法——可能要等、规定不许等、没说；库的回调**作者没写就照推出来的**，写了“不等函数”才不许等。小库自己的高阶函数、“改格子”的改法是写了不许等的。见 B-gen-notes.md 16.1、16.5。）
- 加 4 个元素级宿主接口（页面的根、造元素、放进去、拿走），用积木写了一个 164 行的“画面库”（如果有、每一个按标识、挂上和拿走、两个生命周期）。
- 发请求换成“请求记录 → 回应记录”，任何状态码都拿得到回应，只有网络层失败才出错。
- 标准库加“是不是同一个”；库清单里加一种“先不算的式子”的槽（“当〔这个式子〕变了”要它）。

**第 2 轮看到的**：

- 状态库整个是用积木写的（239 行），没有用原生的小运行时——**能写出来本身就是结论**。
- 组件“只有该变的部分变”是量出来的：改一条只写 1 次；末尾加一条，原来的元素没动；删一条只拿走 1 个元素；调顺序没有新建也没有拿走。
- 非法提交时前端显示的是服务器说的原因，列表不变，填的东西还在。
- 库里“要等的”函数从 50/105 降到 4/106。

**测试中发现的问题（当场查清，单列）**：

- 上面第 1 条的崩溃机制。
- 第 2 轮第一次跑状态库时检查全过，但错误输出多了一行。原因是检查程序里有一处漏标“不用等”；改了那一处调用方式，期望没动。
- 完整流程的运行脚本第一次跑有两处脚本自身的错（少一个括号、算术里用了中文名字），和设计无关，已改。

**没跑、没验证的**：真浏览器；Vue、React；PHP、Go、Java。组件和完整流程的前端只在 Node 的假页面里跑（假页面没有排版、默认行为、捕获阶段）。没验证：组件的方法、动态选组件、路由、文字输入框以外的表单控件、库清单的正式格式。“是不是同一个”对“不是数”和正负零没测；请求超时、两个请求回来顺序颠倒没测。

### 6.6 回答你的问题

**这些积木能不能完整地组建成一个库？能不能完成一个完整流程？**

能。后端库、Web 框架、前端状态库、事件总线、组件、从表单到存储再回到界面的完整流程，都只用“语言核心＋标准库＋一小撮宿主接口”写出来并跑通了。**前提是补上第七部分那张清单**；不补的话，后端带不了状态码的错误、前端状态库在 JS 里写不对、组件写不出来。

要老实说的边界：这是在 Node 和 Python 上、用临时翻译脚本验证的。Go、Java、PHP 上的库、真浏览器、Vue 和 React、手机，都还没有验证。
