# 03 前端小库：状态库 ＋ 事件总线库（任务 F2）

用“语言核心 ＋ 标准库 ＋ 2 个宿主接口（这一段跑完以后做 / 让攒着的先跑完）”写成的两个库，翻成 Node 和 Python（假宿主）真跑。

一条命令：`bash 03-frontend-lib/run.sh`（在 `docs/blocks-v5-prototypes/` 下；约 3 秒）

跑出来什么（2026-11-25 实跑）：

| | Node | Python |
|---|---|---|
| 第 1 轮（只用 F1 第 2 轮的核心） | 48 条里过 6 条，跑到第 [3b] 条程序死了 | 48 条里过 45 条 |
| 第 2 轮（加了 `call!`、`isSame`、“懒值”槽） | 48 / 48 | 48 / 48，和 Node 的输出逐字节相同 |

另有一个探针：把“里面有要等的事”的处理函数交给事件总线，Node 和 Python 的输出不一样（这是要记的事，不算失败）。

目录：

- `expected.txt` 48 条手写的期望（第一次运行之前写好的，两轮共用，没有为了通过改过）
- `round1/` 第 1 轮的库、宿主、检查程序；`round1/RESULT-round1.txt` 第 1 轮的失败输出原样留档
- `libs/状态库/` 状态、派生值、跟着做、当…变了、一起改、归属（自动收尾）
- `libs/事件总线库/` 订阅、退订、只听一次、发出
- `host/` 宿主清单 `natives.json` 和两种语言的宿主文件（Python 的是假宿主：没有“这一段跑完”的时刻，只在“等更新”和程序结束时清队列）
- `app/main.lcx` 检查程序；`probes/async_handler.lcx` 探针
- `tool-f2/` 翻译脚本的拷贝 `lcx_f2.py`（原件 `../tool/lcx.py` 没有动）、`check_lines.py`（逐条比对）
- `out/` 生成物（每次重跑覆盖）

`tool-f2/lcx_f2.py` 比原件多了：`--natives 文件`、`--host-dir 目录`（换宿主）；`--round 3`（＝F2 的第 2 轮；`--round 2`＝F1 的第 2 轮＝F2 的第 1 轮）；
语法 `(call! 函数 参数…)`（调一个“不用等的函数”）；标准库函数 `isSame`；清单里的槽种类 `懒值`。
