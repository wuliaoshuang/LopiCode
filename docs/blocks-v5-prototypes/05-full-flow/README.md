# 05 完整流程：表单 → 发请求 → 后端校验 → 存 → 返回 → 列表更新（任务 F2）

- 后端 `backend/main.lcx`：用 F1 的库“小框架”（`../02-web-framework/libs`，原样引用）写的待办服务，带校验（标题 1–20 字、级别只能是 高/中/低、同名不收）。
  用 F1 的翻译脚本（`../tool/lcx.py`，原样）翻成 Node 服务和 Python 服务，各真起一个。
- 前端 `frontend/`：页面逻辑 ＋ 组件“待办表单”，加上 03 的状态库、04 的画面库和“待办列表”组件。在 Node 的假页面里跑，用宿主的“发请求”接口（Node 自带的 fetch）真发 HTTP。

一条命令：`bash 05-full-flow/run.sh`（在 `docs/blocks-v5-prototypes/` 下；约 6 秒；端口是 18300–18960 之间随机的一段，服务按进程号关掉）

跑出来什么（2026-11-25 实跑）：

| | 对 Node 服务 | 对 Python 服务 | 两边前端的输出 |
|---|---|---|---|
| 第 1 轮（前端发请求只用 F1 的 `net.fetch`） | 15 条里过 11 条 | 15 条里过 11 条 | 逐字节相同 |
| 第 2 轮（换成 D 的“网络.请求”） | 15 / 15 | 15 / 15 | 逐字节相同 |

第 1 轮不过的 4 条是同一个原因：`net.fetch` 不成功时只交回“空”，前端分不出是校验没过、重复、还是连不上，只能显示“提交失败”。

15 条检查了什么：打开加载（空）；合法提交后列表多一条、输入框清空；非法提交（标题空 / 太长＋级别乱填）显示服务器说的原因、列表不变、填的东西还在；
改对再交；原来的元素没被重建；重复提交（同名）服务器不收（409）；连点两下只发一个请求；“提交中”每次先是后否；删除；重新加载后和页面一致；服务器连不上时的提示；请求总数。

目录：`expected.txt`（15 条手写的期望，第一次运行之前写好的）；`round1/libs/待办接口库`（第 1 轮的发请求）；`round1/RESULT-round1.txt`（失败输出留档）；
`frontend/libs/待办接口库`（第 2 轮）、`frontend/libs/表单组件库`、`frontend/app/main.lcx`（页面＋检查程序，两轮共用）；`out/`（生成物和服务日志）。

`run_f2.sh`：把 03、04、05 一起跑一遍，输出存到 `RESULT-F2.txt`（放在这个目录里，是因为任务只许在 03、04、05 三个目录里建文件）。
