# 04 组件“待办列表”：属性、事件、插槽（任务 F2）

一个组件：属性＝条目们；事件＝点了某条、删了某条；插槽＝每一条怎么画、空的时候画什么；自己的状态＝选中的是哪条。
在 Node 里的一棵假页面树（`host/host_node.js`）上真跑。只在 Node 跑，没有做 Python 的假页面。

一条命令：`bash 04-component/run.sh`（在 `docs/blocks-v5-prototypes/` 下；约 2 秒）

跑出来什么（2026-11-25 实跑）：

| | 结果 |
|---|---|
| 第 1 轮（组件只用 D 的甲类界面接口：读、写、当事件；控件事先摆好） | 25 条里过 13 条 |
| 第 2 轮（加 4 个元素级宿主接口，用积木写了“画面库”） | 25 / 25 |

第 1 轮不过的 12 条：行数是摆死的（第四条画不出来）；删一条要把后面每行的字重写一遍、元素对不上原来的条目；
第二个实例、自己画的插槽、放上以后 / 拿走之前、拿走、用积木“放”一个组件——都写不出来。

目录：

- `expected.txt` 25 条手写的期望（第一次运行之前写好的，两轮共用）
- `round1/` 第 1 轮的组件库和检查程序；`round1/RESULT-round1.txt` 失败输出留档
- `libs/画面库/` 元素、如果有（存在条件）、每一个（按标识的重复）、挂上 / 拿走、放上以后 / 拿走之前
- `libs/待办组件库/` 组件“待办列表”和它的一块积木外观
- `host/` 假页面宿主（05 也用这一份）：`natives.json` 里写了每个接口是哪一轮加的；`test.*` 只给检查程序用
- 状态库用的是 `../03-frontend-lib/libs/状态库`（为 04 多加了一个函数“收尾时”）

“只有该变的部分变了”是这样量的：宿主数着自己被要求做了几件事（新建、写、插入、拿走），每一步之后问一次；
“还是原来那个元素”是拿之前记下的元素和现在找到的比“是不是同一个”。
