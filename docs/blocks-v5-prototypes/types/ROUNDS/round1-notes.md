# 第一轮：边做边记的问题（原始记录，整理后的结论在 B-type-system.md 第 12 节）

- F1（p05，Java 编不过）：记录名用中文（`record 点`）时 javac 报 `bad filename RelativeFile[Main$?.class]`。
  原因：Java 每个类型要写成一个同名的 .class 文件，这台机器的区域设置是 POSIX，文件名写不了中文。
  变量名、方法名是中文没事（p01–p04 都过了），只有“类型名”会变成文件名。
- F2（p09，Go 和 Java 都编不过）：“分情况”把每种情况都写到了、每种情况里都“返回”了，我们的规则认为函数一定有返回值；
  但 Go 报 `missing return`（两处），Java 对枚举的 switch 报 `missing return statement`。
  第一次改：在 switch 后面补一句“到不了这里”的抛错 → Go 过了，Java 反而在“变体”那个 switch 后面报 `unreachable statement`
  （Java 知道封闭接口的模式 switch 已经写全了）。第二次改：Java 改成在 switch **里面**加 `default: throw`，两处都过。
  结论：Go / JS / Python 在 switch 后面补抛错；Java 在 switch 里面补 default 抛错。
- F3（p05，没出错但要定规矩）：记录“按内容比较”各语言自带的规矩不一样——Go 的 `==` 碰到可空字段比的是指针；
  Java record 自带的 equals 对小数用 Double.compare（NaN 等于 NaN、0.0 不等于 -0.0）；JS 没有按内容比较；
  Python dataclass 用元组比较。所以四种语言都生成自己的比较函数，不用语言自带的。
- F4（p02 / p05 / p07，Go）：可空的基本类型翻成指针以后，`&"大"`、`&3` 这种写法 Go 不让，要经过小库的 `lc.Some(…)`。
- F5（p03 / p06 / p07，Java）：整数字面量放进泛型位置必须写成 `1L`、`0L`（`Lc.or(岁, 0)` 编不过）；小数同理要写 `0.0`。
  “整数自动变小数”在 Java 的泛型位置不会自动发生（Long 不会自己变成 Double），生成器要自己把字面量写成小数。
- F6（p04 / p07）：文字比大小、字典键排序不能直接用 JS 和 Java 自带的（它们按 UTF-16 比）：`ｚ`（U+FF5A）和 `😀`（U+1F600）
  的先后会反过来。例子里专门放了这两个字，四种语言结果一致靠的是小库的按码点比较。
- F7（p08，Go）：中文名字在 Go 里没法“导出”给别的包用（Go 规定首字母大写才导出，汉字不算大写）。单个包里没问题（p08 过了），
  但库要是各占一个包，类型名 / 函数名就必须有 ASCII 的“代码名”。和 F1 是同一个结论。
- F8（p12，Java）：Java 没有“类型别名”，`处理` 只能在每个用到的地方展开成一长串 `Lc.Fn2<QingQiu, TreeMap<String, String>, XiangYing>`；
  Go（`type 处理 = func(…)`）、Python（`type 处理 = …`）、TS 都有。能编过，只是 Java 代码难看。
- F9（p06 / p12，Python）：Python 的 lambda 里不能写语句。带语句的匿名函数要先在外面生成一个有名字的内层函数（v4 已经这么做）。
- F10（p12，Go）：可空的字典翻成 `map`，空就是 nil。判断过非空之后才会去写它，所以不会碰到“往 nil map 里写”的崩溃。
- F11（p13，预期写错了，不是程序错）：我事先写的预期是 `平均 2.3333333333333335`（JS 自己打印小数的样子），四种语言跑出来都是
  `平均 2.33333333333`。四份互相一致、而且符合“小数最多写 12 位有效数字”的规矩——错的是我写预期时忘了这条规矩。
  预期改成 `2.33333333333`。这件事说明：规矩必须写在一处、而且生成器之外的人（包括写库的人）很容易忘，文档里要单列。

## 推断原型（infer.py）第一次跑出来的不一致

- F12（p13，**我手工推断错了**）：`较大(a, b)` 被 `较大(3, 7)` 和 `较大(2.5, 1)` 调用。我手写的是 `(小数, 小数) → 小数`；
  按规则“每个参数各自合并所有调用处的实参类型”，a 是 整数⊔小数=小数，b 是 整数⊔整数=整数，结果应是 `(小数, 整数) → 小数`。
  原型是对的，我错了。连带：p13 的 Go / Java / Python 第一轮是按错的签名写的（b 写成了 float64 / double），虽然跑出来的字一样，
  但和规则不符 → 第二轮按 `(小数, 整数)` 重写。
- F13（p03、p08，**规则没说清**）：`归并(列表, 0, (acc, h) → acc + h)`，列表元素是小数。第一版原型报了一条假错误：
  “第 3 个参数要 (小数, 小数) → 小数，放进来的是 (整数, 小数) → 小数”。原因：初始值 0 是整数，先把“累计值的类型”定成整数，
  拿它去看匿名函数，匿名函数返回小数，于是累计值变宽成小数——但匿名函数的参数还停在整数。
  规则补一句：看完匿名函数后类型变量要是变宽了，带着变宽后的类型**再看一遍**匿名函数（最多再一遍）。
- F14（e02、e04，连带错误）：一处错引出第二条没用的报错（参数个数不对之后又报“类型对不上”；出错的匿名函数被报“看不出放什么”）。
  规则补一句：一处已经报过错的式子，类型记成“永不”，后面凡是碰到“永不”的检查一律不再报。一处错只说一句。
- F15（p14、p15，我手写的清单漏了几行）：`状态.写.f`、`主.i`、`搅.c` 三个循环变量我没列；p14 我把方法写成了 `栈〈T〉.压`，
  原型写的是 `栈.压`（只是写法不同）。第二轮把手写清单补齐、统一写法。原来的手写稿留在 ROUNDS/round1-hand/。
- F16（e02，规则补充）：判断过“不是空”的变量带不带进匿名函数？第一版写的是“一律不带”，写例子时发现太严（明明没人改它）。
  改成：这个变量在整个函数里从没被“改”过，就带进去；被改过的不带。
