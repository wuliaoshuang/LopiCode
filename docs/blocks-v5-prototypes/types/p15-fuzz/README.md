# p15-fuzz

p15 对拍：用同一个伪随机数列（x = x*48271 余 2147483647）造 2000 组数，做整数的加减乘、整除、余，小数的加减乘除，
把所有结果按“数字的写法”拼起来算一个校验和。四种语言的校验和必须一样——
这是在验证“整数/小数的运算规矩和数字的写法，在四种语言里对每一组输入都一样”，不只是手挑的几个例子。
另外同一组数再走一遍“任意”的路（小库的 dadd 等），两条路的结果必须相同（“开不开类型优化结果一样”）。

## 里面有什么

- `prog.lc`：源程序（S 表达式写的语法树；参数写成 `(名字 类型)` 就是标了类型，只写名字就是没标）
- `types.txt`：**手工**按规则推出来的每个函数签名、每个变量的类型
- `expect.txt`：**事先写下**的预期输出（这一个例外：2000 组数手算不动，预期是第一次跑出来的结果；它验的是四种语言一样、两条路一样）
- `main.js`、`main.py`、`go/main.go`、`Main.java`：按映射表手写的四种语言（Go、Java 用的是原生类型）

## 怎么跑

```
cd ..  &&  ./run_all.sh p15
```

## 跑出来什么

四种语言的输出逐字节相同，都等于 `expect.txt`：

```
校验和（原生类型的路）973361409
校验和（任意的路）973361409
除以 0 的次数 36，两条路不同的次数 0
```

`infer.py` 自动推断的结果和 `types.txt` 一致（不看行的先后）。
