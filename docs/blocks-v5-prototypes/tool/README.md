# tool/ —— 临时翻译脚本 lcx

**这是一次性的验证工具，不是产品的生成器。** 它只为回答一个问题：“只靠语言核心＋标准库＋一小撮宿主原生接口，能不能搭出库？”所以它只管“翻得对、两种语言输出一样”，不管生成的代码好不好看、快不快，也只翻 Node 和 Python。

写给接着用它的同事（F2）：下面四节够你上手——命令行、文本形式的完整语法、怎么加宿主接口、怎么加标准库函数。最后一节是已知的局限，先看一眼能少踩坑。

## 0. 这个目录里有什么

| 文件 | 干什么 |
|---|---|
| `lcx.py` | 翻译脚本本体（只用 Python 标准库，约 1850 行） |
| `natives.json` | 宿主原生接口（L0）的清单：名字、参数、两种语言各对应哪个函数、要不要等 |
| `host_node.js` / `host_python.py` | 宿主原生接口的实现（真的开 HTTP 服务，只用自带的东西） |
| `lcx_ext.js` / `lcx_ext.py` | “核心补充”：类、对象、错误、稍后的结果要用的运行时支持，加上被迫增补的标准库函数 |
| `l2/node/*.js`、`l2/python/*.py` | 标准库（L2）：**从产品代码原样抄出来的现成小库**，一个字没改（`extract_l2.py` 抄的，产品版本 master cc7c7e2） |
| `extract_l2.py` | 重新抄一遍小库：`python3 extract_l2.py`（只读产品代码） |
| `httpcheck.py` | 起服务、发原始 HTTP 请求、逐条比对的小工具（两个原型共用） |
| `selftest/` | 翻译脚本的自测：把语言特性走一遍，Node / Python 输出逐字节相同并等于手写期望 |
| `probes/` | 两个“探针”：故意去碰说不清的地方，看两种语言是不是不一样 |

## 1. 命令行

```
python3 lcx.py build 入口.lcx -o 输出目录 [-L 库目录]… [--target node|python|both] [--round 1|2] [--dump-core 文件] [--report 文件]
```

- `入口.lcx`：入口模块。它 `(uses …)` 的模块先在**同一个目录**找 `名字.lcx`，找不到再去 `-L` 给的目录里找**库**（`库目录/库名/lib.json`）。
- 输出：`输出目录/node/main.js` 和 `输出目录/python/main.py`，旁边自动放好要用的运行文件。直接 `node 输出目录/node/main.js`、`python3 输出目录/python/main.py` 就能跑。
- `--round 1`：只许用积木第 4 版的核心；用到第 2 轮才加的东西会报错并说出是哪条缺口。默认是 2。
- `--dump-core 文件`：把“库积木展开以后”的纯核心写法存下来（想看一块积木到底展开成什么，看这个）。
- `--report 文件`：存一份统计——用到了哪些节点、哪些标准库函数、哪些宿主接口、哪些是核心表以外的。
- 翻译失败会说 `文件:行号：原因`，退出码 1。

服务类的程序：监听的端口和地址可以用环境变量 `PORT`、`HOST` 改（默认用程序里写的端口、`0.0.0.0`）。开始监听后在标准输出打一行 `后端已启动：http://地址:端口`。

自测：`bash tool/selftest/run.sh`。

## 2. 文本形式的完整语法

S 表达式。`;` 到行尾是注释。数字一律是小数（`7` 就是 7.0）。文字用双引号，认 `\" \\ \n \t \r \uXXXX`。`true` / `false` / `null`（空）。名字可以是中文。

节点和积木第 4 版设计稿第 4.2 节那张表一一对应（右边括号里是节点名）。

### 2.1 模块和声明

```
(module 名字                                   ; Module —— 一个文件正好一个
  (uses 模块或库 …)                             ; 用到的别的模块；写库名＝用上这个库所有模块公开的东西
  (native 接口名 (参数 …))                      ; NativeDecl —— 用宿主接口之前先声明（要和 natives.json 对得上）
  (var 名字 式子)   (const 名字 式子)           ; VarDecl
  (func 名字 (参数 …) 语句 …)                   ; FuncDecl
  (interface 名字 (sig 方法名 (参数 …)) …)      ; InterfaceDecl
  (class 名字 [(extends 父类)] [(implements 接口 …)]      ; ClassDecl
    (field 名字 初值)  (private-field 名字 初值)  (static-field 名字 初值)
    (ctor (参数 …) 语句 …)                       ; “创建时”。有父类时第一句可以是 (super-init 参数 …)
    (method 名字 (参数 …) 语句 …)  (static-method 名字 (参数 …) 语句 …)
    (abstract-method 名字 (参数 …)))
  (public 上面任何一个声明)                     ; 公开：别的模块才看得见
  (main 语句 …))                                ; “启动时”做的事
```

参数三种写法：`名字`｜`(名字 默认值)`（默认值只能是直接填的值）｜`(rest 名字)`（剩下的全收，只能放最后）。

内置一个类 **`错误`**（一个字段 `消息`，新建时给 0–1 个参数）。自己的错误类写 `(extends 错误)`。

### 2.2 语句

```
(let 名字 式子)  (const 名字 式子)              ; Let
(set 目标 式子)                                 ; Assign —— 目标：名字 ｜ (index 东西 键) ｜ (. 对象 字段)
(do 式子)                                       ; ExprStmt —— 只为了“做”，结果不要
(if (when 条件 语句 …) … [(else 语句 …)])       ; If —— 可以有好几个 when
(while 条件 语句 …)   (forever 语句 …)          ; While
(for-count 名字 从 到 步长 语句 …)              ; ForCount
(for-each 名字 列表 语句 …)                     ; ForEach；要序号写 (for-each (名字 序号) 列表 …)
(for-pairs (键 值) 字典 语句 …)                 ; ForPairs —— 按键排好序走
(repeat 次数 语句 …)                            ; Repeat
(break)  (continue)  (return [式子])            ; Break / Continue / Return
(throw 式子)                                    ; Throw —— 给“错误”对象就抛它；给别的值就文字化后包成“错误”
(try (body 语句 …)                              ; Try
     [(catch 名字 [(only 类名)] 语句 …)]         ;   接到的一定是“错误”对象；only＝只接这个类（和子类）的
     [(finally 语句 …)])
(note "备注")                                   ; Note
```

### 2.3 式子

```
7  "文字"  true  false  null                    ; Lit
名字                                            ; Name
(list 式子 …)                                   ; ListLit
(dict (键 值) …)                                ; DictLit
(. 对象 字段)                                   ; Field；静态字段写 (. 类名 字段)
(index 东西 键)                                 ; Index
(not x)  (neg x)                                ; Unary
(+ a b) (- a b) (* a b) (/ a b) (% a b) (** a b) (== a b) (!= a b) (< a b) (<= a b) (> a b) (>= a b)   ; Binary
(and a b …)  (or a b …)                         ; Logic —— 结果是 是 / 否
(cond 条件 是的话 否则)                         ; Cond
(call 函数 参数 …)                              ; Call —— 函数可以是名字，也可以是任何得到函数值的式子
(send 对象 方法 参数 …)                         ; Send；静态方法写 (send 类名 方法 …)
(super 方法 参数 …)                             ; SuperSend
(new 类名 参数 …)                               ; New
(is-a 值 类名)                                  ; IsA
(fn (参数 …) 语句 …)                            ; Lambda
(-> (参数 …) 式子)                              ; Lambda 的简写：只有一个式子，结果就是它
(this)                                          ; This
(await 式子)                                    ; Await —— 是“稍后的结果”就等它，别的值原样
(spawn 语句 …)                                  ; Spawn —— 马上开始、不等，得到“稍后的结果”
(rt 函数名 参数 …)                              ; Rt —— 标准库函数，名字照 lib/lang/rt.dart 那两张表
```

### 2.4 库和积木外观（翻译前的一步“展开”）

库＝一个文件夹＋清单 `lib.json`（例子见 `../01-backend-lib/libs/接口服务/lib.json`）。程序里用库的积木写成 `(@积木名 槽 …)`（重名时写 `@库名.积木名`），翻译前先被展开成上面的核心写法。

- 槽按清单里的顺序给；不填写 `_`（只有标了 `optional` 的槽可以不填）。
- 口写成 `(口 语句 …)`。
- 帽子型积木只能放在模块最外面；它展开出来的那句排在 `main` 的最前面。
- `(project-list 清单名 "项" …)`：这个项目里某一类东西有哪些（比如有哪些数据集合）；“清单”种类的槽只能从里面选。
- `(hat-prelude 语句 …)`：这些语句会放进每一个帽子型积木的回调口最前面（用来表达“每次请求都从初始值开始的变量”）。

清单里一块积木要写：

| 字段 | 意思 |
|---|---|
| `name` / `id` | 名字 / 不变的编号 |
| `shape` | `语句型`、`值型`、`是否型`、`收尾型`（展开成“返回 …”）、`帽子型` |
| `slots` | 槽的列表，每个有 `name` 和 `kind`：`值`、`选项`（配 `choices`）、`清单`（配 `list`）、`变量`、`回调口`（配 `params`：口提供给里面的参数）、`内联口` |
| `needs_context` | 要用到哪个“隐含的东西”（比如 `请求`）——只能放在提供它的回调口里 |
| `def` | 展开成什么，四种：`{"fn": 函数名, "args": […], "into": 槽名}`（调库的函数；`into`＝结果放进哪个“变量”槽）；`{"method": 方法名, "on": 对象, "args": […]}`；`{"static": "类名.方法名", "args": […]}`；`{"template": "文件.tpl"}`（有内联口时用：一段原样放进去的模板） |

`args` 里：`"$槽名"`＝那个槽填的东西；`"@名字"`＝外层回调口提供的隐含参数；别的＝常量。
模板文件里：`$槽名`、`($口 槽名)`＝那个口里的语句、`($有 槽名 语句 …)`＝槽填了才要这几句、`%名字`＝自动改成不会撞的临时名字。

## 3. 怎么加一个宿主原生接口

三步：

1. `natives.json` 里加一项：

   ```json
   "dom.query": {"params": ["选择器"], "node": "host.domQuery", "python": "host.dom_query", "async": false, "doc": "…"}
   ```

   `async: true`＝这个接口要“等”（Node 里会自动 `await`，调它的函数自动变成 async）。
   `"sync_params": ["函数"]`＝这个参数收的回调**不许等**（见第 5 节第 3 条）。
   `"round": 2`＝标成第 2 轮才加的（`--round 1` 时用它会报错）。

2. 在宿主实现里写这个函数并导出：`host_node.js` 里 `module.exports` 加上 `domQuery`；`host_python.py` 里写 `def dom_query(...)`。值的规矩用小库的：Node 里 `require("./lc_lang.js")`，Python 里 `import lc_lang as lc`。**出错要抛带统一中文消息的错**（Node：`throw new Error("消息")`；Python：`raise lc.LcError("消息")`），不然两种语言“出错了”接到的消息不一样。

3. 用的模块里声明 `(native dom.query (选择器))`，然后 `(native dom.query "…")`。

要换一套宿主（比如前端的浏览器宿主）：现在宿主文件名是写死的（`lcx.py` 里搜 `host_node.js`）。最省事的做法是另写一份 `host_node.js`（实现你那套接口），用完整的 `natives.json` 替换；只翻 Node 用 `--target node`。生成的代码最后会调一次 `host.ready()`（没有就留个空函数）——这是“所有模块的启动时都做完了”的信号。

## 4. 怎么加一个标准库函数

标准库是产品现成的小库，**原则上不加**：缺什么先记成缺口。确实绕不过去再加：

1. `lcx.py` 最上面的 `EXTRA_RT` 加一项：`'名字': (参数个数, '缺口编号', 第几轮)`；返回的一定是“是 / 否”的再加进 `BOOL_RT`。
2. `lcx_ext.js` 里写实现并加进 `module.exports`（名字一样）；`lcx_ext.py` 里写实现（名字换成下划线写法：`isNumeric` → `is_numeric`）。
3. 用的时候 `(rt 名字 参数 …)`。翻译时会在统计里列出来“核心表以外、被迫加的”。

产品小库更新了：`python3 extract_l2.py` 重新抄。

## 5. 已知的局限和容易踩的坑

1. **只翻 Node 和 Python**。Go / Java / PHP 没做。
2. **变量是函数级的**：一个函数里声明的变量都提到函数开头、先放“空”。所以循环里做的闭包记住的是变量本身、不是那一圈的值（两种语言一致，自测里有这一条）。
3. **“要等”是脚本猜的，猜不准的地方有硬规矩**：
   - 调**有名字的函数**、调**方法**：看被调的那个里面有没有要等的事，有就等。方法是**按方法名**看的——只要有一个同名方法要等，所有同名方法的调用都等。
   - 调**函数值**（变量里的函数、回调）：一律等。代价：调了函数值的函数全变成 async。
   - 例外：直接写在“不会等的地方”的匿名函数——标准库的高阶函数（`listMap` 等）、宿主接口里标了 `sync_params` 的参数——按“不许等”翻：里面调函数值不等，里面有确定要等的事就报错。
   - **坑**：把一个“要等的”**有名字的函数**交给 `listFilter` 这类函数，脚本拦不住，Node 里结果是错的（探针 `probes/async_predicate.lcx`：Node 得 `[1,2,3,4]`，Python 得 `[3,4]`）。
   - “创建时”里不能有要等的事（JavaScript 的构造函数不能是 async），脚本会报错。
4. **对象不能交给标准库**：把类造出来的对象交给 `toJson`、`==`、`size` 等，Node 把它当字典、Python 直接出错（探针 `probes/objects.lcx`）。要输出对象，先自己变成字典。
5. **“开始做”在两种语言里不是一回事**：Node 是单线、轮流做；Python 是真的另开一条线。两件同时做的事谁先谁后、同时改一个变量会怎样，两边不保证一样。
6. **私有字段只按名字粗查**（没有类型信息）：在类外面写 `(. x 秘密)`，只要有任何一个类把 `秘密` 标成私有就报错。
7. **`is-a` 只认类，不认接口**。
8. 生成的名字加了前缀（`M模块_名字`、`v_变量`、`f_字段`、`m_方法`），所以用什么关键字当名字都行。
9. 库积木的隐含参数名（比如 `请求`）会占用这个名字：回调口里别再用同名变量。
10. 库的 `(uses 库名)` 是“这个库所有模块公开的东西都看得见”，没有按清单的 `exports` 再筛一遍。
