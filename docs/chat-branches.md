# 重试、编辑、分支：规矩和数据怎么存

2026-11-25，真机反馈第四轮第 1 条的后半。代码：`lib/session/branch_ops.dart`（纯计算）、`lib/session/message_branches.dart`（落到会话上）、
`lib/state/message_edit.dart`（“正在编辑哪条”）、`lib/ui/message_branch_actions.dart`、`lib/ui/message_edit_bar.dart`。
前半（操作栏、复制、删除、分享、收藏、消息稳定 id）见 `lib/session/message_actions.dart`、`lib/ui/message_action_bar.dart`。

## 一句话

- **分支＝复制出一段新对话**。不做“一个对话文件里的消息树”。
- **重试 / 编辑＝从这条消息重新来**：先把现在的整段另存成一段“旧版本”对话，再把当前对话截到那条消息之前，然后走原有的发送流程。
- 所以整个功能只多了一样存盘内容：对话目录里每段对话多一个可选的 `from`（它是从哪段、哪条消息分出来的）。对话文件的格式没变。

## 为什么不做消息树

对话文件 `chat-<id>.json` 是一个平铺的消息数组。自动压缩（给旧消息打 `_archived`、插摘要）、删除消息、“上一轮没正常结束”的日志都按**数组下标**干活；
发给模型的记录是这个数组过滤出来的。改成树要同时改这几样，还要迁移旧文件，出错就是“对话打不开”。
复制成新对话这些都不用动：旧文件天然能开，新对话就是一段普通对话。代价是占一点存储（一段对话几十 KB 的量级），以及对话列表会变长。

## 存盘

`.lopicode/chats.json`（对话目录）里每段对话可以多一项：

```json
{ "id": "mhx…", "title": "看看首页", "updatedAt": "…",
  "from": { "conv": "main", "msg": "m…", "title": "看看首页", "old": true } }
```

| 键 | 意思 |
| --- | --- |
| `conv` | 原对话的 id |
| `msg` | 原对话里“分出来的那条消息”的 id（可没有：旧版本截在第一条消息上时，原对话里前面没有消息） |
| `title` | 分出来那一刻原对话的名字（原对话后来被删了也还能显示“来自：…”） |
| `old` | `true`＝重试 / 编辑前另存的“旧版本”；没有这一项＝用户自己点的“从这里分支” |

- 没有 `from` 的旧目录文件照常读；`from` 形状不对、字段类型不对、`conv` 不是合法的 id：当普通对话读，不抛异常（`test/safe_file_test.dart`）。
- 分支的消息存在它自己的 `chat-<新 id>.json`，原子写。写不进去：什么都不建；重试 / 编辑时旧内容存不下来就**不动当前对话**并说明原因。
- 另一样新东西在消息上：抄出去的 assistant 消息如果带 `spawn_agent` 调用，会多一个 `_kids`（调用 id → 子对话 id），见下面“子代理”。

## 消息 id

复制时消息的 `_id` **原样保留**。id 只要求在一段对话里不重复；两边用同一个 id 的好处是：收藏、“回到原对话那条消息”、
“这条消息上分出去的对话”都靠它对上。收藏的键是“对话 id + 消息 id”，所以两边各收藏各的，互不影响。

## 分支点怎么定

| 点在哪 | 抄到哪 |
| --- | --- |
| Agent 的回复 | 抄到这段回复为止（含）。如果这样抄出来的记录对模型不合法（这段话后面还跟着工具调用的结果）→ 抄到这一轮结束，并在提示里说明 |
| 我的消息 | 抄到这条消息之前；这条的文字和图片放进新分支的输入框（输入框里已经有草稿就不盖） |

合法性用 `wireProblems` 检查，单元测试对各种组合逐条试过。分支点在压缩之后：摘要和归档的原件一起带过去，标记不变。
分支点在已归档的消息上（压缩之前）：摘要不带，抄过去的内容去掉归档标记，重新发给模型。

## 重试 / 编辑的规矩

- 重试＝用同一条用户消息（文字 + 图片）再发一次；编辑＝换成改过的文字和图片再发。两者截断、另存的规矩完全一样。
- 最后一轮和更早的轮都可以。更早的轮：它和后面的轮一起移走。
- 被移走的内容只要有 Agent 的话 / 步骤，或者后面还有别的轮，就先另存成“旧版本”（整段对话的完整副本，排在原对话下面）；
  只有一条没人回的消息时没有东西可丢，不另存、不弹确认。
- 重发走原有的 `SendFlow.send`：权限档、确认卡、计划模式、额度上限、步数上限、排队照常。
- Agent 已经对文件做的修改**不撤销**；已经花掉的用量不变，新的一轮照常累计。
- 截断点在压缩过的位置：留下来的最后一份摘要及其后面的内容变回“发给模型的”；一份摘要都没留下就全部变回来。
- “上一轮没正常结束”的提示：重试 / 编辑会把它收掉（要重新来了）。
- 回复一个字都没出就报错的那种，原有流程已经把消息交还输入框，没有消息可重试。

## Agent 正在回复时

- 重试、编辑：不可用（灰 + 原因）。压缩在等待期间拿着消息下标，改列表会错位——和“删除”同一个理由。
- 分支：可以，但不能选正在跑的这一轮里的消息；建好以后不切过去（切对话要等 Agent 停下），提示去侧边栏打开。

## 随对话走的东西

| 东西 | 分支 / 旧版本里 |
| --- | --- |
| 模型、权限档、计划模式、Agent 预设 | 照抄 |
| 待办清单、这一轮改过的文件、每轮的用量脚注 | 就在消息上，跟着消息走 |
| 累计用量、上下文占用 | 从 0 计（那些请求不是这段对话发的） |
| “本对话都允许” | **不带**（按对话 id 记在内存里，新对话是新 id，重新逐次问） |
| 子代理对话 | 不复制。抄出去的调用上记 `_kids`，卡片点开的还是原来那段；原来那段不在了卡片就不能点。在分支里删这一轮不会删原对话的子代理对话。重试 / 编辑时，被移走的轮派出的子代理对话改挂到旧版本名下 |
| 收藏 | 指向原对话的不动。重试 / 编辑时指向被移走消息的收藏改指到旧版本（没有另存时标成“原消息已删除”） |
| 后台命令、团队任务板、记忆 | 属于工作区，不动 |

## 在哪看

- 侧边栏对话列表：分支带“分支”标签和分叉图标，旧版本带“旧版本”标签和时钟图标。
- 分支 / 旧版本里：右上角“···”→“回到原对话：<名字>”，切回去并滚到分出来的那条消息。
- 原对话里：分出过对话的那条消息下面多一个强调色的分叉图标，点开是“这里分出去的对话”列表（旧版本挂在截断处之前的最后一条消息上）。
  这条消息已收藏时，图标让位进“⋯”，一排始终不超过 4 个。

## 已知的边界

- 旧版本是整段副本，重试很多次列表会变长；可以像普通对话一样删掉。
- 原对话被删以后，分支还在，只是“回到原对话”会提示原对话已经删掉。
- 没有“把分支合回去”。
