# 积木第 4 版：先把“语言”做全，别的都用封装搭出来（设计稿）

2026-11-25 01:41 霜霜的要求（大意）：现在的积木不高级，因为没有实现对语言的掌握。正常的思路是先实现语言的基础，
剩下的都是用基础语言做的封装，而不是手动硬整一套后端专用的积木；前端的 JS 也好、别的语言也好，都可以抽象、封装，
有的还支持类的各种特性。先把语言基础全部打牢，通过封装，就可以用积木搭各种框架。她说“积木你慢慢做”。

这一页是**设计稿**：只调研、只定方案，没有改任何产品代码。第 3 版（docs/blocks-v3-design.md）的拼图外形、手感、
`BlockHost` 接口、校验画法、顶栏都继续有效，这一版只换“积木背后是什么”。

凡是没在这台机器上跑过的，文中都写了“未验证”。参考过 Scratch、Blockly、Snap! 的公开资料，只学思路，不抄代码和素材，
来源列在最后一节。

## 0. 一页看懂

**现在的问题**：前端逻辑有 10 种积木、后端有 12 种，每一种都是在代码里“手写死”的——想多一种能力（比如“登录校验”），
就得改应用本身。积木里没有函数、没有类、没有“自己造积木”，所以搭不出框架，只能用我们给的那几块。

**新的做法分三层**：

```
第 3 层  库（封装出来的积木）    路由、返回 JSON、数据集合、改控件、点击事件……以后还有 Express / FastAPI 版
                                  ↑ 全部是用第 1 层的积木搭的，用户自己也能照样搭、照样改
第 2 层  封装机制                把一段积木包成一块新积木：起名字、留参数槽、选颜色和分类；可以打包成“积木库”
                                  ↑
第 1 层  语言核心                值、变量、运算、条件、循环、函数、类、模块、错误处理、异步、文字 / 列表 / 字典操作
                                  ↓ 只有最底下这几样没法用积木搭，由应用提供
第 0 层  宿主原生接口（很少）    “开一个 HTTP 服务”“找到页面上的控件”“发一个网络请求”“现在几点”“打印一行”
```

- **第 1 层**：约 110 种基础积木，每一种都说清楚在 JavaScript / TypeScript、Python、Go、Java、PHP 里各生成什么。
- **第 2 层**：“我的积木”。定义一次，积木盒里就多一块；它的样子（文案、槽、颜色、是语句还是值、能不能包住别的积木）自己定。
- **第 3 层**：现有的专用积木（路由、返回、集合、改控件、事件……）**一块都不删、样子不变**，但改成“库里的积木”——点开能看到它是怎么用基础积木搭出来的。
- **旧项目**：照常打开、不改文件；跑出来的结果必须和现在一样（有测试守着）。

**分 8 个阶段做**，每个阶段都能单独验收（第 10 节）。第一阶段只做“语言核心的值、变量、运算、流程”，不动现有页面。

**需要你定的 5 件事**在第 11 节，每件我都给了建议。

### 1.2 为什么说“不高级”

1. **没有函数**。同一段积木要用三次就得拼三遍。
2. **没有自己的积木**。积木目录是 Dart 常量（`lcBlockSpecs`、`beBlockSpecs`），用户加不了，Agent 也加不了。
3. **数据结构不全**。前端没有列表和对象；后端的对象只能字面写，不能改一个字段、不能往列表里加一项。
4. **循环只有“重复 N 次”和“对每一项”**，没有“当…时重复”，没有跳出。
5. **没有类、模块、错误处理**；异步只有“等一会儿”“请求网址”这两块写死的。
6. **后端积木和前端积木是两套**，各有一份目录、读法、校验、翻译。再来一个领域（命令行工具、定时任务、小游戏）就是第三套。
7. **后端的“路由”“集合”是运行时小库里手写的**（每种语言的小库 470–1160 行），用户看不到、改不了、学不到。

### 1.3 现在已经有、可以直接接着用的底子

- 拼图外形和整套手感（帽子 / 语句 / C 形 / E 形 / 胶囊 / 六边形，`lib/blocks/`）——不重做。
- `BlockHost`：编辑器不认识“前端 / 后端”，换一个宿主就能编辑另一种文档——新的语言核心就是第三个宿主，以后变成唯一的一个。
- `backend_ir.dart` 已经是“与语言无关的中间形式”的雏形，只是太小（没有函数、类）。
- “值的规矩由运行时小库保证、五种语言跑同一份样本逐字节比对”的一致性测试（`test/backend_conformance_test.dart`）——新的语言核心照这个办法验。
- 自定义组件（低代码第 2 版）已经有“定义一次、到处放实例、带属性”的概念，“我的积木”的界面可以照它的路子。

## 2. 总思路和几条关键取舍

### 2.1 一棵语法树，所有语言只吃这棵树

积木文档 →（读入、校验）→ **语法树**（第 4 节）→ 各语言的生成器。现有的两条翻译路线（`JsTarget`、`BeCodeTarget`）合成一条。
库里的积木在这一步之前就被“展开”成对函数 / 方法的调用，生成器根本不知道“路由积木”是什么。

### 2.2 值的规矩：沿用“动态值 + 小库”，类型清楚时写原生的

第 3 版后端有一条很值钱的保证：**同一份积木，五种语言跑出来一模一样**。要保住它，默认做法不变——

- 值就是 JSON 值再加三样：**函数、对象（类的实例）、“稍后的结果”**。在 Go 里是 `any`，在 Java 里是 `Object`，数字一律是 64 位小数。
- 运算默认走小库：`lc.add(a, b)`。小库里写死“文字转数字”“除以 0 得 0”这些规矩。

但满篇 `lc.add(…)` 的代码不好看，也不像“掌握了语言”。所以加一条：**两边的类型在写的时候就能确定时，直接生成原生写法**
（都是数字 → `a + b`；都是文字做拼接 → 各语言自己的拼接；条件已经是布尔 → 不包 `truthy`）。
类型说不准（请求里读来的、没标类型的参数）才走小库。这样写得越清楚，生成的代码越地道。（这是第 11 节的问题 1。）

### 2.3 静态语言的类型：能不填就不填

Go 和 Java 要类型。办法是三档，从松到严（第 4.3 节细说）：

1. **什么都不标**：一律按动态值生成（`any` / `Object`），照样能编译、能跑。上手零门槛。
2. **标了**（变量、参数、返回值上可选的类型小标签）：校验多查一层；生成原生类型；运算写原生的。
3. **必须标的地方只有一处**：和**原生库**打交道的边界（比如 Spring Boot 要求控制器方法的参数有确切类型）。那里库的作者已经标好了，用户填槽时照着槽的类型来。

### 2.4 某种语言没有这个特性怎么办

三种处理，按这个顺序选，每块积木在第 3 节的表里都写了用哪种：

- **降级生成**（优先）：用这种语言里等价的写法实现，行为一致。例：Go 没有异常 → `panic / recover`；Java 的闭包不能改外面的变量 → 把变量装进“盒子”。
- **小库兜底**：行为太细、各语言差别太大的，放进运行时小库。例：Go 没有类的继承 → 小库里的“对象 + 方法表”。
- **禁用并说明**（最后手段）：这种语言里做不到、硬做会骗人的。积木在积木盒里变灰，按住显示原因；文档里已经用了的，校验报“这种语言不支持”（新规则 L06，错误级）。例：PHP 的内置服务器里没法做真正的并发等待。

### 2.5 不做的事

- **不做解释器**：不在手机上解释执行积木，仍然是“生成代码 → 交给语言自己跑”。
- **不抄 Scratch / Blockly / Snap! 的代码和素材**，不嵌网页版积木库。
- **不追求把每种语言的每个特性都做成积木**（装饰器、泛型约束、宏、指针运算……）。做不成积木的由“原生片段”兜底（第 5.5 节）。

## 3. 语言核心积木全集

**读法**：`[ ]` 语句块（上凹下凸，能上下拼）；`( )` 值块（胶囊）；`< >` 是否块（六边形）；`{ }` 里面能放积木的口（C 形）；
“帽子”＝一串的开头。外形全部沿用第 3 版，只新增四种变体（见 3.13）。

**表里的生成写法**默认是“动态值”模式（2.2 节）；`lc.` 开头的是运行时小库的函数。TypeScript ＝ JavaScript 的写法加上类型标注
（标了类型才有，没标的写 `unknown`），表里不单列。**除了注明“已在本机跑过”的，表里各语言的写法都是按语言规范写的设计，还没有逐条生成、编译、运行过（未验证）。**

### 3.1 值与类型

| 积木 | 说明 | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- | --- |
| `(12.5)` 数字 | 一律 64 位小数；整数显示不带小数点（沿用第 3 版“数字的写法”） | `12.5` | `12.5` | `12.5`（`float64`） | `12.5`（`Double`） | `12.5` |
| `(你好)` 文字 | Unicode 文字 | `"你好"` | `"你好"` | `"你好"` | `"你好"` | `"你好"` |
| `<是>` / `<否>` | 布尔 | `true` | `True` | `true` | `true` | `true` |
| `(空)` | 没有值 | `null` | `None` | `nil` | `null` | `null` |
| `(列表 [a] [b] ＋)` | 有顺序的一串值，可以嵌套 | `[a, b]` | `[a, b]` | `[]any{a, b}` | `Lc.list(a, b)`（`ArrayList<Object>`） | `[a, b]` |
| `(字典 {键: 值} ＋)` | 文字键 → 值（现在后端的“对象”积木升级而来） | `{k: v}`（无原型对象） | `{k: v}` | `map[string]any{k: v}` | `Lc.dict(k, v)`（`LinkedHashMap`） | `new LcObj([k => v])`（沿用第 3 版，PHP 数组分不清列表和字典） |
| `<(x) 是 [数字▾] 吗>` | 数字 / 文字 / 是否 / 空 / 列表 / 字典 / 函数 / 某个类 | `lc.isType(x, "number")` | 同左 | 同左 | 同左 | 同左 |
| `((x) 转成 [数字▾])` | 数字 / 文字 / 是否；规矩沿用第 3 版（转不了的数字当 0） | `lc.num(x)` | `lc.num(x)` | `lc.Num(x)` | `Lc.num(x)` | `lc_num($x)` |

- 字典**遍历的顺序**定为“键按 Unicode 码点从小到大”（和第 3 版 JSON 输出的顺序一致；Go 的 map 本来就没有顺序，只有这样五种语言才能一样）。自定。
- 新增的三种值：**函数**（3.6）、**对象**（3.7，类的实例）、“稍后的结果”（3.10）。它们不能直接变成 JSON：转文字时函数写成 `[函数 名字]`、对象写成 `[类名]`；输出 JSON 时当空。自定。

### 3.2 变量与作用域

| 积木 | 说明 | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- | --- |
| `[新建变量 [n] ＝ (0)]` | 在所在的函数（或模块）里新建 | `let n = 0;` | `n = 0` | `var n any = 0.0` | `Object n = 0.0;` | `$n = 0.0;` |
| `[新建常量 [N] ＝ (10)]` | 建了以后不许再改（校验拦） | `const N = 10;` | `N = 10` | `var N any = 10.0` | `final Object N = 10.0;` | `$N = 10.0;` |
| `[把 [n▾] 设为 (值)]` | | `n = v;` | `n = v` | `n = v` | `n = v;` | `$n = v;` |
| `[把 [n▾] 加上 (1)]` | 两边先转数字（沿用） | `n = lc.add(n, 1);` | 同理 | 同理 | 同理 | 同理 |
| `(n)` | 读变量；下拉里只列“这里看得见的” | `n` | `n` | `n` | `n` | `$n` |

> 实施时的改动（阶段 1）：上表的生成写法是示意。实际所有声明都提到函数开头，原处只赋值；常量在生成的代码里和变量一样，“不许再改”只靠校验 L11 拦。见第 10 节“实施记录·阶段 1”。

**作用域的规矩（五种语言统一成一种）**：

- 三层：**模块级**（整个文件看得见）、**函数级**（这个函数里，从“新建变量”那一块往下看得见）、**参数 / 循环变量**（只在那个函数 / 那个循环里）。
- 没有“块级”：`如果` 里新建的变量，出了 `如果` 还在（Python 本来就这样；JavaScript、Go、Java 生成时把声明提到函数开头）。同一个函数里同名变量只许新建一次（校验拦，新规则 L09）。
- 里层函数能读、能改外层函数的变量（闭包，3.6）。
- 生成的名字一律带前缀（沿用第 3 版的 `v_名字`），撞不上任何语言的保留字。
- 现在后端“每次请求重置的变量”＝迁移后接口函数里的局部变量；现在页面逻辑的“页面变量”＝模块级变量（第 8 节）。

### 3.3 运算

| 积木 | 说明 | 生成（五种语言同一个思路） |
| --- | --- | --- |
| `((a) [＋▾] (b))` | ＋ − × ÷ 余数 乘方 | 类型都确定是数字：原生运算符（乘方：JS `**`、Python `**`、Go `math.Pow`、Java `Math.pow`、PHP `**`）；否则 `lc.add(a, b)` 等。除以 0 得 0（沿用），所以 ÷ 和余数永远走小库 |
| `([四舍五入▾] (x))` | 四舍五入、向下取整、向上取整、绝对值、平方根、最大、最小 | 小库（各语言“正好一半”的舍入方向不一样，统一成“远离 0”） |
| `(随机数 从 (1) 到 (6))` | 含两头的整数 | 小库 |
| `<(a) [＝▾] (b)>` | ＝ ≠ ＜ ≤ ＞ ≥；“等于”的规矩沿用第 3 版 | 都是数字 / 都是文字：原生比较；否则 `lc.eq(a, b)` 等 |
| `<<a> [并且▾] <b>>` | 并且 / 或者。**前面已经能定结果时，后面的不算**（短路）——现在后端是两边都算，但旧积木的值都没有副作用，看不出区别 | `lc.truthy(a) && lc.truthy(b)`；已经是布尔就不包。Python 用 `and` / `or` |
| `<不是 <a>>` | | `!lc.truthy(a)` |
| `(如果 <c> 就是 (a) 否则是 (b))` | 值版本的“如果” | JS / Java / PHP `c ? a : b`；Python `a if c else b`；Go 没有这种写法 → 小库的 `lc.Pick(c, func() any { return a }, func() any { return b })`，两边包成函数、只算选中的那一边（阶段 1 实施时定的，已真跑验证；原方案“临时变量加 `if`”在式子套式子时要拆句，没用） |

### 3.4 条件

| 积木 | 说明 | 各语言 |
| --- | --- | --- |
| `[如果 <c> 那么 { } 否则如果 <d> 那么 { } … 否则 { }]` | 现在只有“如果 / 否则”两个口；新版可以点“＋”加任意多段“否则如果” | 都有 `if / else if / else`（Python 是 `elif`） |

### 3.5 循环

| 积木 | 说明 | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- | --- |
| `[重复 (10) 次 { }]` | 沿用：封顶 10000 遍 | `for (let i = 0, n = lc.times(x); i < n; i++)` | `for _ in range(lc.times(x)):` | `for i, n := 0, lc.Times(x); i < n; i++` | 同 JS 写法 | 同 JS 写法 |
| `[当 <c> 时重复 { }]` | **新**。不封顶 | `while (c) { }` | `while c:` | `for c { }` | `while (c) { }` | `while (c) { }` |
| `[一直重复 { }]` | **新**。只能靠“跳出”“返回”出来 | `while (true)` | `while True:` | `for { }` | `while (true)` | `while (true)` |
| `[[i] 从 (1) 数到 (10) 每次加 (1) { }]` | **新**。含两头；步长是负数就往下数；步长 0 一遍也不做 | `for` 循环，上下界和步长先算好存进临时变量 | `for` + 小库的 `lc.count(a, b, s)` | 同 JS | 同 JS | 同 JS |
| `[对 (列表) 的每一项 [x]（序号 [i]）{ }]` | 沿用并加上可选的序号；循环中途改列表不影响这一轮 | `for (const x of lc.items(xs))` | `for x in lc.items(xs):` | `for i, x := range lc.Items(xs)` | `for (Object x : Lc.items(xs))` | `foreach (lc_items($xs) as $i => $x)` |

| `[跳出循环]` | **新** | `break;` | `break` | `break` | `break;` | `break;` |
| `[跳过这一轮]` | **新** | `continue;` | `continue` | `continue` | `continue;` | `continue;` |

“当…时重复”和“一直重复”带来了现在没有的风险：**死循环**。两道防线：校验（“一直重复”里没有“跳出 / 返回 / 抛出”、
“当 `<是>` 时重复”——新规则 L13，警告）；“运行”时可选的“防卡死”——同一个循环转满 100 万圈就停下并报错（由小库计数，默认开，设置里能关，自定）。

### 3.6 函数

| 积木 | 说明 | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- | --- |
| 帽子 `定义 [问好] ( [名字] [次数＝1] ＋ )` | 一个函数一串。参数能加减、改名、给默认值、可选地标类型；最后一个参数可以设成“剩下的全收”（不定个数） | `function f(a, b = 1) { }` | `def f(a, b=1):` | `func f(a any, b any) any { }` | `static Object f(Object a, Object b) { }` | `function f($a, $b = 1.0) { }` |
| `[返回 (值)]` / `[返回]` | 结束这个函数。函数里一块“返回 (值)”都没有＝这个函数是“语句型”的 | `return v;` | `return v` | `return v` | `return v;` | `return v;` |
| `[问好 (小明) (3)]` | **调用，语句型**。积木的样子由“封装”定（第 5 节），默认是“名字 ＋ 每个参数一个槽” | `f(a, b);` | `f(a, b)` | `f(a, b)` | `f(a, b);` | `f($a, $b);` |

| `([问好▾] 这个函数本身)` | 把有名字的函数当值传 | `f` | `f` | `lc.Fn(f)` | `Lc.fn(Main::f)` | `'f'` 或 `f(...)` |
| `[调用 (函数值) 带 (参数…)]` / 值型 | 调用一个放在变量里的函数 | `g(a)` | `g(a)` | `lc.Call(g, a)` | `Lc.call(g, a)` | `$g($a)` |

- **闭包**（里层函数用外层的变量）各语言差别最大，生成器要多做的事：
  - Python：里层要**改**外层变量时，自动加一行 `nonlocal 变量`。
  - Java：lambda 只能用“不再改的”外层变量 → 被里层改写的变量自动装进一个一格的“盒子”（`Object[] n = {0.0}`，读写都变成 `n[0]`）。
  - PHP：匿名函数要写明用了外面哪些变量 → 自动生成 `use (&$n)`。
  - JavaScript、Go：原生支持，不用处理。
  - **以上四种写法已在本机跑过**：同一个“计数器闭包 ＋ 路由器类 ＋ 继承 ＋ 出错兜底”的小程序，手写成 Node / Python / Go / Java 四份
    （`docs/blocks-v4-proto/`），输出逐字相同。PHP 本机没有，未验证。
- **实施时和上表不一样的地方**（第 2 阶段，详见“实施记录·阶段 2·语言核心”）：函数当值用时五种语言都包一层小库的函数值、调用都走小库的 `call`（上表写的 JS／Python 直接用原生函数、PHP `$g($a)` 没有照做）；Go／Java 的“剩下的全收”参数就是一个列表、调用处包好；PHP 的短写法也用 `function … use (&…)`，不用 `fn`；生成的函数名是 `f_名字`。
- **默认值**：只许是直接填的值。Go、Java 没有默认参数 → 调用的地方少给了几个，生成器就在调用处把默认值补上（降级）。
- **不定个数的参数**：JS `...xs`、Python `*xs`、Go `xs ...any`、Java `Object... xs`、PHP `...$xs`；函数里拿到的是一个列表。
- **递归**：允许。**按名字传参**（`f(次数=3)`）不做——积木的槽本来就带名字，用不着。
- 没有“返回”的函数被当成值用：得到空。校验提醒（新规则 L03 的一种，警告）。

### 3.7 类

类在画布上不是一块巨大的积木，而是**一个可以点进去的“小画布”**（第 9 节）：里面是字段表、一串“创建时”、每个方法一串。

| 积木 / 设定 | 说明 | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- | --- |
| 类 `[动物]`，父类 `[无▾]` | 只能有一个父类；不许绕圈继承（新规则 L07） | `class A extends B { }` | `class A(B):` | 小库的“类”（见下） | `static class A extends B { }` | `class A extends B { }` |
| 字段 `名字 ＝ (空)`，公开 / 私有，可选类型 | 私有＝只有这个类自己的方法能读写（校验拦；各语言再尽量用自己的办法拦） | 公开 `this.name`；私有 `this.#name` | 公开 `self.name`；私有 `self._name`（Python 只是约定，靠校验） | 字段表里的一项 | 公开 / `private Object name;` | `public $name;` / `private $name;` |
| 帽子 `创建时 ( 参数… )` | 构造。最多一串；没有就是什么都不做。子类的“创建时”里要先“调用父类的创建时”（没写就自动补在最前面） | `constructor(a) { super(…); }` | `def __init__(self, a): super().__init__(…)` | 方法表里的 `init` | 构造函数 | `function __construct($a) { parent::__construct(…); }` |

| 帽子 `静态方法 […]`、字段设成“静态” | 属于类、不属于某个对象 | `static f() { }` / `static n = 0` | `@staticmethod` / 类变量 | 类的静态表 | `static …` | `static function f()` / `static $n` |
| `(这个对象)` | 只能在方法 / 创建时里用 | `this` | `self` | `self` | `this` | `$this` |

| `(新建 [动物▾] (参数…))` | | `new A(a)` | `A(a)` | `lc.New(A, a)` | `new A(a)` | `new A($a)` |
| `[让 (对象) [叫▾] (参数…)]` / 值型 | 调用方法；子类重写了就用子类的 | `o.speak(a)` | `o.speak(a)` | `lc.Send(o, "speak", a)` | 类型确定：`o.speak(a)`；否则 `Lc.send(o, "speak", a)` | `$o->speak($a)` |
| `[调用父类的 [叫▾] (参数…)]` | 只能在方法里用 | `super.speak(a)` | `super().speak(a)` | `lc.Super(self, 本类, "speak", a)` | `super.speak(a)` | `parent::speak($a)` |

| 接口 `[会叫的]`：一组“必须有的方法” | 类可以“实现”多个接口；少实现了一个方法＝校验报错（新规则 L08） | JS 没有接口 → **只做校验**，不生成东西；TypeScript 生成 `interface` | 只做校验 | 动态模式只做校验；全标了类型时生成 Go 的 `interface` | `interface A { }` ＋ `implements` | `interface A { }` ＋ `implements` |

- **Go 没有类和继承**。办法：小库里放一个很小的对象模型——“类”＝名字 ＋ 父类 ＋ 方法表，“对象”＝类 ＋ 字段表，调用方法时沿着父类往上找。
  这样重写、调用父类的行为和别的语言完全一致。**这个办法已在本机跑过**（`docs/blocks-v4-proto/go/main.go`，约 40 行小库就够）。
  代价是生成的 Go 代码不像手写的 Go；以后“字段全标了类型、又没用继承”的类可以改成生成原生的 `struct`（放在最后的优化阶段，未验证）。

- 类型确定不了的对象在 Java 里调用方法要靠小库转一道（`Lc.send`）：每个生成的类自动带一个“按名字调方法”的分发函数，不用反射（未验证）。

### 3.8 模块与导入导出

- **一个积木文件＝一个模块**。里面的顶层东西（函数、类、模块级变量、“启动时”那一串）可以设成“公开”或“只给自己用”。
- 另一个文件里“用上”这个模块以后，它公开的函数和类就出现在积木盒里（一个模块一个分类）。不许两个模块互相用（新规则 L10）。
- **库**就是打包好的模块（第 5 节）。

| | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- |
| 后端 / 命令行：一个模块一个文件 | Node 用 `require` / `module.exports`（和现在生成的一致）；以后可选 ES 模块 | `import 模块` | Go 的“包”是按目录分的 → 所有模块生成在同一个包里的不同文件，公开不公开只由校验管，名字加模块前缀 | 一个模块一个类文件，顶层函数是它的 `static` 方法 | `require_once`，名字加模块前缀 |
| 网页：`logic.js` 只有一个文件 | 所有模块按依赖顺序拼进一个文件，各包在自己的函数作用域里 | — | — | — | — |

- **第三方包**（npm、pip、Maven、Go 模块、Composer）不能随手导入：只能通过带“原生绑定”的库（5.5），因为它涉及联网安装和各语言的写法。

### 3.9 错误处理

| 积木 | 说明 | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- | --- |
| `[试着做 { } 出错了 [e] { } 最后总要 { }]` | 三个口；“最后总要”可以不要 | `try { } catch (e) { } finally { }` | `try: / except Exception as e: / finally:` | 没有异常 → 小库 `lc.Try(做, 出错了, 最后)`，里面用 `panic` / `recover`（**“出错兜底”这一半已在本机跑过**；口里面有“返回 / 跳出”的情况未验证，见下） | `try { } catch (RuntimeException e) { } finally { }` | `try { } catch (\Throwable $e) { } finally { }` |
| `[抛出错误 (消息)]` | | `throw new Error(m);` | `raise Exception(m)` | `panic(lc.Err(m))` | `throw new LcError(m);` | `throw new \Exception($m);` |
| `((e) 的消息)` | 接到的错误是一个值，能取它的说明文字 | `lc.errText(e)` | 同理 | 同理 | 同理 | 同理 |

- 自定义错误＝继承内置的“错误”类（3.7）；“出错了”的口可以只接某一个类的错误（下拉选类，默认“任何错误”）。
- **Go 的难点（未验证）**：“试着做”的口在 Go 里是一个内层函数，口里的“返回”“跳出循环”出不了这个内层函数。
  办法：内层函数返回一个“是怎么出来的”的标记（做完了 / 要返回某个值 / 要跳出 / 要跳过），外面按标记接着做。实现前要先写原型。
- Go 惯用的“多返回一个 `err`”不做成积木（和其他四种语言差得太远）；和 Go 原生库打交道时由绑定把 `err` 变成“抛出”。
- 小库自己的规矩不变：除以 0 得 0、取不到得空，这些**不**抛错。新加的会抛错的操作在 3.11 里标了。

### 3.10 异步

**用户不用标“这是异步函数”**。规矩只有一句：**“等”＝拿到结果再往下走**。哪些函数要写成 `async`、哪里要加 `await`，生成器自己推（只要函数里直接或间接“等”了什么，它就是异步的，调用它的地方自动等）。现在 Node 后端的“请求网址”已经是这么生成的。

| 积木 | 说明 | JavaScript | Python | Go | Java | PHP |
| --- | --- | --- | --- | --- | --- | --- |
| `[等 (1000) 毫秒]` | 现在页面逻辑的“等一会儿”是 C 形（等完做里面的）；新版是普通语句，下面的积木自然就是“等完再做” | `await lc.sleep(ms);` | `time.sleep(…)` | `time.Sleep(…)` | `Thread.sleep(…)` | `usleep(…)` |
| `(开始做 { })` | 马上开始、不等它，得到一个“稍后的结果” | 一个立刻调用的 `async` 函数（得到 Promise） | 线程池里的一个任务（`Future`） | 一个 goroutine ＋ 通道 | 虚拟线程里的 `CompletableFuture`（JDK 21） | **禁用**：PHP 内置服务器一个请求一个进程，没有后台 |
| `(等 (稍后的结果))` | 等它做完，拿到它“返回”的值；它里面抛的错在这里抛出来 | `await p` | `f.result()` | 从通道里收 | `f.join()` | 禁用 |
| `(同时做这几件，都做完 ＋)` | 几个“稍后的结果”一起等，得到结果的列表 | `await Promise.all([…])` | 逐个 `result()` | 逐个收 | `allOf(…).join()` | **降级**：一件一件按顺序做（结果一样，只是不同时） |
| `[过 (毫秒) 以后做 { }]` / `[每隔 (毫秒) 做 { }]` | 定时器。只在一直开着的环境里有意义（网页、Node、常驻服务） | `setTimeout` / `setInterval` | 定时线程 | `time.AfterFunc` / `time.Ticker` | 定时线程池 | 禁用 |

- 浏览器和 Node 是“一条线、等的时候别的事接着跑”；Python、Go、Java 这里是“等的时候这条线停住，别的请求在别的线上”。
  对积木来说看到的结果一样；不一样的只有“同时做”是不是真的同时——所以它在 PHP 里是降级，其他是真的。
- Python 的 `async / await`（asyncio）**不用**：标准库的 HTTP 服务器是同步的，混用很麻烦。以后接 FastAPI 这类异步框架时，由那个库的原生绑定声明“我的回调是异步的”（5.5，未验证）。
- 多条线同时改同一个模块级变量会出乱子。第一版的办法：小库的列表 / 字典操作自己加锁（Go、Java、Python）；更细的“锁”积木先不做。未验证。

### 3.11 文字、列表、字典的常用操作

全部由小库实现（类型确定、且原生写法的行为完全一样时才生成原生的）。**位置从 0 开始数**（和生成的代码一致，“看代码”时对得上；自定——Scratch、Snap! 是从 1 开始）。
文字按 Unicode 码点算（沿用）。**读**不到一律得空、不抛错；**写**到不存在的位置抛错（能被“试着做”接住）。

- **文字（14）**：拼接（沿用“拼成文字”）、长度、第几个字、截取一段、包含吗、以…开头吗 / 结尾吗、找位置（找不到是 −1）、替换（全部）、
  按…切成列表、去掉两头空白、转大写 / 小写、重复几遍、套模板（`你好，{名字}`）、和数字互转（见 3.1）。
- **列表（22）**：长度、第几项、改第几项⚠、末尾加一项、在第几项前插入⚠、删第几项⚠、取走最后一项、包含吗、找位置、截取一段、
  接上另一个列表、倒过来、排序（按大小 / 按一个给分的函数）、从 a 到 b 的数列、用…连成文字；
  **拿函数当参数的**：每一项变一下（map）、只留满足的（filter）、合成一个值（reduce）、第一个满足的、都满足吗 / 有满足的吗、每一项做一遍。（⚠＝位置不存在会抛错）
- **字典（9）**：取一个键（现在的“对象的字段”）、设一个键、删一个键、有这个键吗、所有的键、所有的值、所有的“键值对”、个数、合并两个。
- **其他（4）**：转成 JSON 文字 / 从 JSON 文字解析（解析失败得空）、现在的时间（沿用）、打印一行（沿用“写到控制台 / 写日志”）。

“改列表”的积木是**原地改**（变量里那个列表本身变了），和各语言的习惯一致。当参数传给函数的列表也是同一个（不复制）。

### 3.13 编辑器要新增的四种外形 / 能力（`lib/blocks/`）

1. **多口的 E 形**：现在最多两个口（那么 / 否则）。“否则如果”链和“试着做 / 出错了 / 最后总要”要 3 个以上的口，口数可以增减。
2. **带口的值块**：匿名函数是一个值（能放进槽里），但里面有一个能放语句的口。Snap! 里对应的东西叫“环”（见第 12 节来源）。
3. **能改参数表的定义帽子**：“定义 [名字] (参数…＋)”——参数是帽子上的小块，能加、删、改名，也能从帽子上**拖出来**当值用（Scratch 的做法，见来源）。
4. **点进去的容器**（类、库里某块积木的定义）：画布支持“进入一层 / 返回上一层”，顶栏显示现在在哪。

## 4. 统一的中间表示：一棵和语言无关的语法树

现在有两套：页面逻辑直接从积木翻 JavaScript（`logic_js_core.dart`）；后端先翻成 `backend_ir.dart` 的小中间形式。
新版只有一套，暂定放在新目录 `lib/lang/`（纯 Dart，不依赖界面，不依赖 `lowcode` / `backend`）。

### 4.1 流水线

```
积木文档（*.lcb.json / 旧的 page.lc.json、backend.lc.json）
   │ ① 读入（容错，和现在一样：坏的逐条跳过，不许抛异常）
   ▼
积木树（LcBlockTree，编辑器直接改的就是它，沿用）
   │ ② 展开封装：库里的积木 → 函数调用 / 方法调用 / 内联的一段（第 5 节）
   ▼
语法树（下面这张表）
   │ ③ 检查：名字解析（这个变量是哪一层的）、类型推断、校验规则
   │ ④ 整理（各语言共用）：闭包里被改写的变量做标记、推断哪些函数是异步的、Go 需要的“先算进临时变量”、默认参数在调用处补齐
   ▼
带标注的语法树
   │ ⑤ 各语言的生成器（只吃这棵树）＋ 该语言的运行时小库 ＋ 用到的宿主原生接口的实现
   ▼
能直接跑的小工程
```

### 4.2 节点种类

每个节点都带：**来源**（哪一串、第几块、哪个槽——校验问题和“看代码时点一行跳到积木”都靠它）、**类型**（推断出来的或标的）。

**声明（模块顶层）**

| 节点 | 内容 |
| --- | --- |
| `Module` | 名字、用上的模块、下面这些声明、“启动时”的语句 |
| `VarDecl` | 名字、初始值、是不是常量、公开吗、类型标注（可无） |
| `FuncDecl` | 名字、参数表（名字、默认值、类型标注、是不是“剩下的全收”）、返回类型标注、函数体、公开吗；推断出来的：是不是异步、有没有返回值 |
| `ClassDecl` | 名字、父类、实现的接口、字段表（名字、初始值、公开 / 私有、静态吗、类型）、构造、方法表（`FuncDecl` ＋ 静态吗 ＋ 抽象吗） |
| `InterfaceDecl` | 名字、方法签名表 |
| `NativeDecl` | 一个由宿主或原生库提供的函数 / 类的“签名”（名字、参数、返回、类型），没有函数体；各语言的实现在别处（5.5） |

**语句**

`Let`（新建变量）、`Assign`（给变量 / 字段 / 列表某项 / 字典某键赋值——左边是一个“能赋值的位置”）、`ExprStmt`（只为效果算一个式子）、
`If`（若干段条件 ＋ 可选的否则）、`While`、`ForCount`（从…数到…）、`ForEach`（列表）、`ForPairs`（字典）、`Repeat`（重复 N 次，带封顶）、
`Break`、`Continue`、`Return`、`Throw`、`Try`（做 / 出错了＋错误变量＋可选的类 / 最后）、`Note`（一行注释：积木的中文读法，或“这里没填好”）。

**式子**

`Lit`（数字 / 文字 / 是否 / 空）、`ListLit`、`DictLit`、`Name`（读变量 / 参数 / 函数名 / 类名——解析后知道是哪一种、哪一层）、
`Field`（对象.字段）、`Index`（列表[位置] / 字典[键]）、`Unary`、`Binary`（带运算符；`并且 / 或者`单列为 `Logic`，因为要短路）、`Cond`（值版的如果）、
`Call`（调函数：被调的是一个式子）、`Send`（调方法：对象、方法名、参数）、`SuperSend`、`New`、`IsA`、`Lambda`（参数 ＋ 函数体）、
`This`、`Await`、`Spawn`（开始做）、`Rt`（调运行时小库的函数——文字 / 列表 / 字典操作、类型转换都是它；名字在一张表里，像现在的 `kBeRuntimeFns`）、
`Native`（调宿主 / 原生库的函数）。

和现在的 `backend_ir.dart` 的关系：它的 5 种式子、7 种语句是这张表的子集（`BeXCall` → `Rt`，`BeXReq` → 一个普通参数，`BeSRespond` → `Return`）。
实现时从它长出来，不是推倒重写。

### 4.3 类型系统做到什么程度

**类型有这些**：数字、文字、是否、空、列表〈元素类型〉、字典〈值类型〉、函数（参数类型…→返回类型）、某个类 / 接口、“稍后的结果〈类型〉”、
**任意**（说不准）。再加“可以是空”的标记。没有泛型函数、没有联合类型——说不清的一律是“任意”。

**怎么得到类型**：

- 直接填的值、运算的结果（比较一定是“是否”，算术一定是数字）、`新建 类`、小库函数（表里写了返回什么）——**自动推**。
- 变量：没标类型时，取“所有赋给它的值的类型”——都一样就是那个类型，不一样就是“任意”。
- 参数、返回值、字段：**可选地标**（参数小块 / 字段行上的一个类型小标签，点一下选；默认不显示，选了“任意”以外的才显示）。
- 宿主接口和原生库：签名里**必须**写全（库的作者写，不是用户）。

**拿类型做什么**：

1. **校验**（现有的 G10 扩大范围）：确定对不上＝按现有定级（错误 / 警告）；只要有一边是“任意”就不报。这条原则不变。
2. **生成更地道的代码**（2.2 节）：两边类型都确定时写原生运算。
3. **静态语言的声明**：
   - 类型是“任意”→ Go `any`、Java `Object`、TypeScript `unknown`。
   - 类型确定 → Go `float64` / `string` / `bool` / `[]T` / `map[string]T`，Java `double` / `String` / `boolean` / `List<T>` / `Map<String, T>`，TypeScript 对应的标注；Python 生成类型提示（只是提示）；PHP 生成参数 / 返回类型声明。
   - **确定的类型和“任意”相遇的地方**（把“任意”的值赋给标了“数字”的变量）：生成一次小库的转换（`lc.Num(x)`），规矩就是 3.1 的“转成数字”。不会编译不过，也不会运行时崩。

**什么时候类型必须填**：只有一种情况——把函数 / 对象交给**原生库**、而那个库的签名要求确切类型（比如 Spring Boot 的控制器方法）。
这时槽上会显示要求的类型，放进去的东西类型对不上＝校验错误（新规则 L05）。纯积木搭的东西**永远不强制**标类型。

**分两步落地**：先只做“全部按任意生成 ＋ 类型只用于校验”（和现在后端一样，稳）；“类型确定时写原生的”放在后面的阶段，
并且要过同一套一致性测试（开和不开这个优化，跑出来的结果必须一样）。

### 4.4 生成器的接口（给实现的人）

沿用 `BeCodeTarget` 的思路并扩大——一种语言实现这些“怎么写”：

- 字面量、名字（变量 / 函数 / 类 / 字段，各带前缀）、注释；
- 每种语句怎么写、每种式子怎么写（`Rt` / `Native` 调用怎么写）；
- 函数 / 匿名函数 / 类 / 接口的壳怎么写；闭包的处理（Java 的盒子、Python 的 `nonlocal`、PHP 的 `use`）；
- 模块怎么落成文件、怎么互相引用；入口文件怎么写；
- **能力表**：这种语言“原生支持 / 降级 / 禁用”哪些节点（2.4 节）——积木盒变灰、校验 L06 都查它，文档第 3 节的表就是它的内容。

加一种语言要写的东西从现在的“三样”变成：运行时小库 ＋ 生成器 ＋ 能力表 ＋ 每个宿主接口的实现；一致性测试自动覆盖。

## 5. 封装：怎样把一段积木包成一块新积木

### 5.1 概念

**一块自定义积木 ＝ 一个定义（函数 / 方法 / 类的构造）＋ 一个“外观”**。定义决定它做什么；外观决定它在积木盒里和画布上长什么样。
生成代码时它就是一次普通的函数调用，没有任何魔法。（Scratch 的“自制积木”只能做语句型、没有返回值；Snap! 的口号就是“造你自己的积木”，
值型、是否型、带口的都能造——我们照 Snap! 的能力来，见第 12 节来源。）

### 5.2 外观里能定什么

| 能定的 | 选项 |
| --- | --- |
| **形状** | 语句型 / 值型 / 是否型——默认按定义自动选（有没有“返回 (值)”）；另有两种特殊的：**收尾型**（下面不能再接积木）、**帽子型**（当一串的开头） |
| **文案模板** | `把 {集合} 里编号是 {id} 的那条删掉`——花括号是参数槽，其余是字。沿用第 3 版的句子模板（`BlockHost.blockSentence`）。没写就是“名字 ＋ 每个参数一个槽” |
| **每个槽的种类** | 值（可选类型）、是否、**固定选项**（下拉）、**从某一类东西里选**（变量 / 类 / 宿主给的清单，比如“页面上的控件”“数据集合”）、**口**（能放积木） |
| **口的两种** | **内联口**：口里的积木原样放进定义里指定的位置，口里的“返回”“跳出”作用于外面（像“如果”“重复”这类流程积木）；**回调口**：口里的积木包成一个函数传进去，可以带参数（参数小块能从积木上拖出来用） |
| **颜色和分类** | 选一个现有的颜色类别，或给库定一个新的；放在积木盒的哪一类 |
| **说明** | 一句话，积木盒里按住显示 |

- **收尾型**解决“返回数据”这种积木：它的意思是“算出一个响应，并且让所在的接口到此结束”。展开规则：`[返回数据 …]` → `Return(调用(…))`。
- **帽子型**解决“当收到 GET /hello”“当按钮被点击”：展开规则：帽子下面那一串包成一个函数，在模块启动时调用一次“注册”函数把它传进去。
  帽子上可以带参数小块（“请求”“输入的内容”），就是那个函数的参数。
- **内联口**是在第 ② 步（展开）做的文字替换式展开，所以带内联口的定义不许递归（校验拦），口里也看不到定义内部的局部变量（展开时自动改名）。
  这是为了不引入 Snap! 那样的“续延”机制——我们是生成代码，没法在五种语言里都实现它。自定。

### 5.3 怎么造（用户看到的流程）

1. 积木盒“我的积木”分类 →“新建积木”。弹一页：起名字、选形状、写文案（一边写一边在上面预览真的积木）、加参数槽。
2. 确定后：画布上多一串“定义 …”，积木盒里多一块。往定义下面拼积木就行。
3. 另一条路：在画布上选中一段积木 →“包成积木”。自动把这段里用到的外面的变量变成参数（照低代码“存成组件”的路子）。
4. 改定义的参数（加、删、改名、换顺序）→ 所有用到它的地方跟着变：多出来的槽填默认值，删掉的槽里的东西丢掉前先提示有几处在用。
5. 封装可以套封装（积木的定义里用别的自定义积木）；可以递归（内联口的除外）。

### 5.4 积木库

- **库 ＝ 一个或几个模块 ＋ 一张清单**：名字、版本、作者、说明、它公开了哪些积木、需要哪些宿主接口、支持哪些语言。文件夹形式，放在项目的 `blocks/库名/`。
- **内置库**跟着应用走（只读，能“看里面”）；**项目库**在项目里；**我的库**在应用的文档目录里，任何项目都能“用上”（实际是复制一份进项目，项目才能脱离手机单独存在）。
- 导出 / 导入：一个库打成一个文件（zip），可以发给别人。**不做在线积木商店**（涉及联网、审核；真要做另议）。
- 库的版本：项目里记着用的是哪一版；库更新后不自动换，提示“有新版，要不要换”，换之前列出哪些积木的参数变了。
- Agent 可以读写库（新工具，照 `backend_update_blocks` 的路子），所以“让 Agent 帮我封装一个登录校验积木”做得到。

### 5.5 原生绑定和原生片段（封装的最底下一层）

纯积木搭不出“开一个 HTTP 端口”。最底下总要有几块是**每种语言各写一段真代码**实现的：

- **原生绑定**：`NativeDecl`——一块积木的签名，加上“在 Node 里是这段代码、在 Python 里是那段”。Blockly 给每块积木每种语言各写一个生成函数，是同一个思路（见来源）；
  区别是我们只有最底层的少数几块这么做，其余全是积木搭的。
- 一种语言没给实现 → 这块积木、以及所有用到它的积木，在那种语言下变灰（L06）。
- **谁能写**：内置库由我们写；用户库里**也允许**写（高级功能，默认收起）：一个“原生片段”积木，里面是一小段手写代码，参数用 `{名字}` 引用。
  它是“积木做不到时的出口”（装饰器、某个第三方包的特殊写法）。片段原样进生成的代码，不做检查——界面上要标明“这一块是手写代码，不保证各语言都能跑”。
- 原生库要装第三方包（npm / pip / Maven…）时，清单里写明包名和版本；“运行”前检查有没有装，没装就走现有的“自动配环境”流程（要联网，照规矩先问）。

## 6. 现有的积木怎么变成“库”

原则：**op 的名字、存盘的样子、积木上的话、颜色都不变**（老文件不动、用户看不出区别），变的只是“它背后是一个库里的定义”。

### 6.1 必须由宿主提供的最小原生接口

**通用（哪种项目都有，其实就是运行时小库的一部分）**：打印一行、现在的时间、随机数、JSON 互转、网址的百分号编码 / 解码、睡眠、发网络请求（`net.fetch`，规矩沿用第 3 版）。

**后端宿主（3 个）**

| 接口 | 意思 |
| --- | --- |
| `http.serve(端口, 处理函数)` | 开服务。每来一个请求就调一次 `处理函数(请求)`，它返回一个响应。`请求`是个字典：方式、原始路径、原始网址参数、请求头（名字小写）、请求内容（文字，或空）。`响应`是个字典：状态码、响应头、内容。读请求、写响应、超过 1MB 回 413 这些“值的规矩的细则”留在宿主里（各语言 HTTP 库的差别在这里抹平） |
| `store.get(名字)` / `store.set(名字, 值)` | 一个“在请求之间留得住”的格子。Node / Python / Go / Java 就是内存里的一个表；PHP 是带锁的文件（它每个请求都是新进程，沿用第 3 版的 `lc_data.json`） |

**页面宿主（6 个）**

| 接口 | 意思 |
| --- | --- |
| `dom.find(控件编号)` | 拿到页面上的一个控件 |
| `dom.get(控件, 属性)` / `dom.set(控件, 属性, 值)` | 读 / 改：文字、输入内容、是否显示、背景色、文字颜色、图片地址、提示文字 |
| `dom.on(控件, 事件, 函数)` | 点击、内容变化；函数的参数是事件（能取“输入的内容”） |
| `page.onLoad(函数)` | 页面打开时 |
| `page.alert(文字)` | 弹提示 |
| `page.go(网址)` | 跳转 |

页面宿主有三份实现——普通网页（直接操作 DOM）、Vue（`ref`）、React（状态对象）——就是现在 `JsTarget` 的三个子类干的事，换个地方放。

### 6.2 后端：每块现有积木对应的封装定义（库名“接口服务”）

库里先用基础积木写好这几样（全是 3.x 的积木，没有新魔法）：

- 模块级的 `路由表`（列表）；函数 `注册(方式, 路径, 处理函数)`：往路由表里加一项。
- 函数 `对得上(模式, 路径)`：把两边按 `/` 切开逐段比，`:名字` 的段记进一个字典，返回这个字典或空。（用“按…切成列表”“对每一项”“以…开头吗”。）
- 函数 `分发(请求)`：按顺序找第一个方式和路径都对得上的，调它的处理函数；路径对了方式不对回 405；都对不上回 404；处理函数抛错回 500；没返回回 204。
- 类 `集合`：字段 `名字`；方法 `全部 / 取 / 找 / 个数 / 加 / 改 / 删`，数据放在 `store` 的格子里（`{下一个编号, 记录列表}`）。
- “启动时”：`http.serve(端口, 分发)`。

| 现有的积木 | 封装成什么 | 展开后（定义里是什么） |
| --- | --- | --- |
| 帽子 `当收到 [GET▾] [/todos/:id]` | 帽子型，回调口带一个参数“请求” | `注册("GET", "/todos/:id", 函数(请求){ 这一串 })` |
| `respondJson` 返回数据 | 收尾型 | `返回 JSON响应(状态, 值)`——`JSON响应` 是库里的函数：拼出 `{状态, 响应头, 内容: 转成JSON(值)}`，状态不在 200–599 当 200 |
| `respondText` 返回文字 | 收尾型 | `返回 文字响应(状态, 值)` |
| `dbInsert`（可把结果放进变量） | 语句型；“放进变量”那一格是可选的赋值目标 | `变量 ＝ 集合("todos").加(值)` |
| `dbUpdate` / `dbDelete` | 语句型 | `集合(名).改(id, 值)` / `集合(名).删(id)` |
| `setVar` / `changeVar` | **就是核心积木**（3.2） | — |
| `if` / `repeat` / `forEach` | **就是核心积木**（3.4、3.5） | — |
| `log` | **就是核心积木**“打印一行” | — |
| `fetch`（成功后 / 失败后，结果放进变量） | 语句型，两个**内联口** | `结果 ＝ 等(net.fetch(方式, 网址, 数据))；如果 结果 不是空 { 变量 ＝ 结果；成功的口 } 否则 { 失败的口 }` |
| `pathParam` 路径参数 | 值型 | `请求.路径参数[名字]`（`分发`在调处理函数前把 `对得上` 的结果放进请求里） |
| `query` 网址参数 | 值型 | `网址参数(请求)[名字]`——库里的函数：把原始网址参数按 `&` `=` 切开、解码，重名取第一个 |
| `body` / `bodyField` | 值型 | `从JSON解析(请求.内容)` / 再取一个键 |
| `header` | 值型 | `请求.请求头[转小写(名字)]` |
| `dbAll` / `dbGet` / `dbFind` / `dbCount` | 值型 | `集合(名).全部()` 等 |
| `len` / `isNull` / `now` / `obj` / `pair` / `field` / `text` / `num` / `bool` / `var` / `bin` / `not` / `join` | **就是核心积木** | — |

“数据集合”的清单（现在 `backend.lc.json` 的 `collections`）＝这个库给的“从某一类东西里选”的清单；“集合名”的槽就是从它里面选。

**这件事的实际意义**：路由怎么匹配、集合怎么存，从“每种语言手写在小库里的一千行”变成“一份用积木写的库”，五种语言自动都有。
小库里只剩值的规矩和宿主接口。用户能点进“返回数据”看它是怎么搭的，照着搭一个“返回网页”“返回文件”。

### 6.3 页面逻辑：每块现有积木对应的封装定义（库名“页面”）

| 现有的积木 | 封装成什么 | 展开后 |
| --- | --- | --- |
| 帽子 `当 [按钮“提交”▾] 被点击` | 帽子型，回调口 | `dom.on(dom.find("n3"), "click", 函数(){ 这一串 })` |
| 帽子 `当 [输入框▾] 的内容变化` | 帽子型，回调口带参数“输入的内容” | `dom.on(dom.find(id), "input", 函数(事件){ … })` |
| 帽子 `当页面打开` | 帽子型 | `page.onLoad(函数(){ … })` |
| `event` 输入的内容 | 帽子上的参数小块（只在那个帽子下面能用——现在的规则 P05 自然成立） | 回调的参数 |
| `setProp` 改控件 | 语句型；“控件”槽是“从页面控件里选”，“改什么”是固定选项 | `dom.set(dom.find(id), 属性, 值)` |
| `prop` 控件的属性 | 值型 | `dom.get(dom.find(id), 属性)` |
| `alert` / `navigate` | 语句型 | `page.alert(文字)` / `page.go(网址)` |
| `wait` 等一会儿（C 形，后面的积木不等它） | 语句型，一个**回调口** | 核心的 `[过 (毫秒) 以后做 { }]`（3.10） |
| `fetch`（成功后 / 失败后，后面的积木不等它） | 语句型，两个回调口 | `开始做 { 结果 ＝ 等(net.fetch(…))；如果 … { 成功的口 } 否则 { 失败的口 } }` |
| `setVar` / `changeVar` / `if` / `repeat` / `log`、所有值积木 | **就是核心积木** | — |

注意同名的 `fetch` 在两边行为不同（后端等它、页面不等它）——这是现状，迁移时各归各的库，行为不变。

### 7.1 例一：封装一个 Express 风格的路由库，再用它搭一个接口

app.use((req) => { lc.print(lc.join(req.method, " ", req.path)); });

### 7.3 真正的框架（Express / FastAPI / Flask / Spring Boot …）怎么接

它们作为**带原生绑定的库**接入（5.5），和 7.1 的“小路由”对用户来说是同一种东西，只是最底下那几块不是积木搭的：

| | 原生绑定要写的（每个框架一份，只支持它自己的语言） | 积木外观 |
| --- | --- | --- |
| Express（Node） | `新的应用` → `express()`；`加路由` → `app.get(路径, (req, res) => …)`；`回应` → `res.status(…).json(…)`；`开始服务` → `app.listen(…)` | 可以和“小路由”**一模一样** |
| FastAPI（Python） | `加路由` → 装饰器 `@app.get(路径)`（装饰器不是积木能表达的，正好由原生片段负责）；回调是异步的；启动靠 `uvicorn` | 同上 |
| Spring Boot（Java） | 帽子 → 一个带 `@RestController` 的类里带 `@GetMapping` 的方法；参数要确切类型（4.3 节“必须填类型”的那种情况）；工程要 Maven / Gradle | 同上，多几个类型小标签 |

- 外观一样的好处：同一份积木，换一个库就从“零依赖版”换成“Express 版”。能不能真做到“一键换”取决于两个库公开的积木是否对齐——内置的我们负责对齐。
- 框架版要**联网装包**（npm / pip / Maven），手机上要先配好环境；每个框架的写法要先对着官方文档核对并记进 `docs/api-notes.md`（工程规矩）。
  **以上三个框架的绑定都还没写、没验证**；这台机器上没有装任何一个框架。
- 建议的顺序和要不要做见第 11 节问题 5。

## 8. 旧文档怎么办、34 条校验怎么并进来

### 8.1 旧文档：原样能开，不改就不重写

- `page.lc.json` 里的 `logic`（第 1 版）和 `backend.lc.json`（第 1 版）**读入规则不变**：op 名、参数名、存盘的结构都保留（第 6 节：每个旧 op 就是库里同名的一块积木）。
  所以“迁移”不是一次转换文件的动作，而是**读进来以后在内存里按新模型理解**：
  - 文档自动“用上”对应的内置库（页面逻辑 →“页面”库；后端 →“接口服务”库）。
  - 页面逻辑的 `variables` → 模块级变量；后端的 `variables` → 每个接口函数开头的局部变量（保持“每次请求重置”）；`collections` →“接口服务”库的集合清单。
  - 后端的 `port` / `target` → 模块的设置（“启动时：在端口…开始服务”这一串是自动的，不显示成积木，除非用户点“显示启动积木”）。
- **不改就不重写文件**（和第 3 版对 `x` / `y` 的处理一致）：只是打开看看，文件一个字节都不变。
- **一用到新东西才升版本**：文档里出现了旧版没有的积木（函数、类、“当…时重复”…）或新的顶层内容，存盘时版本号升到 2。
  旧版应用打开第 2 版文档：按现在的规矩，不认识的 op 保留并标 G05，不会崩、不会丢。
- 新写的文件格式：顶层从“一组事件串”扩大成“一组**顶层项**”——事件串（帽子）、函数定义、类、模块级变量；每项仍然带 `x` / `y`。字段只增不改名。

### 8.2 行为不变，靠什么保证

- **后端**：现有的一致性测试（`test/backend_conformance_test.dart`——同一份积木生成各语言、真的起服务、发同样的请求、比对响应）原封不动地当门槛：
  改成“库 ＋ 新生成器”以后，这套测试必须一条不改地全过。生成的**源码文字会变**（多了库里的函数），**行为不许变**。
- **页面逻辑**：现有的 `test/lowcode_logic_js_test.dart`、`test/lowcode_logic_export_test.dart` 里“生成的 JavaScript 跑出来的效果”的断言保留；
  逐字比对生成文本的断言要改成比对行为（这是唯一会动到旧测试断言的地方，实现时逐条列出、说明理由，不许顺手放宽别的）。
- **没写逻辑的页面**：`exportHtml` 的输出继续逐字不变（低代码第 2 版定的规矩）。
- 新增一个“旧文档库”测试：把现有模板（`backend_templates.dart` 里的、低代码模板里带逻辑的）全部用新流水线打开、生成、运行，和旧流水线的结果比对；比对通过以后旧流水线才删。

### 8.3 34 条规则的去向

规则编号是文档化的、用户见过的，**一个都不改号**。

| 现在 | 以后 |
| --- | --- |
| **G01–G08、G10–G13**（必填、值不对、没声明的变量、变量名、不认识的积木 / 值、套太深、乱放积木、类型对不上、空的一串、重复次数、除以 0） | 留在核心，适用范围自然扩大到所有新积木。G03 扩大成“用了这里看不见的名字”（变量、参数）。G07 的“12 层”只算积木套积木，进函数 / 类不累计 |
| **G09**（“加上”用在不是数字的变量上） | 并进 G10 的一种情况，编号保留 |
| **G14**（网址不像网址） | 变成 `net.fetch` 这个接口**自带的槽检查** |
| **P01–P07**（页面的 7 条） | 变成“页面”库**自带的规则**。库的清单里可以声明规则：槽的取值检查（P01、P02、P03、P06）、“只能在某种帽子下面用”（P05——现在由“参数小块只在它的帽子下面看得见”自然成立）、“同一个帽子不许重复”（P07） |
| **S01–S09、S12、S13**（端口、语言、集合、方式、路径、重复 / 被挡住的接口、路径参数、对象字段、状态码） | 变成“接口服务”库自带的规则；S02“选的语言不能生成”并进新的 L06；S12 变成核心“字典”积木的规则，编号保留 |
| **S10**（“返回”后面还有积木） | 升级成核心规则：**任何**“返回 / 跳出 / 跳过 / 抛出 / 收尾型积木”后面还有积木。编号保留 |
| **S11**（有的走法没有“返回”） | 升级成核心规则：有返回值的函数“有的走法没返回值”。对接口来说就是原来的意思。编号保留 |

库自带规则的三种声明方式（不用写代码）：**槽约束**（取值范围、正则、必须是某类东西）、**位置约束**（只能在某帽子下 / 不能在某处）、**唯一约束**（同一文档里某几个槽的组合不许重复）。
S08“被前面的挡住”这种要算的规则，由内置库用 Dart 写（内置库可以带代码规则，用户库不行）。

**新增的语言规则（L 开头，暂定 15 条）**

| 号 | 级别 | 内容 |
| --- | --- | --- |
| L01 | 错误 | 调用的函数 / 方法 / 类不存在（被删了、库没“用上”） |
| L02 | 错误 | 参数个数对不上（少了没有默认值的） |
| L03 | 错误 / 警告 | “返回”不在函数里（错误）；把没有返回值的函数当值用（警告） |
| L04 | 错误 | “跳出 / 跳过”不在循环里；“这个对象 / 调用父类的…”不在方法里 |
| L05 | 错误 | 原生库要求确切类型的槽，放进去的类型对不上或说不准 |
| L06 | 错误 | 这块积木在选的语言里用不了（禁用的那类，附一句为什么、怎么换） |
| L07 | 错误 | 继承绕圈；父类不存在 |
| L08 | 错误 | 说了实现某接口 / 继承抽象类，却少实现了方法；“新建”了一个抽象类 |
| L09 | 错误 | 同一层里名字重复（两个同名函数、同名字段、同一函数里新建两次同名变量、参数重名） |
| L10 | 错误 | 模块互相用上（绕圈） |
| L11 | 错误 | 给常量重新赋值；在类外面读写私有字段 |
| L12 | 警告 | “试着做”里面是空的；“出错了”里什么都没做（错误被悄悄吞掉） |
| L13 | 警告 | 可能的死循环（“一直重复”里没有出口；条件写死成“是”） |
| L14 | 警告 | 定义了但没人用的函数 / 变量 / 参数（只在“问题”面板里列，不在积木上标） |
| L15 | 错误 | 函数里用了宿主的东西（后端的“这次请求”、“返回响应”）：要用就当参数传进来（第 2 阶段实施时加的） |

错误照旧拦“生成 / 导出 / 运行”，警告不拦。校验仍然是纯函数、不抛异常、Agent 存盘时附带结果。

## 9. 手机上怎么不乱（390 宽）

积木从 30 来种变成 110 种以上，再加上库。下面每一条都是为了“一只手、一块小屏也能搭”。**这一节全是设计，没有做出来在真机上试过（未验证）。**

### 9.1 积木盒

1. **两级分类**。第一级横向滑动的页签，按颜色：`常用` `变量` `运算` `流程` `函数` `文字` `列表` `字典` `类` `出错` `等待` `我的积木`，后面跟着每个“用上”的库一个页签。
   第二级是页签里的小标题（“列表”里：读 / 改 / 拿函数来处理），一屏只放一级的内容，上下滑。
2. **“常用”页签排第一**：自动放“这个项目里用得最多的 12 块”＋“我按住加了星的”。新项目里是固定的一套入门积木。大多数时候不用离开这个页签。
   （实现时定的：统计的是当前这份积木文档；数字 / 文字 / 是否这种“光杆”的值不算进“用得最多”——每个空槽里本来就有一个。）
3. **搜索**：页签那一行最左边一个放大镜，点了以后这一整行换成搜索框（实现时改的：常驻一个搜索框要多占一行，默认档 248 高里就放不下两排积木了），按积木上的字搜，也按别名搜（“循环”“for”“遍历”都能搜到“对每一项”）；结果直接能拖。
4. **按语言隐藏**：选的语言里用不了的积木默认**不显示**（不是变灰一大片），页签底部一行“还有 3 块在 PHP 里用不了 ›”，点开才看到灰的和原因。
5. **入门 / 全部 开关**：默认“入门”只显示约 40 块（值、变量、运算、如果、重复、对每一项、函数、常用的文字列表操作＋当前项目类型的库）；
   切到“全部”才有类、异步、模块这些。画布上已经用到的高级积木不受开关影响。
6. **一块顶多块**：`＋ − × ÷`、`＝ ≠ ＜ ＞`、“转大写 / 小写”这类用积木上的下拉切换（现在的 `bin` 已经是这样），积木盒里只占一个位置。109 块在盒里实际约 70 个位置。
7. **就地补全**：点一个空槽时，下面弹出“这个槽常放的东西”（类型合适的变量、参数、最近用过的值积木），点一下就填，不用回积木盒拖。

### 9.2 定义在画布上怎么摆

1. **一个函数一串**，和事件串并排摆在画布上（现在的自由画布已经支持很多串）。
2. **折叠**：每一串的帽子上有个折叠钮，折起来只剩帽子那一行。打开文档时默认只展开上次在编辑的那几串。
3. **大纲**：顶栏一个“大纲”按钮，弹出列表——事件、函数、类、变量，带搜索；点一项，画布滑到那一串并展开。这是在小屏上找东西的主要办法，比在大画布上乱拖强。
4. **类是“点进去”的**：画布上类只是一张小卡片（类名、父类、几个字段几个方法）；点开进入类自己的画布，里面上面是字段表（普通的表单行，不是积木），
   下面是“创建时”和各个方法的串。顶栏显示“画布 › 动物”，返回键回上一层。**不做**一块套着所有方法的巨型积木——390 宽里套三层就没法看了。
5. **从调用跳到定义**：长按一块自定义积木 →“看它的定义”；库里的积木 → 只读地打开库里的定义（能不能改见第 11 节问题 4）。
6. **匿名函数太长时**：值块里的口超过 5 块，提示“要不要提成一个有名字的函数”，一键转换。

### 9.3 长式子和深嵌套

- 沿用第 3 版的“太长自动折行”；再加：一个值套到第 4 层以上时，长按 →“提成变量”（自动在上面加一块“新建变量”，原处换成读变量）。
- 一块积木的宽度超过屏幕时，只在这一块里横向折行，不让整个画布跟着变宽。
- 字段、方法的下拉（“(对象) 的 [名字▾]”）：对象的类型确定时只列那个类的；不确定时列所有类的并分组，顶上可以直接打字。

### 9.4 “看代码”

顶栏的“看代码”继续保留并加强：选语言、看生成的完整文件；点代码里的一行跳到对应的积木（靠语法树节点上的“来源”）。
学的人能对照着看“这块积木在 Python 里长这样”，这是“对语言的掌握”最直接的体现。

#### 二、入口函数（给第三步）

```dart
// package:lopicode/lang/lang.dart
LangFragment langFragment(String language, List<LStmt> body, {LangHost host = const LangHost(), LangCtx? ctx});

class LangFragment {
  final List<String> declares; // 要在函数开头声明的名字（用户起的原名）：变量、常量、循环变量
  final List<String> lines;    // 代码，一行一项，不带这一层的缩进
}

// package:lopicode/lang/analyze.dart —— 生成前先检查；有错误（isError）就不要生成
LangAnalysis analyzeBody(List<LStmt> body, {Set<String> outer, Set<String> outerConsts, bool inFunction = true});
```

- `language`：`node` / `python` / `go` / `java` / `php`（`kLangTargets`）。不认识的语言、这一阶段不支持的节点抛 `LangUnsupported`（`message` 是给人看的整句话，带“第几阶段才有”）。
- 同一个函数体里分几段生成，要传同一个 `LangCtx`（循环用的临时名字才不会重）。
- `LangHost`：宿主接进来的两样东西——`call`（`LNative` 怎么写）、`stmt`（`LHost` 怎么写），以及 `allowReturn`（后端的接口函数里不许直接 `LReturn`，要用“返回响应”）。
- **在后端里不用直接调它**：把新积木降级成 `BeSLang(语句表)` / `BeXLang(式子)` 放进现有的 `BeS` / `BeX` 里就行，`BeCodeTarget` 会自己调生成器、在接口函数开头声明新名字、按需带上语言核心的小库文件。详见下面“四”。

#### 三、对照表：新积木 op ／ 表达式 e → 语法树节点 ／ 小库函数

op 名的风格跟 `backend_blocks.dart` 一致。**这些名字是这边提议的**，第三步写积木规格时照这张表；要改名只改规格那一头，语法树不受影响。

**语句（op）**

| op | 积木 | 参数（args）／口 | 降级成 |
| --- | --- | --- | --- |
| `let` | 新建变量 [n] ＝ (值) | `name`、`value` | `LLet(name, value)` |
| `const` | 新建常量 [N] ＝ (值) | `name`、`value` | `LLet(name, value, isConst: true)` |
| `setVar`（沿用） | 把 [n] 设为 (值) | `name`、`value` | 旧变量照旧 `BeSSet`；新变量 `LAssign(LTName(name), value)` |
| `setItem` | 把 (列表／字典) 的第 (k) 项设为 (值) | `of`、`key`、`value` | `LAssign(LTIndex(of, key), value)` |
| `do` | 只为了效果算一个式子（比如“末尾加一项”） | `value` | `LExprStmt(value)` |
| `if`（沿用，扩展） | 如果 … 否则如果 … 否则 | `cond`、口 `body`；**否则如果链存在 `args['elseIfs']`**：一个列表，每项 `{'cond': 式子, 'body': [积木…]}`；口 `orElse` | `LIf([LIfArm(cond, body), …每段否则如果一个 LIfArm], orElse: …)`。没有 `elseIfs` 的旧积木照旧走 `BeSIf` |
| `switch` | 按 (x) 分情况 | `value`；`args['cases']`：列表，每项 `{'is': 式子, 'body': [积木…]}`；口 `orElse` | `lSwitch(临时名, value, [LIfArm(is, body)…], orElse: …)`——x 存进一个临时值、只算一次，然后是一串 `LIf`，比法是“等于”（`eq`）。**临时名在一个函数里不许重**（建议用积木的 id） |
| `while` | 当 <c> 时重复 | `cond`、口 `body` | `LWhile(cond, body)` |
| `forever` | 一直重复 | 口 `body` | `LWhile(null, body)` |
| `forCount` | [i] 从 (a) 数到 (b) 每次加 (s) | `name`、`from`、`to`、`step`、口 `body` | `LForCount(name, from, to, step, body)` |
| `forEach`（沿用，扩展） | 对 (列表) 的每一项 [x]（序号 [i]） | `list`、`name`、可选 `index`、口 `body` | `LForEach(list, name, body, index: index)`。旧的（把每一项赋给已声明的变量）照旧走 `BeSForEach`；要用新路又想沿用“赋给已有变量”，传 `reuse: true` |
| `forPairs` | 对 (字典) 的每一对 [键] [值] | `dict`、`key`、`value`、口 `body` | `LForPairs(dict, key, value, body)` |
| `repeat`（沿用） | 重复 (n) 次 | `times`、口 `body` | 旧路 `BeSRepeat`；口里有新积木（尤其“跳出／跳过”）时走新路 `LRepeat(times, body)`，“跳出／跳过在不在循环里”的检查才算得对 |
| `break` | 跳出循环 | — | `LBreak()` |
| `continue` | 跳过这一轮 | — | `LContinue()` |
| `note`（沿用） | 注释 | `text` | `LNote(text)` |
| `listPush`、`listInsert`、`listRemove`、`listSet`、`dictSet`、`dictRemove` | 原地改列表／字典 | 同小库函数的参数名 | `LExprStmt(LRt(同名函数, 参数))` |

**式子（e）**

| e | 积木 | 降级成 |
| --- | --- | --- |
| `listLit` | 列表 [ … ] | `LListLit(items)` |
| `dictLit` | 字典 { 键: 值 … } | `LDictLit([LDictEntry(键, 值)…])`（键可以是任何式子，文字化后当键；重复的后面盖前面） |
| `index` | (x) 的第 (k) 项／键 | `LIndex(of, key)` → 小库 `item` |
| `and`、`or` | 并且／或者（短路） | `LLogic('and' ｜ 'or', l, r)`。**注意**：旧积木的 `bin` 里 `and`／`or` 是两边都算（`allOf`／`anyOf`），照旧；新积木用这两个 |
| `cond` | 如果 <c> 就是 (a) 否则是 (b) | `LCond(cond, then, orElse)` |
| `neg` | 负 (x) | `LUnary('neg', x)` |
| `not`（沿用） | 不是 <a> | 旧路 `isNot`；新路 `LUnary('not', x)` |
| `bin`（沿用）＋ `**` | ＋ − × ÷ 余数 乘方、比较 | 旧路照旧；新路 `LBinary(op, l, r)`，op 是 `+ - * / % ** == != < <= > >=` → 小库 `add sub mul div mod pow eq ne lt le gt ge` |
| `var`（沿用） | 读变量 | 旧变量 `BeXVar`；新变量 `LName(name)` |
| 字面量 | 数字、文字、是否、空 | `LLit(值)` |
| 其余每个小库函数一个 e，名字就是函数名 | 见下表 | `LRt(函数名, 参数)` |

**小库函数（`LRt`）**——55 个第 1 阶段的 ＋ 8 个先占位的。规矩的全文在 `lib/lang/rt.dart` 每个函数的说明里。

| 类别 | 函数 |
| --- | --- |
| 类型（5） | `isType(x, 类型名)`（number／text／bool／null／list／dict）、`toNumber`、`toText`、`toBool`、`copy` |

#### 四、现有后端流水线怎么接的（取舍）

**取舍：新旧并存，不一步到位替换（按稳妥的办法先做，可改）。** 理由：现有一致性测试逐字节比对 135 条请求的响应，还有测试直接调 `target.literal(…)`、`target.call(…)`、核对文件清单；一步到位把旧 IR 全换成新树，生成文本一定会变，风险和收益不成比例。第 3 阶段把后端积木改写成库时再整体换。

- 旧积木：照旧翻成 `BeS`／`BeX`，由各语言的 `BeCodeTarget` 写代码。**没用到新节点的文档，生成的入口文件、README 一个字都没变**（拿 master `a63f47c` 的生成结果逐文件比过：一致性样本和空文档、五种语言，入口文件和 README 全部相同；变的只有下面“六”里列的小库文件）。
- 新积木：翻成本目录的语法树，包进 `BeSLang(List<LStmt>)`（语句）或 `BeXLang(LExpr)`（式子），夹在同一串 `BeS`／`BeX` 里。
- 两边可以互相套（`lib/backend/backend_lang.dart`）：
  - 新节点里放旧语句：`beHostStmts(旧语句表)` 包成 `LHost`，生成时交回给后端照旧路写；
  - 新式子里放旧式子（网址参数、数据库…）：`beToLangExpr(旧式子, request: target.request)`，小库调用变成 `LNative`，生成时交回给后端的 `call`；
  - 旧语句（如果／重复／对每一项）的口里放新节点：直接把 `BeSLang` 放进语句表；旧式子里放新式子：`BeXLang`。
- `BeSLang`／`BeXLang` 做成了 `BeSNote`／`BeXLit` 的**子类**，不是 `BeS`／`BeX` 的新分支：`BeS`、`BeX` 是 sealed，现有测试（`_collectFns`）对它们做了穷尽的 switch，加分支就要改测试，而现有测试一条都不许改。第 3 阶段整体换的时候去掉这个绕法。
- 接口函数开头会多声明新节点新建的名字（`beLangDeclares`），初值是空；文档里已经声明的变量不重复声明。
- 用到新节点的工程多带一个语言核心的小库文件；没用到的工程文件清单和以前一样。
- 碰到这一阶段不支持的节点（函数、类…），后端**不让整份生成失败**：那一段留一行说明；这一段本来“怎么走都会返回”的话补一个 500 的响应，生成的代码照样能编译。

#### 五、生成时的做法和自定的数值（都可改）

- **运算全走小库**（第 11 节问题 1 的建议 A，**按建议先做，可改**）：`a + b` 生成成 `lc.add(a, b)`。只有两处用语言自己的写法：条件已经是布尔时不再包 `truthy`；“并且／或者”用 `&&`／`||`（Python `and`／`or`）保证短路。
- **Go／Java 里值一律是 `any`／`Object`**（问题 2 的建议，**按建议先做，可改**）：标的类型只用于校验，不进生成的代码。
- **声明一律提到函数开头，原处只赋值**；常量在生成的代码里和变量一样，“不许再改”只靠 L11 拦。（3.2 的表里常量写成 `const`／`final`、变量在原处声明，那是提到函数开头之前的示意；提上去以后 `const` 没法先声明后赋值，所以统一成普通变量。3.2 已加注。）
- “一定退出”的语句（返回／跳出／跳过）后面的语句不生成（Java、Go 不许有执行不到的代码）；校验给 S10 警告。
- 值版的“如果”：JS／Java／PHP 三目、Python `a if c else b`；**Go 用小库的 `lc.Pick(条件, func() any {…}, func() any {…})`**，两边包成函数、只算选中的那一边（3.3 原来写的是“临时变量加 if”，那样式子里套式子时要把整句拆开，改成了这个；3.3 已改）。
- 循环一律生成成“按遍数的循环”，不用各语言的 `for…of`／`range`（3.5 的表是示意，已加注）：
  - 从…数到…：三个数进循环前各算一次；第 k 遍的值是 `a + k×s`（不是一路累加，0.1 这种步长不走样）；遍数 `⌊(b − a) ÷ s + 1e-9⌋ + 1`，步长 0、方向不对是 0 遍，最多 2147483647 遍。
  - 对每一项：先取列表当时的一份拷贝，循环中途改列表不影响这一轮。
  - 对每一对：先取排好序的键，再逐个取值；循环中途删掉的键取到空。
  - 重复 N 次：沿用封顶 10000。
- 循环用的临时名字 `lcv<字母><编号>`；“分情况”的临时值 `lcT<名>`；变量 `v_名`（沿用）。
- 列表和字典是“同一个”，不是复制（赋给另一个变量、放进别的列表、当参数，改一处都变）；要复制用 `copy`。
- 小库里自定的规矩：位置数字化后去掉小数；`upper`／`lower` **只转 a–z／A–Z**（各语言的 Unicode 大小写表不一样）；`trim` 只去空格／制表／回车／换行四种；`template` 的 `{键}` 字典里没有、或花括号没配上就原样留着；`listSort` 数字在前按大小、其余文字化后按码点、一样的保持原来先后；`sqrt` 负数得 0；`pow` 结果不是有限的数得 0；`random` 两边去掉小数后含两头，反着给也行；`repeatText`／`range` 封顶 10000；`dictOf` 最后落单的键丢掉；`fromJson` 解析失败、套超过 64 层得空；数字写出来的样子沿用第 3 版（12 位有效数字，所以 `0.1 + 0.2` 是 `0.3`）。
- 3.11 说“写到不存在的位置抛错（能被‘试着做’接住）”：现在会抛，但“试着做”第 6 阶段才有，所以这一阶段抛了就是整个程序／这次请求出错收场。

#### 一、多口积木

**一块积木的口由三样拼成（都可以没有）**：

| 哪一截 | 规格里怎么写 | 存在哪 | 个数 |
| --- | --- | --- | --- |
| 开头口（“那么”“试着做”） | `LcBlockSpec.bodyLabel` | `body` | 0 或 1 |
| 中间的段（“否则如果 <c>”“是 (v) 时”“出错了”） | `LcBlockSpec.arms: LcArmSpec(...)` | `arms[i].args` ＋ `arms[i].body` | `min`…`max` |
| 收尾口（“否则”“都不是”“最后总要”） | `LcBlockSpec.elseLabel` | `else` | 0 或 1；`tailOptional` 时用户能收起 |

**规格怎么写**（`lib/lowcode/logic_blocks.dart`）：

```dart
// 如果 … 否则如果 … 否则
'if': LcBlockSpec('if', '如果', '流程', [cond], bodyLabel: '那么', elseLabel: '否则',
    arms: LcArmSpec('否则如果', [cond], tailOptional: true)),
// 按 (x) 分情况：没有开头口（不给 bodyLabel），最少 1 段
'switch': LcBlockSpec('switch', '分情况', '流程', [LcArgSpec('x', '看谁', LcArgKind.expr)], elseLabel: '都不是',
    arms: LcArmSpec('是…时', [LcArgSpec('value', '值', LcArgKind.expr)], min: 1, tailOptional: true)),
// 试着做 / 出错了 / 最后总要：段不带参数，正好 1 段（不出“＋ / −”），收尾口能收起
'try': LcBlockSpec('try', '试着做', '出错', [], bodyLabel: '试着做', elseLabel: '最后总要',
    arms: LcArmSpec('出错了', [], min: 1, max: 1, tailOptional: true)),
```

`LcArmSpec(label, args, {min = 0, max = 16, tailOptional = false})`：`label` 用在“加一段“…””“删掉这一段？”里；`args` 每段各存一份；
到了 `min` 不给删、到了 `max` 不给加；每块积木不管规格怎么写最多 32 段（`LcBlock.maxArms`，自定，防坏数据）。
测试用的完整例子在 `test/support/blocks_fake_host.dart`。

**宿主要实现什么**（`lib/blocks/block_host.dart`，都有默认实现）：

- `blockSpec(op)` 返回带 `arms` 的规格——只这一样是必须的。
- `armSentence(op)`：段横栏上的话，如 `'否则如果 {cond}'`、`'是 {value} 时'`、`'出错了'`。不给就是“段的名字 ＋ 各参数”。
- `newArm(block)`：点“＋”时新的一段。默认按规格给每个参数填 `defaultExpr`，一般不用覆盖。
- `newBlock(op)`：从积木盒拿出来时带几段由它定（“分情况”建议带 1 段 ＋ 收尾口）。
- `issues`：问题要标到某一段的槽上，`BlockIssue.arg` 填 `lcArmArg(段号, 参数名)`（即 `'@0:cond'`）；标到段里的积木，`path` 里那一步用 `lcStep(i, arm: 段号)`。
- 增减段、收起收尾口都走 `host.edit`，一次＝一条撤销记录，宿主不用另外做什么。

**存盘长什么样**（`LcBlock.toJson`，键的顺序固定：op, args, body, arms, else, noElse）：

```json
{"op": "if", "args": {"cond": {"e": "bool", "v": true}},
 "body": [ … ],
 "arms": [ {"args": {"cond": { … }}, "body": [ … ]}, {"args": {"cond": { … }}, "body": []} ],
 "else": [ … ]}
```

- `arms` 只在有段时才写；`noElse: true` 只在收尾口被收起时才写。所以**旧文档（只有 body / else 的如果）读进来再写出去一个字节都不变**（测试守着）。
- 收起收尾口时如果里面有积木，会先问一句再删（和删一段一样）。
- 读的时候：`arms` 不是列表、某一段不是对象、`args` / `body` 类型不对——坏的那一截当空的，不崩；超过 32 段的丢掉。
- 路径：`LcBlockStep` 这个 record 多了一个 `arm` 字段（`-1`＝不在段里）。**一律用 `lcStep(index, inElse:, arm:)` 造**，不要写字面量 `(inElse: …, index: …)`——那样现在编译不过。
  语言核心那边（`lib/lang`）如果有字面量，合并时会报编译错，改成 `lcStep` 即可。
- 遍历顺序（`visitBlocks`）：自己 → 开头口 → 各段 → 收尾口。

**接新规格时还要补的地方**（现有两个宿主没有段，这次没动，它们只认 `inElse`）：
`lib/backend/backend_text.dart:163-164`、`lib/lowcode/logic_text.dart:156-157`（读法）、`lib/backend/backend_validate.dart:254`、`lib/lowcode/logic_validate.dart:251`（按路径找积木）。
生成代码的地方同理：要自己遍历 `block.arms`。

**积木上的样子和手势**（自定的数值）：

- 段的横栏：带槽的和积木头一样高；不带槽的（“出错了”“否则”）是矮横栏。口与口之间就是原来“否则”那种横栏，凹凸不变。
- 每段横栏右端一个“−”（圆直径 20，点击范围 44×40）；到了最少段数就不出。收尾口横栏右端的“−”＝收起它。
- 能加的时候积木底条加高到 30，左端一个“＋”；点了：只能加一种时直接加，“加段”和“加回收尾口”都行时弹两项的小菜单。
- 段里有积木时删之前先问。积木盒里的样品不画“＋ / −”（那里点不了）。
- 拖进任意口、从任意口拖出、让位、落点剪影、校验标记、撤销重做、长按 280ms 拿起、单指滑动只平移——和原来两个口时是同一套代码，测试逐项守着。

#### 二、入口（给第三步）

```dart
// package:lopicode/backend/backend_lang.dart
BeProgram beWithFunctions(BeProgram program, List<LFuncDecl> functions); // 给翻好的后端加上文档级函数；空表原样返回
LHostUse  beHostInspect(Object payload);                                 // 一句旧语句读了／改了哪些变量、用没用“这次请求”
LangScope beRouteScope(BeRouteProgram r, List<LFuncDecl> functions);     // 生成器自己用，第三步一般不用碰

// package:lopicode/lang/lang.dart
LangFunctionsAnalysis analyzeFunctions(List<LFuncDecl> functions,
    {Set<String> outer, Set<String> outerConsts, LHostInspect? inspect, bool hostAllowed = false});
LangAnalysis analyzeBody(List<LStmt> body, {…阶段 1 的参数…,
    Iterable<LFuncDecl> functions, Map<String, LFuncSig> signatures, LHostInspect? inspect});
```

第三步的做法：

1. 把文档里每个“定义”帽子降级成一个 `LFuncDecl`（函数体里的旧积木用 `beHostStmts` 包、旧式子用 `beToLangExpr` 转，和阶段 1 一样）。
2. `fa = analyzeFunctions(函数表, inspect: beHostInspect)`：`fa.issues` 是函数这一边的问题；`fa.functions[名字]`（`LFuncInfo`）给出
   `returnsValue`（有没有返回值）、`returnType`、`returnsBool`、`minArgs`／`maxArgs`、`unusedParams`、`calls`、`recursive`、`hostNames`／`natives`／`hostStmts`／`hostReturns`。
   调用积木的形状：`resolveLookShape(look.shape, hasValue: info.returnsValue, returnsBool: info.returnsBool)`。
3. 每个接口体：`analyzeBody(体, outer: 文档变量, functions: 函数表, signatures: fa.signatures, inspect: beHostInspect)`；它的 `usedFunctions` 是这个接口用到的函数。
4. “没人用的函数”（L14）要看所有接口：`fa.unusedIssues({所有接口的 usedFunctions 并起来})`。（`analyzeModule` 自己就是这么做的，后端有多个接口所以拆开给。）
5. 没有错误再生成：`target.generateProgram(beWithFunctions(program, 函数表))`。函数排在接口前面，由 `BeCodeTarget.moduleFunctions(program)` 写（五个 target 的 `entrySource` 都接好了）；函数里出现这一阶段还不支持的节点时，那个函数留一行说明、函数体是空的，整份照样生成（和接口的做法一致）。

**没有函数的文档，生成结果一个字不变**（有测试守着：`beWithFunctions(p, [])` 就是 `p` 本身，五种语言的生成结果和不走这条路的完全相同；阶段 1 的一致性测试、codegen 测试一条没改）。

作用域：每个函数体是自己的一层；接口体仍是一层。函数里能用：自己的参数和变量、别的函数（排在后面的也行）、里层匿名函数能读能改外层的变量。函数里**看不见**接口的变量和文档变量（文档变量是每个接口各一份的局部变量，不是模块级的），也不能用“这次请求”——见下面的 L15。接口体里的匿名函数能读能改接口的变量、能用“这次请求”。

#### 三、对照表：op ／ e → 语法树节点（建议第三步用的名字）

| 积木 | 名字 | 节点 |
| --- | --- | --- |
| 帽子“定义 [名字]（参数…）”（文档顶层的一串） | op `defFunc` | `LFuncDecl(name, params, body)`；参数 `LParam(name, defaultValue: LLit?, type: LType?, rest: bool)` |
| 返回 (值) ／ 返回 | op `return` | `LReturn(value)` ／ `LReturn(null)` |
| 调用，语句型 | op `callStmt` | `LExprStmt(LCall(LName(函数名), args))` |
| 调用，值型／是否型 | e `call` | `LCall(LName(函数名), args)` |
| 调用放在变量里的函数 | e `callValue`（语句型 op `callValueStmt`） | `LCall(任意式子, args)` |
| 匿名函数（带函数体） | e `lambda` | `LLambda(params, body)` |
| 匿名函数（短写法） | e `lambdaExpr` | `LLambda.short(params, expr)` |
| “[名字] 这个函数本身” | e `funcRef` | `LName(函数名)` |
| 参数 | e `param` | `LName(参数名)`（和变量一样） |
| 8 个列表操作 | e `listMap`、`listFilter`、`listReduce`、`listFind`、`listEvery`、`listSome`、`listSortBy`；op `listEach` | `LRt(同名, [列表, 函数(, 初始值)])` |

名字怎么认：`LName(x)` 先找变量（参数、本函数的变量、外层函数的变量、模块级变量），找不到再找函数。所以变量可以盖住同名的函数。

8 个列表操作的规矩（五种语言一样）：开始时先抄一份列表再走（回调里改原列表不影响这一趟）；`listEvery`／`listSome`／`listFind` 碰到结果就停；`listReduce` 的回调是 `fn(累计, 项)`；`listSortBy` 是稳定的、每一项只调一次给分函数、分的比法同 `listSort`（数字在前）；回调里出的错原样往外传；第二个参数不是函数报“这不是函数，不能调用”。

#### 四、生成时的做法和自定的数值（都可改）

- **名字**：有名字的函数生成成 `f_名字`（和变量的 `v_名字` 同一个办法，撞不上保留字）；带体的匿名函数先定义成 `lcF1`、`lcF2`…（它的参数表在 Go／Java 里叫 `lcA1`…），再在用的地方写名字；短写法就地写。测试用的整份脚本里是 `f{模块号}_名字`、模块级变量 `g{模块号}_名字`。
- **函数一律有返回值**：没写“返回”的函数返回空（Node／Go／Java 末尾补一句，Python／PHP 天然如此）。所以“把没有返回值的函数当值用”得到空，五种语言一致。
- **直接调用**生成原生调用（`f_名字(a, b)`）。**默认值**：Node／Python／PHP 用语言自己的默认参数；Go／Java 在调用处补齐。**剩下的全收**：Node `...xs`、Python `*xs`、PHP `...$xs` 进来后转成列表；Go／Java 的函数就收一个列表，调用处包成 `listOf(…)`（设计稿原写 `xs ...any`／`Object... xs`，这样改是为了函数值的调用和直接调用走同一个签名）。
- **函数值**：只有“函数当值用”的地方才包一层小库的函数值——`fn(名字, 最少几个, 最多几个, 实现)`，调用走小库的 `call`（查个数、查是不是函数）。五种语言都这么做（设计稿原写 JS／Python 直接用原生函数；统一包一层是为了出错的话、转文字的结果五种语言一样）。Go：`lc.NewFn`／`lc.Call`／`lc.Arg`／`lc.ArgOr`／`lc.Rest`，类型 `*lc.Fn`；Java：`LcLang.fn`／`LcLang.call`／`arg`／`argOr`／`rest`，类型 `Lc.Fn`；PHP：类 `LcFn`、`lc_fn`／`lc_call`。
- **函数值的规矩**：转文字是 `[函数 名字]`（匿名的 `[函数]`）；输出 JSON 当空；“类型是 函数 吗”认它；相等＝同一个值，或者是同一个有名字的函数。
- **闭包**：JS／Go 原生。Python 里层改外层变量加 `nonlocal`，改模块级变量加 `global`。Java 被里层用到并且有人改的变量装进一格的盒子 `final Object[] v_x = {…}`、读写变 `v_x[0]`；参数要装盒时参数改叫 `lcP_名字`；里层的变量和外层重名时里层改叫 `v{层数}_名字`（Java 不许 lambda 里的局部变量和外面重名）。PHP 用到的外层变量全部按引用写进 `use (&$x)`，模块级的写 `global`；PHP 不用箭头函数（它按值抓变量）。
- 调用时参数个数不对：能在生成前查出来的由 L02 拦；查不出来的（调变量里的函数）运行时报“调用函数时给的参数个数对不上”。调的不是函数报“这不是函数，不能调用”。
- 函数名只差大小写也算重名（PHP 的函数名不分大小写）。
- 外观模型：一块积木最多 32 个槽、一个下拉最多 64 个选项（多出来的读的时候丢掉）。

| L14 | 警告 | 没人用的函数（只有自己调自己的也算）、没用到的参数 |
| **L15**（新加） | 错误 | 函数里用了宿主的东西：“这次请求”，或“返回响应”这类会结束接口的语句。提示“当参数传进来”。宿主觉得可以时传 `hostAllowed: true` 关掉 |
| S11 | 警告 | 推广了：有返回值的函数有的走法没有返回值（包括带值和不带值的“返回”混用）。匿名函数也查 |

G03、L04、L11、L13、S10 在函数体和匿名函数体里照样查（“跳出”不能穿过函数）。类型推断：函数的返回类型由各个“返回”的值合出来，调用式的类型跟着被调函数走（互相调用的几个函数一起推，推不动就是“说不准”）。

**内联口**：这一阶段不做，划到**第 3 阶段**（和回调口、收尾型、帽子型一起，库才需要）。位置留好了：`CustomSlotKind.inlineMouth`（现在用它，`validateLook` 报 B08“还不能用”）和 `LFuncInfo.recursive`（这个函数会不会绕回自己）；第 3 阶段加一条“带内联口的定义不许递归”只要把这两样接起来。

**类型标注**（第 11 节问题 2）：`LParam.type`、`LFuncDecl.type` 只存不用，不影响生成，也不参与检查。**按建议先做，可改。**

#### 六、“我的积木”的外观：存盘格式

一块自定义积木＝一个 `LFuncDecl` ＋ 一个 `CustomBlockLook`。存盘是一个 JSON 对象，键的顺序固定；以后只增字段不改名；读的时候每个字段先判类型，坏的那一截当默认值、坏的槽逐条跳过，不崩：

```json
{"name": "问好", "shape": "auto", "template": "向 {名字} 问好 {次数} 次", "colorKey": "custom", "hint": "打几声招呼",
 "slots": [{"name": "名字", "kind": "value"},
           {"name": "次数", "kind": "value", "defaultValue": 1},
           {"name": "语气", "kind": "choice", "options": ["客气", "随便"], "defaultValue": "客气"}]}
```

- `shape`：`auto`（默认，按定义自动选）、`statement`、`value`、`boolean`；`cap`（收尾型）、`hat`（帽子型）只占位，第 3 阶段才能用。
- 槽的 `kind`：`value`、`boolean`、`choice`（下拉，传给函数的是选中的那段文字）；`inlineMouth`、`callbackMouth` 只占位，第 3 阶段才能用。
- `hint` 是空、`options` 是空、`defaultValue` 是空时不写这个键。`slots` 里没列到的参数按“值槽、没有先放的内容”算。
- 模板：`{参数名}` 是槽，`{{`、`}}` 是花括号本身；`parseLookTemplate` 切成“字”和“槽”，`formatLookTemplate` 拼回去，`defaultLookTemplate(名字, 参数表)` 给没写模板时的样子。
- `validateLook(look, 参数名表)` 的规则 B01–B09（B＝积木外观）：B01 没名字、B02 模板里的槽不是参数、B03 有参数在模板里没有槽、B04 同一个参数出现两次、B05 槽表里有不是参数的名字或列了两次、B06 下拉没有选项或选项空／重复、B07 先放的内容和槽的种类对不上、B08 用了第 3 阶段才有的外观；B09 是警告（模板里一个字都没有；形状和定义对不上）。
- 改参数联动（`custom_block_edit.dart`）：`remapCallArgs(oldParams, newParams, origin, args, fill)` → 新实参表 ＋ 被丢掉的内容清单（`DroppedArg`）；`origin[i]` 说新参数 i 是原来的第几个（新加的是空）；编辑器不记来历时用 `paramOriginsByName` 按名字对。`remapCallArgsByName` 是按名字存实参时用的；`remapLook` 让外观（模板、槽表）跟着参数表变。

#### 七、行为变化

- **没有函数的文档：入口文件一个字不变。** 但各语言的**基础小库文件**（`lc_runtime.js`、`lc_runtime.py`、`lc/values.go`、`Lc.java`、`lc_runtime.php`）多了几行认“函数值”的代码（转文字、判类型、比相等、输出 JSON），所以重新生成的工程里这几个文件的内容会变；对现有积木的行为没有影响（现有的一致性测试全过）。
- 文档里有函数时，即使接口里没用新积木，工程也会带上语言核心的小库文件。
- `kLangStage` 从 1 变成 2：函数、调用、匿名函数、8 个列表操作不再报“第 2 阶段才有”。
- `LangAnalysis` 的私有构造改名 `LangAnalysis.raw`（`lib/lang` 内部用）。

#### 八、测试

#### 九、测试里查出来、当场修掉的问题

- **阶段 1 留下的**：`lAlwaysReturns`（“这一串语句是不是怎么走都返回了”）只看最后一句。“返回”后面还跟着别的语句时（生成器本来就不翻译后面的），它说“没返回”，于是函数／接口末尾又补一句返回——Java 里这一句执行不到，**编译不过**（`unreachable statement`）。阶段 1 的接口体同样会中（新节点里“返回响应”后面还有语句）。改成从前往后看、碰到第一句“一定出去了”的就定；检查器的 S11 也不再对这种写法误报。加了真跑的用例和单元测试。

## 11. 需要你定的 5 件事

每件都给了我的建议；你回“都按建议”也行。

> 2026-11-25：你说“开始吧”，五件都**按建议先做，可改**。阶段 1 做到的：问题 1 现在全走小库（即 A，C 的开关留到第 8 阶段）；

**问题 1：生成的代码，要“各语言结果完全一样”，还是“像人手写的”？**
- A. 一致优先：全部走小库（`lc.add(a, b)`）。五种语言结果保证一样，但代码不好看、学不到各语言真正的写法。
- B. 地道优先：直接写 `a + b`。好看，但同一份积木在不同语言里可能算出不同的结果（比如 `"3" + 4`）。
- C. **（建议）混合**：类型确定的地方写原生的，说不准的地方走小库；“看代码”里加个开关可以看“全走小库”的版本。先按 A 落地，第 8 阶段再开 C。

**问题 2：Go / Java 这种要写类型的语言，要不要让用户标类型？**
- A. 必须标：代码最地道，但每个变量、参数都要选类型，手机上很烦，初学的人会被劝退。
- B. 完全不标：全是 `any` / `Object`。
- C. **（建议）可标可不标**：不标就按“任意”生成，标了就用原生类型并多做检查；只有接原生框架（比如 Spring Boot）的那几个槽必须标。

**问题 3：类在画布上怎么摆？**
- A. 一块大积木，方法都套在里面（Scratch 那种一眼看全的感觉，但 390 宽里会非常挤）。
- B. **（建议）一张卡片，点进去是它自己的画布**（字段是表单，方法各一串），顶栏显示现在在哪一层。

**问题 4：内置库里的积木（比如“返回数据”），用户能不能点进去改？**
- A. 完全打不开（简单，但违背“剩下的都是封装”的本意）。
- B. 能直接改（灵活，但改坏了所有项目一起坏，升级应用时也会冲突）。
- C. **（建议）能点进去看（只读）＋“复制一份来改”**：复制出来的归项目自己，原来的不受影响。

**问题 5：框架版（Express / FastAPI / Spring Boot）先做哪个、做不做？**
- 要知道的事：框架版要在手机上联网装包（Express 几 MB，Spring Boot 要 Maven 或 Gradle、上百 MB），而且每个框架只支持它自己的语言。
- A. **（建议）先不做任何真框架**：第 5 阶段把“小路由”（7.1，零依赖、五种语言都能跑）做成内置示例库，证明“用基础积木能搭出框架”；
  第 7 阶段再接**一个**真框架，建议 Express（包最小、和现在生成的 Node 最接近），其余的等你要再做。
- B. 三个都做。工作量大约是 A 的三倍，Spring Boot 在手机上跑起来的把握不大（未验证）。

另有三件我先自己定了、你不同意随时说：位置从 0 开始数（3.11）；字典按键的字母顺序遍历（3.1）；不做在线积木商店（5.4）。
